# 開いている間の監視フォルダの見張り（今の決め事）

> **要点**：設定「開いている間も、監視フォルダに置かれたファイルを探す」（既定は切）を入れると、アプリを開いている間に監視フォルダへ置かれた新しいファイルに気付き、
> 既定は下の帯で件数を知らせる。設定「見つけたら、そのまま取り込みを始める」（既定は切。親が入のときだけ押せる）を入れると、帯の代わりにそのまま取り込む。
> 取り込みは人が始めた取り込みと同じ道・同じ優先度。切なら前と全く同じ（新着を見るのは起動時と「新しいファイルを取り込む」を押したときだけ）。
>
> **ユーザ判断 2026-11-13**（plan 49）：「常時監視自体にオンオフをつけて、そのうえでオンの時は既定で帯を出し、設定から自動取り込みを許可できるようにしよう。優先順位は普通の取り込みと同じで良いと思う。」
>
> **コード**：`Core/Scanning/LiveFolderWatch`（見張りの回り）・`FolderEvents`（`FileSystemWatcher` を包んだ物と差し替え口）・`FileSettleProbe`（書き終わったか）・`FolderWatch`（新しいかの判定。起動時と同じ）、
> `App/ViewModels/MainViewModel.LiveWatch.cs`（張る・止める・帯・自動の取り込み）、`AppServiceContainer.CreateLiveFolderWatch`（試験は作り物）。試験は `LiveFolderWatchTests`・`LiveWatchNoticeTests`

## 何を新しいと数えるか

- **出来事は「探し直すきっかけ」だけに使い、中身を信じない。**新しいかは起動時と同じ `FolderWatch.FindNewAsync` で決め直す（走査の控え・外した物・商品に紐付けたフォルダ・まだ取り込んでいない物。BOOTH の不調で取れなかった物は取り直すまで新しい。[import.md](import.md)）。
  Windows の見張りは、あふれると出来事を落とし、改名を削除と作成に分けて届けることがある。毎回判定し直せば、取りこぼしても次の探し直しで拾える。
- 帯の件数は今の新着の全部（起動時の知らせ・取り込み画面の「新しいファイルが n 件あります」と同じ一覧）。［取り込む］は取り込み画面の「新しいファイルを取り込む」と同じ道で、押した時に探し直して取り込む（帯に出した一覧を使い回さない）。
- 出来事を数えない物：保存先の中（保存先が監視フォルダの中にあると、アプリが書くたびに探し直してしまう）、ダウンロードの途中の名前（`.crdownload`・`.part`・`.partial`・`.opdownload`・`.download`・`.tmp`。出来上がると改名の出来事が来る）。

## 待ち方（数字の根拠はコードのコメント）

| 待ち | 長さ | 何のため |
|---|---|---|
| 静けさ | 5秒 | 最後の出来事からこれだけ何も来なければ探す。続けて置かれた物（コピー・展開で数百の出来事）を1回にまとめる。待つ間に来たら待ち直す |
| 落ち着き | 2秒 | 新着の大きさと更新日時を2回見る間。同じで、書いている途中の印が無ければ書き終わった |
| 張り直し | 30秒 | 壊れた見張りを張り直してみる間（フォルダが在るかは3秒で打ち切る `FilePresenceProbe`） |
| 確かめ直し | 60回まで | 書いている途中の物が残ったとき、出来事を待たずに静けさごとに確かめ直す回数（約5分）。それより長いダウンロードは出来上がった時の改名で拾う |

- **書いている途中と見る物**：隣にダウンロードの途中のファイルがある（Firefox は出来上がる名前の空のファイルを先に作る）・書き込みの共有を許さずに開けない（掴まれている）・2回見た大きさか更新日時が違う。途中の物は渡さず、落ち着いた物だけ渡す（ずっと掴まれた物でほかを止めない）。
- **オンラインのみの物は開かない**（開くとダウンロードが始まる。走査もこれを数えない）。権限が無くて開けない物は途中と見ない（取り込みが「読めなかったファイル」として数える）。

## 知らせる・取り込む

- **既定は帯**（`MainWindow` の下の帯。取り込みの帯と同じ場所・同じ見た目）：「監視フォルダに新しいファイルが n 件あります。」［取り込む］［×］。
  × は「知らせなくてよい」と同じ（同じ顔ぶれの指紋を覚え、その間は出さない。何か増えたらまた出す・G16）。取り込み画面では出さない（同じことがその画面に出ている）。新着が無くなれば下げる。
- **自動の取り込み**：落としたときと同じ取り込みの道（`ImportViewModel.AddDroppedPaths`）で始め、画面は移さず取り込みの帯に進み具合を出す。押していないので展開先のファイルは窓で尋ねず通知に出す・「監視しますか」も聞かない（起動時の自動の取り込みと同じ・G2）。
  - **優先度は人が始めた取り込みと同じ**：取り込みの梯子が段を決める（①②は `BoothPriority.Metadata`）。ここでは優先度を張らない。BOOTH への問い合わせは取り込みの梯子と門（`BoothClient`・`BoothMachineGate`）を通るだけで、新しい通信の道は無い。
  - **見張り始めた後に現れた物だけ**を取り込む。見張り始めたときに控えた新着（場所・大きさ・更新日時の指紋）は、関係の無いファイルが1つ置かれたのをきっかけに取り込まない（前から置いてあって取り込まずにいた物・「知らせなくてよい」にした物）。それは起動時の確かめと「新しいファイルを取り込む」で今までどおり扱う。中身が変わった（大きさか日時が違う）物は現れた物。
  - **同じ物は開いている間に2度は自動で始めない**。BOOTH の不調で取れなかった物・読めなかった物は取り込みの後も新着に数えられるので、探し直すたびに始めると不調の BOOTH へ問い合わせを重ねる。取り直しは下の帯の「続きから進む」。
- **取り込み中に見つけた物は、終わってから知らせる・取り込む**（今の取り込みに黙って混ぜない）。走っているか・立ち上げの途中か（`ImportRunner.IsBusy`）を見張りが探す前後と、画面が受け取る時の3か所で見る。終わったら（`ImportRunner.Finished`）、預けた物があるときだけ探し直す（その間に取り込まれた物は新しくなくなっているので、一覧を使い回さない）。取り込みは1本ずつ（2本目は起こさない）。

## 張る・止める

- 張るのは主画面を作ったときだけ（設定が入で監視フォルダがあるとき）。画面の無い起動（通知領域だけ）・API・MCP では張らない。窓を隠して通知領域にいる間は主画面が残るので見張り続け、自動の取り込みも走る。
- 設定を切る・監視フォルダが0個になると止める（帯も下げる）。入れ直すと張る。監視フォルダを足し引きすると張り直す（見張り始めの控えも取り直す）。「そのまま取り込む」の切り替えは張り直さず、次に見つけた時から効く。
- 閉じる・保存先を変える（`MainViewModel.StopBackgroundWork`）と止める。止めた後に届いた出来事は捨てる（見張りごとの中断の印）。
- **あふれ**（`InternalBufferOverflowException`）は探し直すだけ（見張りは生きている。受け皿は Windows の上限の 64KB）。**壊れた**（フォルダが消えた・ドライブが外れた・ネットワークが切れた）は見張りを外して探し直し、30秒ごとに在るかを見て張り直し、張り直せたら探し直す（その間に置かれた物を拾う）。張れない間も、つないだ後の起動時の確かめと「新しいファイルを取り込む」で拾える。

## 当てにならない所

- **ネットワークの場所**（共有フォルダ・NAS）：相手の作りによって出来事が届かない・遅れる・切れると黙って止まることがある。
- **OneDrive などの同期のアプリのフォルダ**：オンラインのみの物は手元に中身が無いので数えない（走査と同じ）。同期で降りてきたファイルの出来事が届かないことがある。
- どちらも、気付かなかった物は起動時の確かめと「新しいファイルを取り込む」で拾う（マニュアルにも書く）。
- 試験は作り物の見張りと手で進める待ちで確かめる（実際のファイルの出来事・時計に結果を左右させない）。本物の Windows の見張りでの手触りは、統合の側で実機で確かめる。
