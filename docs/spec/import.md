# 取り込みと BOOTH への問い合わせ（今の決め事）

> **要点**：BOOTH への問い合わせは1本ずつ、1.5秒以上空ける（**絶対に破らない**）。順番は1本の梯子
> 「人が押した通信 ＞ 指名された画像 ＞ ①JSON ②HTML ＞ ③検出 ＞ ④1枚目 ＞ ⑤残りの画像 ＞ ⑥ショップのアイコン ＞ ⑦期限の来た商品」。
> 取り込み中もアプリは使え、取り込みは積め、取り消しは即座。1商品ずつ保存するのでどこで止めても壊れない。
>
> **コード**：`Core/Scanning/ImportPipeline.cs`（周回と画像の列）・`ImportWorkSet`・`FolderScanner`・`ScanCacheIndex`・`UnresolvedMerge`、
> `Core/Booth/BoothClient.cs`（ゲート）・`BoothPriority`、`Core/Services/ImageBacklog`（⑤の再開）・`DueRefresh`（⑦）・`BoothChanges`・`UnityPackageCatalog`・`VolumeTable`
>
> **経緯**：`docs/history/import-order.md`（梯子を決めた理由）、`docs/history/import-concurrency.md`（取り込み中に使える・⑦・印）、
> `docs/history/tech-debt-2026-09-14.md` 1-2・1-3（未確定の一覧）、`docs/research/id-resolution.md`（商品IDの決め方）

## 梯子と優先度

- 全部の問い合わせは `BoothClient` の1つのゲートを通る。**並列化しない・間隔を縮めない**（相手への負担を避ける決め事で、性能の妥協ではない）。
- 優先度は引数ではなく `BoothClient.Prioritize(…)` の範囲（`AsyncLocal`）で決まる。何も張らなければ ①② と同じ段。
- 画面から押した操作は `CommandHandler` の入口で「人が押した」になる。開いただけで取る物（ショップのアイコン＝⑥・バナー＝指名された画像）はハンドラーの中で段を下げる。
- 起動時の裏の作業（⑤・持っていないアバターの画像・⑦）は人の操作ではないので `UiCommand` を通さない。
- 「この商品の画像取得を優先」はその商品の残りを全部取り切ってから戻る。割り込みはリクエストの切れ目で起きる。

## 対象と履歴（ユーザ判断 2026-09-21・G1〜G4）

- **対象は「今積んだ物」だけ。**起動時は空で、落とした物・選んだ物・履歴から積んだ物・監視の新着が入る。落としたとき・フォルダビューから始めたときは取り込み画面へ移らない（下の帯で進み具合と入口を出す。`MainViewModel.ImportNotice`）。
  前は履歴を全部「対象」に積んでいたので、1本落としたつもりでも過去に指したフォルダ全部が走っていた。
- **履歴（`ImportFolders`）は「何を読んだか」の記録**で、対象ではない。取り込み画面に別の一覧として出し、1件ずつ「対象に積む」。
  ファイルも残す（何を読んだかは確かめたい）が、**監視の対象にはしない**（監視は人が「はい」と答えたフォルダだけ）。
- **履歴と監視は1件ずつ足し引きする**（`FolderListChange` を `ChangeSettings` に渡す）。画面の一覧の写しで丸ごと書かない。
  取り込み画面は起動時に1回読んだ写しで、設定画面は保存のたびに自分の一覧で書いていて、片方で足した物をもう片方が消していた
  （2026-09-23・技術的負債 1-1 の再発）。取り込み画面の一覧は開くたびと変えた後に今の設定から並べ直す。
- **起動時の自動取り込みの対象は監視フォルダの新着だけ。**設定の説明どおり。
- **自動で始めたときは窓で尋ねない。**展開先のファイルを指していたらそのまま取り込み、**要確認に出して**後から差し替えられるようにする
  （押してもいないのに応答待ちの窓が黙って出ていた）。
- **見つからないファイルは監視フォルダの中から中身で探して結び直せる**（`MissingFileFinder`）。
  同一性はハッシュなので、移した・名前を変えただけなら戻る。大きさが合う物だけ中身を確かめる（全部をハッシュすると数百GBを読む）。

## 周回

1. 対象（`ImportWorkSet`）から走査 → 商品IDを決める → ①JSON ②HTML（全商品まとめて）→ ③対応アバターの検出。
   **①②を全商品まとめてやるのは、部分的な知識で作業を始めさせないため**（候補に種類の名前などが揃ってから）。
2. ④1枚目・⑤残り・⑥アイコンは周回の外の**画像の列**で1件ずつ取る。1件ごとに積まれたフォルダを見て、あれば次の周回へ移る。
   新しい周回の1枚目は列の先頭に入れる。
   **④の並びは検索の既定・編集の待ち行列と同じ規則**（`ItemOrder.ByAcquired`＝入手日の新しい順、同じなら商品名順。ユーザ判断 2026-09-21）。
   走査した順のままだと、絵が埋まっていく順と人が上から片付けていく順が無関係になり、待ち行列の先頭の絵だけが来なかった。
   入手日は人が手で入れたときしか入らないので、取り込んだばかりの商品は同着になる——**同着の決め手を3か所でそろえることが要点**。
3. **1枚目が取れた時点で、その商品を画面に出す**（白いカードを並べない）。取れなかったら「画像なし」として出す（消さない）。
4. 検索・要確認・未確定の一覧は勝手に並べ替えず、「取り込み中に n 件増えました（押すと反映）」を出す。画面を離れたら黙って最新にする。
5. 取り込み中は「保存先を変える」を押せない。
6. **途中で止まったままなら、どの画面からでも分かるようにする**（ユーザ指摘 2026-09-22）。下の帯に
   「前回は n / N 件まで進んで中断しました」＋［続きから進む］［続きを捨てる］を出す。**帯は常設ではない**
   ——続きが残っている間と通信している間だけで、走り出したら通信の帯に替わる（2本並べない）。
   解消するまで出し続けるのは、②が済んでいない商品は説明文が無く、③が走っていないので編集にも出てこないため
   （未確定・要確認・形式の変化と同じ扱い）。続ける気の無い人のために「続きを捨てる」で記録だけ消せる（取れた分は消さない）。
   - 「続きを捨てる」は**戻せない**ので、ツールチップと確認の窓（既定はキャンセル）で言う。やり直すには履歴の「対象に積む」から始め直せばよいことも書く
     （2026-09-23：「やめる」では何が無くなるか読めず、確認も無かった）。記録を消すのは `UiCommand.DiscardInterruptedImport`、帯は書き終わってから下ろす。
   - 「続きから進む」は**対象を積むところまでやる**。取り込み対象は次の起動で空に戻るので、
     前は「もう一度押すと続きから進みます」が**押せないボタンを指していた**。
     積むのは前回の対象だけ（`ImportState.Targets`）——履歴を全部積むと対象外のフォルダまで走査してしまう。

## 積む・取り消す・中断

- 実行中でも「今の取り込みに積む」。同じフォルダは集合なので1つになる。まだ走査していない物は一覧から外せば取り下がる。
- 取り消しは**全体を即座に**（段の切れ目まで待たない）。
- **次の起動で①②は自動では続けない**（フォルダの走査は人が指示した読み取りだけ）。中断した事実は `import-state.json` から「前回は 34 / 100 件まで進んで中断しました」と出す。①が全部済んだ後に閉じたなら出さない。
- ⑤（画像）は手元の JSON だけで対象が決まるので、起動時に再開してよい（設定「起動したとき、裏で取得を始める」で切れる）。
- 取得済みでも説明のファイルが無い商品は②の対象に戻す（説明が無い商品には空のファイルを置く）。

## 走査と手元のファイル

- ハッシュは「パス・大きさ・更新日時」が `scan-cache.json` と同じなら計算しない。
- 走査で飛ばす再解析点は**ジャンクションとシンボリックリンクだけ**（ループの元）。OneDrive の中はフォルダもファイルも再解析点なので、前は丸ごと飛んでいた（2026-09-23）。
  **中身が手元に無いクラウドのファイル（オンラインのみ）は読まない**——ハッシュを取るとダウンロードが始まる。**勝手にダウンロードはしない。**
  数は取り込みの結果に「N 件は OneDrive の『オンラインのみ』なので読めませんでした」と次の手（フォルダを「常にこのデバイスに保持する」にする）を添えて出し（0件なら出さない）、どのフォルダで何件かはログに残す（ユーザ判断 2026-09-23）。
- **ハッシュを計算できなかったファイル**（書き込み中のダウンロード・ほかのアプリが開いている物）は、走査で読めなかった物と同じ「読めなかったファイル」の数に入れて結果に出し、パスをログに残す（前は黙って飛ばしていた）。控えには書かないので次の取り込みで読み直す。
- 新しい商品を①で書くとき・未確定の「このIDで登録」・フォルダの登録は、**書く直前に読み直し、在れば booth だけを重ねて手元のファイルは足す**（L13。取る数秒の間に別の道が同じ商品を作ることがある）。
- ②は節を**今の booth に足す**（`ItemRepository.ChangeBoothAsync`）。①と②の間に人が「商品情報を取り直す」を押して今の方が新しく取れていれば（`Booth.FetchedAt` で比べる）触らない。前は①の写しで丸ごと書き、取り直した新しい booth を古い物に戻していた。
- 商品のファイルを足すとき、実在しなくなったパスは落とす（移した・消した）が、**つながっていないボリュームの上のパスは残す**（`LocalFileMerger`。外付けを外している間に同じ商品へファイルを足すと、外付けの上の記録が消えていた・2026-09-23）。
- 管理から外したファイルは、まずパスで（計算なしで）外し、知らないパスだけハッシュで突き合わせる。
- 既に商品に紐付けたフォルダの中は見に行かない。zip を展開したフォルダは元の zip と見分ける。
- 取り込むフォルダのドライブ文字と通し番号の組をその周回で控える（`volumes.json`）。

## 未確定の一覧（`unresolved.json`）

- 取り込みは周回で見つけた物で一覧を作り直すが、**丸ごと上書きしない**：前に書いた一覧と今の一覧を比べ、その間に人が外した物は戻さず、足した物は消さない（`UnresolvedMerge`）。
- **ボリュームがつながっていない取り込み元の下の未確定は引き継ぐ**（外付けを外したまま取り込んでも消えない）。フォルダが消えただけなら片付いたとして落とす。
- BOOTH に無かった（404）ファイルも未確定へ回す（手元から消さない）。
- 未確定の画面の操作（割り当て・外す・戻す）は錠の中で1件ずつ足し引きする。

## 取れなかった物

- 404だけが「非公開」の数えに入る（3回連続で確定）。タイムアウト・5xx・接続失敗は数えず、同じ実行の中で2回まで間隔を空けて（2秒→8秒）試し、だめならその回は飛ばす。429 を受けたら間隔を倍にして30秒で頭打ち。Retry-After は60秒まで付き合う。
- **①で BOOTH の不調（タイムアウト・5xx・接続失敗・200 でも読めない応答）で取れなかった商品は「続きから」に残す**（ユーザ判断 2026-09-23・#10）。
  前は飛ばすだけで、そのファイルは商品にも未確定にも入らず、ハッシュが走査の控えに載るので監視も新しいと数えず、黙って消えたように見えた。
  - `import-state.json` の `unfetched`（商品IDとファイル）に書く。**最後まで走っても空でなければ記録を消さず**、下の帯に「前回の取り込みで N 件は BOOTH の不調で取れませんでした。少し待ってから「続きから進む」で取り直せます」を出す。別の取り込みを始めても引き継ぎ、取れた・商品が既にあった・404 で未確定へ回したら外す。
  - 「続きから進む」は前回の対象と、取れなかったファイルを積む（最後まで走った回はファイルだけ）。取り直しは同じ梯子の①を通る（1本ずつ・1.5秒・優先度は変わらない）。
  - 取り込みの結果にも件数と次の手を出す。監視は取り直すまでそのファイルを「新しい」と数える（`FolderWatch`）。「続きを捨てる」はこれも消す。
- 404で取れなかった画像には `{ハッシュ}.missing` を置く。**日数では外さず、その商品の JSON を取り直したときに外す**。印の付いた画像は「決着済み」として数え、優先ボタンの代わりに「n 枚は取得できませんでした」を出す。

## ⑦ 期限の来た商品の取り直し

- `NextFetchDueAt <= 今` を古い順に、暇になってから（梯子の最下位）。間隔は7日±3日（設定画面には出さない）。連続404が3回以上なら30日（**季節ものは1ヶ月ほどしか公開されない。延ばすと原理的に取り逃す**）。
- 取り直しは画像を落とさない。増えた画像は④⑤の列に積む（人が押した取り直しも同じ経路で先頭に来る）。
- 変わっていたら要確認（`ItemUpdated`）：販売終了・価格・種類の増減・画像の増減・商品名。**スキ数と説明文は知らせない**（必ず動く・誤字直しで出る）。何が変わったかを1件に列挙する。
- 対応アバターの節が読めなくなったら `PageStructureChanged`。

## 取り込みの裏で読む物

- **unitypackage の中身**：zip の中の unitypackage を①と同時に裏で読み（小さい zip から・画面を止めない優先度）、入る先の要約を①の後で商品に写す（`UnityPackageCatalog`）。手でファイルを付けた後も同じ。
- 失敗は `logs/app.log` に残す（取り込みは止めない）。
