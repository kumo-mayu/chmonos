# 空のとき・失敗したとき・押せないとき

画面の中の決まりは [ui-rules.md](ui-rules.md)、別の窓は [ui-dialogs.md](ui-dialogs.md)。
ここは**出す物が無いとき・うまくいかなかったとき・押せないとき**に何を出すか
（ユーザ判断 2026-09-20。洗い出しの E1〜E11・`docs/feedback/ui-consistency-2026-09-20.md`）。

## 空の表示は3通りに言い分ける（E1・E2）

一覧が0件になる理由は3つあって、書くべき次の一手も3つとも違う。**真っ白のまま返さない。**

| どれか | 書くこと | 例 |
|---|---|---|
| 読み込み中 | 「読み込んでいます…」 | |
| 探して0件 | 当てはまらなかったと言い、**絞り込みを消す道**を出す | 「探している言葉に当てはまる大分類がありません。言葉を変えるか、絞り込みを消してください。」 |
| そもそも1つも無い | **ここに並ぶようにする方法**を書く | 「大分類はまだありません。上の「大分類を追加」に名前を入れるか、商品の編集画面でユーザータグを付けると、ここに並びます。」 |

絞って0件のときに「まだ見つかっていません・検出してください」と書くと、
打ち込んだ言葉のせいで消えているだけなのに、登録簿が空だと読める（アバターの管理で実際にそうなっていた）。

## 押せないときは理由を出す（E9・E11）

- 窓の確定ボタンは、**何を入れれば押せるか**をボタンの上の行に出す（`CommitHint`）。
  ボタンの列に混ぜると窓の幅からはみ出して、文の頭と終わりが切れる。
- 画面の中で押せなくなる部品は、`ToolTipService.ShowOnDisabled="True"` を付けて
  **押せないときの文**を出す（普通の説明文と差し替える。`MinHint`・`MoveBackHint`・`OpenHint` のような形）。
  付けないと、吹き出しは押せる間しか出ない。
- **まとまりごと押せなくなるとき**は、部品ひとつひとつの吹き出しより、
  見える所に1行書く方が読まれる（属性の管理の「並べ方と絞り込みは使えません」）。

## 失敗を黙って捨てない（E4）

- 走査の途中で1件ずつ起きるもの（読めないファイル・読めないフォルダ）は、**数だけ**を結果に足す。
  1件ずつ言うと何千件も出る。文には「取り込めていない」ことと、思い当たる原因（開いている・つながっていない・権限）を書く。
- 0 件のときは何も出さない。普段0の数字を常設で並べない（ナビのバッジと同じ）。

## 利用者に見せない文（E5）

組み立てのときに依存を渡し忘れた、のような**利用者の操作では起こらない**失敗は、
画面に文を出さず `InvalidOperationException` で落とす。意味の取れない文
（「〜手段が設定されていません。」）を見せても、直せるのは書いた側だけ。

## 内部の言葉を混ぜない（E6）

`CommandHandler` の失敗の文はそのまま画面に出る。`item` は**商品データ**と書く。
ほかの言い換えは `docs/research/ui-wording.md`。

## 通信の失敗は2通りに言い分ける（E3）

種類を見分けているのは通信の入口1か所で、外へ出るときには**見つからない／一時的に届かない**の2つに畳まれる。
**この2つは次の一手が違う**ので、文も2通りに分ける。

- 届かなかった：「通信を確かめて、少し待ってからもう一度お試しください」。待てば直る。
- BOOTH に無かった：「IDが違うか、販売が終わって非公開になっています」。待っても変わらない。

**0件と、届かなかったのを混ぜない。**未確定の候補の検索は、通信に失敗しても「候補がありません。商品IDを直接入れてください」と出ていた。
待てば出る物を手で入れさせることになるので、届かなかったときは専用の文にする。
