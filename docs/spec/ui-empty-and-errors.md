# 空のとき・失敗したとき・押せないとき

画面の中の決まりは [ui-rules.md](ui-rules.md)、別の窓は [ui-dialogs.md](ui-dialogs.md)。
ここは**表示するものが無いとき・うまくいかなかったとき・押せないとき**に何を表示するか
（ユーザ判断 2026-09-20。洗い出しの E1〜E11・`docs/feedback/ui-consistency-2026-09-20.md`）。

## 空の表示は3通りに書き分ける（E1・E2）

一覧が0件になる理由は3つあって、書くべき次の一手も3つとも違う。**真っ白のまま返さない。**

| どれか | 書くこと | 例 |
|---|---|---|
| 読み込み中 | 「読み込んでいます…」 | |
| 探して0件 | 当てはまらなかったことと、**絞り込みを解除する方法**を書く | 「探している言葉に当てはまる大分類がありません。言葉を変えるか、絞り込みを消してください。」 |
| そもそも1つも無い | **ここに並ぶようにする方法**を書く | 「大分類はまだありません。上の欄に名前を入れて追加するか、商品の編集画面でユーザータグを付けると、ここに並びます。」 |

絞って0件のときに「まだ見つかっていません・検出してください」と書くと、
打ち込んだ言葉のせいで消えているだけなのに、登録簿が空だと読める（アバターの管理で実際にそうなっていた）。

**空の文は `EmptyTitle`（見出し）と `EmptyNote`（説明）の型で置く**（`App.xaml`。2026-10-02 メモ6-④）。欄の幅で折り返して中央に置く（`MaxWidth` 520 は広い窓での上限）。
折り返しを指定しない文は1行ぶんの幅を要求するので、狭い窓で欄の外へ両側にはみ出して切れた（要確認の画面で幅500のとき）。
窓が左右の列の最小の合計より狭いときは画面ごと横に送るので（`ViewportFitHost`）、右の列が見えている幅の外にあるときは、その列の中央の文も見えている幅の外になる。これは文の置き方では直らない。

## 押せないときは理由を表示する（E9・E11）

- 窓の確定ボタンは、**何を入れれば押せるか**をボタンの上の行に表示する（`CommitHint`）。
  ボタンの列に混ぜると窓の幅からはみ出して、文の頭と終わりが切れる。
- 画面の中で押せなくなる部品は、`ToolTipService.ShowOnDisabled="True"` を付けて
  **押せないときの文**を表示する（普通の説明文と差し替える。`MinHint`・`MoveBackHint`・`OpenHint` のような形）。
  付けないと、吹き出しは押せる間しか表示されない。
- **まとまりごと押せなくなるとき**は、部品ひとつひとつの吹き出しより、
  見える所に1行書く方が読まれる（属性の管理の「並べ方と絞り込みは使えません」）。

## 失敗を知らせずに捨てない（E4）

- 走査の途中で1件ずつ起きるもの（読めないファイル・読めないフォルダ）は、**数だけ**を結果に足す。
  1件ずつ知らせると何千件にもなる。文には「取り込めていない」ことと、考えられる原因（開いている・つながっていない・権限）を書く。
- 0 件のときは何も表示しない。普段0の数字を常設で並べない（ナビのバッジと同じ）。

## 利用者に見せない文（E5）

組み立てのときに依存を渡し忘れた、のような**利用者の操作では起こらない**失敗は、
画面に文を表示せず `InvalidOperationException` で落とす。意味の取れない文
（「〜手段が設定されていません。」）を見せても、直せるのは書いた側だけ。

**.NET の例外の文（`exception.Message`）も画面に表示しない**（2026-09-23）。英語や内部のパス・型の名前が混ざり、
読んでも次の一手が分からない。例外の種類から分かる**考えられる原因**（`Core/Services/FailureText.Cause`：
別のアプリが開いている・空きが足りない・見つからない・権限・壊れている・届かない）と**次にやること**だけを表示し、
詳しい中身は `AppLog`（保存先の `logs\app.log`）へ書く。

## 内部の言葉を混ぜない（E6）

`CommandHandler` の失敗の文はそのまま画面に出る。`item` は**商品データ**と書く。
ほかの言い換えは [ui-terms.md](ui-terms.md)。

## 失敗の文は事象・原因・対処

何が起きたか（事象）・なぜか（原因）・どうすればよいか（対処）の順に書く。場所が足りなければ原因から削り、次に対処を削る。事象は最後まで残す。
例：「保存できませんでした。ディスクの空きが足りません。空きを作ってからもう一度お試しください。」（型と長さは [ui-writing.md](ui-writing.md)）

## 通信の失敗は2通りに書き分ける（E3）

種類を見分けているのは通信の入口1か所で、外へ渡すときには**見つからない／一時的に届かない**の2つにまとめている。
**この2つは次の一手が違う**ので、文も2通りに分ける。

- 届かなかった：「通信を確かめて、少し待ってからもう一度お試しください」。待てば直る。
- BOOTH に無かった：「IDが違うか、販売が終わって非公開になっています」。待っても変わらない。

**0件と、届かなかったのを混ぜない。**未確定の候補の検索は、通信に失敗しても「候補がありません。商品IDを直接入れてください」と出ていた。
待てば表示される候補を手で入れさせることになるので、届かなかったときは専用の文にする。

## 押した結果を必ず知らせる（I1・I2）

- **空のまま押したときに、何も知らせずに終わらない。**「名前を入れてから押してください。」のように、何が足りないかを1行で知らせる。
- **していないことを「しました」と表示しない。**既にある名前を追加しようとしたら「既にあります。」と表示し、その行を選び直す。
  前は足されていないのに「追加しました。」と表示されていた。

## 打ったものを勝手に捨てない（I3・I4・I5・I10・I11）

- **基本的な書き方は受ける。**日付は `DateText`（2026-09-20／2026/9/20／2026年9月20日／20260920／全角）、
  金額は `MoneyText`（1200／¥1,200／1,200円／全角）。
- **それでも読めなかったら、止めずに注意を表示する。**保存はして、「読めなかったので空のまま保存しました」と知らせる。
  入力を突き返すと、ほかの欄まで保存できなくなる。
- **打ちかけは消さない。**編集画面の候補付きの欄は、決める前の字も書きかけに入れる。
  アバターの管理は、行を選び直しても名前・呼び方・素体の打ちかけを覚えておく（保存したら捨てる）。
- **押さずに残る欄には、保存できたかを表示する**（「書いています…」→「保存しました。」）。
  0.8 秒待ってから書くので、打ち終えてすぐ閉じると入力が消えていた。画面を離れるときと閉じるときに、待っている分を今書く。
- **範囲の外は知らせずに丸めない。**入れられる範囲を欄の横に表示し、丸めたら「1〜365 日です。365 日にしました。」と知らせる。
- **設定の知らせの置き場**（`docs/feedback/notice-placement-2026-10-03.md`）：丸めたことはその欄のすぐ下（`FieldWarning`。出ていない間も1行ぶん空けてある）。
  割り当てを外したことはその行の横。幅を戻した・書き出し／戻す／引越しの途中経過と結果・「エクスプローラで開く」・フォルダを開けなかった・別の作業中で押せないは、押したボタンの下。
  非表示・外した記録・除外の解除は、行ごと消えるのでその一覧の見出しの横。上の段に残すのは「保存できませんでした」だけ（どの欄か決まらない）。

## 要確認：行のボタンの結果の置き場（2026-10-04・メモ20-③）

行のボタン（zipで登録しなおす・商品情報を取り直す）の途中経過と失敗は、押した行の日時の行の中（`NotificationRow.ActionNotice`。一覧を読み直して行が作り直されても、知らせのID単位で残る）。
成功（行が片付く）は、一覧の見出しのすぐ下の1行（`InboxViewModel.ListNotice`。出ていない間も場所を取る）。画面を開いたときの検出の結果は、今までどおり一覧の先頭の文。
