# タグの管理・属性の管理（今の決め事）

> **要点**：ユーザータグ（大分類・小分類）と属性の一覧を、JSON を手で直さずに育てる画面。商品は名前で参照しているので、
> 名前の変更・統合・削除は付いている商品の書き換えを伴い、押す前に件数を言う。**2つの画面の操作感は揃える**（ユーザ指示 2026-09-19）。
>
> **コード**：`App/Views/TagManageView.xaml`・`AttributeManageView.xaml`・`ManageResources.xaml`（共用の部品）・`Controls/SearchSyntaxHint`・`Core/Services/ItemTextFilter.cs`・`RenameTagDialog`（名前の変更の窓。3つで共用）・`MoveSubDialog`・`MergeAttributeDialog`、
> `App/ViewModels/TagManageViewModel.cs`・`AttributeManageViewModel.cs`、`Core/Services/UserTagService.cs`、
> `Core/Commands/UiCommand.cs`（`AddUserTag`・`RenameUserTag`・`DeleteUserTag`・`SetUserTagMemo`・`ReorderUserTags`・`MoveUserTagSub`・`*Attribute*`）
>
> **経緯**：`docs/feedback/done-2026-09.md`「タグの管理：…」の4節（2026-09-18）と「タグの管理と属性の管理を揃える」（2026-09-19）。作ったのは 2026-09-08（`features.md`）

## 言葉

- 画面では**「大分類」「小分類」**だけを使う（ユーザ指示 2026-09-19）。「トップ」「サブ」はコードの中の名前で、画面に出さない
  （一覧の「サブ 5 件」、説明の「トップに従属します」、移す窓・編集画面の入力欄に残っていたのを直した）。
- 保存先のファイル名（`userTags.json`・`attributes.json`）も「JSON」も画面に出さない。一覧に無い名前の説明は「アプリの外で保存先のファイルを直したか」と言う。
  例外は設定画面の保存先の説明（人がファイルを開いて直せることを伝える場所なので、そこだけは言う）。

## 画面の形（両方に共通）

- 左：一覧（検索欄・足す欄・行）。行は名前と件数（件数が0なら「未使用」）。ドラッグで並べ替えられる（検索の絞り込みと編集の候補も同じ並びを使う）。
- 右：選んだものの中身。**使える幅いっぱいを使う**（上限を付けると広い画面で中央に寄り、左の一覧との間に大きな空白ができた。2026-09-19）。
- 見出しのカード：種類の小見出し・名前・**名前の横に「名前を変更」**・件数と「検索で開く」・右上に赤い「この〜を削除」・その下にメモ。
  名前の変更のために専用の段（説明と区切り線）を設けない（ボタン1つに2段使っていた。2026-09-19）。何件が書き換わるかは窓が言う。
- **使っていないものも、ボタンは消さずに押せない形で置く**（ユーザ指示 2026-09-19）。消すと行ごとに頭やボタンの位置がずれる。
  押せない理由はツールチップで言う（`ToolTipService.ShowOnDisabled`）。小分類の開く三角も同じで、押せないときは薄くする。
- メモは**押さずに残す**（打ち止めてから 0.8 秒で書く。ショップ・アバターと同じ）。
  選び直す・読み直す前に、待っているメモを**今の対象へ書き切る**（待ちの間に移ると、移った先の名前と欄の文で書いて、打った文が消えていた。2026-09-19）。
  保存したら行の値も書き換える（読み込み時の値のままだと、選び直したときに古いメモが出る）。
- **商品を探す欄は、検索画面と同じ書き方**（ユーザ指示 2026-09-19）：スペース＝AND・`-語`・`"…"`・`OR`・`( )`・`name:` などの前置き。
  探す所は検索画面の既定（商品名・ショップ名・メモ）で、オプション（大文字小文字など）も既定のまま。分類・属性の名前にも同じ式を当てる（名前は商品名として扱う）。
  部品は `Core/Services/ItemTextFilter`（`SearchQuery.Parse`・`Matches` をそのまま使う・試験あり）、欄の下の案内は `Controls/SearchSyntaxHint`（詳しくはホバー）。
- 左の一覧を探して作り直す間も、**右で見ている物は外さない**（一覧を作り直す瞬間に「選択なし」が書き戻され、探すたびに右が空になっていた。2026-09-19）。当たりから外れても右はそのまま。
- 中に入っている商品の行（絵・商品名・ショップ名・押すと商品ページ・ホバーで大きめの絵）と畳む三角は、2つの画面で同じ物を使う（`Views/ManageResources.xaml`）。
  大きめの絵は行の**左**に出す（右に出すと、小さな絵に乗せたマウスから行の幅ぶん離れて遠い。ユーザ指摘 2026-09-19）。
- 右は**平らな1本の一覧にして仮想化する**（頭 → 小分類・中の商品の段 → 下の枠。2026-09-24：中の商品を WrapPanel に全部並べていた頃は、2000件の属性を開くと約7秒固まり、小分類をすべて開くとメモリが約300MB増えた）。
  中の商品は、前の並べ方が1段に置いていた数で段に切る（`ManageItemLines`。幅は一覧の幅から枠の分を引いて View が渡す）。畳んだ小分類は前と同じ `ColumnsPanel` でまとまりごとに並べる。
- 一覧に無い名前（商品は参照しているのに一覧に無い）は右の上に注意の色の欄で出し、「一覧に追加」「既にある物へ寄せる」「商品から外す」を選ばせる。
  編集画面で付けた名前はその場で一覧に入るので、ここに出るのは外でファイルを直したか、一覧から消した後に商品側が残った場合だけ。

## 名前の変更・統合・削除

- 名前の変更は**ボタン → 窓**（`RenameTagDialog`。大分類・小分類・属性で同じ窓）。候補付きの欄で、既にある名前を選ぶと**統合**になり、
  ボタンが「まとめる」に変わって「まとめた後は元に戻せません」と言う。窓を閉じた後にもう一度確かめる（件数と、統合なら戻せないこと）。
  - 属性の統合は、両方に値が入っている商品でどちらを残すかを別の窓で聞く（`MergeAttributeDialog`）。
  - 大分類の統合は、小分類を統合先へまとめる。メモも捨てない。
- 削除は付いている商品からも外す（一覧から消すだけだと商品側に参照が残る）。取り返しがつかないこと・作り直しても割り当ては戻らないことを確認で言う。
  ユーザータグが空になった商品は編集の対象に戻る（その件数も結果で言う）。属性は「未設定」が既定なので、空になっても編集の対象には戻らない。

## タグの管理だけにあるもの

- **並べ方**：名前順（既定）・件数順・手で並べた順。**一覧のすぐ上に、つながった3つのボタン**で置く（`ManageResources.xaml` の `Segment*`。頭の右端に置いていたら、どの一覧の並びか分かりにくかった。ユーザ指示 2026-09-19）。選ぶと `userTags.json` の並びも同じ順に書き換える
  （検索の候補がこの並びをそのまま使うので、画面だけ並べ替えると食い違う）。小分類も同じ並べ方に揃える。ドラッグで並べ替えると「手で並べた順」になる。状態は `ui-state.json` の `tagSort`。
- 左の検索は、大分類の名前・小分類の名前・商品のどれでも引く。当たった件数を欄の下に出す。
- 小分類は幅に応じて列を増やす（`ColumnsPanel`・1列の最小 540）。**開いた行は幅いっぱい**（列の中で開くと並びが飛んだ）。左から右へ置き、はみ出したら次の段。
- 小分類は三角で開くと中の商品（絵・商品名・ショップ名）が並び、押すと商品ページ。開いたときだけ読む。開いた中身には左の縦線。絵に乗せると大きめの絵。
- 小分類の上の欄で、**この大分類の中を小分類名・商品で探す**（2026-09-19 に小分類名を足した）。
  - 小分類の名前で当たったら、その小分類を出して中の商品を全部並べる（名前で探した人は中身を見たい）。中身が無くても出す。
  - 商品で当たったら、当たった商品を持つ小分類だけを開き、中身も当たった商品だけにする。
  - 欄の下に「当たる小分類 n 件・商品 m 件」。
- ＋の隣の**「すべて開く」**で、中身のある小分類をまとめて開く（ユーザ指示 2026-09-19：1つずつ三角を押して回るのは手間）。全部開いている間は「すべて畳む」になり、1つずつ開け閉めしても言い方が合う。探している間は、出ている小分類だけが相手。
- 小分類を足すのは、探す欄の隣の**丸い＋ボタン**。押すと同じ枠の中で右へ伸びて入力欄になり、開いている間は×。
  中の入力欄は枠と地を消して、丸い枠そのものを欄に見せる（`SuggestBox.IsFrameless`。四角い欄が中で浮いていた）。
  伸び縮みは欄の側の Style に持たせる。ボタンの側から名前で欄を指すと、開いたまま別の画面へ移ったときに例外で画面の切り替えが止まった（2026-09-19）。
- 小分類の行のボタンは「検索で開く → 名前を変更 → 別の大分類へ移す →（間を空けて）削除」。よく使う物から並べ、取り返しのつかない物を右端に置く。
  「別の大分類へ移す」は窓（`MoveSubDialog`）で移し先を選び、移すと小分類が1つも残らない商品で元の大分類を残すかを聞く。移し先が無い（大分類が1つだけ）ときは押せない。
- 小分類のメモは行の下の欄（空のときは「メモ（何をここに入れるかの基準）」と欄の中で言う）。
- 商品ページから戻ったとき、選んでいた大分類と開いていた小分類を戻す（アプリを閉じるまで覚える）。

## 属性の管理だけにあるもの

- 行の2行目は平均（値の入り方が偏っていないか見えるように）。見出しの件数は「n 件の商品で評価済み（平均 x %）」。
- **並べ方**（タグの管理と同じ3つを同じ場所に・ユーザ指示 2026-09-19）。選ぶと `attributes.json` の並びも書き換える。状態は `ui-state.json` の `attributeSort`。
  既定は**手で並べた順**（それまで並べ方はドラッグしか無く、ファイルの並びは人が置いた順なので、名前順を既定にすると表示と印が食い違う）。
- 左の検索は、属性の名前と、この属性を持つ商品で引く。
- **この属性を持つ商品**のカード（タグの管理の小分類の中身と同じ形。「評価した商品」と呼んでいたのをユーザ指示で改めた）：三角で開くと並び、名前の右に値の札（「85 %」）。
  見出しの横のつながったボタンで**値の高い順（既定）・低い順**を切り替える（低い順は、付けたが弱い物を見直すため）。同じ値の中は名前順。
  開き方と向きは属性をまたいで持ち、アプリを閉じるまで覚える。
  **並ぶ向き**を「横に並べる（左から右・次の段へ）｜縦に並べる（上から下・次の列へ）」で切り替える（ユーザ指示 2026-09-19：値の順の並びが横固定だと、縦に読む人には追いにくい）。
  `ui-state.json` の `attributeItemsVertical`（既定は横）。列の数を幅から決め、段の数を出してから並べる（`Controls/FlowGridPanel`。縦の WrapPanel は高さの上限が無いと1列になる）。
  タグの管理は名前順なので向きを選ばせない（ユーザ判断 同日）。
  行は画面を移るまで使い回し、畳んでも消さない。向きを変える・中を探すときも、作り直さず並べ替えと出し入れで済ませる
  （開くたびに作り直していて、113件で開き直すたびに約 250ms 固まっていた → 約 5ms。初めて開くときの約 155ms は部品を作る分で変わらない。2026-09-19 に測った）。上の欄で中を探す（探している間は開いて見せる）。評価していない属性では三角と欄が押せない。
- 商品ページから戻ったとき、選んでいた属性を戻す（タグの管理と同じ）。
- 「編集画面での扱い」：編集画面に最初から並べるかを切り替える。**並べるだけで保存はしない**（全商品に同じ値の行が並ぶと、付けていないのかそう評価したのかが区別できない）。
- 確かめの写しは `attrcheck`（属性12種類・195件に値・一覧に無い属性の参照5件。`ui-check` スキルの `sandboxes.md`）。
