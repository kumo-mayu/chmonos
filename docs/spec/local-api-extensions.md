# 外のソフトの情報を置く（拡張データ）[採用]

> **要点**：許したソフト（[api-clients.md](api-clients.md)）が、商品・改変などに自分の情報を書いておける置き場。Chmonos を「情報をまとめておくソフト」にする。
> ソフトは先に欄を宣言してから値を書き、Chmonos はその値を商品ページに見せ、検索の条件に使う。人は見るだけ。
> 段階：形の決め事は [採用]（2026-11-27・ユーザ判断。下の各節の「決定」）。URL と答えの形・上限の数は [案]（作る時に詰める）。まだ作っていない。
> 仮の呼び名は「拡張データ」（画面の語は作る時に `ui-terms.md` で決める）。

## なぜ

ユーザの言葉（2026-11-27）：「chmonosに情報をまとめておくソフトとしての役割を想定したいです。」

今、外のソフトが書ける欄は、メモ・ユーザータグ・属性・印（お気に入り・非表示）だけ（[local-api.md](local-api.md)）。どれも人が画面で使う物で、ソフトが自分用の値を入れると人の分類と混ざる。
置き場が無いので、ソフトは別のファイルを持つしかなく、そのファイルは ID の付け替え・引越し・書き出しに付いてこない。

## 名前空間 [決定]

- 許しを求める時（`POST /v1/clients/request`）に、ソフトが**名前空間**を宣言する（例 `outfit-checker`。英小文字・数字・ハイフン）。許しの窓に出す。データはこの名前で分ける。
- 理由：許しの行の ID は、求め直すと置き換わる（api-clients.md「前に許した同じソフトが求め直したら」）。表示名は自由に付けられ、ほかのソフトと重なる。
- 同じ名前空間を、前と違う exe（ブラウザならオリジン）が求めたら、窓で知らせる。

## 付け先 [決定]

| 付け先 | 鍵 | 付いていく事 |
|---|---|---|
| 商品（アバターを含む） | 商品 ID | 仮 ID から BOOTH の ID への付け替え・統合・商品の削除 |
| 改変 | 改変 ID | 改変の削除 |
| ソフトごとの全体 | 名前空間 | — |
| ファイル（zip・unitypackage など） | 中身のハッシュ | — （商品から外されても残る。版ごとに情報を持てる唯一の付け先） |
| ショップ | ショップ一覧の鍵（サブドメインか `local-` の鍵） | BOOTH に無いショップの鍵は名前から作るので、人が名前を直したら付け替える |

- BOOTH のサブドメインは、ショップを公開した後はオーナーでも変えにくい（ユーザ 2026-11-27）。だからショップも付け先にした。
- **足さなかった付け先**（2026-11-27。足すのは互換の変更なので、使い道が出たら足す）：
  - バリエーション：商品の表に「バリエーション」の列を置けばほぼ同じ事ができる。**表の1列では足りない場面が見えたら、最初に足す候補**（鍵は商品 ID ＋ バリエーション ID で安定）
  - 共通素体・ユーザータグ・属性：鍵が名前で、名前の変更・統合に付いていく処理が要る。素体に属するアバターへ書く・全体の表で用が足りる
  - Unity プロジェクト・登録したフォルダ：鍵が場所で、移したことが Chmonos に分からず、値が宙に浮く
  - 購入記録・通知・保存した検索：並びが変わる・消える・押し出される物で、長く残す鍵にならない

## 中身の形 [決定]

ソフトは先に**欄の宣言**（名前空間ごとに1つ）を出し、その後で値を書く。

```
欄の宣言
{ "label": "試着チェッカー",
  "fields": [
    { "key": "testedOn",  "label": "試着したアバター", "type": "avatarList" },
    { "key": "polyCount", "label": "ポリゴン数",       "type": "number" },
    { "key": "checkedAt", "label": "調べた日",         "type": "date" } ] }

商品への値
{ "testedOn": ["4567"], "polyCount": 70000, "checkedAt": "2026-11-27" }
```

- 値は入れ子の無い「欄 → 値」。型は文字・数・真偽・日付・URL・文字の一覧、Chmonos の物を指す型（`avatarList` など。画面で名前の札にする。ただの文字だと名前が変わった時に追えない）、**表**。
- **表**：列を宣言した行の並び（例：アバターごとの試着の結果＝アバター・合うか・メモ）。入れ子の多くは表で書け、表なら画面に出せて探せる。
- 宣言に無い欄の値は断る（画面に出せず探せない値が溜まらないように）。
- **メモ欄**：宣言の外に、ソフトが自分の形で置ける欄を1つ持つ（内部の状態・同期の印・入れ子の大きな物）。守りを3つ付ける：
  - **持ち主のソフトだけが読める**（下の「誰が読めるか」の例外。秘密を入れてもほかのソフトへ漏れない）
  - 大きさに上限を置く（数は [案]・測ってから決める）
  - 画面には量だけを出す（例「画面に出ない情報 12KB」）
- メモ欄を足した理由：無いとソフトは別のファイルを持ち、それは付け替え・引越し・書き出しに付いてこない。困る点（人に見えない・宣言の欄が使われなくなる・膨らむ）は上の守りで抑える。

### この形で出来ない事（2026-11-27 にユーザへ示して受けた）

- 画像・ファイル・長い文を置く（メモ欄の上限まで）
- 値の履歴（今の値だけ。要ればソフトが日付付きの表で書く）
- Chmonos の判断を変える：所持・対応アバター・「見つからない」などの判定に効かない。対応アバターを変えるなら今ある書き込み（`avatars`）を使う
- 画面の見た目を決める：欄は Chmonos が決まった形で並べる（色・ボタン・グラフは無い。押す物はプラグインの項目 [plugins.md](plugins.md)）
- カードの札・並べ替えの鍵に使う（今の想定に無い。後から足せる）
- ほかのソフトの値を書く・共通の欄を持つ（書けるのは持ち主だけ）
- 人が値を入れる・直す（下の「画面」）

## 誰が読めるか・誰が書けるか [決定]

- 許したソフトは、どれもほかのソフトの宣言の欄を読める（メモ欄を除く）。書けるのは持ち主のソフトだけ。
- 理由：まとめ役として、ソフトどうしで情報を渡せるようにする。同じ Windows ユーザーで動くソフトは保存先のファイルを直に読めるので、読むのを止めても守りにならない（blueprint ID と同じ判断。[local-api.md](local-api.md)）。
- 書き込みの種類を1つ足す：`extensions`（自分の名前空間だけ。[api-clients.md](api-clients.md)「書き込みの種類」）。
- 同じ物を2つのソフトが書く事は無いので、同じソフトの書き込みが重なった時だけ `ETag`／`If-Match` で弾く。
- 変わった事は変化の知らせ（SSE・`/v1/changes`）に流す（ほかのソフトが気付けるように）。

## 画面 [決定]

- 人は見るだけ（ユーザ判断 2026-11-27「人は見るだけで良いと考えている」）。直す欄は作らない。ソフトの持ち物を人が変えると、ソフトの側と食い違う。
- 商品ページなどに、名前空間ごとの欄（宣言の `label`）として値を並べる。検索の条件に「拡張データ」を足す（ソフト → 欄 → 値）。形は作る時に決める [案]。
- 許しを取り消しても値は残す。設定の「つないでいるソフト」から、名前空間ごとに消せる。

## 置き場 [決定]

- 商品の JSON には入れず、別のファイルに置く（例 `extensions/<名前空間>/items/<商品ID>.json`。分け方は [案]）。
- 理由：
  - 形式の版を上げずに足せる（新しいファイルは古い版が読まず、消しもしない。[data-format.md](data-format.md)）。商品の JSON に欄を足すと、古い版（v1.0.0）が商品を保存した時に消える
  - 壊れても商品は読める。人の記録とソフトの記録を混ぜない方が、どちらかが壊れた時の被害が小さい
  - ソフトの書き込みが編集画面とぶつからない（商品の記録への書き込みは、編集中は 409 `itemBeingEdited`）
- 代わりに、付け先の「付いていく事」（ID の付け替え・統合・削除・ショップの名前の変更）を自分で書く。名前の変更などで使っている「途中の操作」（`pending-operations.json`）の付け替えに足す。
- 引越し・書き出しと「すべてを戻す」・形式の控えに入れる（使う人のデータ。許しの `api-clients.json` とは違う）。
- 保存先の直下のファイルではなくフォルダなので、書き出し（`BackupArchive`）・引越しが拾うかは作る時に確かめる [要確認]。

## まだ決めていない事 [案]

- URL と答えの形（例：`PUT /v1/extensions/{名前空間}/schema`・`PUT /v1/items/{id}/extensions/{名前空間}`・商品の答えの `?include=extensions`）
- 宣言を変えた時（欄を消した・型を変えた）の、前の値の扱い
- 大きさ・欄の数・表の行の数の上限（メモリに乗る量を測ってから）
- 画面の欄の置き場所と語、検索の条件の形
- 名前空間の文字数と、予約する名前（`chmonos` など）
