# 外のソフトから操作を足す（プラグイン）[採用]

> **要点**：許したソフト（[api-clients.md](api-clients.md)）が、Chmonos の右クリックなどに項目を宣言して足し、人が押したら、そのソフトが宣言した情報を詰めて知らせる。
> 画面の操作（商品を開いた・選択が変わった など）も、そのソフトが選んだ種類だけ知らせる。知らせは**ソフトが取りに来る**（長く待つ問い合わせ）。Chmonos から外へつながない。
> 段階：[案]（2026-11-12。ユーザ判断「Aで良いでしょう。APIが変わるのでv1.3.0に入れたいかも」）。決めた事は [決定]（2026-11-12 にユーザが4点を決めた）。細かい数は作る担当が決めて報告で見せる（ユーザ判断「それで良いです」）。

## なぜ

ユーザの言葉（2026-11-12）：「アプリ毎のトークンを持てるようになったので、chmonosがアプリに対して話しかけられるようになりましたよね？つまり、chmonos本体の右クリックメニューにプラグインのように項目を外部から増やしてしまって、商品に対してそれが実行されたらIDを投げるような動作が可能になりました。」
「右クリックは私が例として出しただけで、操作全般を監視しても良いし、右クリックには決まった形式で言われた構造と、それぞれが求める情報を返してあげたいかも。」

最初の使い手の見込み：別のセッションで作っている「Unity 無しの衣装プレビュー」（商品の右クリックから商品 ID を受ける）。

## 届け方：ソフトが取りに来る [決定]

`GET /v1/plugin/events?after=<通番>&wait=<秒>`（ソフトのトークンで）。出来事があればすぐ返し、無ければ `wait`（0〜30）秒で空を返す。ソフトは返ってきたらすぐ次を聞く。

比べた案（2026-11-12）：

| | A：ソフトが取りに来る（採用） | B：Chmonos がソフトへ送る |
|---|---|---|
| ソフトを作る手間 | GET を繰り返すだけ。PowerShell・Python・Unity のエディタ拡張・ブラウザのページ（fetch）で書ける | ソフトごとに HTTP の待ち受け（ポート・ぶつかり・ファイアウォール）。ブラウザと Unity のエディタ拡張ではほぼ作れない |
| 守り | 今のまま（`127.0.0.1` で受けるだけ・外へつながない・相手はトークンで決まる） | 登録された URL がほかのソフトの口を指しても送ってしまう。ソフトの側は本物の Chmonos かを確かめる署名が要る |
| 取りこぼし | 通番で続きから取れる（列の上限まで） | 落ちていた間の分を Chmonos が溜めて送り直す仕組みが要る |
| つながっているか | 最後に取りに来た時刻で分かる | 送るまで分からない |
| その場の答えが要る使い方 | 苦手（往復）。項目の条件（`when`）を宣言して埋める | 得意 |

- 今ある `/v1/events`（SSE）・`/v1/changes` は**保存先のファイルの変化**を全員へ流す物で、そのまま残す（タグ・印の変更などはそちらで足りる）。新しい流れは**ソフトごと**で、画面の操作と項目の呼び出しを載せる。
- 列はソフトごとに上限つき（件数は作る担当が決める。あふれたら `dropped: n` を1つ流す）。通番はアプリの起動ごとに数え直し、起動の名前（`epoch`）を添える（`/v1/changes` と同じ考え）。
- ブラウザの `EventSource` はトークンを見出しに載せられない（トークンを URL に入れない決まり）ので、SSE ではなく長く待つ GET にした。

## 項目を宣言する

`PUT /v1/plugin/menu`（ソフトのトークンで。丸ごと置き換える。空の `items` で消す）：

```json
{ "items": [
  { "id": "preview", "label": "衣装をプレビュー",
    "where": ["item", "selection"],
    "when": { "hasUnityPackage": true },
    "needs": ["itemId", "name", "unityPackages", "avatars"] },
  { "id": "export", "label": "書き出す", "children": [
    { "id": "export-csv", "label": "CSV", "where": ["selection"], "needs": ["itemId", "name"] } ] }
]}
```

- `where`：出す場所。[案] `item`（検索のカード・商品ページの右クリック）・`selection`（複数選択の帯）・`file`（ファイルの右クリック）・`modification`・`avatar`。**最初は `item` と `selection` だけ** [決定]（ユーザ判断 2026-11-12「おすすめに賛成します」）。ほかは後から足す。
- `when`：押せる条件。**Chmonos がその場で決める**（往復しない）。[案] `hasUnityPackage`・`owned`・`category`・`hasAvatar` など、検索の条件の一部。合わなければ灰色にして吹き出しで言う。
- `children`：下の段。深さは2段まで [案]。
- `needs`：押されたときに詰める情報。そのソフトに許した読み取りの範囲だけ（読み取りは今は全員に許しているので全部）。[案] `itemId`・`name`・`shop`・`files`（パス・大きさ）・`unityPackages`（名前・中身の GUID の数）・`avatars`・`tags`・`modification`。
- **宣言は控えに書く** [決定]（ユーザ判断 2026-11-12「書いた方が良いと思います。変っていたら再認証が必要でしょう」）。ソフトが起動していない間も、控えた項目を灰色で出せる。
  - **宣言が控えと変わったら、もう一度人に許しを求める**：許しの窓に、足す・変わる・消える項目を並べる。許すまでは控えた前の宣言のまま出す。拒否したら前の宣言のまま（拒否の回数の数え方は [api-clients.md](api-clients.md) と同じ）。
  - 同じ宣言を送り直しただけなら聞かない（ソフトは起動のたびに送ってよい）。

### 画面での出し方 [案]

- 本物の項目と取り違えないよう、全部を「ほかのソフト ▸ {ソフトの名前} ▸ …」の下にまとめる（名前はソフトが付けた物で、本人の確かめにならないため）。
- **つながっている間だけ押せる**：最後に取りに来てから一定の時間（作る担当が決める）を過ぎたら灰色にし、「{ソフトの名前}が応答していません」。
- 押したら帯で「{ソフトの名前}に送りました」。ソフトが結果を返したら、その文に差し替える（下）。

## 出来事の形

```json
{ "seq": 12, "epoch": "…", "kind": "menu", "at": "…",
  "menu": "preview", "where": "item",
  "items": [ { "itemId": "…", "name": "…", "unityPackages": [ … ] } ] }
```

- `kind: "menu"`：そのソフトの項目が押された。複数選択なら `items` に並べる。
- `kind: "<操作>"`：購読した画面の操作（下）。

## 画面の操作を購読する

`PUT /v1/plugin/subscriptions` に `{ "kinds": ["itemOpened", "selectionChanged", "importFinished"] }`。

- 最初の種類の [案]：`itemOpened`（商品ページを開いた）・`selectionChanged`（複数選択が変わった。まとめてから流す）・`importFinished`（取り込みが終わった）。
- 後から足す候補：`screenChanged`・`unitySent`・`modificationChanged`・`searchChanged`。
- **何を見られるかは許しの窓で人が選ぶ** [決定]（ユーザ判断 2026-11-12「選ばせましょう」）。見張りは書き込みでないが、使う人の操作を外へ出すため。許していない種類を購読しようとしたら 403 で断り、許しを求め直してもらう。

## ソフトから結果を返す

`POST /v1/plugin/events/{seq}/result` に `{ "ok": true, "message": "プレビューを開きました" }`。Chmonos は帯の「送りました」をこの文に差し替える（文は短く切る・制御文字を断る）。返さなければそのまま。

## 守り

- 読み取りだけ。Chmonos の中を変えるのは、今ある書き込みの API（種類ごとの許し・`UiCommand`）で行う。
- BOOTH へ問い合わせない。外へつながない。
- 項目の数・ラベルの長さ・`children` の深さに上限（作る担当が決める）。
- 止めたソフト・取り消したソフトの項目は出さない。

## まだ決めていない事

- 細かい数（列の上限・応答していないとみなす時間・項目の数とラベルの長さ）は作る担当が決めて報告で見せる
- 最初の使い手として「Unity 無しの衣装プレビュー」のセッションに試してもらうか（ユーザに聞いている）
