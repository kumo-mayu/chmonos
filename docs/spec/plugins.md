# 外のソフトから操作を足す（プラグイン）[採用]

> **要点**：許したソフト（[api-clients.md](api-clients.md)）が、Chmonos の右クリックなどに項目を宣言して足し、人が押したら、そのソフトが宣言した情報を詰めて知らせる。
> 画面の操作（商品を開いた・選択が変わった など）も、そのソフトが選んだ種類だけ知らせる。知らせは**ソフトが取りに来る**（長く待つ問い合わせ）。Chmonos から外へつながない。
> 段階：[採用]（2026-11-12。ユーザ判断「Aで良いでしょう。APIが変わるのでv1.3.0に入れたいかも」）。決めた事は [決定]（2026-11-12 にユーザが4点を決めた）。細かい数は作る担当が決めて報告で見せる（ユーザ判断「それで良いです」）。
> **①出来事の流れと購読は [実装]**（2026-11-12。下の「作った形（①）」）。**②項目の宣言と結果を返す口も [実装]**（2026-11-12。形と決めた数は [plugins-menu.md](plugins-menu.md)）。

## なぜ

ユーザの言葉（2026-11-12）：「アプリ毎のトークンを持てるようになったので、chmonosがアプリに対して話しかけられるようになりましたよね？つまり、chmonos本体の右クリックメニューにプラグインのように項目を外部から増やしてしまって、商品に対してそれが実行されたらIDを投げるような動作が可能になりました。」
「右クリックは私が例として出しただけで、操作全般を監視しても良いし、右クリックには決まった形式で言われた構造と、それぞれが求める情報を返してあげたいかも。」

最初の試し：まとめ役が作った最小の見本 [tools/plugin-sample/](../../tools/plugin-sample/README.md)（PowerShell 7 の台本1本。商品名をコピー・IDを表示）。2026-11-12 に写しで、許可の窓2つ・右クリック・複数選択の帯・結果の帯まで実機で通した [実測]（ユーザ指示「最初の試しはあなたが自分で最小構成を作成してくれ」）。

## 届け方：ソフトが取りに来る [決定]

`GET /v1/plugin/events?after=<通番>&wait=<秒>&epoch=<起動の名前>`（ソフトのトークンで）。出来事があればすぐ返し、無ければ `wait`（0〜30）秒で空を返す。ソフトは返ってきたらすぐ次を聞く。[実装]

比べた案（2026-11-12）：

| | A：ソフトが取りに来る（採用） | B：Chmonos がソフトへ送る |
|---|---|---|
| ソフトを作る手間 | GET を繰り返すだけ。PowerShell・Python・Unity のエディタ拡張・ブラウザのページ（fetch）で書ける | ソフトごとに HTTP の待ち受け（ポート・ぶつかり・ファイアウォール）。ブラウザと Unity のエディタ拡張ではほぼ作れない |
| 守り | 今のまま（`127.0.0.1` で受けるだけ・外へつながない・相手はトークンで決まる） | 登録された URL がほかのソフトの口を指しても送ってしまう。ソフトの側は本物の Chmonos かを確かめる署名が要る |
| 取りこぼし | 通番で続きから取れる（列の上限まで） | 落ちていた間の分を Chmonos が溜めて送り直す仕組みが要る |
| つながっているか | 最後に取りに来た時刻で分かる | 送るまで分からない |
| その場の答えが要る使い方 | 苦手（往復）。項目の条件（`when`）を宣言して埋める | 得意 |

- 今ある `/v1/events`（SSE）・`/v1/changes` は**保存先のファイルの変化**を全員へ流す物で、そのまま残す（タグ・印の変更などはそちらで足りる）。新しい流れは**ソフトごと**で、画面の操作と項目の呼び出しを載せる。
- 列はソフトごとに上限つき（256件。あふれたら古い方から捨て、答えの `dropped` に捨てた数）。通番はソフトごと・アプリの起動ごとに 1 から数え直し、起動の名前（`epoch`）を添える（`/v1/changes` と同じ考え）。
- ブラウザの `EventSource` はトークンを見出しに載せられない（トークンを URL に入れない決まり）ので、SSE ではなく長く待つ GET にした。

## 項目を宣言する

`PUT /v1/plugin/menu`（ソフトのトークンで。丸ごと置き換える。空の `items` で消す）：

```json
{ "items": [
  { "id": "preview", "label": "衣装をプレビュー",
    "where": ["item", "selection"],
    "when": { "hasUnityPackage": true },
    "needs": ["itemId", "name", "unityPackages", "avatars"] },
  { "id": "export", "label": "書き出す", "children": [
    { "id": "export-csv", "label": "CSV", "where": ["selection"], "needs": ["itemId", "name"] } ] }
]}
```

- `where`：出す場所。[案] `item`（検索のカード・商品ページの右クリック）・`selection`（複数選択の帯）・`file`（ファイルの右クリック）・`modification`・`avatar`。**最初は `item` と `selection` だけ** [決定]（ユーザ判断 2026-11-12「おすすめに賛成します」）。ほかは後から足す。商品ページには全体の右クリックが無いので、上の帯の「ほかのソフト ▾」に出す（作る担当の判断 2026-11-12）。
- `when`：押せる条件。**Chmonos がその場で決める**（往復しない）。[実装] `hasUnityPackage`・`owned`・`category`・`hasAvatar`（検索の条件の一部）。合わなければ灰色にして吹き出しで言う。
- `children`：下の段。深さは2段まで [実装]。
- `needs`：押されたときに詰める情報。そのソフトに許した読み取りの範囲だけ（読み取りは今は全員に許しているので全部）。[実装] `itemId`・`name`・`shop`・`category`・`files`・`unityPackages`・`avatars`・`tags`（形は読み取りの API と同じ。`modification` は後で）。
- **宣言は控えに書く** [決定]（ユーザ判断 2026-11-12「書いた方が良いと思います。変っていたら再認証が必要でしょう」）。ソフトが起動していない間も、控えた項目を灰色で出せる。
  - **宣言が控えと変わったら、もう一度人に許しを求める**：許しの窓に、足す・変わる・消える項目を並べる。許すまでは控えた前の宣言のまま出す。拒否したら前の宣言のまま（拒否の回数の数え方は [api-clients.md](api-clients.md) と同じ）。 [実装]。ただし**消えるだけの変更は聞かない**（[決定] ユーザ判断 2026-11-12「聞かなくても良いでしょう」。[plugins-menu.md](plugins-menu.md)）。
  - 同じ宣言を送り直しただけなら聞かない（ソフトは起動のたびに送ってよい）。

### 画面での出し方 [実装]（詳しくは [plugins-menu.md](plugins-menu.md)）

- 本物の項目と取り違えないよう、全部を「ほかのソフト ▸ {ソフトの名前} ▸ …」の下にまとめる（名前はソフトが付けた物で、本人の確かめにならないため）。
- **つながっている間だけ押せる**：最後に取りに来てから60秒を過ぎたら灰色にし、「{ソフトの名前}が応答していません」。
- 押したら帯で「{ソフトの名前}に送りました」。ソフトが結果を返したら、その文に差し替える（下）。

## 出来事の形

答え（[実装]）：`{ "epoch", "last", "reset", "dropped", "events": [ … ] }`。出来事1つは種類と同じ名前の欄に中身を入れ、ほかの種類の欄は `null`（項目を省かない決まり）。

```json
{ "seq": 12, "epoch": "…", "kind": "itemOpened", "at": "…",
  "itemOpened": { "itemId": "…" }, "selectionChanged": null, "importFinished": null }
```

- `kind: "<操作>"`：購読した画面の操作（下）。
- `kind: "menu"`（② [実装]。形は [plugins-menu.md](plugins-menu.md)）：そのソフトの項目が押された。`menu` の欄に項目の ID・場所・`needs` で詰めた商品の並び。

## 画面の操作を購読する

`PUT /v1/plugin/subscriptions` に `{ "kinds": ["itemOpened", "selectionChanged", "importFinished"] }`（丸ごと置き換え。空の配列で止める）。[実装]

| 種類 | いつ | 中身 |
|---|---|---|
| `itemOpened` | 主の窓で商品ページを開いた（戻る・進む・API の `…/show` も。開き直し〔取り直し・API が書いた後〕は出さない） | `itemId` |
| `selectionChanged` | 検索・フォルダの右側・ショップの複数選択が変わった（300ms まとめる。同じ選択は流し直さない。全部外すと `count: 0`） | `screen`（search・folder・shop）・`itemIds`（表示の並びの順に1000まで）・`count`・`truncated` |
| `importFinished` | 取り込みが終わった（「取り込み中」を解いた後） | `outcome`（imported・failed・cancelled）・`itemsAdded`・`itemsAlreadyKnown`・`unresolvedFiles`（imported のときだけ。ほかは null） |

- 後から足す候補：`screenChanged`・`unitySent`・`modificationChanged`・`searchChanged`・フォルダの画面の右に組み込んだ商品ページ（行を選ぶたびに開くので、今は `itemOpened` に入れない）。
- **何を見られるかは許しの窓で人が選ぶ** [決定]（ユーザ判断 2026-11-12「選ばせましょう」）。見張りは書き込みでないが、使う人の操作を外へ出すため。許していない種類を購読しようとしたら 403 で断り、許しを求め直してもらう。
  許しの名前は `watch.` と種類（`watch.itemOpened` など。[api-clients.md](api-clients.md)「見張りの種類」）。

## 作った形（①）[実装]

自分で決めた点（2026-11-12・作る担当。数はユーザ判断「それで良いです」で担当に任された）：

- **ソフトごとのトークンだけで使う**：`api.json` のトークン（古い1本）は 403 `clientTokenRequired`。列はソフトごとに持つので、誰か分からないトークンでは列を決められない。
- **列の上限 256件**：1件は数百バイト、選択でも ID 1000個で約20KB、1ソフト最大約5MB。ソフトが数分止まっていても選択の変化を取りこぼさない程度。
- **選択の ID は1000まで**：2万件を全部選ぶと ID だけで約40万字。超えたら `count`（全部の数）と `truncated: true` で伝える。ID を数えるのはまとめの時間が切れた時だけで、選ぶ操作のたびには数えない。
- **まとめる間 300ms**（最後の変化から。人が続けて選ぶ間隔より長く、遅れが気にならない。見張りの知らせをまとめる間と同じ）。
- **起動し直しを見分ける**：`epoch` を送って今と違えば、または `after` がまだ無い通番なら、待たずに頭から返して `reset: true`（空の `epoch=` は送っていないのと同じ）。ソフトは購読を送り直す（購読はメモリだけで、控えに書かない）。
- **`dropped`**：送られた `after` と残っているいちばん古い通番の間で、捨てた数（あふれと古い `after` を同じ式で扱う）。
- **列はアプリが1つ持つ**（`AppServiceContainer.PluginEvents`。API の係とは別に持ち、出来事を出すだけで API の係を作らない）：設定で API を止めて始め直しても（ポート・トークンの作り直し）購読と通番を保つ。止まっている間は出来事を作らない。
- **許しを外したら、その場で購読も外す**：設定でチェックを外す・取り消す・求め直して ID が変わったら、控えを読み直した時に列へ映す。取り消したソフトの待っている問い合わせは空で返す。
- **最後に取りに来た時刻**：メモリに正確な値と「今待っているか」を持つ（②の「応答していない」に使う）。控えの `lastPolledAt` には使った日時と同じく10分ごとに間引いて書く。
- 同じソフトが2本同時に待ってもよい（どちらにも同じ物が返る。列は読んでも減らない）。止めるとき（オフ・閉じる）は待ちを解いて空で返す。始められなかった（ポートが塞がっている）ときも列を外し、出来事を作らせない。
- 答えは `Cache-Control: no-store`（ETag なし）。ログには購読した時だけ、ソフトの名前と種類を1行（商品 ID は書かない）。
- 取り込みの終わりは API の写しの読み直しより先に届き得る。終わりを受けてすぐ読むと古いことがあるので、変化の知らせ（`/v1/changes`）も見る。
- コード：`Chmonos.Api/PluginEvents.cs`（`PluginEventHub`）・`PluginEndpoints.cs`、`Chmonos.App/Services/PluginSelectionBatcher.cs`、出す所は `MainViewModel.ShowItem`・3画面の `OnCardSelectionChanged`・`ImportRunner.RunAsync`。
  試験 `PluginEventTests`（Api）・`ApiPluginEventTests`（App）・`SettingsApiTests`（許しの窓と設定のチェック）。

## ソフトから結果を返す [実装]

`POST /v1/plugin/events/{seq}/result` に `{ "ok": true, "message": "プレビューを開きました" }`。Chmonos は帯の「送りました」をこの文に差し替える（文は短く切る・制御文字を断る）。返さなければそのまま。100字で切り、押してから10分・新しい32件まで受ける（[plugins-menu.md](plugins-menu.md)）。

## 守り

- 読み取りだけ。Chmonos の中を変えるのは、今ある書き込みの API（種類ごとの許し・`UiCommand`）で行う。
- BOOTH へ問い合わせない。外へつながない。
- 項目の数・ラベルの長さ・`children` の深さに上限（16個・下の段も合わせて32個・40字・2段。[plugins-menu.md](plugins-menu.md)）。
- 止めたソフト・取り消したソフトの項目は出さない。 止めたソフトは、拒否が続いて止めたソフト（許しの窓と同じ記録）。
