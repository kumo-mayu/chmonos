> **要点**：絞り込み（離散値）と文字列検索（自由記述）を分け、並べ替えは単一値の欄だけ。絞り込みは**モジュール方式**（「＋ 条件を追加」から条件を1つずつ足す。有効／無効のチェックと ×。**足した条件・有効か・値まで覚える**。同じ種類を複数・「除く」は [search-filters.md](search-filters.md)）。非表示と（設定で隠しているときの）R-18 は条件より先に外す。

## 文字列

- 構文：スペース＝AND・`-語`＝除外・`"…"`＝フレーズ・`OR`・`( )`・`name:語`＝探す所を絞る（ユーザ案 2026-09-15）。入力欄の下に見本1行、説明はホバーで。
  **構文の記号は1字ずつ NFKC で畳んでから読む**（全角の括弧・引用符・ハイフン・空白・コロンも効く・ユーザ判断「記号も畳みましょう」）。絵文字は畳まずに語として探す（`Nfkc`。1字ずつ畳むと片割れになって落ちていた）。
  - `OR` は**大文字だけ**（全角の「ＯＲ」も）。小文字の or は語（「Black or White」）。
  - 書きかけでも後ろを捨てない（2026-09-23）：対の無い `)` は読み飛ばし、空の `()`・打ちかけの `-` `name:` は無いものとして次へ進む。閉じていない `(` は終わりで閉じる。
  - 前置きは決めた名前だけ（`name` `shop` `subdomain` `memo` `main` `path` `id` `variation` `file` `content` `tag`）。知らない語（`Re:Zero`・`https:`）はふつうの文字。
    `"…"` の中の `name:` は前置きにしない。`name:"夏 セット"`・`tag:(夏 OR 冬)`・`-tag:無料` と書ける。前置きがあれば「対象」で切っている所でも探す（ユーザ判断 2026-09-16）。
- **対象**（検索欄の右の「対象」・1つずつ切り替え）：商品名・ショップ名・メモ（ここまで既定オン）／サブドメイン・本文（説明と h2）・BOOTHタグ・バリエーション名・商品ID・ファイル名・ファイルの場所（パス）・zip の中のファイル名（既定オフ）。
  **本文・パス・BOOTHタグは既定に入れない**（当たりすぎて「なぜ出たか」が分からない。BOOTHタグは絞り込みの条件で探す物・ユーザ判断 2026-09-16）。自分で入れたカテゴリは文字列の対象にしない。
  畳んだ文字列はその対象を初めて探すときに作って持つ（本文や zip の中身は使うまで作らない・`SearchHaystack`）。
- **オプション**（検索欄の右の「オプション」）：大文字と小文字を区別する（既定オフ）・全角と半角を区別する（既定オフ）・ひらがなとカタカナを区別する（既定オン）。
  既定の組み合わせ（とカタカナをひらがなに寄せるだけ）は前もって畳んだ文字列で速く比べ、それ以外は元の文字列を日本語の比べ方（`CompareInfo`）で照らす。
  **照合の答えは商品ごとに覚え、同じ式と切り替えなら使い回す**（`SearchQuery.Matches`。結果と選択肢の件数で同じ式を（条件数＋1）回照らすため）。
  2000件・条件3つの1回の絞り込みで、既定 3.9ms→0.7ms・割り当て 938KB→3KB、区別して本文も探すと 約680ms→約170ms（日本語の比べ方そのものが1回 約170ms。2026-09-24）。
- **別表記でも検索**（既定オフ）：中の5つをそれぞれ切り替える——ローマ字変換（tori → とり・トリ）・漢字変換（とり → 鳥。ローマ字から直した読みにも効く）・英日変換（shark → サメ）・
  日英変換（リボン → ribbon）・造語変換（商品名を漢字1字ごとの音訓で読む・撫で音 → なでおと）。同梱の JMdict（読み→表記・英語→表記・読み→英語）と KANJIDIC2。
  - **0件でも自動では広げない**（ユーザ判断 2026-09-16：切っているのに広げると切っている意味が無い）。0件の所に「別表記でも検索する」ボタン。
  - 日英変換の英語は**英単語の区切りで当てる**（top が stop に当たらない。関係のある当たりの目安 32% → 64%・`docs/history/search-redesign.md` §4）。
  - 式の木を `Or(Term, 別表記…)` に組み替える（`-無料` などの意味を壊さない・前置きは別表記にも当てる）。打ち直したら広げた式を捨てる。
  - **何で当たったかを必ず出す**（「『tori』を とり・トリ・鳥 としても探しました」）。1文字のかなは候補にしない。漢字を含む語には架けない。
  - 辞書は無改変で同梱し、索引は初回に手元で組む（CC BY-SA 4.0 の継承条項に触れる配布物を作らない）。出典は設定画面に。
    索引の控え（`search-bridge.cache`・人が読めるタブ区切り）は**変換の節ごとに、引かれたときに読み**、文字列を1本に詰めて持つ（3つとも引いて 44.6MB。前は 105.7MB・`docs/research/memory-budget.md` §6）。
    KANJIDIC2 の字の表も控え（`kanji-readings.cache`）を持つ（XML から 0.3秒・19MB → 14ms・4MB）。**商品名の読みは造語変換で初めて照らすときに作る**
    （2000件で1回 23ms・画面のスレッド。切れていても全商品で作るのをやめ、読み込みのたびの作り直しが 23ms→3.5ms・割り当て 8.6MB→2.1MB になった。2026-09-24）。
    字の表の控えは `AppPaths.KanjiReadingsCacheFile`。`KanjiReadings` に渡さなければ毎回 XML から組む。
- **ショップの一覧の検索欄も同じ書き方を受け付ける**（ユーザ判断 2026-09-28。`ShopSearch`）。読み方・畳み方は検索画面と同じで、探す材料だけがショップの物：
  「対象」のショップ名はショップ名とサブドメイン（`local-` の鍵は除く）、メモはショップのメモ。前置きは `name:`・`shop:`（ショップ名）・`subdomain:`・`memo:` が効く。
  区別の切り替えと別表記は無い。書き方は欄の吹き出しで示す（欄が狭く見本の行を置けない）。
- 類義語（Sudachi 同義語辞書・日本語 WordNet）は**入れない推し**（足した分の4件に3件が関係の無い物だった）。

## 結果

- 並べ替えは単一値の欄だけ。項目と向きを分け、意味の近い項目を隣に置く（2026-09-24）：
  入手日・払った額・公開日・BOOTHの価格（「今の価格」だと払った額と取り違えるので、絞り込みと同じ名前。ユーザ判断 2026-09-24）・スキ数／名前・ショップ・カテゴリ／容量／使った日・見た日・取り込んだ日／属性。
  向きの言い方は項目ごと（日付は新しい／古い・数は多い／少ない・額は高い／安い・名前とショップは 昇順／降順（2026-10-01 に あ→わ から変えた。英字などがどこに来るかが分からなかった）・カテゴリは BOOTHの並び／逆順）。
  並べ方の決まりは Core の `ItemOrder` に1か所（試験付き）。
  - 入手日は**代表の日付**＝購入記録ごとの日付のうち最も早い物（購入記録が無ければ入手日。手で入れた値だけ。メモ45・ユーザ判断 2026-10-05。`PurchaseDates.EnteredEarliest`）。区切りの札・2つ目の鍵・検索の写しの並びも同じ値。
  - **値が無い商品は、どちらの向きでも後ろにまとめる**：入手日・払った額（額を1つも入れていない）・公開日・BOOTHの価格（バリエーションが取れていない）・
    スキ数（BOOTH から一度も取れていない）・容量（ファイルを持っていない）・最近の足跡・属性。0 や一番古い日として混ぜると、昇順で先頭に来る
    （容量とスキ数はそうなっていた。2026-09-24 に直した）。
  - 払った額は「自分用」の額の合計（`Purchases.SelfPaidOrNull`。統計の自分用の支出・価格の絞り込みの既定と同じ数え方）。贈った・貰ったは含めない。無料は 0。
  - BOOTHの価格はいちばん安いバリエーション（商品ページの「¥300〜」と同じ読み方）。呼び方は絞り込みの「BOOTHの価格」に揃えた。
  - カテゴリは候補と同じ表の順（`CategoryTable.RankOf`：3Dモデルの子を先に、後は同梱の表の親の順・親の中は子の順）。表に無いカテゴリ（その名前の読みの順）→ カテゴリの無い商品、の順に後ろ。
    BOOTH に無い商品で人が入れたカテゴリも同じ表で引く。
  - **2つ目の鍵**：ショップとカテゴリは、同じショップ・カテゴリの中を入手日の新しい順（その店・種類で最近何を買ったかを見る）。それ以外は名前の読みの順。
- **並べ替えの区切りの札**（ユーザ判断 2026-10-01「イメージは図書館やビデオショップの分類の為の偽アイテムだ」）：まとまりのある順で並べているとき、まとまりの最初の商品の前に札を1枚入れる。
  見出しの帯を別に挟むのではなく、**カードと同じ升に入る偽の項目**（リストでは列をまたぐ同じ高さの1行）。並べ方の決まりと切り方は Core の `ItemGroups`、札は `SortDivider`。
  - 出す並べ替え：**カテゴリ**（子の名前。親は小さく上に。商品ページと同じく人が入れたカテゴリを先に見て、親は表から、表に無ければ BOOTH から取れた親）・
    **ショップ**（画面に出るショップ名）・**公開日**（年と月「2026年9月」。仮決め）・**入手日**（公開日と同じ年と月。並べ替えと同じ代表の日付で切る。ユーザ判断 2026-10-01）。
    値の無い商品は「カテゴリなし」「ショップなし」「公開日なし」「入手日なし」の札にまとめる（並べ替えも向きによらず後ろにまとめている）。
    出さない（ユーザ判断 2026-10-01）：数の項目（帯の切り方を決めていない）・名前（読みが推定で頭の字の境が誤る）・「最近」の3種（時計で切ることになる）。
  - 札の中身：何で並べたか（「カテゴリ」）・名前・件数（「{n} 件」）。まとまりが1つでも出す。読み上げの名前は「カテゴリ：3Dモデル / 3D衣装、4 件」（ID `SortDivider`・リストの行は `SortDividerRow`）。
  - **札は商品ではない**：一覧の件数（「n 件」）・「すべて選択」・まとめて操作・商品の右クリックのメニューの対象に入らない。選ぶ箱も星も無い。
  - **ショップの札だけ操作を持つ**（ユーザ判断 2026-10-02・メモ2-⑤）：そのショップのアイコンを出す（無ければ何も出さない。頭文字のタイルなどの代わりの絵は出さない）。カードの札のアイコンは**カードの幅の3割**（160〜360 で 48〜108。前は44の固定。メモ16-④ 2026-10-03。`CardMetrics.ShopIconSize`）で、スライダーに合わせて伸び縮みする。
    左クリックでアプリのショップの画面、中クリックで BOOTH のショップのページ、右クリックのメニュー「ショップを開く」「BOOTHで開く」（商品の右クリックと同じ言い方）。
    手元だけのショップ（`local-`）は BOOTH の行を出さず中クリックも効かない。「ショップなし」の札とカテゴリ・公開日・入手日の札は今までどおり押しても何も起きない。
    読み上げ・自動操作の「押す」は左クリックと同じ（`SortDividerBorder`）。**キーボードの止まりにはしない**（下）。
    件数と選ぶ対象は今までどおり商品だけの並びから数え、札は画面に出す並び（`DisplayItems`）にだけ混ぜる。
  - キーボード：**札には止まらない**（並び `ArrowGroup` の止まり先に入らない。矢印はカードからカードへ札を飛ばす。リストの ↑↓ も札の行を飛ばす）。`docs/spec/ui-input.md`。
  - 札は鍵ごとに使い回し、絞り込みで件数だけ替える。作り直すと段の組み方（`CardRowLayout`）が同じ物と見なせず、最初の札から後ろの段を全部抜き差しする。
    列の数が変わっただけ（幅・カードの大きさ）なら数え直さない。札は部品が少ないので、カードのように後から作らない（`DeferredCardHost` を通さない）。
  - 設定「並べ替えたとき、まとまりごとに区切りを表示」（`AppSettings.ShowSortDividers`・既定は入）で切れる。
    入手日の札だけは、そのすぐ下の子の設定「入手日で並べたときも区切りを表示」（`ShowAcquiredSortDividers`・**既定は切**。入手日は既定の並べ替えで、入だと開くたびに一覧に札が並んで邪魔だった・ユーザ判断 2026-10-01）で入れられる
    （入手日は既定の並べ替えで、普段の一覧に札が並ぶのを好まない人のため。ユーザ判断 2026-10-01）。子は親の文字の頭に揃えて下げ、親が切れている間は押せず薄い（値は残す）。
  - 入れたのは検索だけ。同じカードの一覧を持つほかの画面（ショップの中・フォルダの右・タグと属性の管理・改変の使ったもの）は並べ替えを選べないので入れない。
- **名前の読みの順**（名前・ショップ、ほかの項目の2つ目の鍵。`NameCollation`・2026-09-24）：先頭の括弧の塊（【】［］[]（）〔〕など）と記号・空白を飛ばす
  （括弧しか無い名前は括弧の中身で比べる）。漢字は同梱の KANJIDIC2 の読みでひらがなに（熟語は音・1字は訓の最初の読み）、カタカナもひらがなに寄せ、
  英字は大文字小文字を区別せず、数字は数として比べる（2 が 10 より前）。鍵の中では 数字 → 英字 → かな → 読めない漢字 の順。
  - **読みは推定なので、実際の読みと違う順になることがある**（指輪 → しりん・衣装 → いそう）。辞書（JMdict）の表記→読みは引かない（索引が要り、並べ替えのために持つほどの差が無い）。
  - 鍵は名前ごとに1度だけ作って控える（2000件で作るのに約4ms・控えた鍵で並べるのに約2.5ms。前の符号の順は約1.3ms）。字の表は検索の文字列を作るとき（読み込みの裏）に読んである。
- カード：1枚目の絵（マウスの横位置で切り替え・止まったときだけ150ms）、名前の下にユーザータグ・属性の札と払った額・対応の1行（下の「カードとリストに出す中身」）、下段に容量と所持・状態のチップ（所持／未編集／見つからない。持っている物が全部見つからなければ「見つからない」、一部だけなら「一部見つからない」・ユーザ判断 2026-10-06）。**チップが入り切らないときは容量を先に取り、入らない分を後ろのチップから文字の無い色の丸にして幅に収める**（ユーザ判断 2026-10-06「+3 などにたたむのではなく…ただの丸に」。前は残りを「+n」にまとめていた・メモ52）。
  並びは**左から字の少ない順**：所持・未編集・更新あり・取り込み中・見つからない（一部見つからない）（ユーザ判断 2026-10-06「要素を並べる順番は左から文字数の少ないものとし、丸くなるのは右側の要素から」。同じ字数の札はカードには無い）。入らないときは**右の札から**丸になり、丸は並びの右の端に続くので、札と丸が混ざっても左から同じ順（丸だけを寄せ集めない）。リストの行も同じ順で、未所持（未編集と同じ3字）は所持と入れ替わりに出る札なので所持の所（所持・未所持・未編集・…）。丸は直径8・押せる幅10で、**丸の隣（丸どうし・丸と札）の間は8**（見える隙間は丸どうし10・丸と札9。前は札どうしと同じ4で、見える隙間6が直径8より狭く詰まって見えた・ユーザ指摘 2026-10-06）、札どうしは4。幅160のカード（容量の残り約86）でも5つ全部の丸（82）が入る。段の高さはチップと同じ。色はそのチップの文字の色。**「更新あり」は通知の未読の色（`Unread`）**、「取り込み中」は青（`Accent`）——丸では文字が消えるので色で見分ける（ユーザ判断 2026-10-06。前はどちらも青）。
  丸に乗せると吹き出しの1行目にチップの名前、2行目にチップの吹き出し（あれば）。読み上げもチップのまま（中の文字を消さずに大きさ0で置く）。「更新あり」は丸でも同じボタンで、押せばチップと同じく通知を開く。
  全部を丸にしても入らないほど狭いときだけ、後ろの丸を出さない（ふつうのカードの幅では起きない）。丸は同じ部品の描き方を替えるだけ（`BadgeOverflowPanel`・`StatusBadge`。カード1枚の部品の数を増やさない）。カードの左端を越えず、容量の文字に重ならない。リストの行のチップは折り返すので丸にしない。未所持は左下に「未所持」の襷。お気に入りの星は名前の欄の右下で、字の大きさ22（2026-10-06 に15 → 17 → 22。周りが空いて小さく見えた・ユーザ判断「カードはもう5px,リストはあと3px」）。リストの行の星は18（15から）。カードの高さ・行の高さは変えていない。

  **値はアプリに1つ**で、どの画面で動かしても全部の画面が同じ大きさになる（設定の `cardWidth`・`listRowHeight`。止まって0.4秒で書く・`ItemViewSize`）。改変の使ったもの・アバターのカードも同じ値を見る。
  カードの大きさは `CardMetrics` の1か所：絵の高さは幅−28、絵を読む長辺は幅×1.05 を40刻みに切り上げ（228 → 240。刻みを越えたときだけ見えているカードを読み直し、読み終わるまで前の大きさの絵を出す）。
  動かしている間は列数が変わったときだけ行を組み直し、ずれた所だけを抜き差しする（`CardRowLayout`。ショップとフォルダも検索と同じにした）。
  文字の欄の高さ（176。2026-10-04 に札の段を足して 136 から 158、その後 176。`CardMetrics.TextAreaHeight`）は変えない。ショップ画面・改変の使ったものも同じカード（`ItemCardResources.xaml`）を使う。
  ショップ画面・検索・フォルダビューの右の欄のカードとリストの行に、通知に未読の「商品の更新」がある商品の「更新あり」の札を出す（ショップの一覧の「更新のあった商品が {n} 件」と同じ数え方。検索とフォルダはユーザ判断 2026-10-02「検索にも出しましょう」。改変・アバターなどほかの画面のカードには出さない）。
  押すと通知を開き、その知らせまで送る（ユーザ判断 2026-09-27）。
  ショップの中は「所持しているものだけ」の横の「更新があるものだけ」で札の付いた商品に絞れる（2026-09-28）。札が1枚も無い店ではこのチェックを出さず、読み直して0件になったら外す。
  ショップの一覧にも同じ「更新があるものだけ」を置き、カードに「更新のあった商品が {n} 件」が出ている店だけに絞る（2026-10-02 のメモ7）。更新のある店が無ければ出さず、外す。一覧のほかの絞りと同じく、アプリを閉じるまで覚える。
- カードは白い枠だけ先に並べ、中身を4枚ずつ作る（`DeferredCardHost`）。サムネイルの保持は画素で132MBまで（`docs/research/memory-budget.md`）。
  全件の読み直しでは、**記録が前と同じ商品のカードと検索用の文字列を使い回す**（記録の指紋 `ItemFingerprint`、2026-09-24）。カードに効く記録の外の値（③待ち・画像を取得中・サムネイルの役割・札の出し方）が変わった物だけ作り直す。選択は今までどおり読み直しで外す。「画像を取得中」のフォルダ見は読み直しの裏でまとめて行い、フォルダの日時が前の読み直しと同じ商品は前の答えを使う（`ImageFolderPresence`、2026-09-29）。
- 右クリック（検索・フォルダビュー・改変の詳細・ショップで共通。`ItemCardResources.xaml` の `CardMenu`）：BOOTHで開く／ショップを開く／リンクをコピー／編集に入る／改変に追加…／お気に入り／選ぶ／更新の通知を開く／**既読にする**（その商品の未読の更新の通知を既読にする。商品ページの「既読にする」と同じ命令。札が下り、ナビの通知の数も減る。ユーザ指示 2026-10-02）／**開く ▸**（エクスプローラで開く…・一時的に展開して開く…）／**Unity ▸**（Unityへ送る…・改変に追加して送る…・Unityで選択…）／非表示にする。
  **項目は全部出し、できない操作は押せなくして吹き出しで理由を言う**（2026-10-04 から。前は未読の更新があるときだけ「更新の知らせを開く」「既読にする」を出していた。決まりは [ui-input.md](ui-input.md)「右クリックのメニュー」）。中クリックは BOOTH を開く近道。
- 右クリックの「非表示にする」は窓で聞かず、下の帯に「〇〇を非表示にしました。設定の「非表示にした商品」から戻せます。」と「非表示を解除」を出す（続けて非表示にした分は束ね、解除は束ねた全部に効く。点検 2026-09-23・B2：戻し方が画面のどこにも出ていなかった）。

  カードには結果を出す行が無いので、選択・改変に足した結果は知らせの窓で言う。

  - **既読にする**（ユーザ判断 2026-10-02「4は入れましょう」）：選んだ物に未読の更新がある商品があるときだけ、帯の右の並びの左端に出す（出し入れでほかのボタンが動かない所）。

## カードとリストに出す中身（ユーザ判断 2026-10-04：案A と案C の両方を採る）

決めた絵は担当SVD の案（`mock/svd-saved-search-card-info` の B1・B3）。コードは `ViewModels/CardInfo.cs`（`CardInfo`・`CardPeek`・`CardInfoOptions`）・`Controls/CardInfoStrip`。

- **R-18 の商品は、カードとリストの名前の頭にピンクの「R-18」**（メモ82・ユーザ判断 2026-10-06。色は `AdultText`。赤は消す操作の色なので使わない）。見分けは条件「R-18」と同じ `Booth.IsAdult`。名前の文字の中の1区切りで描き、名前そのもの（読み上げ・吹き出し）には混ぜない。
- **カードの名前の下（案A）**：ユーザータグの札（大分類ごと。設定「一覧のカードに小分類のタグも表示」なら「衣装：夏・冬」）＋入らない分の数「+2」／
  属性の札「質感 63」/「¥3,000・対応 24体」の1行。**札は決め打ちの数にせず、カードの幅に入るだけ並べる**（`CardInfoStrip` が描くときに数える。入らないユーザータグは「+n」にまとめ、入らない属性は出さない。高さは変えない。メモ37-③・2026-10-05）。**幅が200未満なら1行は「¥3,000・24体」**。
  名前の欄は2行ぶんの高さで固定し、1行の名前でも札と1行が同じ高さに出る（メモ37-①。カードの文字の欄を 158 → 176 にした）。
  - 評価していない属性は出さない（札を空けず、次に評価してある属性を出す）。値が何も無い商品も、札の段と1行の高さは同じ（一覧の段が揃う）。
  - 払った額は並べ替えの「払った額」と同じ自分用の合計（`Purchases.SelfPaidOrNull`）。無料は「無料」、額を入れていなければ書かない。
    対応は商品ページの欄と同じく、消した物を除き、確かめていない候補は数える。どちらも無ければ1行は空。
  - 未所持の襷に掛からないよう、未所持のカードは1行を右へ寄せる（前のユーザータグの札と同じ 46）。右下の星にも掛けない。
  - **札は部品で組まず、`CardInfoStrip` が自分で描く**。枠と文字の部品で組むと、作り物の2000件を同じ歩みで流す時間が 1.37秒 → 2.12秒
    （33ms を超えた歩み 60 歩中 2 → 44）になった。描く形で 1.40秒・2回と、前と同じ（測り方は下）。読み上げには札の文字を1つの文で渡す。
- **出す属性**：設定の表示「一覧と検索」の「カードに表示する属性」で選ぶ（`AppSettings.CardAttributes`。候補付きの欄から1つずつ足し、札の × で外す）。
  **選んでいなければ属性の管理の全部を候補にする**。**出す順は、設定で選んだ順でも管理の並びでもなく、その商品に付いている順**（ユーザ判断 2026-10-04。商品の JSON の並び）。**並べ替えに属性を使っているときは、その属性を先に出す**（選んでいない属性でも。並べた値が見えないと順が読めない）。
  検索の一覧のカードだけ並べ替えを持ち込み、ほかの画面へ渡すカード（フォルダの右・アバター・タグと属性の管理など）とショップの中は設定と属性の並びだけで決める。
  決め方は画面ごとに1つ（`CardInfoContext`）で、絞り込みのたびに今の設定・属性の並び・並べ替えに合わせ、変わったときだけカードに知らせる。
  設定を変えたら一覧を読み直す（小分類のタグの設定と同じ）。属性の名前を変える・統合する命令（`RenameAttribute`）は、設定で選んだ名前も同じ命令の中で書き換える（統合なら統合先へ。重なれば1つに）。消す命令（`DeleteAttribute`）は設定からも外す。
- **カードの属性の段は設定で出し入れする**（設定の表示「一覧のカードに属性の札を表示」・`AppSettings.ShowCardAttributes`・ユーザ判断 2026-10-06。**既定は出さない**：既定のカードが縦に長い印象だったため）。
  切っているとカードの属性の札の段（札18＋間4＝**22**。`CardInfoStrip` の札の段・間と同じ定数）を畳み、カードの高さが **22 低くなる**（`CardMetrics.Height`：絵の高さ＋176、切っているときは＋154）。
  高さは `CardMetrics` が持ち、DynamicResource の `CardHeight` を使う画面（検索・ショップ・フォルダ・アバター・並べ替えの区切りの札）が全部その場で追う。1つの値なので画面ごとにずれない。
  **カードだけに効かせる**：リストの「属性」の列と、乗せたときの重ねの属性の棒は消さない（設定の名前が「カード」で、重ねは切ったときも属性を見る道だから）。
  切っている間は「カードに表示する属性」の欄を押せず薄くする（選んだ属性は残り、入れ直すと戻る。親に従う子の設定と同じ作法）。
  設定を変えたら一覧を組み直し（`RefreshCardInfo` が札の決め方とカードの高さを同じ歩みで替える）、開いている一覧がその場で替わる。起動のときは `ItemViewSize` がカードの幅と一緒に当てる。
  JSON は `showCardAttributes`（欠けていれば切）。
- **乗せたとき・キーボードで止まったとき（案C）**：絵の上にユーザータグ（全部・小分類つき）・属性の棒（札と同じ順。札に出さない属性は後ろに、同じく付いている順。管理に無い属性も出す）・払った額・対応を重ねる。
  **ユーザータグ・属性の札に乗せて少し待ってから出し**（ギャラリーの乗せて切り替える待ちと同じ設定 `GalleryHoverDelayMs`・同じ作法で、離れたらすぐ下ろす。メモ37-②・2026-10-05。前は名前の欄に乗せた瞬間に出て、絵に被るのが唐突だった）、**絵に乗せている間は出さない**——絵はなぞって送る所で、重ねると送った絵が見えない。キーボードで止まったときは待たずに出す。
  絵の枠に入る数だけ棒を出し、入らない分は最後の行を「ほか n 件」にする（幅160のカードで1本＋「ほか n 件」）。幅200未満は棒を短くし、名前に幅を譲る。
  出す物が何も無い商品には重ねない。重ねる部品は出すときに作る（畳んでいる間は型を当てない）。
- **リストの列（案C）**：検索のリストだけに「ユーザータグ・属性・払った額・対応」の列を名前の直後に足す（`SearchItemListGridView`）。属性の列は選んだ属性のうち評価した物を全部（札と同じく商品に付いている順）
  「質感 63　かわいい 66」と並べる（属性ごとに列を作ると、選んだ数で列が増減して幅を覚えられない）。幅は今の列と同じく `search.col.tags`・`attrs`・`paid`・`avatars` に覚える。
