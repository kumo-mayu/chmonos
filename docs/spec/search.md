# 検索（今の決め事）

> **要点**：絞り込み（離散値）と文字列検索（自由記述）を分け、並べ替えは単一値の欄だけ。絞り込みは**モジュール方式**（「＋ 条件を追加」から条件を1つずつ足す。有効／無効のチェックと ×。**足した条件・有効か・値まで覚える**）。非表示と（設定で隠しているときの）R-18 は条件より先に外す。
> 文字列は同梱の辞書で表記（ローマ字・かな・漢字・英語）をまたげる。**意味検索（埋め込み）はしない**——辞書は引いた結果を説明できる。
>
> **コード**：`App/ViewModels/SearchViewModel*.cs`（`.Modules`・`.Filtering`・`.History` など partial）・`SearchModules.cs`（条件の種類と形）・`ItemCardViewModel`・`DeferredCardHost`・`Controls/ContentItemsControl`、`Core/Models/SearchModuleState`・`Core/Services/DateText`・`Core/Search/`（`SearchQuery`・`SearchBridge`・`ReadingMatch`）・`Core/Services/ItemOrder`・`FolderTree`
>
> **経緯**：`docs/history/search-redesign.md`（2026-09-15〜16 の刷新：案の原文・決めたこと・実装）、`docs/history/ui-revision.md` §1〜3（絞り込み・文字列・カード・辞書の実測）、`docs/history/grill-2-ui-and-data-model.md`、`docs/research/fuzzy-search.md`（類義語は入れない推し）

## 絞り込み

- **モジュール方式**（ユーザ案 2026-09-15）。「＋ 条件を追加」のメニューは見出し（BOOTHの情報・商品の情報・カレンダー・スライダー・利用状況）の下に条件が並ぶ。
  同じ条件が2つの見出しに出ることがある。**各条件は一度しか足せない**（足してある物はどの見出しの下でもグレー）。
- 条件ごとに、左のチェックで値を残したまま効かせない・右上の × で外す。
- 最初の起動は 所持（所持している）・ユーザタグ・対応アバター。**足した条件・有効か無効か・値まで覚える**（`ui-state.json` の `searchModules`。2026-09-16 に「種類だけ覚える」から変えた・ユーザ判断 Q10）。
- 形：
  - 選ぶ（三項）：所持・販売終了・R-18・有料無料・お気に入り・非表示・未編集は「両方」を持つ（その選択肢で何も絞らない）。ギフトは「両方」を持たず、チェックで切る。
  - 候補から積む：カテゴリ（親でも選べる）・BOOTHタグ・ショップ（1商品に1つなので OR だけ）・ユーザタグ（親・親›子）・対応アバター・改変・Unityプロジェクト・ファイルの場所（子孫を含む）。
    2つ以上積むと「すべてに当てはまる商品だけ（AND）」を出す（切れば OR）。候補は全部並べず入力欄から1件ずつ積む。
  - 範囲：スキ数・価格（スライダ2本と数の欄。空欄の側は制限しない）、属性（属性ごとに 0〜100、複数は AND／OR。足した属性は未評価を外す）。
  - 日付：公開日・入手日。**始まり・終わりに効かせるトグル**（ユーザ指示 2026-09-16。空欄を「制限なし」と読ませるより、切ってあることが見える方が分かる）。
    足したときは**手元で一番古い日〜一番新しい日**が入り、両方効く（日付の分かる商品が1件も無いときだけ両方切って足す）。始まりは終わりを越えられない（数の範囲と同じ）。
    欄に打つかカレンダー。`2026/9/1`・`2026-9-1`・`2026年9月1日`・`20260901`、年の無い `9/1` は今日以前で最も近い日、
    `2026/9` は開始なら月初め・終わりなら月末、`2026` は年の初め／終わり。全角可（`DateText`）。指定した日をまるまる含む。日付の無い商品は外す。どう読んだかを欄の下に出す。
  - 最近：使った（Unityへ送った）・見た・手元に入った ＋ 日数。記録の無い商品は外す。
- 意味：
  - 所持＝ファイルかフォルダを1つ以上持つ。未編集＝ユーザタグが0件（取り込みの③待ちは除く）。
  - 価格＝既定は**自分が払った額**（値段を入れていない商品は範囲に入らない）。切り替えで BOOTH の価格（種類ごとの価格のどれか1つでも範囲に入れば当たり）。
  - 有料・無料＝払った額があればそれ、無ければ BOOTH の種類ごとの価格（無料と有料の種類が両方あれば両方に出る）。どちらも分からなければ「両方」のときだけ。
  - ギフト＝ギフトされた・ギフトした・その他（自分で入手・購入記録なし）。貰って自分でも買った物は両方に出る。
  - 販売終了＝販売終了＋非公開・削除（BOOTH で見つからないのが続いた）。非公開・削除は「非公開・削除された商品も表示する」を入れたときだけ出す。売り切れは含めない。
  - 対応アバター：**「出すもの」の2つのチェック**（ユーザ判断 2026-09-16・案C）。商品を「対応が書いてある」と「対応の指定が無い」に分け、どちらを出すかを選ぶ。
    - ☑ 対応している商品（既定で入）／☐ 対応の指定が無い商品（既定で切）。BOOTH には対応を書かずに「どのアバターでも使える」商品がある。
    - 3つの意味がそのまま印の付け方になる：上だけ＝対応のみ・両方＝指定なしも含める・下だけ＝指定なしのみ。**最後の1つは外せない**（両方切ると何も出ない）。
    - 「指定が無い」は、出品者の宣言（消していない分）と共通素体の宣言が両方とも無いこと。1つでも書いてある商品は書いてあるとおりに照らす。要確認（説明文のリンク）は宣言に数えない。
    - 下だけのときは、選んだアバターが意味を持たないので、アバターの欄・チップ・「素体経由」を薄くして触れなくする。**アバターを選んでいなくても絞る。**
    - 各行に「他の条件を当てたうえでの件数」を添える。実データ（友人の写し205件）でアバター1体：対応77件・指定なし84件・両方161件。
  - 対応アバター：候補は 持っているアバター → 共通素体 → 持っていないアバター（`名前（商品ID）`・IDでも引ける）。アバターは直接対応＋素体経由（「素体経由の対応も含める」・既定で入。`docs/spec/avatars.md` の相性）。
    共通素体は素体への対応の宣言で当たり、素体経由を含めるなら素体に属するアバターへの対応でも当たる。
  - ショップ：**「★ お気に入りのショップの商品（件数）」のチェック**を持つ（ショップ画面の星・`shops.json`。別の条件にせずここに置く・ユーザ指示 2026-09-16）。
    ショップの条件は「選んだどれか」なので、入れるとお気に入りのショップを全部選んだのと同じに働く（選んだショップと合わせてどれか、選んでいなければお気に入りだけ）。
    星を変えたらショップ画面から知らせを受けて絞り直す。
  - 改変：改変1つ、またはアバター（そのアバターの改変すべて＝前の「着せているアバター」）。Unityプロジェクト＝改変を通して紐付いた商品（プロジェクトの中身は見ない）。
- 見た目（ユーザ指示 2026-09-16）：
  - 条件ごとに畳める（見出しの山形）。**畳んでも効いたまま**なので、畳んだ姿に効いている中身を1行で出す（何も絞っていなければそう言う）。畳んだかどうかも覚える。
  - 順番は見出しの左のつまみ（⋮⋮）のドラッグで変える。よく触る条件を上に置けるようにするため。掴めるのはつまみだけ——カードのどこでも掴めると、スライダを動かすたびに並べ替えが始まる。
    落とし先は線で出す（`Controls/RowReorder`。タグ・属性の管理と共通。条件は種類が違っても同じ並びに混ざる＝`ReorderGroup`）。並べ替えは結果を変えないので絞り直さない。
  - **左端はいつでも0**（ユーザ指示 2026-09-16。手元の商品で左端が動くと、同じ位置が日によって違う数を指す）。右端は手元の一番大きい数。
  - **上下は越えられない**（同。下限は上限まで、上限は下限までで止まる。同じ数は許す）。触った側を相手に合わせる。片側を切っているときは止めない（止める相手がいない）。
    小さい方を下限と読み替える案は採らなかった——上下が名前の付いた別の行なので、「下限」の行が上限として働くと、行の名前と左のトグルが指すものが食い違う。属性のスライダも越えられない作りで揃えている。
  - スライダは目盛を出し、両端の数（0 と手元の最大値）を下に添える。つまみは割合（0〜100）で動かし、**対数で数に割り戻す**（ユーザ判断 2026-09-16・案1）。
    等間隔だと、1件だけ高い商品があるだけで実際に使う範囲が潰れる（5万円が1つあると1目盛が500円になり、2千円付近を指せない）。価格もスキ数も安い側・少ない側に集まっている。
  - **数が詰まっていない帯は、左端の1目盛（10%）に畳む**（価格の 0〜100円。BOOTH の有料販売は100円から・ユーザ指摘 2026-09-16）。
    0 を含む対数だとこの帯が目盛の大半を取る（上限500円で約74%・実測）。畳んだ中は直線なので **0〜100円も連続で指せる**（飛ばさない。0%→0円・5%→50円・10%→100円・55%→224円・100%→500円）。
    小さい数にも意味がある条件（スキ数）は畳まず、0からの対数にする。配り方はスライダのツールチップに書く。
  - スライダの背に**分布の帯**を敷く（同・案5）。商品が多い所が見えると範囲を決められる。棒は40本で、つまみと同じ対数の配り方で数える。
  - 価格は**「外れ値を無視」**（既定で入・ユーザ判断 2026-09-16）。**95%の位置の価格の5倍以上**を外れ値とし（`Core/Services/Outliers`）、目盛の幅と照合の両方から外す。
    外すのは数だけで、商品は外さない（その商品は他の種類の価格で照らす）。止め値の種類しか無い商品は「価格が分からない」扱い。
    当たるのは支援用の種類（0円・150円の商品に 99,999円の種類がある）や、販売を止めるためのあり得ない高値（購入者のダウンロードの権利は残したい）。
    統計の定義（Tukey・MAD）は高い側の普通の商品まで外れ値にし、隣との切れ目は止め値が何段もあると取りこぼすので採らなかった。
    何円以上を何個外しているかをチェックの横に出す（友人の写し：BOOTHの価格で「10,000円以上の1個」、右端が 99,999円→8,500円）。
  - **足したときの値は端から端まで**（0〜手元の最大値）。数が分かる商品が1件も無いときだけ、上下とも切って足す（足した瞬間に0件になるのを避ける）。
  - ドラッグ中は**数と要約をすぐ出し、絞り直しは止まってから1回**（150ms・`Debounced`）。2000件での絞り込み1回は 11〜20ms（照合 1.4〜6.6ms＋選択肢の件数 4〜14ms。件数は条件の数に比例）なので、
    毎回絞っても動かなくはないが、1秒に数十回は無駄（計測：`docs/feedback/done-2026-09.md` 2026-09-16）。属性のスライダも同じ扱い。
    **端も値として受ける**（左端＝0以上・右端＝手元の最大値以下）。片側を外すのは各スライダの左のトグルで、**既定は上下とも効く**（ユーザ指示 2026-09-16）。
    前は端に寄せると黙って「制限なし」になり、「0以上」と「下限なし」を言い分けられなかった。
    上下とも効く既定のため、**数の範囲は足した時点で絞り始める**（数の分からない商品——値段を入れていない・BOOTH に無い——は外れる。属性と同じ考え方）。
  - 入力が残る欄（検索の文字・数の範囲・日付・日数）には、値があるときだけ消す × を出す。検索の文字の × は文字だけを消す（条件は触らない）。
  - 日付は「欄 → から／まで」の順に置く（日本語では値のあとに付く）。
- **非表示と R-18 は条件より先に外す**：非表示の商品は「非表示」の条件を足して効かせていなければ出さない（設定「非表示にしている件数を検索結果に出す」で件数を添える）。
  設定で R-18 を隠しているときは R-18 の商品を出さず、R-18 の条件はグレーにして理由を書く。**2026-09-16 まで検索画面だけどちらも外していなかった。**
- 外した条件：更新の有無（要確認の画面で見る）・見つからない（フォルダビューと未確定で見る。統計の「ファイルが見つからない」はフォルダビューへ移る）。
- **選択肢には件数**：今の他の条件を当てた後の件数。自分の条件は自分を除いて数える。
- 「条件をクリア」は文字列と値を戻す（足した条件は残す）。消す前の条件は検索の履歴に積む。
- 他の画面から入る口（タグ・属性・アバター・ショップ・フォルダ・カテゴリ）は、値を戻してからその条件を足して値を入れる。入った後もパネルで触れる。
- 絞り込みパネルは畳める（幅はドラッグで変えられる ⇄ 34px）。畳んだ姿に効いている条件の数とその中身のツールチップ。
- 検索の履歴：絞り込み（効いている条件の状態そのまま）と文字列を1セット。名前を付けた物は件数で落とさない。書くのは `UiCommand.ChangeSearchHistory`。
- 条件の中の部品は `ContentItemsControl` に並べる（素の ItemsControl だと項目の中の入力欄・チェックが UI Automation から1つも見えない）。

## 文字列

- 構文：スペース＝AND・`-語`＝除外・`"…"`＝フレーズ・`OR`・`( )`・`name:語`＝探す所を絞る（ユーザ案 2026-09-15）。入力欄の下に見本1行、説明はホバーで。
  **構文の記号は1字ずつ NFKC で畳んでから読む**（全角の括弧・引用符・ハイフン・空白・コロンも効く・ユーザ判断「記号も畳みましょう」）。
  - 前置きは決めた名前だけ（`name` `shop` `subdomain` `memo` `main` `path` `id` `variation` `file` `content` `tag`）。知らない語（`Re:Zero`・`https:`）はふつうの文字。
    `"…"` の中の `name:` は前置きにしない。`name:"夏 セット"`・`tag:(夏 OR 冬)`・`-tag:無料` と書ける。前置きがあれば「対象」で切っている所でも探す（ユーザ判断 2026-09-16）。
- **対象**（検索欄の右の「対象」・1つずつ切り替え）：商品名・ショップ名・メモ（ここまで既定オン）／サブドメイン・本文（説明と h2）・BOOTHタグ・バリエーション名・商品ID・ファイル名・ファイルの場所（パス）・zip の中のファイル名（既定オフ）。
  **本文・パス・BOOTHタグは既定に入れない**（当たりすぎて「なぜ出たか」が分からない。BOOTHタグは絞り込みの条件で探す物・ユーザ判断 2026-09-16）。自分で入れたカテゴリは文字列の対象にしない。
  畳んだ文字列はその対象を初めて探すときに作って持つ（本文や zip の中身は使うまで作らない・`SearchHaystack`）。
- **オプション**（検索欄の右の「オプション」）：大文字と小文字を区別する（既定オフ）・全角と半角を区別する（既定オフ）・ひらがなとカタカナを区別する（既定オン）。
  既定の組み合わせ（とカタカナをひらがなに寄せるだけ）は前もって畳んだ文字列で速く比べ、それ以外は元の文字列を日本語の比べ方（`CompareInfo`）で照らす。
- **別表記でも検索**（既定オフ）：中の5つをそれぞれ切り替える——ローマ字変換（tori → とり・トリ）・漢字変換（とり → 鳥。ローマ字から直した読みにも効く）・英日変換（shark → サメ）・
  日英変換（リボン → ribbon）・造語変換（商品名を漢字1字ごとの音訓で読む・撫で音 → なでおと）。同梱の JMdict（読み→表記・英語→表記・読み→英語）と KANJIDIC2。
  - **0件でも自動では広げない**（ユーザ判断 2026-09-16：切っているのに広げると切っている意味が無い）。0件の所に「別表記でも検索する」ボタン。
  - 日英変換の英語は**英単語の区切りで当てる**（top が stop に当たらない。関係のある当たりの目安 32% → 64%・`docs/history/search-redesign.md` §4）。
  - 式の木を `Or(Term, 別表記…)` に組み替える（`-無料` などの意味を壊さない・前置きは別表記にも当てる）。打ち直したら広げた式を捨てる。
  - **何で当たったかを必ず出す**（「『tori』を とり・トリ・鳥 としても探しました」）。1文字のかなは候補にしない。漢字を含む語には架けない。
  - 辞書は無改変で同梱し、索引は初回に手元で組む（CC BY-SA 4.0 の継承条項に触れる配布物を作らない）。出典は設定画面に。
- 類義語（Sudachi 同義語辞書・日本語 WordNet）は**入れない推し**（足した分の4件に3件が関係の無い物だった）。

## 結果

- 並べ替えは単一値の欄だけ（名前・入手日・払った額・容量・公開日・スキ数・最近など）。値が無い商品は後ろにまとめる（`ItemOrder`）。
- カード：1枚目の絵（マウスの横位置で切り替え・止まったときだけ150ms）、下段に容量と所持・状態のチップ（所持／未編集／ファイルが見つからない）。未所持は左下に「未所持」の襷。お気に入りの星は下の真ん中。
- **カードとリストを切り替えられる**（ユーザ指示 2026-09-14）。切り替えは一覧の右下に重ねて置く。どちらで出すかは画面ごとに `ui-state.json` の `itemListScreens` に覚える。
  - リストの1行：選ぶチェック・小さな絵（乗せると大きな絵）・星・名前・ショップ・札（見つからない・取り込み中・未編集・所持／未所持）。押す・右クリック・中クリック・星はカードと同じ。
  - 列の幅は見出しの境目をドラッグで変え、全部の行で共通（`docs/spec/ui-rules.md`「商品のリストの列」）。
  - カードとリストの見た目と操作は1か所（`Views/ItemCardResources.xaml`・`IItemCardHost`）にあり、フォルダビューの右側も同じ物を使う。
- カードの大きさは設定の「サムネイルの大きさ（小・中・大）」で変わり、その場で列を割り直す（ユーザ判断 2026-09-15。前は保存されるだけだった・R2）。
  大きさは `CardMetrics` の1か所：中が前からの大きさ（幅228・絵の高さ200・絵を読む長辺240）、小（180・150・190）と大（300・270・320）は**仮の値**で、ユーザが触って決め直す。
  文字の欄の高さ（136）は変えない。ショップ画面・改変の使ったものも同じカード（`ItemCardResources.xaml`）を使う。
- カードは白い枠だけ先に並べ、中身を4枚ずつ作る（`DeferredCardHost`）。サムネイルの保持は画素で132MBまで（`docs/research/memory-budget.md`）。
- 右クリック：BOOTHで開く／ショップを開く／編集に入る／エクスプローラで開く／非表示にする。中クリックは BOOTH を開く近道。
