# 外から使う API：ソフトごとの許し

> **要点**：ソフトが `POST /v1/clients/request` で許しを求め、Chmonos の画面に窓を出し、人が許したときだけ、そのソフトだけのトークンを1回返す（2026-11-11。plan 31）。
> 読むのはいつも許し、書き込みは種類ごとに人が選んだ物だけ許す。Chmonos はトークンのハッシュだけを保存先の `api-clients.json` に控える。
> 今までの `api.json` のトークン（1本）は当面そのまま残り、今と同じ権限で動く。API の決め事の全体は [local-api.md](local-api.md)、URL の形は [local-api-shapes.md](local-api-shapes.md)。

## なぜ

ユーザの言葉（2026-11-11）：「APIが全体での書き込み許可しかできないのは危険なので、ソフト毎に保存出来るようにしたいです。」
今までは設定の「ほかのアプリからの変更を許す」1つで、`api.json` を読めるすべての道具に、すべての書き込みを許していた。

**守れる範囲**：同じ Windows ユーザーで動く悪意のあるソフトは、保存先を直に読める（`api.json` のトークンも）。
防げるのは、許していない所への書き換えの事故と、誰が書いたか分からない事。

## 流れ

1. ソフトが `POST /v1/clients/request` に `{"name": "名前", "scopes": ["marks", …]}` を送る（トークンなし）。
   - 答えは 202 `{"requestId", "state": "pending"}`。`requestId` は結果を取る合言葉（32バイトの乱数）で、URL に入れず本文で送り返してもらう（履歴とログに残さない。トークンを URL に入れないのと同じ）。
2. Chmonos は答える前に、接続を開いた exe を引く（下の「exe の引き方」）。ブラウザのページからならオリジンも添える。
3. 主の窓の上に「APIの利用の許可」の窓を出す：名前・exe（引けなければ「確かめられませんでした」）・オリジン・求められた書き込みの種類（既定でチェック。外せる）。
   名前はソフトが自分で付けた物で本人の確かめにならないと窓に書く。
4. 人が［許可］か［拒否］を押す。**Enter と Esc はどちらも拒否**（頼んでいないのに出る窓なので、打っている途中の Enter で許さない）。
5. ソフトは `POST /v1/clients/request/result` に `{"requestId", "wait": 秒}` を送って結果を取る。
   - `wait`（0〜30）秒まで決まるのを待つ（長く待たせない：道具の HTTP の時間切れ、HttpClient の既定 100秒より十分短く）。決まらなければ `pending` のまま返し、送り直してもらう。
   - 許されていれば、**ここでトークンを作り**、控えにハッシュを書いてから `approved` とトークンを返す。2回目からは `delivered`（トークンは入らない）。
   - 拒否なら `denied`。決まってから10分取りに来なければ捨てる（許しても受け取られなかった物は控えに書かない）。知らない合言葉は 404 `requestNotFound`。
   - 答えは `Cache-Control: no-store`。

**待たせる形にしなかった理由**：人が答えるまで1本の要求を待たせると、道具の時間切れに当たる。Unity へ送る（202 と `sendId`）と同じ「受けて、問い合わせ直す」にした。

## まとめ役が決めた事（2026-11-11・ユーザ離席中。後で変えられる形にした）

- **窓を出せないときは、すぐ断る**：503 `approvalUnavailable`「Chmonos の画面を開いてから、もう一度求めてください。」。待たせない。
  決めるのは起動の引数ではなく「今、主の窓が見えているか」（`ApiClientApprovalPrompt.CanAsk`）。`--headless` で窓を開いていない・閉じて隠している間は断り、通知領域から窓を開いた後は聞く。待たせる形に変えるなら、ここと列の扱いを変える。
- **`api.json` のトークン（古い1本）は当面残し、今と同じ権限で動く**（今ある道具を壊さない）。「ほかのアプリからの変更を許す」（`allowWrites`）は、この古いトークンにだけ効く（画面の文言も「api.jsonのトークンからの変更を許す」に直した）。
  ソフトごとのトークンは、それぞれの権限で動き、`allowWrites` を見ない。
  [要確認] 古いトークンをいずれ消すか（消すなら、使っている道具に求め直してもらう段取りと、設定の「作り直す」の扱い）。
- **窓は1つずつ**（列を1本の流れで回す）。同じソフト（名前・exe・オリジンが同じ）から答える前に重ねて来たら、同じ `requestId` を返して1つにまとめる。答えていない求めは8つまで（超えたら 429 `tooManyRequests`。人が1つずつ答える窓なので、溜まるのは道具の誤りか嫌がらせ）。
- **ブラウザのページから**は、許可するオリジン（今の CORS の設定）に入っているオリジンだけ受ける（ほかの道と同じ守りで 403 `originNotAllowed`）。

## 自分で決めた細かい点（2026-11-11）

- **前に許した同じソフトが求め直したら**、窓に「前に許可したソフトです。許可すると、前のトークンは使えなくなります。」と出し、許したら前の行を置き換える（トークンを失くして求め直したときに、古い行が溜まらない）。
- 人が選べるのは求められた種類の中だけ（窓が別の種類を返しても許さない）。何も求めなければ「読み取りだけを許可します」。
- 名前は前後の空白を除いて1〜64字。改行などの制御文字は断る（400 `invalidName`）。窓とログに出す物なので。知らない種類は 400 `unknownScope`（`read` は書いても書かなくてもよい）。
- 求めた・許した・断ったは、ログに1行（名前と種類だけ。トークンは書かない）。
- `GET /v1/clients/me`（トークン要）：今のトークンが誰で何を許されているか（`kind`：`legacy`・`client`）。道具が自分の権限を確かめるため。

## 書き込みの種類

今ある書き込みの道（[local-api.md](local-api.md) の 3a・3b・3c・段4）を、使う人に分かる粒で分けた。名前は API と保存のファイルで変えない英字（`Core/Models/ApiScopes`）。

| 名前 | 画面の名前 | 道 |
|---|---|---|
| `marks` | お気に入り・非表示 | `PUT …/favorite`・`…/hidden` |
| `recent` | 「使った」の記録 | `POST …/recent` |
| `notifications` | 通知の既読・解消 | `PUT /v1/notifications/{id}/read`・`POST /v1/notifications/read`・`…/resolve` |
| `tags` | タグ・属性・メモ | 商品の `user-tags`・`attributes`・`memo`、一覧に足す `POST /v1/user-tags`・`/v1/attributes` |
| `avatars` | 対応アバター・共通素体 | `…/avatars`・`…/avatars/remove`・`…/avatars/confirm`・`…/avatar-bases`・`…/avatar-bases/remove` |
| `modifications` | 改変 | `POST /v1/modifications`・改変の `memo`・`blueprint-id`・`unity-project`・`members`（足す・外す・戻す） |
| `unity` | Unityへ送る | `POST …/send-to-unity`（商品・改変）・`/v1/unity/sends/{sendId}/cancel` |
| `open` | 画面・エクスプローラで開く | `POST …/show`・`…/reveal`（データは変えないが、使う人の画面を動かす） |

- 書き込みの守り（`ApiWriter.Guard`）は種類を**省けない引数**で受ける（入れ忘れた道が黙って通らないように）。足りなければ 403 `scopeNotGranted`。古いトークンは今までどおり 403 `writesDisabled`。
- 1つの道に1つの種類。Unity へ送った後の「使った」の足跡・改変の行の記録は、送るの一部として `unity` だけで許す。
- 読むのは種類を問わず許す（SSE も）。
- ブラウザの事前の確かめ（OPTIONS）にはトークンが付かないので、`allowWrites` か、書き込みを1つでも許したソフトがあれば、書く方法（PUT・PATCH・DELETE）も許す。本当に書けるかは本番の要求で見る。

## トークンを照らす

- まず `api.json` のトークンを今までどおり同じ長さの比べ方で照らし、外れたら `Bearer ` の後ろの SHA-256 でソフトの索引を引く（ハッシュは送られた値から予め作れないので、引く時間から控えを推し量れない）。トークンは256ビットの乱数なので、塩や遅いハッシュは要らない。
- 誰の要求かを要求に添え（`ApiCallerInfo`）、命令の口のログの1行に「（ソフト「名前」）」「（api.json のトークン）」を添える（`Core/Commands/ApiCaller`。要求の間だけ持つ値なので、要求の中から裏へ渡した作業にも引き継ぐ）。画面で開く・エクスプローラで開くの1行にも添える。
  Unity へ送るの結果の1行と、送った後の足跡・印の命令にも名前が付く（送りは要求の中で `Task.Run` で始めるので、要求の値が送りごとに引き継がれる。コードを読んで確かめた。試験はまだ）。
- 取り消し・権限の変更は、設定の画面が書いた直後に API へ読み直させる（`ApiRunner.ReloadClients`）。ファイルを手で書いたときも、見張りが `api-settings.json` と同じ部分として拾い、取り込みの途中でもすぐ読み直す。
  **制限**：取り消す前から開いている SSE（`/v1/events`）は流れ続ける（流すのは変わった物の種類と ID だけ。つなぎ直すと 401）。切るかは [要確認]。
- 止めるとき（オフ・ポートの変更・トークンの作り直し・閉じる）は、聞いている窓を閉じ、結果を待っている問い合わせも `pending` で解く（解かないと、待ち受けを止めるのが待ちの終わりまで約30秒止まった。試験で確かめた）。
- **最後に使った日時**は、前に書いてから10分経ったときだけ書く（要求ごとに書くと、SSE をつないだ道具の問い合わせのたびに保存先へ書き、見張りが読み直す。一覧で見る目安には10分の粗さで足りる）。

## exe の引き方

- 要求を受けたその場で、Windows の TCP の表（`GetExtendedTcpTable`・IPv4・プロセスの番号付き）から、「ローカルのポート＝相手のポート、かつリモートのポート＝API の待つポート」の行を選ぶ（ループバックは1本の接続に両側の行が並ぶ）。表のポートはネットワークの順。
- 番号から `QueryFullProcessImageName`（`PROCESS_QUERY_LIMITED_INFORMATION`）で exe を引く。別の Windows ユーザーのプロセス・もう終わったプロセスは引けず、窓に「確かめられませんでした」と出して人に委ねる。
- 引く所は差し替えられる（`IConnectionOwners`）。試験は作り物と、実際に自分でつないで自分の exe が返る1本（`ApiClientTests`）。

## 控えのファイル（`api-clients.json`）

```json
{ "version": 1, "clients": [ { "id": "…", "name": "作り物の道具", "exePath": "C:\\作り物\\Tool.exe", "origin": null,
  "scopes": ["marks", "tags"], "tokenHash": "<SHA-256 の16進>", "grantedAt": "…", "lastUsedAt": null } ] }
```

- 保存先の直下。**形式の版は上げない**（新しいファイルを足すだけ。古い版は知らないファイルを読まず、消しもしない。[data-format.md](data-format.md)）。いちばん外側をオブジェクトにして版を書き、種類は列挙ではなく文字列で持つ（種類を足すたびに形式を上げずに済む。知らない種類は読むときに捨てる）。
- 書くのは2つの道：許す・最後に使った日時は API が自分の控えとして書く（`api.json` と同じく `UiCommand` を通さない。人の操作は窓で済んでいて、書くのはトークンの受け渡しと使った印だけ。
  保存先を運ぶ間の門も通らないが、API は運ぶ前に止まるので重ならない）。権限の変更・取り消しは設定の画面が `UiCommand.ChangeApiClients` で書く。どちらも同じ入れ物の錠の中で今の値に当てる。
- 読めない（手で壊した JSON）ときは、誰のソフトのトークンも通さない（空として扱い、ログに残す）。
- **引越し**（保存先ごと運ぶ）・**形式を上げる前の控え**（直下の `*.json`）には入る。
- **書き出しと「すべてを戻す」には入れない**（`api.json` と同じ。`BackupArchive`）。許しはその PC の exe へ人が出した物で、別の PC へ戻すと人が見ていない許しが生き返る。exe のパスには Windows のユーザー名も入る。戻した後は、ソフトが求め直す。[要確認] 戻した後も同じ PC なら許しを残したい、という声があれば考え直す。

## 設定の「つないでいるソフト」

- 設定の「API」の節、トークンの下。ソフトごとに、名前・exe（ブラウザならオリジンも）・最後に使った日時・書き込みの種類のチェック（全部の種類を並べ、持っている物にチェック）・［取り消す］。
- チェックを変えたら、その場で書いて効かせる。［取り消す］は確かめの窓（「…もう一度許可を求めて許可されるまでAPIを使えません。元に戻せません。」・既定はキャンセル）の後に消す。
- 許した・使った日時を書いたと API が知らせたら、一覧を読み直す（中身が同じなら作り直さない）。
- 許したソフトが無ければ「許可したソフトはありません。ソフトが許可を求めると、確かめる窓が開きます。」
