# 外のソフトが足す項目と結果を返す口（プラグインの②）[実装]

> **要点**：許したソフトが `PUT /v1/plugin/menu` で項目を宣言し、Chmonos は控え（`api-clients.json`）に書いて、検索のカード・商品ページ・複数選択の帯の「ほかのソフト ▸ {名前} ▸ …」に出す。
> 押したら、そのソフトの列に `kind: "menu"` の出来事を積み、ソフトは `POST /v1/plugin/events/{seq}/result` で結果を返す（下の帯の文が替わる）。
> 宣言が控えと変わったら人に聞き直す（同じなら聞かない・消えるだけなら聞かない）。段階：[実装]（2026-11-12・plan 44 の②）。全体の考えと①は [plugins.md](plugins.md)。

## 宣言 `PUT /v1/plugin/menu`

ソフトのトークンだけ（`api.json` のトークンは 403 `clientTokenRequired`）。丸ごと置き換え、空の `items` で消す。形は [plugins.md](plugins.md)「項目を宣言する」の例のとおり。

- **検証**（合わなければ 400。黙って捨てない：思った所に出ない・押させたくない商品で押せる、を避ける）：
  - `where` は `item`・`selection` だけ（`unknownWhere`）。子を持たない項目には1つ以上（`invalidWhere`）。
  - `needs` は `itemId`・`name`・`shop`・`category`・`files`・`unityPackages`・`avatars`・`tags`（`unknownNeed`）。`modification` は改変の場所（`where: modification`）と一緒に後で足す。
  - `when` は `hasUnityPackage`・`owned`・`hasAvatar`（true・false）と `category`（名前・64字まで）。知らない条件は `unknownWhen`、型違いは `invalidWhen`。
  - `id` は英数字と `- _ .` の64字まで、下の段も含めて重ならない（`invalidId`・`duplicateId`）。`label` は1〜40字・制御文字なし（`invalidLabel`）。
  - `children` は2段まで（`tooDeep`）。子を持つ項目に `where`・`when`・`needs` は書けない（`invalidItem`）。
  - 1つ目の段は16個まで、下の段も合わせて32個まで（`tooManyItems`）。
- **整える**：`where`・`needs` は決まった順に並べ直し重なりを除く。比べるのはこの形（順が違うだけなら同じ）。
- **答え**（`PluginMenuAnswer`：`state`・`items`〔今出している、人が許した宣言〕・`pending`〔聞いている宣言〕）：
  - 控えと同じ → 200 `approved`（聞かない。ソフトは起動のたびに送ってよい）。聞いている途中の別の宣言は取り下げる。
  - 消えるだけ（足す・変わるが無い。空の `items` も）→ 聞かずに控えへ書き 200 `approved`。**作る担当の判断**：出す物が減るだけで、人が見ていない項目は増えない。消すのに許しを求めると、拒否したとき消したい項目が残る。
  - それ以外 → 202 `pending`。許しの窓の列（1本・窓は1つずつ・答えていない求めは合わせて8つまで〔429〕）に入れる。止めたソフトは 403 `requestBlocked`、窓を出せなければ 503 `approvalUnavailable`（許しを求めるのと同じ）。
  - 窓をまだ出していない間に同じソフトが送り直したら、聞く宣言を差し替える。窓を出している最中なら後ろに並べる（人が見ている物と違う物を許させない）。
- `GET /v1/plugin/menu`：今の状態。`denied` は最後に聞いた宣言を人が許さなかった（窓を閉じた・聞けなかったも含む）。起動の間だけ覚える。

## 許し直しの窓（「メニューの項目の許可」）

- 見出し：最初の宣言は「「{名前}」がメニューに項目を追加しようとしています」、変えたときは「…メニューの項目を変えようとしています」。実行ファイル・オリジンは許した時の物。
- 「追加する項目」「変わる項目」「なくなる項目」の節に、押せる項目ごとに名前（下の段は「親 ▸ 子」）と「表示する場所：…　渡す情報：…」（商品IDはいつも渡すので必ず書く）。比べるのは ID で対にし、名前・場所・条件・情報・親のどれかが変われば「変わる」。
- 並びは高さ340で縦に送る（32個でも窓が画面に収まる。ViewShot `plugin-menu-approval-many`）。
- 許すまでは前の宣言のまま出す（変えたときだけ1行で言う）。［拒否］の数え方は許しの窓と同じ（マウスのクリックだけ数え、Enter・Space・Esc・×・閉じたは数えない。`RefusalClick`）。許せば回数は0に戻る。拒否が続いて止めたら、そのソフトの項目は出さない（下）。

## 控え

- `api-clients.json` の許しの行に `menu`（`items` の1つと同じ形の配列。無ければ欄ごと書かない）を足した。**ファイルの版も保存先の形式の版も上げない**（欄を足しただけ。古い版は知らない欄を読まずに捨てる。[api-clients.md](api-clients.md)）。
- 許しの行に持たせた理由：取り消すと宣言も消える。求め直して行を置き換えたら宣言も消え、新しいトークンのソフトにはもう一度聞く。引越し・書き出しに入れない扱いも許しと同じ。
- 読み直すときに入口と同じ検証を通し、合わない宣言（手で書き換えた）は出さない（ログに1行）。

## 画面

- **出す所**：検索・フォルダの右側・ショップのカード（アバター・改変の行のカードも同じメニュー）の右クリックの末尾に、区切りと「ほかのソフト ▸」。商品ページは**全体の右クリックが無い**ので、上の帯の「編集」の左に「ほかのソフト ▾」（「開く ▾」と同じ押すと開くボタン。↓でも開く）。複数選択の帯は右の並びの左端に「ほかのソフト ▾」を**いつも1つ**（項目が多くても帯を長くしない）。押すとソフトごとの段を開く。
  - カードのメニューは全カードで1つを使い回すので、項目は XAML に置かず、開くたびに区切りと一緒に足し直す（区切りが端に残らない。`PluginMenuItems.AttachTo`）。
- **出さない時**：API が止まっている・写しをまだ読んでいない・項目を宣言したソフトが無い・その場所の項目が無い。止めた（拒否が続いた）ソフト・取り消したソフトの項目も出さない。
- **押せない時**（灰色＋吹き出し。子が全部押せない親は押せなくして最初の子の理由。ソフトの段・「ほかのソフト」も同じ）：
  - 応答していない：今待っている問い合わせが無く、最後に取りに来てから **60秒**（待ちの最長30秒の2倍）を過ぎた。「{名前}が応答していません。」 起動し直した直後も、取りに来るまでは応答していない。
  - 条件に合わない：「unitypackageがある商品で使えます。」など、合う商品を肯定で言う。**選択は全部が合うときだけ**押せる（合う物だけを黙って送ると、選んだ物とソフトが受けた物が食い違う）。
  - 選択が1000件を超えた：「一度に送れるのは1000 件までです。」（選択の出来事の ID と同じ上限。詰めた情報が数十MB にならない）。API の写しにまだ無い商品は「読み込みの途中です。…」。
- 条件と詰める情報は API の写し（`QuerySnapshot`）から作る：読み取りの API と同じ値・同じ形にする（保存先の変化を読むまでの少しの遅れはある）。
- ソフトが付けた名前の `_` はアクセスキーにしない（`__` にして渡す）。

## 押したとき

- 押した瞬間に応答と条件を確かめ直し、合わなければ積まずに下の帯で理由を言う（開いた後に切れたソフトへ積むと、後で起動したときに古い操作が走る）。
- そのソフトの列に `kind: "menu"` を積む（購読していなくても）。`menu` の欄は `{ "id", "where", "items": [ … ] }`、`items` の1つは `itemId` といつも書く欄、needs で頼んだ欄だけ値・ほかは null：
  `name`・`shop`・`category`・`files`・`folders`（`files` を頼むと両方）は `/v1/items/{id}` と同じ形、`unityPackages` は `/v1/unitypackages` の1行、`avatars` は `compatibleAvatars`、`tags` は `userTags`。
  選択は表示の並びの順（選択の出来事と同じ）。詰めるのは画面のスレッドの外。
- ほかの出来事の欄にも `"menu": null` が付く（項目を省かない決まり）。
- 下の帯（主の窓の下・非表示の帯と同じ置き場）に「{名前}に送りました。」。ログには名前と件数だけ（商品 ID・パス・結果の文は書かない）。

## 結果を返す `POST /v1/plugin/events/{seq}/result`

- 本文 `{ "ok": true, "message": "…", "epoch": "…" }`（`epoch` は書けば今の起動と照らす。通番は起動ごとに1からなので、前の起動の通番が今の別の出来事に当たり得る）。`ok` が無ければ 400 `invalidRequest`。
- 受けるのは、そのソフトの列に積んだ `menu` の出来事で、押してから **10分**以内・新しい **32件**まで。ほかは 404 `eventNotFound`（別のソフトの通番・無い通番・古い通番・違う起動）。同じ通番に何度返してもよい（帯はそのたびに替わる）。
- 文は前後の空白を除き、空・制御文字は 400 `invalidMessage`。**100字**を超えたら切って「…」（断るとソフトが結果を伝え損ねる）。答えは `{ "seq", "ok", "message" }`（切った後の文）。
- 帯は「{名前}：{文}」（ソフトの文を Chmonos の言葉と取り違えないよう名前を前に付ける）。`ok: false` は注意の色。**帯が今出している送りと同じ通番のときだけ**差し替える（続けて押した後に、前の結果で今の知らせを上書きしない）。

## 数の根拠（作る担当が決めた。ユーザ判断「それで良いです」）

| 数 | 値 | 根拠 |
|---|---|---|
| 応答していないとみなす時間 | 60秒 | 長く待つ問い合わせは最長30秒で、返ればすぐ次を聞く。2倍あれば、数秒おきに聞くソフトも、次を聞くのに手間取ったソフトも応答中に入る |
| 1つ目の段の項目 | 16 | メニューの1段は十数項目まで。1つのソフトが足すのはそれより少ない見込み |
| 下の段も合わせた項目 | 32 | 許しの窓に並べる行の数でもある |
| ラベル | 40字 | メニューの幅が画面の3分の1を超えない程度（ほかの項目は長くて15字ほど） |
| children の深さ | 2段 | 「ほかのソフト ▸ 名前 ▸」の下なので、実際は4段目まで開く |
| 結果の文 | 100字 | 帯は1行。名前と合わせても窓の幅に収まる程度 |
| 結果を受ける時間・件数 | 10分・32件 | 重い処理（プレビューを開く）を終えて返すまでの見込みより十分長く、続けて押す回数より多く |
