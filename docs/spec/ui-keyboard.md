# キー・キーボードの決め事

画面全体の決め事は [ui-rules.md](ui-rules.md)、入力欄・候補・右クリックのメニュー・読み上げの名前は [ui-input.md](ui-input.md)。
2026-10-05 に ui-input.md が200行に近づいたので、キーの節をここへ分けた（中身は変えず、書き直した所だけ下に日付を残した）。

## キー
- Ctrl+F：**どの画面でも画面内検索**（右上の帯・全部を薄い黄・今の1つを橙・Enter/Shift+Enter・Esc。折りたたんだ説明の中の一致は開いて見せる。仮想化した一覧の画面外は探せない）。検索とショップだけ検索欄へ移していたのをやめた（ユーザ判断 2026-09-20・B2：同じキーで見ていた画面を失うのは食い違い）。
- **編集画面のスキップは Ctrl+N、「← 前へ」は Ctrl+P**（ユーザ判断 2026-10-02）。**どちらも入力欄の中でも効かせる**——編集画面はほぼ常に欄の中にいる。
  Ctrl＋文字は欄で使う操作が無く、このアプリには新規も印刷も無いのでぶつからない（Microsoft IME の変換中の Ctrl+P は IME が先に受ける）。
  ボタンの吹き出しに今の割り当てのキーを出す（「前の商品へ戻ります（Ctrl + P）」。設定で外したらキーは出さない）。割り当ては設定画面で変えられる（`AppSettings.Shortcuts.Skip`・`Previous`）。
- Alt+矢印（戻る・進む）と Ctrl+Shift+矢印の割り当ては**入力欄の中でも効かせる**。代償は欄の「1語ずつ選ぶ」で、Shift+矢印とマウスで足りる。どのキーを欄に譲るかは操作によらず1か所で決める（`Shortcuts.YieldsToText`）。
- Ctrl+Enter：編集画面の「保存して次へ」と、**未確定の画面の「このIDで登録」**（ユーザ判断 2026-10-01。同じ割り当て `AppSettings.Shortcuts.SaveAndNext`。どちらも「この1件を決めて次へ」）。
  未確定では欄の Enter が「情報を確認」、登録すると次の行の空の欄へ戻る。守りと理由は [id-resolution.md](id-resolution.md)「未確定の画面」。
- Ctrl+プラス／Ctrl+マイナス／Ctrl+0：表示の大きさ（90〜150%）を上げる・下げる・100% に戻す（2026-09-29）。**入力欄の中でも効かせる**（欄の中でこの組み合わせを使う操作は無い）。Shift 付きの Ctrl+＋（＋を打つのに Shift が要る配列）とテンキーの ＋ − 0 も同じに扱う。設定のショートカットの一覧で変えられる
- **Shift＋ホイールと横ホイール（チルト）は横送り**（ユーザ指摘 2026-10-02）。マウスの下からたどって、いちばん内側のその向きへまだ送れる入れ物を送り、端まで来ていたら外の入れ物へ渡す（組み込んだ商品ページ → 画面全体）。
  横に送れる物が無ければ何もしない（縦に流れる）。所ごとに付けず、`ScrollViewer` の型に1回で掛ける（`Controls/HorizontalWheel`。付け忘れた所だけ黙って効かないため）。素のホイールを横に読み替える帯（検索の履歴・編集画面の続く商品）はそのまま。
- Alt+← とマウスの戻るボタン：画面の履歴を戻る（入力欄にいても）。左右キーの画像送りは入力欄と**スライダー**では効かせない（スライダーの左右は値を動かす）。 **Tab で止まるリンク（商品ページのショップ名・ID）の上でも送らず、何もしない**（メモ27-③ 2026-10-04。離れたギャラリーの絵が変わり、止まっている所は動かなかった。渡すと WPF の矢印の移動で別の列へ飛ぶ）。説明の本文とその中のリンクは Tab で止まらずカーソルも見えないので、今まで通り送る。絵が1枚で送れないときも受けたことにする。決め事は `GalleryArrows` の1か所
- 割り当ては設定画面で変えられる（`docs/spec/item-page.md` の編集画面）。スライダーに止まっている間の素の矢印・Home・End・PageUp・PageDown は割り当てより先にスライダーへ渡す。

### キーボードだけで進める（点検 2026-09-23）

- **商品のカードと行**（検索・ショップ・フォルダの右・改変の使ったもの など同じ部品の所）：Enter・Space で押したのと同じ（何も選んでいなければ商品ページ、選んでいる最中は選択の切り替え。フォルダの行はそのフォルダへ）。
  カードは矢印で隣へ移る（横は同じ段、縦は次の段の横の位置がいちばん近いカード。Home・End は最初と最後のカード）。右クリックのメニューは Shift+F10・アプリケーションキー。止まったカードは選んだ色の枠で示す。
  **マウスで押したカードは、一部だけ見えていても流さない**（2026-10-02 のメモ7「この機能は必要ない」）。矢印・Tab で移ったときは見える所まで流す（見えない所へ移るため）。
  カードの一覧の部品（`CardRowsListBox`）が自分で付ける（`Controls/NoScrollOnClick`。別の一覧にも1行で付けられる）。ボタンで作ったカード（ショップ一覧・フォルダの右の子フォルダ）は押した瞬間にフォーカスを取り、WPF の既定でその全体が見える所まで流れていた。商品のカードは押してもフォーカスが移らないので、もともと流れない。
  フォーカスを受けた部品を流すときは、上下左右に 4 だけ余分に流す（`Controls/FocusScrollMargin`。型に1回で掛ける。2026-10-03）。最小限だと部品が流れの端に付き、外側に出す印（札・三角・星・×）の外の辺が縁で欠けた。
  **カードの一覧は並び**（下の「並び」。ユーザ判断 2026-10-01）：Tab で1回だけ入り、もう1回で一覧の外へ出る。前は1枚ずつ止まり、検索の結果を抜けるのに見えているカードの数だけ押した。
  - 並びにした一覧：検索・ショップ（その店の商品）・ショップ一覧・フォルダの右（`CardRowsListBox` が自分で並びになる）、タグと属性の管理の右（商品の段。見出しと下の枠は `IsOutside`）、改変の使ったもの（カードと ◀ ▶・Unity・外す）。
    リスト表示（`ItemListView`）は今までどおり一覧に1回止まり、↑↓ で行を移る。
  - **カードの中の押せる物（星・選ぶ箱・「更新あり」・選んでいる最中の「中を見る」）は矢印の止まりにしない**。同じ操作を右クリックのメニュー（Shift+F10）に置く：
    「お気に入りに入れる／外す」「選ぶ」「更新の通知を開く」「既読にする」「商品ページを開く」。メニューは項目を全部出し、できない物は押せなくして吹き出しで理由を言う（[ui-input.md](ui-input.md)「右クリックのメニュー」。2026-10-04 から。前は「更新があるときだけ」「選んでいる最中だけ」と項目を出し入れしていた）。ショップのカードの星も同じ（メニューの「お気に入りのショップにする／から外す」）。
    札の並びの × のように矢印で中へ入れると、カード1枚に中の物が最大4つあり、隣のカードへ移るのに最大5回押すことになる。カードは眺めて選ぶ物なので、矢印はカードからカードへの1手に残した。
    選ぶ箱はマウスで押せるまま、キーボードでは止まらない（選んでいる最中は全部のカードに出るので、止まりにすると矢印がカードと箱を交互に通る）。
    カードの重ねの入れ物（選んでいる最中に出る）も止まらない（既定で止まる ContentControl で、選んでいる間はカードごとに名前の無い止まりが1つ増えていた）。
    メニューの「商品ページを開く」をキーで押したときも、戻ったらそのカードに止まり直す。
  - **検索の並べ替えの区切りの札**（カテゴリ順・ショップ順などで入る偽の項目。`search.md`「結果」）は止まりにしない。矢印・Home・End は札を飛ばしてカードからカードへ、
    リストの ↑↓ も札の行を飛ばす。札は商品ではなく、止まってできることが無い（2026-10-01・仮決め。止まって「このまとまりを全部選ぶ」を置く案は判断待ち）。
    読み上げでは名前を持つ文字1つ（「カテゴリ：3Dモデル / 3D衣装、4 件」）として出し、押す・選ぶは持たない。
    ショップの札は押せる（アプリのショップの画面・中クリックで BOOTH・右クリックのメニュー。2026-10-02）が、**止まりにはしないまま**（ユーザ判断 2026-10-01 を保つ）。
    読み上げではボタンとして「押す」だけを持つ。キーボードからは、商品のカードの右クリックの「ショップを開く」とショップの一覧から同じ所へ届く。
  - カードの中身は画面が空いたときに後から作る（`DeferredCardHost`）。作ったカードはその場で並びの止まらない物にし（`ArrowGroup.Adopt`）、矢印で移る先の段がまだ白い枠だけなら、その段のカードをその場で作る。
- **キーで開いて戻ったら、開いたカード・行に止まり直す**（画面は作り直されるので、止まり先を覚えておく）。マウスで開いたとき・戻る間に別の所へ止まったときはしない。
- **属性のスライダー**（編集画面）：←→ で 5（1目盛り）、PageUp/PageDown で 25、Home/End で 0/100。検索の属性の範囲は ←→ 10・PageUp/PageDown 20。
  **キーで値が変わったら触ったのと同じ**：並べてあるだけの行（`docs/features.md`「既定の属性を並べておき、触るまで保存しない」）も、その時点で保存する行になる。値が変わらないキー（端での Home など）は触ったことにしない。
- 繋がったボタンの切り替え（カード／リスト・アバターとして扱うか）は、読み上げ・自動操作で「選ぶ」でも押したのと同じことが起きる（`CommandRadioButton`）。
- **並び（札の並び・行ごとにボタンのある一覧）は、Tab で1回だけ入り、中は矢印で移る**（ユーザ判断 2026-10-01。`Controls/ArrowGroup` を一覧に付ける）。
  前は札・×・行のボタンの1つずつに止まり、対応アバター29体の商品で欄を抜けるのに Tab を62回、除外400件の一覧で400回押した。
  - Tab で入ると、前にいた所（初めてなら見えている先頭）に止まる。**もう1回 Tab で並びの外へ出る**。Shift+Tab で戻ると、また前にいた所。
  - ←→ は並びの順（札 → その × → 次の札）に1つずつ。↑↓ は上下の段の、横の位置がいちばん近い札（× へは降りない）。Home・End は端へ。端では止まる（回り込まない）。修飾キー付きの矢印は画面の物（Alt+← の戻る）。
  - **行を見える分だけ作る一覧**（除外したファイル・通知・改変の左の一覧）は、↑↓・Home・End は隣の行へ番号で（画面の外の行へも流して届く）、←→ は行の中だけ。押す物の無い行は飛ばす。
  - Enter・Space は止まっている物（札・ボタン）がそのまま受ける。入力欄・選ぶ欄・スライダーは並びに数えない（矢印はその部品の物）。
  - **止まっていた行が消えたら**（「除外を解除」・× で外した札）、**次の行、最後の行なら前の行に止まり直す**。前は窓そのものへ落ち、次の Tab が画面の先頭（ナビの「戻る」）から始まって一覧の中の位置を失っていた。
    **最後の1つが消えて並びが空になったら**、並びを含む欄の中で並びのすぐ後ろの止まり先（小分類の札なら「小分類を追加」の欄）、後ろに無ければすぐ前の止まり先（付けたファイルなら同じバリエーションの［追加…］）へ止まる。
    前を後回しにするのは、前には欄ごと消すボタン（大分類の「外す」）があり、続けて Enter を押すと消えるため。
  - 行を見える分だけ作る一覧に、並びでない行（管理の画面の見出し・下の枠）が混ざるときは、その行の根に `ArrowGroup.IsOutside` を付ける。並びから Tab で出るときは、次の並びでない行をその場で作らせてそこへ止まる
    （作られていない行は WPF の Tab が飛ばし、カードで並べた属性の管理で下の「編集画面に最初から並べる」へ行けず画面の先頭へ戻った。商品の段は作らずに飛ばす）。
  - 並びの中でも別に止まる物は `ArrowGroup.IsOutside`（対応アバターの末尾の「＋ 追加」とその入力欄・「閉じる」）。WPF の `TabNavigation="Once"` は中を丸ごと1つにするので使わない。
  - 商品ページの左右キーの絵送りは、並びの中では並びに譲る（`MainWindow.TryMoveGallery`）。
    **画像の小さな絵の並びでは、←→ は隣の小さな絵へ止まりを移すだけで、大きな絵は替えない。Enter・Space でその絵を表示する**（ユーザ判断 2026-10-01：このまま）。
    並びの外（大きな絵・ほかの欄）にいるときの ←→ が絵送り。
  - **入力欄のある行の一覧は並びにしない**（ユーザ判断 2026-10-01）：設定のショートカットの行（キーの欄と「既定に戻す」）、編集画面のタグの行（小分類を足す欄）とバリエーションの行（支払額・誰のための購入か）など。
    並びの中では矢印が「止まりを移すキー」になるが、入力欄では矢印は文字を動かすキーで、行の中で両方を使い分けることになる。欄に Tab で順に止まれる今の形の方が、打ちながら進める。
    行の中の札の並び（小分類の ✕・付けたファイルの ✕）だけを並びにする。
  - 札の多い並びの「残り n を表示」も、並びとは別に止まる（札ではなく並びの操作）。
  - 付けた所：対応アバター・共通素体・説明文の候補・消したもの（商品ページと編集画面）、画像の小さな絵（末尾の「＋」は別に止まる）、説明の見出し、ローカルファイルのフォルダとファイルの行、
    検索の条件の札・検索の履歴、アバターの呼び方・検出に使わない呼び方、未確定の候補、通知、改変の左の一覧、
    設定の取り込み元・監視・非表示・除外・外したファイル、取り込みの対象・監視・取り込み元の履歴。
  - 2026-10-01（担当KEY2）に足した所：カードの一覧（上）、編集画面の小分類の ✕・付けたファイルの ✕、改変の「（プロジェクト）に紐付ける」の行・使ったもの、アバターの管理の「この素体を使っているアバター」の行。
  - 主の窓の画面の入れ物（`ScreenHost`）は止まらない（どの画面でも、ナビの後に名前の無い止まりが1つ入っていた）。
- **ナビ（左の項目の縦の並び）は、矢印で1つずつ移り、Tab では項目の塊と「設定」の2回で通る**（メモ47・ユーザ判断 2026-10-05「案X」。`Controls/NavKeys`）。
  - 戻る・進む・畳む・各画面の項目・「設定」（と出ているときの BOOTH の形式の知らせ）が1つの並び。**↑↓ で1つずつ**、横に並ぶ戻る・進むの間だけ ←→。Home・End で端へ。端では止まる。押せない戻る・出ていない知らせは飛ばす。畳んだナビでも同じ。
  - **外から Tab（Shift+Tab）で入ると、今開いている画面の項目に止まる**（前は戻るから14回以上押して目当てへ着いた）。ナビに無い画面のときは今までどおり先頭。マウスで押したときは触らない。
  - **Tab はナビの項目（戻る・進む・畳む・各画面）で1回だけ止まる**（メモ64。最初の案Xの「Tab でも1つずつ」は回数が減らなかった）。項目のどこからでも Tab で直接「設定」へ、「設定」から Tab で画面の中身へ。Shift+Tab は逆（中身 → 設定 → 項目の今の画面 → ナビの前）。今の画面が「設定」のときは「設定」が塊を兼ね、そこから Shift+Tab でナビの前へ出る。矢印は項目の中を ↑↓、最後の項目から ↓ で「設定」、「設定」から ↑ で最後の項目へ。
  - ほかの並び（`ArrowGroup`）と作りを分けた：向きが逆（ArrowGroup は Tab で1回だけ止まる）で、入れ物も2つに分かれる（送る入れ物の中と、下端に固定した「設定」）ため。矢印の移りは並びの順に隣へで足りる。窓の左右の絵送りはナビの項目の上では渡す（`GalleryArrows`）。
  - Alt+←→・Ctrl+Tab などの修飾キー付きは今までどおり。止まった項目が送る入れ物の外なら WPF が送り、続きの印（`OnNavScrollChanged`）が付き直る。
- **マウスで押せるのにキーボードで届かなかった所を塞いだ**（点検 2026-10-01）。どれも Enter・Space で押せ、止まると選んだ色の枠が出る：
  編集画面の星（`EditFavorite`）・小分類の ✕（`EditSubRemove`）・付けたファイルの ✕（`EditLinkedFileUnlink`）、通知の束の見出しの開閉（`InboxGroupToggle`。並びの中で ↑↓ で行と見出しを渡る）、
  アバターの管理の「この素体を使っているアバター」の行（`AvatarBaseMemberRow`「（アバター名）を開く」）、カードの中の押せる物（右クリックのメニューへ。上）。
  - 見つからないファイルの「取り込みを開く」は文字リンク（Hyperlink）から、同じ見た目のボタン（`HyperlinkButton`）にした。Hyperlink は画面の部品でなく文の一部なので並びに数えられず、行の数だけ Tab が止まっていた。
    ID は `ItemFileImportLink`・`ItemFolderImportLink`、名前は「（ファイル名）を付け直す取り込みを開く」。**繰り返す行の中の文字リンクはボタンで作る。**
  - 残した物：下の通信の帯（ナビの「取り込み」と同じ行き先）、編集画面の続く商品の小さな絵（キーボードの操作を奪わないよう止まらない作り。前へ・スキップ・「1件目へ」「最初の未保存へ」がある）、
    タグの管理の小分類の開閉の三角（上の `TagToggle`。「すべて折りたたむ」がある）。
- **検索の条件の見出し**（2026-10-01・`search-filters.md`）：Tab はチェック → 札「除く」→「…」→ ⌃ → × の順（前は × が先）。「…」は枠の中に止まると出る。
  条件のメニュー（除く・折りたたむ・上へ移動・下へ移動・この条件を外す）は「…」の Enter・Space か、枠の中のどこからでも Shift+F10・アプリケーションキー
  （入力欄の上では欄のメニュー）。パネルの見出しの「…」（いつも見える。「同じ種類の条件を隣に並べる」「条件をクリア」「絞り込みを折りたたむ」）も同じ。並べ替えはメニューの上へ／下へ移動でキーボードからもできる。
  動かした・外した・札を押して除くをやめた後は、その条件（外したら次、最後なら前、無くなれば「条件をクリア」）の「…」に止まり直す。
  **条件の並びは2段の止まり**（ユーザ判断 2026-10-02・メモ1-③「条件の並びを1つの止まりにする」。`Controls/FrameList`・枠は `FocusFrame`）：
  - Tab で並びに入ると**前にいた条件の枠**（初めてなら Tab で先頭・Shift+Tab で末尾の枠）に止まる。枠の上では ↑↓ で隣の枠、Home・End で端の枠（端では止まる）。
    枠に止まると「…」が出て、Shift+F10・アプリケーションキーで条件のメニューが開く。
  - **枠の中へは Enter で**入り、見出しのチェックに止まる。中は今までどおり チェック → 札「除く」→「…」→ ⌃ → × → 中身の部品 の順に Tab で進む。同じ作りの保存した検索の行は中に部品が無く、Enter で呼び出す（[search-saved.md](search-saved.md)）。
  - **枠の上の Tab は並びの後ろへ、Shift+Tab は並びの前（「＋ 条件を追加」）へ抜ける**（ユーザ判断 2026-10-02。初めは枠の上の Tab でも中へ入り、並びを素通りするには中の部品を送っていた）。
  - 中から出るのは **Esc（その枠へ戻る。候補を閉じるなど中の部品が Esc を使ったときは戻らない）**。枠の中の Tab・Shift+Tab は枠の中の部品だけを巡り、
    最後の部品から Tab で最初へ、最初の部品から Shift+Tab で最後へ戻る（ユーザ判断 2026-10-03・メモ16-②。次の条件へも並びの外へも出ない）。
  - 前は条件ごとに見出しの5つと中身の部品の全部に止まり、条件10個で数十回押さないと結果へ届かなかった（作り物の条件3つの場面で、並びの中の止まり 18 → 9）。
  - カードの一覧の「並び」（`ArrowGroup`）にしないのは、並びは中の止まり先を全部1段に並べて矢印で渡る作りで、条件の中の入力欄・選ぶ欄・スライダーの矢印と食い合うため。
    矢印は枠の上だけで使い、中は Tab のままにした。
- **乗せたときだけ出すボタンは、その項目にキーボードのフォーカスがあるときにも出す**（ユーザ判断 2026-09-30）。条件は「マウスが乗っている、または、その項目（札・行）かその中にフォーカスがある」。
  中のボタンへフォーカスが移っても、項目の中にある間は消えない。マウスだけで使うときの見た目は変わらない（乗せていなければ出ない）。
  - **商品ページの対応アバターの札**：Tab で並びに入り札に止まる（Enter・Space でそのアバターを開く）→ × が出る → → で × → Enter で外す。
  - **共通素体の札**：札そのものは押せないので、止まるのは × だけ（止まると出る）。**説明文の共通素体の候補**：「追加」に止まると × も出て、→ で × に移る。
  - **通知の行**：Tab で一覧に入り行に止まる（Enter・Space で商品を開く）→「商品ページを開く」と種類ごとのボタンが出る → ←→ で既読の丸・ボタンへ、↑↓ で隣の行へ。
    **既読の丸**は Enter・Space で既読⇄未読（ユーザ判断 2026-09-30）。
    読み上げの名前は「（行の題）を既読にする」⇄「（行の題）を未読に戻す」（`NotificationRow.ReadButtonName`。ID は `InboxRowRead`）。
- **商品ページの星（お気に入り）・バリエーションとローカルファイルの開閉にも Tab で止まる**（点検 2026-10-01。読み上げの「押す」は届くのに止まれなかった）。開閉の丸い三角の型（`TagToggle`）は、管理の画面の行の中では止まらない物のまま。
