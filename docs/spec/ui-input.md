# 入力の決め事

画面全体の決め事は [ui-rules.md](ui-rules.md)、別の窓は [ui-dialogs.md](ui-dialogs.md)、
空のとき・失敗したとき・押せないときは [ui-empty-and-errors.md](ui-empty-and-errors.md)。

## 候補と札

- 入力欄には候補を付ける（`SuggestBox`）。候補に無い語は「（新規）」の行として示し、選ばせる（表記が揺れると、名前でつないだ絞り込みが分かれてしまう）。
  **例外：新しい物を名付ける欄には付けない**（共通素体を足す欄。メモ9-⑥ 2026-10-02）。今ある名前を並べても重複を誘うだけなので、ふつうの欄にし、今ある名前と同じなら「既にあります」と言う。
- 頭の絵の無い候補（配布商品を結んでいない共通素体など）は頭文字を出す（メモ3-① 2026-10-02。空の四角が読み込みの失敗に見えた）。
- **候補を全部並べて選ばせる画面は作らない**。候補付きの入力欄から1件ずつ追加するか、折りたためるようにする。
- 空の欄を押すと候補を全部出す。決めた後もフォーカスは欄に残す（続けて足せるように）ので、**同じ欄を押し直したときも候補を出す**
  （ユーザ指摘 2026-09-29：検索のユーザータグで、2つ目の大分類・小分類を足すときだけ押しても出なかった）。決めた直後は、押すか打つまで出さない。
- 多い札（対応アバター・BOOTHのタグ）は50件までは全部、超えたら40件と「残り n を表示」。作った札は捨てずに隠す（`ChipStrip`：差し替えると全部作り直すため）。20体を超えたら「アバター名で絞る」欄。
- 探す語はひらがな・カタカナ／全角・半角／大文字小文字を区別しない。
- **打つたびに一覧を絞る検索欄は、打ち終わって 200ms 待ってからまとめて絞る**（結び付けの `Delay=200`。2026-10-02 のメモ7：文字を1つずつ消す間に、その数だけ絞り直しが走って重かった）。
  検索・フォルダの右・改変・ショップの一覧・タグと属性の管理（左の検索と中を探す欄）・アバター・商品ページの対応アバターの絞り込み・未確定の検索欄。フォルダの木だけ 250ms。
- **既にある名前と同じ綴りを打ったら、候補から選んだのと同じに扱う**（タグ・属性の名前の変更の窓。点検 2026-09-23）。綴りは候補の側に揃える。
  既にある名前は表記の揺れを生まないので、選び直させない。無い名前は打っただけでは決めず、候補の「新規」の行を選ばせる（押せない理由にそう書く）。

## 決め方と保存

- **Enter は入力の確定**（ユーザ判断 2026-09-20・I12）。1行の入力欄は、横のボタンと同じことが Enter で起きる
  （呼び方を追加・素体の商品を設定・改変を作る・未確定は「このIDで確認」まで）。
  **取り返しのつかない確定は Enter で走らせない**（未確定の「このIDで確定する」は押して決める）。
- 名前を変えるのは**欄の中**（Enter か「名前を保存」。変えたときだけボタンを表示する）。OS の入力窓は使わない（B10：共通素体だけ残っていた）。
- **メモはどこでも押さずに残る**（I9）。商品のメモは商品ページでも書ける
  （編集画面の中に入れているときは、右の欄と二重にしないので表示しない）。
- **保存のしかたが画面の中で分かれるときは、画面に書く。**編集画面の左（画像・星など）は押した時点で保存し、右は「保存して次へ」で保存する。
  この形のままにすると決めたので（ユーザ判断 2026-09-20・B7）、左の列の頭に「この列は押した時点で保存されます。右の欄は「保存して次へ」で保存します。」と出す。

## キー

- Ctrl+F：**どの画面でも画面内検索**（右上の帯・全部を薄い黄・今の1つを橙・Enter/Shift+Enter・Esc。折りたたんだ説明の中の一致は開いて見せる。仮想化した一覧の画面外は探せない）。検索とショップだけ検索欄へ移していたのをやめた（ユーザ判断 2026-09-20・B2：同じキーで見ていた画面を失うのは食い違い）。
- Ctrl+Shift+→（スキップ）と Alt+矢印（戻る・進む）は**入力欄の中でも効かせる**。譲ると、入力欄だらけの編集画面では一度も効かない（ユーザ判断 2026-09-20・B11。代償は欄の「1語ずつ選ぶ」で、Shift+矢印とマウスで足りる）。
- Ctrl+Enter：編集画面の「保存して次へ」と、**未確定の画面の「このIDで確定する」**（ユーザ判断 2026-10-01。同じ割り当て `AppSettings.Shortcuts.SaveAndNext`。どちらも「この1件を決めて次へ」）。
  未確定では欄の Enter が「このIDで確認」、確定すると次の行の空の欄へ戻る。守りと理由は [id-resolution.md](id-resolution.md)「未確定の画面」。
- Ctrl+Shift+←：編集画面の「← 前へ」。**入力欄にいないときだけ効かせる**（ユーザ判断 2026-09-28）。欄の中では1語ずつ選ぶ操作に譲る——スキップと両方を取ると、欄で語を選ぶ手が矢印キーから消える。割り当ては設定画面の「編集画面で前へ」で変えられる（`AppSettings.Shortcuts.Previous`）。
- Ctrl+プラス／Ctrl+マイナス／Ctrl+0：表示の大きさ（90〜150%）を上げる・下げる・100% に戻す（2026-09-29）。**入力欄の中でも効かせる**（欄の中でこの組み合わせを使う操作は無い）。Shift 付きの Ctrl+＋（＋を打つのに Shift が要る配列）とテンキーの ＋ − 0 も同じに扱う。設定のショートカットの一覧で変えられる
- Alt+← とマウスの戻るボタン：画面の履歴を戻る（入力欄にいても）。左右キーの画像送りは入力欄と**スライダー**では効かせない（スライダーの左右は値を動かす）。
- 割り当ては設定画面で変えられる（`docs/spec/item-page.md` の編集画面）。スライダーに止まっている間の素の矢印・Home・End・PageUp・PageDown は割り当てより先にスライダーへ渡す。

### キーボードだけで進める（点検 2026-09-23）

- **商品のカードと行**（検索・ショップ・フォルダの右・改変の使ったもの など同じ部品の所）：Enter・Space で押したのと同じ（何も選んでいなければ商品ページ、選んでいる最中は選択の切り替え。フォルダの行はそのフォルダへ）。
  カードは矢印で隣へ移る（横は同じ段、縦は次の段の横の位置がいちばん近いカード。Home・End は最初と最後のカード）。右クリックのメニューは Shift+F10・アプリケーションキー。止まったカードは選んだ色の枠で示す。
  **マウスで押したカードは、一部だけ見えていても流さない**（2026-10-02 のメモ7「この機能は必要ない」）。矢印・Tab で移ったときは見える所まで流す（見えない所へ移るため）。
  カードの一覧の部品（`CardRowsListBox`）が自分で付ける（`Controls/NoScrollOnClick`。別の一覧にも1行で付けられる）。ボタンで作ったカード（ショップ一覧・フォルダの右の子フォルダ）は押した瞬間にフォーカスを取り、WPF の既定でその全体が見える所まで流れていた。商品のカードは押してもフォーカスが移らないので、もともと流れない。
  **カードの一覧は並び**（下の「並び」。ユーザ判断 2026-10-01）：Tab で1回だけ入り、もう1回で一覧の外へ出る。前は1枚ずつ止まり、検索の結果を抜けるのに見えているカードの数だけ押した。
  - 並びにした一覧：検索・ショップ（その店の商品）・ショップ一覧・フォルダの右（`CardRowsListBox` が自分で並びになる）、タグと属性の管理の右（商品の段。見出しと下の枠は `IsOutside`）、改変の使ったもの（カードと ◀ ▶・Unity・外す）。
    リスト表示（`ItemListView`）は今までどおり一覧に1回止まり、↑↓ で行を移る。
  - **カードの中の押せる物（星・選ぶ箱・「更新あり」・選んでいる最中の「中を見る」）は矢印の止まりにしない**。同じ操作を右クリックのメニュー（Shift+F10）に置く：
    「お気に入りに入れる／外す」「選ぶ」「更新の知らせを開く」（更新があるときだけ）「商品ページを開く」（選んでいる最中だけ）。ショップのカードの星も同じ（メニューの「お気に入りのショップにする／から外す」）。
    札の並びの × のように矢印で中へ入れると、カード1枚に中の物が最大4つあり、隣のカードへ移るのに最大5回押すことになる。カードは眺めて選ぶ物なので、矢印はカードからカードへの1手に残した。
    選ぶ箱はマウスで押せるまま、キーボードでは止まらない（選んでいる最中は全部のカードに出るので、止まりにすると矢印がカードと箱を交互に通る）。
    カードの重ねの入れ物（選んでいる最中に出る）も止まらない（既定で止まる ContentControl で、選んでいる間はカードごとに名前の無い止まりが1つ増えていた）。
    メニューの「商品ページを開く」をキーで押したときも、戻ったらそのカードに止まり直す。
  - **検索の並べ替えの区切りの札**（カテゴリ順・ショップ順などで入る偽の項目。`search.md`「結果」）は止まりにしない。矢印・Home・End は札を飛ばしてカードからカードへ、
    リストの ↑↓ も札の行を飛ばす。札は商品ではなく、止まってできることが無い（2026-10-01・仮決め。止まって「このまとまりを全部選ぶ」を置く案は判断待ち）。
    読み上げでは名前を持つ文字1つ（「カテゴリ：3Dモデル / 3D衣装、4 件」）として出し、押す・選ぶは持たない。
  - カードの中身は画面が空いたときに後から作る（`DeferredCardHost`）。作ったカードはその場で並びの止まらない物にし（`ArrowGroup.Adopt`）、矢印で移る先の段がまだ白い枠だけなら、その段のカードをその場で作る。
- **キーで開いて戻ったら、開いたカード・行に止まり直す**（画面は作り直されるので、止まり先を覚えておく）。マウスで開いたとき・戻る間に別の所へ止まったときはしない。
- **属性のスライダー**（編集画面）：←→ で 5（1目盛り）、PageUp/PageDown で 25、Home/End で 0/100。検索の属性の範囲は ←→ 10・PageUp/PageDown 20。
  **キーで値が変わったら触ったのと同じ**：並べてあるだけの行（`docs/features.md`「既定の属性を並べておき、触るまで保存しない」）も、その時点で保存する行になる。値が変わらないキー（端での Home など）は触ったことにしない。
- 繋がったボタンの切り替え（カード／リスト・アバターとして扱うか）は、読み上げ・自動操作で「選ぶ」でも押したのと同じことが起きる（`CommandRadioButton`）。
- **並び（札の並び・行ごとにボタンのある一覧）は、Tab で1回だけ入り、中は矢印で移る**（ユーザ判断 2026-10-01。`Controls/ArrowGroup` を一覧に付ける）。
  前は札・×・行のボタンの1つずつに止まり、対応アバター29体の商品で欄を抜けるのに Tab を62回、除外400件の一覧で400回押した。
  - Tab で入ると、前にいた所（初めてなら見えている先頭）に止まる。**もう1回 Tab で並びの外へ出る**。Shift+Tab で戻ると、また前にいた所。
  - ←→ は並びの順（札 → その × → 次の札）に1つずつ。↑↓ は上下の段の、横の位置がいちばん近い札（× へは降りない）。Home・End は端へ。端では止まる（回り込まない）。修飾キー付きの矢印は画面の物（Alt+← の戻る）。
  - **行を見える分だけ作る一覧**（除外したファイル・要確認・改変の左の一覧）は、↑↓・Home・End は隣の行へ番号で（画面の外の行へも流して届く）、←→ は行の中だけ。押す物の無い行は飛ばす。
  - Enter・Space は止まっている物（札・ボタン）がそのまま受ける。入力欄・選ぶ欄・スライダーは並びに数えない（矢印はその部品の物）。
  - **止まっていた行が消えたら**（「除外を解除」・× で外した札）、**次の行、最後の行なら前の行に止まり直す**。前は窓そのものへ落ち、次の Tab が画面の先頭（ナビの「戻る」）から始まって一覧の中の位置を失っていた。
    **最後の1つが消えて並びが空になったら**、並びを含む欄の中で並びのすぐ後ろの止まり先（小分類の札なら「小分類を追加」の欄）、後ろに無ければすぐ前の止まり先（付けたファイルなら同じバリエーションの「ファイルを追加」）へ止まる。
    前を後回しにするのは、前には欄ごと消すボタン（大分類の「外す」）があり、続けて Enter を押すと消えるため。
  - 行を見える分だけ作る一覧に、並びでない行（管理の画面の見出し・下の枠）が混ざるときは、その行の根に `ArrowGroup.IsOutside` を付ける。並びから Tab で出るときは、次の並びでない行をその場で作らせてそこへ止まる
    （作られていない行は WPF の Tab が飛ばし、カードで並べた属性の管理で下の「編集画面に最初から並べる」へ行けず画面の先頭へ戻った。商品の段は作らずに飛ばす）。
  - 並びの中でも別に止まる物は `ArrowGroup.IsOutside`（対応アバターの末尾の「＋ 追加」とその入力欄・「閉じる」）。WPF の `TabNavigation="Once"` は中を丸ごと1つにするので使わない。
  - 商品ページの左右キーの絵送りは、並びの中では並びに譲る（`MainWindow.TryMoveGallery`）。
    **画像の小さな絵の並びでは、←→ は隣の小さな絵へ止まりを移すだけで、大きな絵は替えない。Enter・Space でその絵を表示する**（ユーザ判断 2026-10-01：このまま）。
    並びの外（大きな絵・ほかの欄）にいるときの ←→ が絵送り。
  - **入力欄のある行の一覧は並びにしない**（ユーザ判断 2026-10-01）：設定のショートカットの行（キーの欄と「既定に戻す」）、検索の条件、編集画面のタグの行（小分類を足す欄）とバリエーションの行（支払額・誰のための購入か）など。
    並びの中では矢印が「止まりを移すキー」になるが、入力欄では矢印は文字を動かすキーで、行の中で両方を使い分けることになる。欄に Tab で順に止まれる今の形の方が、打ちながら進める。
    行の中の札の並び（小分類の ✕・付けたファイルの ✕）だけを並びにする。
  - 札の多い並びの「残り n を表示」も、並びとは別に止まる（札ではなく並びの操作）。
  - 付けた所：対応アバター・共通素体・説明文の候補・消したもの（商品ページと編集画面）、画像の小さな絵（末尾の「＋」は別に止まる）、説明の見出し、ローカルファイルのフォルダとファイルの行、
    検索の条件の札・検索の履歴、アバターの呼び方・検出に使わない呼び方、未確定の候補、要確認、改変の左の一覧、
    設定の取り込み元・監視・非表示・除外・外したファイル、取り込みの対象・監視・取り込み元の履歴。
  - 2026-10-01（担当KEY2）に足した所：カードの一覧（上）、編集画面の小分類の ✕・付けたファイルの ✕、改変の「（プロジェクト）に紐付ける」の行・使ったもの、アバターの管理の「この素体を使っているアバター」の行。
  - 主の窓の画面の入れ物（`ScreenHost`）は止まらない（どの画面でも、ナビの後に名前の無い止まりが1つ入っていた）。
- **マウスで押せるのにキーボードで届かなかった所を塞いだ**（点検 2026-10-01）。どれも Enter・Space で押せ、止まると選んだ色の枠が出る：
  編集画面の星（`EditFavorite`）・小分類の ✕（`EditSubRemove`）・付けたファイルの ✕（`EditLinkedFileUnlink`）、要確認の束の見出しの開閉（`InboxGroupToggle`。並びの中で ↑↓ で行と見出しを渡る）、
  アバターの管理の「この素体を使っているアバター」の行（`AvatarBaseMemberRow`「（アバター名）を開く」）、カードの中の押せる物（右クリックのメニューへ。上）。
  - 見つからないファイルの「取り込みを開く」は文字リンク（Hyperlink）から、同じ見た目のボタン（`HyperlinkButton`）にした。Hyperlink は画面の部品でなく文の一部なので並びに数えられず、行の数だけ Tab が止まっていた。
    ID は `ItemFileImportLink`・`ItemFolderImportLink`、名前は「（ファイル名）を付け直す取り込みを開く」。**繰り返す行の中の文字リンクはボタンで作る。**
  - 残した物：下の通信の帯（ナビの「取り込み」と同じ行き先）、編集画面の続く商品の小さな絵（キーボードの操作を奪わないよう止まらない作り。前へ・スキップ・「1件目へ」「最初の未保存へ」がある）、
    タグの管理の小分類の開閉の三角（上の `TagToggle`。「すべて折りたたむ」がある）。
- **検索の条件の見出し**（2026-10-01・`search-filters.md`）：Tab はチェック → 札「除く」→「…」→ ⌃ → × の順（前は × が先）。「…」は枠の中に止まると出る。
  条件のメニュー（除く・折りたたむ・上へ移動・下へ移動・この条件を外す）は「…」の Enter・Space か、枠の中のどこからでも Shift+F10・アプリケーションキー
  （入力欄の上では欄のメニュー）。パネルの見出しの「…」（「同じ種類の条件を隣に並べる」）も同じ。並べ替えはメニューの上へ／下へ移動でキーボードからもできる。
  動かした・外した・札を押して除くをやめた後は、その条件（外したら次、最後なら前、無くなれば「条件をクリア」）の「…」に止まり直す。
  条件の並びは並び（`ArrowGroup`）にしない（入力欄のある行の一覧。下の決まり）。
- **乗せたときだけ出すボタンは、その項目にキーボードのフォーカスがあるときにも出す**（ユーザ判断 2026-09-30）。条件は「マウスが乗っている、または、その項目（札・行）かその中にフォーカスがある」。
  中のボタンへフォーカスが移っても、項目の中にある間は消えない。マウスだけで使うときの見た目は変わらない（乗せていなければ出ない）。
  - **商品ページの対応アバターの札**：Tab で並びに入り札に止まる（Enter・Space でそのアバターを開く）→ × が出る → → で × → Enter で外す。
  - **共通素体の札**：札そのものは押せないので、止まるのは × だけ（止まると出る）。**説明文の共通素体の候補**：「追加」に止まると × も出て、→ で × に移る。
  - **要確認の行**：Tab で一覧に入り行に止まる（Enter・Space で商品を開く）→「商品ページを開く」と種類ごとのボタンが出る → ←→ で既読の丸・ボタンへ、↑↓ で隣の行へ。
    **既読の丸**は Enter・Space で既読⇄未読（ユーザ判断 2026-09-30）。
    読み上げの名前は「（行の題）を既読にする」⇄「（行の題）を未読に戻す」（`NotificationRow.ReadButtonName`。ID は `InboxRowRead`）。
- **商品ページの星（お気に入り）・バリエーションとローカルファイルの開閉にも Tab で止まる**（点検 2026-10-01。読み上げの「押す」は届くのに止まれなかった）。開閉の丸い三角の型（`TagToggle`）は、管理の画面の行の中では止まらない物のまま。
  - 止まった所は選んだ色（`Accent`）の枠で示す（札・行・× とも。カードの枠と同じ作り：`ChipFocusVisual`・`RowFocusVisual`・`SmallFocusVisual`）。
  - 札の × は、Hidden で隠すとフォーカスを受けられないので、透明にして隠す（`RevealOnHoverOrFocusButton`。透明な間はマウスを受けない）。
- **並べるだけの一覧（`ContentItemsControl`）は Tab で止まらない**（2026-09-30）。既定のままだと一覧ごとに「何も起きない止まり」が入り、フォーカスがどこにも見えなくなっていた。中の部品には今までどおり順に止まる。

### 読み上げの名前

- 候補付きの入力欄は、置き場所で付けた `AutomationProperties.Name`（無ければ薄い字の案内）を中の欄の名前にする。候補の行は語そのもの（新しい語は「（新規）」付き）を読ませる。
- カードは商品名を「押せる1件」として読ませ（`ItemCardBorder`）、リストの行も商品・フォルダの名前を読ませる（型の名前を読ませない）。

**操作できる部品には、UI Automation の名前を付ける**（2026-09-30。名前の無い部品は読み上げで何か分からず、画面の確かめでは座標を取って実際のマウスで押すしかなかった）。
名前は読み上げソフトがそのまま読むので、画面の語（[ui-terms.md](ui-terms.md)）で書く。内部の言葉と型の名前は読ませない。

| 何に | どう付けるか |
|---|---|
| 文字のボタン・チェック | 付けなくてよい（文字が名前になる） |
| 絵・記号だけのボタン（×・＋・‹ ›・◀ ▶・三角）、中身が絵と文字の並びのボタン | 吹き出しと同じ意味の短い名前（「前の画像」「画像を追加」） |
| 入力欄・選ぶ欄・スライダー | 左や上の見出しの語（「商品名」「表示の大きさ」）。見出しが無ければ薄い字の案内の語 |
| 行ごとに繰り返す部品 | どの行の物かを入れる：「（商品名）をお気に入りに入れる」「（ファイル名）を開く」「（候補の名前）で確認」「（バリエーション名）の支払額」。見えている文字はそのまま含める |
| 同じ画面に同じ名前が並ぶ物（検索の条件の「下限」「上限」） | 何の物かを頭に付ける：「価格の下限」 |
| 畳める欄（`Expander`）で、見出しが文字の並びや札の物 | `Expander` に欄の名前を付ける（見出しの押す所は、型がその名前から「（欄）を開く」⇄「（欄）を折りたたむ」を作る） |
| 欄や行を開閉する部品（三角・ナビ・検索の絞り込み・検索の条件・フォルダの木の印） | **押すと起きることを名前にし、状態で替える**：「（欄）を開く」⇄「（欄）を折りたたむ」。開いていても「〜を開く」と読まれる名前にしない（確かめの道具が、開いている欄を押して畳んでいた） |
| そのうち、三角（`ToggleButton` で作った物） | `Controls/ExpandToggle` にして、何の開閉かだけを `Subject` に渡す（「ローカルファイル」「（小分類名）の商品」「（改変名）の使ったもの」）。名前は部品が状態から作り、開いているかを UI Automation の開閉（ExpandCollapse）でも渡す（「開く」「畳む」を名指しで呼べる）。商品ページのバリエーションの三角は ViewModel が同じ言い方で名前を作っている（`ItemViewModel.ToggleName`） |
| 選ぶ一覧（`ListBox`）の行 | 行の名前（未確定はファイル名）。付けないと行の型の名前が読まれる |
| 欄を開閉する三角（`Expander` でない、切り替えのボタン） | **押すと起きること**を名前にする：畳んでいるとき「（欄の名前）を開く」、開いているとき「（欄の名前）を折りたたむ」（`ItemViewModel.ToggleName`）。開閉は、切り替えの入・切としても出る（入＝開いている） |
| 名前の無い物が並ぶ一覧（ギャラリーの小さな絵） | 並びの番号で言う：「n 枚目の画像を表示」。番号は行が持つ（一覧を組み直すたびに振る） |

- **押せる枠は `PressableBorder`、繰り返しの一覧は `ContentItemsControl`、商品のリストは `ItemListView`。**
  素の `Border`・文字に押す動きを付けただけの物は UI Automation に出ない（カードの星・「中を見る」・札・下の通信の帯・要確認の行・編集画面の ✕）。
  見た目は変えずに「押せるボタン」として出し、読み上げ・自動操作の「押す」をマウスで押したときと同じ処理につなぐ。
  素の `ItemsControl` は、行を型の名前で読ませ、値の等しい行を1つにまとめる（`docs/dev/wpf.md`）。
- **カードの「段」は木に出さない**（ユーザ判断 2026-09-30）。カードの一覧は、窓の幅から列数を決めてカードを段に切り、段を縦に並べている（仮想化のため）。
  段は並べ方の都合の入れ物で、選べず、止まれず、幅を変えれば中身が入れ替わる。前は一覧の項目として型の名前（`…CardRow`）で読まれていた。
  検索・ショップ・ショップ一覧・フォルダの右は `Controls/CardRowsListBox`（カードを一覧の直下に出す。「選ぶ」は持たない）、段そのものは `Controls/CardRowItems`。
  タグと属性の管理の段（行ごとに型の違う一覧の中）は木には残るが、「操作できる部品」から外してある（相手の既定の見方では、カードが一覧の直下に出る）。
  見た目・Tab・矢印・Enter・仮想化は ListBox のまま。**カードを段から探さない**（ID `ItemCard`・`ShopCard` と名前で探す）。
- **カードとリストの行は「押す」で開く。**キーボードの Enter と同じ処理で、戻ったら開いた所に止まり直す（リストの行は「選ぶ」しか持たず、読み上げ・自動操作から商品ページへ移れなかった）。
- **名前で見分けられない物には AutomationId を付ける**（画面には出ない。英字）。同じ条件が2つの見出しの下に出るメニュー（`SearchAddModule.<条件の種類>`）、
  条件の中の欄（`SearchModule.<条件の種類>.<部品>`。同じ種類の2つ目から `<条件の種類>-2`、名前も「カテゴリ（2つ目）の〜」。見出しの「…」は `.Menu`、
  その行は `.Menu.Exclude`・`.Menu.Collapse`・`.Menu.MoveUp`・`.Menu.MoveDown`・`.Menu.Remove`、札は `.Excluded`、編集状況の項目は `SearchModule.Unedited.Field.<項目>`、
  パネルの「…」は `SearchFilterMenu`・行 `SearchFilterMenu.GroupKinds`）、行ごとに並ぶボタン（`ItemFileOpenMenu`・`ResolveCandidateUse`）、
  確かめで読みたい文（`ImportSummary.<数>`・`UnitySendText`）。頭は画面の名前（`Search`・`Item`・`Edit`・`Resolve`・`Import`・`Settings.`）で始める。一覧は XAML を `AutomationProperties.AutomationId="` で引く。
- **名前の「_」は消えない**（2026-09-30）。WPF は、中身が文字のボタン・チェック・メニューの項目の名前から、アクセスキーの印として最初の「_」を消す（名前を付けていても。「file_000.pngを開く」が「file000.pngを開く」で読まれた）。
  消されるのと同じ決まりで先に重ねておく（`Services/AutomationNames`。部品の型に1回で掛けるので、名前を付ける所は何もしなくてよい）。名前を付けていないボタンも、中身の文字に「_」があれば同じに守る。
  メニューの項目のうち、名前を付けずに見出しの文字をそのまま読ませている物は守れない（見出しが替わった知らせを受ける口が無い）。人が決めた文字を見出しにする項目には、名前も付ける。
- **候補付きの入力欄の候補の行は「押す」で決まる**（`Controls/InvokableListBox`。クリック・Enter と同じ処理）。「選ぶ」だけでは色が付くだけで決まらなかった。
- **束（見出しでまとめた行）の見出しの中のボタンは、束が開いていても木に出す**（`Controls/GroupedListBox`。未確定の「まとめて扱う」「元zipとして扱う」「このフォルダを選択」）。
  WPF は開いている束の子として行だけを渡すので、名前も ID も付いているのに、束を畳んでいる間しか出なかった。開いている束のすぐ後ろに並べて渡す。
- **取り込みの結果の文は、種類ごとに ID を分ける**：`ImportUnreadableLine`（読めなかった）・`ImportOnlineOnlyLine`（オンラインのみ）・`ImportBrokenZipLine`（未確定の壊れたzip）・`ImportBrokenZipOnItemsLine`（商品の壊れたzip）。
- **管理の画面の行ごとのボタン**にも「行の物＋操作」の名前と ID を付けた（2026-09-30）：改変の画面（`Modifications〜`）・改変の詳細（`ModificationMember〜`）・アバターの管理（`AvatarBase〜`・`AvatarMod〜`）・
  タグと属性の管理（`TagSub〜`・`TagOrphan〜`・`AttributeOrphan〜`）・統計（`StatsBacklogRow`・`StatsPriceChangeRow`）・フォルダ（`FolderRow〜`）・ショップ一覧の右クリック（`ShopCardMenu.〜`）・小窓（`PickModificationPick`・`ChangeItemIdDuplicate`・`Choice〜`・`NoticeBody`）。
  リスト表示の行は `ItemListRow`、未確定の一覧の行は `ResolveFileRow`、未確定の上の検索欄は `ResolveFilter`。
- **付け残しを埋めた**（2026-09-30。画面の確かめで見つかった分）：
  - 左の一覧の行（選ぶ一覧）に行の名前と ID：フォルダの木 `FolderTreeRow`・タグの大分類 `TagTopRow`・属性 `AttributeRow`・アバター `AvatarRow`・共通素体 `AvatarBaseRow`・
