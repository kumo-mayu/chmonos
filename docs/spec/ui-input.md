# 入力の決め事

画面全体の決め事は [ui-rules.md](ui-rules.md)、別の窓は [ui-dialogs.md](ui-dialogs.md)、
空のとき・失敗したとき・押せないときは [ui-empty-and-errors.md](ui-empty-and-errors.md)、キーと止まり方は [ui-keyboard.md](ui-keyboard.md)。

## 候補と札

- 入力欄には候補を付ける（`SuggestBox`）。候補に無い語は「（新規）」の行として示し、選ばせる（表記が揺れると、名前でつないだ絞り込みが分かれてしまう）。
  **例外：新しく名付けて作る欄には付けない**（共通素体・大分類・属性を足す欄。メモ9-⑥・メモ10-① 2026-10-02）。今ある名前を並べても重複を誘うだけなので、ふつうの欄にし、Enter か「追加」で足し、今ある名前と同じなら「既にあります」と言う。
  **大分類と属性は、左の検索欄と1本**（ユーザ指示 2026-10-02。`Controls/SearchAddBox`。形は編集画面のユーザータグの欄に合わせ、高さ30・薄い字の案内）。打つと左の一覧が絞られ（200ms）、
  **欄の右の「追加」で足す**（メモ21-① 2026-10-03。共通素体の欄と同じ形。前は欄の下に「追加」の行が出ていた）。押すと足した物を選び、欄を空にする。空白だけの間は押せない。Enter は、同じ名前（前後の空白を除き、大文字小文字は問わない）があればその行を選び、無ければ足す。
  **同じ名前で「追加」を押したときは、欄のすぐ下に「「〇〇」は既にあります。」を出す**（画面の右上の状態の1行には出さない）。その1行の場所は常に取っておき、出入りで下の一覧が跳ねない（ユーザ注意 2026-10-03）。打ち直すと消える。同じ名前の行は一覧で強調する（名前を太く・アクセント色）。候補の一覧は出さない（打った結果が下の一覧そのもの）。
  **タグの管理で小分類を足す欄**（丸い＋の右に伸びる）も同じ形：候補なしのふつうの欄と「追加」。同じ名前なら欄のすぐ下に「既にあります」（場所は常に取る。メモ25 C）。
  付けるのは**今ある物を選ぶ欄**（商品にタグ・属性・小分類を付ける、統合先など）。
- 頭の絵の無い候補（配布商品を結んでいない共通素体など）は頭文字を出す（メモ3-① 2026-10-02。空の四角が読み込みの失敗に見えた）。
- **候補を全部並べて選ばせる画面は作らない**。候補付きの入力欄から1件ずつ追加するか、折りたためるようにする。
- 空の欄を押すと候補を全部出す。決めた後もフォーカスは欄に残す（続けて足せるように）ので、**同じ欄を押し直したときも候補を出す**
  （ユーザ指摘 2026-09-29：検索のユーザータグで、2つ目の大分類・小分類を足すときだけ押しても出なかった）。決めた直後は、押すか打つまで出さない。
- 多い札（対応アバター・BOOTHのタグ）は50件までは全部、超えたら40件と「残り n を表示」。作った札は捨てずに隠す（`ChipStrip`：差し替えると全部作り直すため）。20体を超えたら「アバター名で絞る」欄。
- 探す語はひらがな・カタカナ／全角・半角／大文字小文字を区別しない。
- **打つたびに一覧を絞る検索欄は、打ち終わって 200ms 待ってからまとめて絞る**（結び付けの `Delay=200`。2026-10-02 のメモ7：文字を1つずつ消す間に、その数だけ絞り直しが走って重かった）。
  検索・フォルダの右・改変・ショップの一覧・タグと属性の管理（左の検索と中を探す欄）・アバター・商品ページの対応アバターの絞り込み・未確定の検索欄。フォルダの木だけ 250ms。
- **既にある名前と同じ綴りを打ったら、候補から選んだのと同じに扱う**（タグ・属性の名前の変更の窓。点検 2026-09-23）。綴りは候補の側に揃える。
  既にある名前は表記の揺れを生まないので、選び直させない。無い名前は打っただけでは決めず、候補の「新規」の行を選ばせる（押せない理由にそう書く）。

## 決め方と保存

- **Enter は入力の確定**（ユーザ判断 2026-09-20・I12）。1行の入力欄は、横のボタンと同じことが Enter で起きる
  （呼び方を追加・素体の商品を設定・改変を作る・未確定は「情報を確認」まで）。
  **取り返しのつかない確定は Enter で走らせない**（未確定の「このIDで登録」は押して決める）。
- 名前を変えるのは**欄の中**（Enter か「名前を保存」。変えたときだけボタンを表示する）。OS の入力窓は使わない（B10：共通素体だけ残っていた）。
- **メモはどこでも押さずに残る**（I9）。商品のメモは商品ページでも書ける
  （編集画面の中に入れているときは、右の欄と二重にしないので表示しない）。
- **保存のしかたが画面の中で分かれるときは、画面に書く。**編集画面の左（画像・星など）は押した時点で保存し、右は「保存して次へ」で保存する。
  この形のままにすると決めたので（ユーザ判断 2026-09-20・B7）、左の列の頭に「この列は押した時点で保存されます。右の欄は「保存して次へ」で保存します。」と出す。

## 右クリックのメニュー

**右クリックのメニューは、どの画面でも項目を全部出し、できない操作は押せなくして吹き出しで理由を言う**（ユーザ判断 2026-10-04・メモ20-①。条件で項目を隠すと、画面・商品ごとに並びが変わり、なぜ無いのか分からない）。
商品のカード・行（`CardMenu`）は要る物で分ける。**商品の JSON が要る**（カードを持つこと。名前が挙がっただけで商品が手元に無いアバターの行は持たない）＝お気に入り・商品ページを開く・編集に入る・BOOTHで開く・ショップを開く・リンクをコピー・改変に追加…・非表示にする
（BOOTHで開く・リンクはさらに BOOTH にページがあること、ショップを開くは店が分かること）。**手元のファイルが要る**（ファイルかフォルダを1つ以上持つ）＝エクスプローラで開く・一時的に展開して開く・Unityへ送る・改変に追加して送る・Unityで選択。
展開は zip が要る（zip を持たない商品は「手元にzipがありません」、zip を持っているが全部見つからずフォルダだけ在る商品は「zipが見つかりません」。ユーザ判断 2026-10-05）。Unity の3つは**送れる unitypackage があるか**で決める：zip の中（`contents`）か、登録したフォルダの中（数えたときの `unityPackages`）に1つでもあれば押せる。無ければ「手元にunitypackageがありません」（メモ65-③・2026-10-05）。
**持っているファイル・フォルダが全部見つからない商品**（場所が空か、見つからなくなった日時が付いている）は、これらを全部押せなくし、親（開く ▸・Unity ▸）も「手元のファイルが見つかりません」で薄くする。1つでも在れば今のまま。つながっていないドライブの上の物は日時が付かないので押せ、押すと「取り外しているドライブ」と言う（メモ65-①。判定は記録だけで、カードの札の `HasMissingFile` とは別に `CardMenuState.AllMissing`）。
**そのほか**：「選ぶ」はカードそのものだけ（行の一覧には選ぶ箱が無い。吹き出しは「この一覧では選べません」）。「更新の通知を開く」「既読にする」は未読の更新がある商品のカードだけ押せる（無ければ「未読の更新の通知はありません」、行の一覧では「この画面では使えません」）。
**並び**（`ItemCardResources.xaml` の `CardMenu`）：商品ページを開く・BOOTHで開く・ショップを開く・リンクをコピー・編集に入る・改変に追加…・お気に入り・選ぶ・更新の通知を開く・既読にする、区切り、開く ▸（エクスプローラで開く…・一時的に展開して開く…）・Unity ▸（Unityへ送る…・改変に追加して送る…・Unityで選択…）・非表示にする。
選んだ商品をまとめて既読にするのは右クリックには置かず、複数選んだときの下の帯の「既読にする」だけ（メモ33-①・2026-10-05）。
タグ・属性の管理の左の一覧の行にも同じ作りのメニューを出す（[tags.md](tags.md)）。押せるかと吹き出しは `CardMenuState` に集め、メニューを開くたびに引き直す。押せるときと押せないときで吹き出しを分けたい項目は `MenuTips.Enabled`／`Disabled`（`ToolTip` を直に書くと、押せないときも同じ文が出る）。吹き出しは「商品の情報がまだありません」「手元にファイルがありません」のように短く理由だけ。
**子を持つ親（開く ▸・Unity ▸）は、子が全部押せないとき親も押せなくし、吹き出しに子の理由（そろわなければ「今は使える操作がありません」）を言う**（メモ49・2026-10-05。`CardMenuState` の `Parents`）。
**消す・外す・初期化する項目（削除・履歴から消す・素体から外すなど）は、戻せるかに関わらず、右の欄の `DangerButton` と同じ赤の文字（`DangerMenuItem`）にする**（メモ56・2026-10-05。同日の決定で「取り返しのつかない物だけ」から広げた。V4）。「外す」（登録や対応を外す）も同じ赤にする（メモ68 決定 B）。「非表示にする」「除外」「条件をクリア」「この条件を外す」は普通の色のまま。

## キー

キーの割り当て・キーボードだけで進める決まり（並び・止まり直し・乗せたときだけ出すボタンへのフォーカス）は [ui-keyboard.md](ui-keyboard.md)（2026-10-05 にこのファイルが200行に近づいたので分けた）。

### 読み上げの名前

- 候補付きの入力欄は、置き場所で付けた `AutomationProperties.Name`（無ければ薄い字の案内）を中の欄の名前にする。候補の行は語そのもの（新しい語は「（新規）」付き）を読ませる。
- カードは商品名を「押せる1件」として読ませ（`ItemCardBorder`）、リストの行も商品・フォルダの名前を読ませる（型の名前を読ませない）。

**操作できる部品には、UI Automation の名前を付ける**（2026-09-30。名前の無い部品は読み上げで何か分からず、画面の確かめでは座標を取って実際のマウスで押すしかなかった）。
名前は読み上げソフトがそのまま読むので、画面の語（[ui-terms.md](ui-terms.md)）で書く。内部の言葉と型の名前は読ませない。

| 何に | どう付けるか |
|---|---|
| 文字のボタン・チェック | 付けなくてよい（文字が名前になる） |
| 絵・記号だけのボタン（×・＋・‹ ›・◀ ▶・三角）、中身が絵と文字の並びのボタン | 吹き出しと同じ意味の短い名前（「前の画像」「画像を追加」） |
| 入力欄・選ぶ欄・スライダー | 左や上の見出しの語（「商品名」「表示の大きさ」）。見出しが無ければ薄い字の案内の語 |
| 行ごとに繰り返す部品 | どの行の物かを入れる：「（商品名）をお気に入りに入れる」「（ファイル名）を開く」「（候補の名前）で確認」「（バリエーション名）の支払額」。見えている文字はそのまま含める |
| 同じ画面に同じ名前が並ぶ物（検索の条件の「下限」「上限」） | 何の物かを頭に付ける：「価格の下限」 |
| 畳める欄（`Expander`）で、見出しが文字の並びや札の物 | `Expander` に欄の名前を付ける（見出しの押す所は、型がその名前から「（欄）を開く」⇄「（欄）を折りたたむ」を作る） |
| 欄や行を開閉する部品（三角・ナビ・検索の絞り込み・検索の条件・フォルダの木の印） | **押すと起きることを名前にし、状態で替える**：「（欄）を開く」⇄「（欄）を折りたたむ」。開いていても「〜を開く」と読まれる名前にしない（確かめの道具が、開いている欄を押して畳んでいた） |
| そのうち、三角（`ToggleButton` で作った物） | `Controls/ExpandToggle` にして、何の開閉かだけを `Subject` に渡す（「ローカルファイル」「（小分類名）の商品」「（改変名）の使ったもの」）。名前は部品が状態から作り、開いているかを UI Automation の開閉（ExpandCollapse）でも渡す（「開く」「畳む」を名指しで呼べる）。商品ページのバリエーションの三角は ViewModel が同じ言い方で名前を作っている（`ItemViewModel.ToggleName`） |
| 選ぶ一覧（`ListBox`）の行 | 行の名前（未確定はファイル名）。付けないと行の型の名前が読まれる |
| 欄を開閉する三角（`Expander` でない、切り替えのボタン） | **押すと起きること**を名前にする：畳んでいるとき「（欄の名前）を開く」、開いているとき「（欄の名前）を折りたたむ」（`ItemViewModel.ToggleName`）。開閉は、切り替えの入・切としても出る（入＝開いている） |
| 名前の無い物が並ぶ一覧（ギャラリーの小さな絵） | 並びの番号で言う：「n 枚目の画像を表示」。番号は行が持つ（一覧を組み直すたびに振る） |

- **押せる枠は `PressableBorder`、繰り返しの一覧は `ContentItemsControl`、商品のリストは `ItemListView`。**
  素の `Border`・文字に押す動きを付けただけの物は UI Automation に出ない（カードの星・「中を見る」・札・下の通信の帯・通知の行・編集画面の ✕）。
  見た目は変えずに「押せるボタン」として出し、読み上げ・自動操作の「押す」をマウスで押したときと同じ処理につなぐ。
  素の `ItemsControl` は、行を型の名前で読ませ、値の等しい行を1つにまとめる（`docs/dev/wpf.md`）。
- **カードの「段」は木に出さない**（ユーザ判断 2026-09-30）。カードの一覧は、窓の幅から列数を決めてカードを段に切り、段を縦に並べている（仮想化のため）。
  段は並べ方の都合の入れ物で、選べず、止まれず、幅を変えれば中身が入れ替わる。前は一覧の項目として型の名前（`…CardRow`）で読まれていた。
  検索・ショップ・ショップ一覧・フォルダの右は `Controls/CardRowsListBox`（カードを一覧の直下に出す。「選ぶ」は持たない）、段そのものは `Controls/CardRowItems`。
  タグと属性の管理の段（行ごとに型の違う一覧の中）は木には残るが、「操作できる部品」から外してある（相手の既定の見方では、カードが一覧の直下に出る）。
  見た目・Tab・矢印・Enter・仮想化は ListBox のまま。**カードを段から探さない**（ID `ItemCard`・`ShopCard` と名前で探す）。
- **カードとリストの行は「押す」で開く。**キーボードの Enter と同じ処理で、戻ったら開いた所に止まり直す（リストの行は「選ぶ」しか持たず、読み上げ・自動操作から商品ページへ移れなかった）。
- **名前で見分けられない物には AutomationId を付ける**（画面には出ない。英字）。同じ条件が2つの見出しの下に出るメニュー（`SearchAddModule.<条件の種類>`）、
  条件の中の欄（`SearchModule.<条件の種類>.<部品>`。同じ種類の2つ目から `<条件の種類>-2`、名前も「カテゴリ（2つ目）の〜」。見出しの「…」は `.Menu`、
  その行は `.Menu.Exclude`・`.Menu.Collapse`・`.Menu.MoveUp`・`.Menu.MoveDown`・`.Menu.Remove`、札は `.Excluded`、編集状況の項目は `SearchModule.Unedited.Field.<項目>`、
  パネルの「…」は `SearchFilterMenu`・行 `SearchFilterMenu.GroupKinds`・`.Clear`・`.Collapse`）、行ごとに並ぶボタン（`ItemFileOpenMenu`・`ResolveCandidateUse`）、
  確かめで読みたい文（`ImportSummary.<数>`・`UnitySendText`）。頭は画面の名前（`Search`・`Item`・`Edit`・`Resolve`・`Import`・`Settings.`）で始める。一覧は XAML を `AutomationProperties.AutomationId="` で引く。
- **名前の「_」は消えない**（2026-09-30）。WPF は、中身が文字のボタン・チェック・メニューの項目の名前から、アクセスキーの印として最初の「_」を消す（名前を付けていても。「file_000.pngを開く」が「file000.pngを開く」で読まれた）。
  消されるのと同じ決まりで先に重ねておく（`Services/AutomationNames`。部品の型に1回で掛けるので、名前を付ける所は何もしなくてよい）。名前を付けていないボタンも、中身の文字に「_」があれば同じに守る。
  メニューの項目のうち、名前を付けずに見出しの文字をそのまま読ませている物は守れない（見出しが替わった知らせを受ける口が無い）。人が決めた文字を見出しにする項目には、名前も付ける。
- **候補付きの入力欄の候補の行は「押す」で決まる**（`Controls/InvokableListBox`。クリック・Enter と同じ処理）。「選ぶ」だけでは色が付くだけで決まらなかった。
- **束（見出しでまとめた行）の見出しの中のボタンは、束が開いていても木に出す**（`Controls/GroupedListBox`。未確定の「まとめて扱う」「元zipとして扱う」「このフォルダを選択」）。
  WPF は開いている束の子として行だけを渡すので、名前も ID も付いているのに、束を畳んでいる間しか出なかった。開いている束のすぐ後ろに並べて渡す。
- **取り込みの結果の文は、種類ごとに ID を分ける**：`ImportUnreadableLine`（読めなかった）・`ImportOnlineOnlyLine`（オンラインのみ）・`ImportBrokenZipLine`（未確定の壊れたzip）・`ImportBrokenZipOnItemsLine`（商品の壊れたzip）。
- **管理の画面の行ごとのボタン**にも「行の物＋操作」の名前と ID を付けた（2026-09-30）：改変の画面（`Modifications〜`）・改変の詳細（`ModificationMember〜`）・アバターの管理（`AvatarBase〜`・`AvatarMod〜`）・
  タグと属性の管理（`TagSub〜`・`TagOrphan〜`・`AttributeOrphan〜`）・統計（`StatsBacklogRow`・`StatsPriceChangeRow`）・フォルダ（`FolderRow〜`）・ショップ一覧の右クリック（`ShopCardMenu.〜`）・小窓（`PickModificationPick`・`ChangeItemIdDuplicate`・`Choice〜`・`NoticeBody`）。
  リスト表示の行は `ItemListRow`、未確定の一覧の行は `ResolveFileRow`、未確定の上の検索欄は `ResolveFilter`。
- **付け残しを埋めた**（2026-09-30。画面の確かめで見つかった分）：
  - 左の一覧の行（選ぶ一覧）に行の名前と ID：フォルダの木 `FolderTreeRow`・タグの大分類 `TagTopRow`・属性 `AttributeRow`・アバター `AvatarRow`・共通素体 `AvatarBaseRow`・
    改変の詳細の「使ったもの」のリスト `ModificationMemberRow`。どれも型の名前（`…FolderViewRow` など）で読まれていた。
  - 統計の「よく買っているショップ」「ディスク使用量の内訳」の行：`StatsShopRow`「（ショップ名）を開く」・`StatsCategoryRow`「（カテゴリ名）を検索で開く」。
  - ショップの星：`ShopFavorite`（ショップ画面）・`ShopCardFavorite`（一覧のカード）。名前は「（ショップ名）をお気に入りのショップにする／から外す」。
  - 商品ページ：ショップ名のリンク `ItemShopLink`「（ショップ名）の商品を見る」（前は空白1文字）。ID のリンク `ItemIdCopy`（名前は「ID 1234567」。確かめの道具が今の商品を読む場所）。
  - ナビのボタン `Nav.<画面>`（`Nav.Search`・`Nav.Settings`…。戻る・進む・開閉は `Nav.Back`・`Nav.Forward`・`Nav.Toggle`）、
