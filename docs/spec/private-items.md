# BOOTH に無い商品（今の決め事）

> **要点**：BOOTH から取れない（404）ファイルも落とさず未確定へ流す。未確定には3つ目の出口「BOOTHに無い商品として登録する」があり、
> 仮ID `local-{ファイルのハッシュ先頭8桁}` で商品を作る。名前・カテゴリ・ショップは `Local` に入れられる。本物のIDが分かったら「IDを変更」で寄せる。
>
> **コード**：`Core/Services/ItemService.cs`（登録・`ChangeItemIdAsync`）、`Core/Models/LocalBlock`（`DisplayName` `Category` `Shop`）、
> `Core/Models/BoothBlock.FetchedAt`（`null`＝一度も取れていない）、`Core/Models/Purchase`（`VariationId` は `long?`）、`FallbackResolver`（候補）
>
> **経緯**：`docs/history/private-items.md`（38問のgrillと実装した段）

## 落とさない

- 新しく取る商品が404なら、**1回で**試すのをやめて未確定へ送る（既存商品の「3回で非公開」とは別。こちらが非公開と確定する必要はなく、一時的な障害なら次の取り込みで確定するだけ）。
- 取り込み結果には、0件でないときだけ「BOOTHで見つからなかったものが n 件あります。未確定に置いてあります」を1行出す。
- 未確定に置き続ける案は採らない（二度と復活しない物で作業一覧が埋まる）。

## 仮ID

- `local-{ハッシュ先頭8桁}`。連番は保存先を移すと衝突し、GUIDは人が読めない。接頭辞で JSON を開いた人に一目で分かる。
- 仮ID商品は①②も⑦も走らない。**商品ページに常設で1行、登録時にも1行**そう書く。「BOOTHから取り直す」「BOOTHで開く」は押せなくして、理由をツールチップに置く。
- **登録と一緒に画像を入れられる**（ユーザ判断 2026-09-29：BOOTHから取らないので画像が1枚も無かった）。「この名前で登録する」の横の「画像を選ぶ」か、その枠へのドロップ（画像だけのとき。ほかはウィンドウの振り分けのまま）。
  入れ方は商品ページと同じ「自分で足す画像」（`AddUserImage`）。選び直すと添えた画像は捨てる（別のファイルの登録に持ち越さない）。入らなかった分があっても登録は取り消さない。登録の後は商品ページの「＋」。
- 「一度も取れていない」と「非公開になった」は `Booth.FetchedAt is null` で見分ける（フラグを足さない。二重に持つと片方だけ更新される）。
  文言は「BOOTHで見つかりません（情報を取れたことがありません）」と「販売終了」。

## 商品IDは分かるがBOOTHで見つからない（本物のIDのまま登録）

- ユーザ判断 2026-09-29：仮IDで登録すると⑦に乗らず、**再び公開されても情報を取れない**。未確定の「このIDで確認」でBOOTHが「無い」と答えたとき（404。一時的に届かないときは出さない）だけ、確定の欄に「ID … のまま登録する」を出す。
- 作る商品（`AssignUnpublishedItemIdAsync`・`UiCommand.AssignUnpublishedItemId`）：`Booth` は空（`FetchedAt` null＝一度も取れていない）、名前はファイル名（元zipが分かればzipの名前）から作って `Local.DisplayName`。
  **販売終了と同じ状態**にする：`IsDelisted`、見つからない回数は非公開と確定する回数（`NotFoundThreshold`）、予定日は確かめ直しの間隔（30日）。回数を1で始めると、次の404で「回数が足りない」として印が外れる。
- **BOOTHへは問い合わせない**（直前の確かめで見つからなかったID）。同じIDが既にあれば（見つからなかった後に別の道で作られた）ファイルを足すだけで、名前と取得の記録は触らない。
- ⑦で見つからなければ回数が増えるだけ。公開されたら `RefreshAsync` が booth を埋め、印を外し、要確認に「BOOTHに現れました」（`NoteBackOnBoothAsync`。付けた名前は残る）。
- 仮IDとの違い：仮IDは IDが分からない物（⑦に乗らない）。こちらは IDが分かっている物。IDを間違えたら商品ページの「IDを変更」で移す。

## 人が入れる項目（`Local`）

- **名前・カテゴリ・ショップ**。観測（`Booth`）と入力（`Local`）を分けたまま置くので、後で BOOTH が復活しても両方残る。
- 復活したら**人が入れた名前を出す**（登録簿の `DisplayName` と `BoothName` と同じ形）。人の命名だと明記し、どちらの名前も検索に掛ける。
- カテゴリは子の名前1つ（絞り込みは子の名前の平坦な一覧なので `ParentName` は要らない）。検索対象にし、絞り込みにも出す。
- **ショップの鍵**：ショップの URL を貼れば本物のサブドメイン。貼らないときは `local-` を付けた鍵（ローマ字化は本物と衝突し、漢字の読みも一意でない）。手元のショップ名を候補に出す。

## 候補の出し方

- 登録簿は未所持の商品の名前まで持つので、そこから引く。**自動では入れず、押したら入る**（推定か観測かが後から分からなくなるため）。
- 判定には商品ID・表示名・BOOTHの正式名・別名、表記の橋渡し（`SearchBridge` / `ReadingMatch`）を使う。通信は増えない。
- 候補は既存の `CandidateItemIds` に一緒に載せる（欄を2つにしない）。押した先で「BOOTHでは見つかりません。手元の記録では『…』です」。
- 名前の取れないアバター候補は、それを参照している商品の名前を並べる。名前の候補は別名から取り、1つに絞って先頭、残りも並べる。`AvatarText.ShortenName` は別名が無いときの最後の手段。

## BOOTH との往復

- `IsDelisted` を立てて⑦に乗せる（30日ごとに確かめ直す）。
- 復活したら要確認に出す（「BOOTHに現れました。名前は『…』のままです」）。黙って埋めると画像や価格が急に増え「壊れた」と読まれる。
- 統計には別の行（「販売終了」と金額の意味が違う：こちらは人が入れた額しかない）。
- 画面では印を付けて普通に並べる（検索から既定で外すと所持を隠すことになる）。

## 支払額

- `Purchase.VariationId` は `long?`。「種類が分からない」は「種類が無い」ではない。
- **種類を指さない購入はいつでも足せる**（販売終了は種類単位でも起こり、後から記録を入れる行が無くなるため）。
- 集計は `Kind` と `Price` だけを見るので、`null` の購入を複数持っても自分用とギフトは分かれて数えられる。

## カテゴリの一覧

- **BOOTH のカテゴリ表を同梱する**（全員が同じ静的な表を別々に取りに行くのは、負担を減らす方針に反する）。取得は開発時の一度きりで `tools/` のスクリプトから `BoothClient` を通す。取るのはカテゴリ表だけ。出典と判断は `NOTICE` に書く。
- 「カテゴリの候補をすべて出す」は既定オフ（オフで VRChat 向けの物を上に、残りは「その他」の下）。トグルは広げる側を名乗る（他の「〜も探す」と同じ向き）。
- アバター判定の⓪は「`Booth.Category` または `Local.Category` が3Dキャラクター」。3Dキャラクターにしたときだけ「アバターとして扱われるようになります」を1行出す。`AvatarOverride`（3値）は例外の上書きとして残る。

## IDを変更する

- 商品ページの「IDを変更」。ファイルを動かす「この商品から外す」とは別の操作（商品ごとを動かす）。
- 手順：新しいIDを入れる（「この商品を自動検索」もある）→ ①②を取る（取れなくても止めず「このIDで登録しますか」）→ 移す → 衝突した購入だけ聞く。
- **移せる物は全部移す**。移さず捨てる物：対応アバターの検出結果（説明文から出た物なので新しい商品で検出し直す）、取得の状態（`LastFetchedAt` `NextFetchDueAt` `ConsecutiveNotFoundCount` `IsDelisted`）。
  種類を指す物（`Purchases[].VariationId`・**`LocalFiles[].VariationId`**）は移した先に無ければ `ExistsOnBooth=false` として残る。
- 聞くのは購入記録だけ：移した先と**金額が一致する**ものを「同じ買い物かもしれない」として出す（種類が違う・金額が未入力なら疑わない）。既定は「移す」。
- 移した先が持っている入力は潰さない。**メモはどちらも残す**。
- **自分で足した画像・役割・サムネイルの指定・お気に入りも移す**（2026-09-23。前は引き継がず、元の商品を消すときに画像のフォルダごと消えて取り返せなかった）。
  - 画像のファイルは**何かを書く前に**移した先のフォルダへ写す。写せなければ何も書かずに元を残す（`ImagesNotMoved`。BOOTH から取るより前に行うので、取ってきた空の商品も残らない）。
  - 同じ名前は同じ絵（保存名が中身のハッシュ）なので写さず1枚にまとめ、覚え書きは空いている方を埋める。
  - サムネイルの指定は他の1つだけの欄と同じく移した先が優先。お気に入りはどちらかが付けていれば付ける。役割は移した先を優先し、自分で足した画像の分だけ足す。
  - **BOOTH の画像に付けた指定は移らない**（名前が元URLのハッシュで、URLに商品IDが入るので移した先と合わない）。下見の「移らない物」に件数を出す。
- 既にある先へは `ChangeLocalAsync` で、錠の中で読み直した今の値に重ねる。**移す元も BOOTH から取った後で読み直す**
  （取る数秒の間に取り込みが元へ足したファイルが、元の商品ごと消えていた）。取れなかった間に同じIDが別の道で作られていたら、そちらへ重ねる。
- 改変の付け替えも `Modifications.UpdateAsync` で1件ずつ今の値に当てる（全件を読んだ写しで書くと、その間に改変の画面が書いた名前が消える）。
- 非公開アバターの本体を仮IDで持っていて「未所有」と出る問題は、本物のIDに寄せれば消える（ヒント欄は作らない。「IDは何か」の答えが2つになる）。
