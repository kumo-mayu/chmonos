# 窓（ダイアログ）と知らせの決まり

画面の中の決まりは [ui-rules.md](ui-rules.md)。ここは**別の窓で聞く・言う**ときの決まり
（ユーザ判断 2026-09-20。洗い出しの D1〜D11・`docs/feedback/ui-consistency-2026-09-20.md`）。
主の窓を止めずに横で使う別の窓（サブ画面）の決まりは [ui-subwindows.md](ui-subwindows.md)。キーのうち「Esc で閉じる」は同じで、「Enter で決める」ボタンは置かない。

## キー

- **Esc でどの窓も閉じられる**（D1）。やめる側のボタンに `IsCancel="True"` を付ける。
  ボタンを置かない窓（初回の窓）は code-behind で Esc を受け、×と同じに閉じる。
  API の許しの窓も code-behind で Esc を受ける（［拒否］に `IsCancel` を付けると Esc でも拒否を押したことになり、止めるまでの回数に数えてしまう。[api-clients.md](api-clients.md)）。
- **Enter で決められる**（D2）。主のボタンに `IsDefault="True"` を付ける。
  入れる物が足りない窓は、そのボタンの `IsEnabled` を条件に結ぶ（空欄の Enter は何も起こさない）。
- 例外は**意図を聞く三択**（`ChoiceDialog`）。どちらの意図か分からないから聞いているので、Enter で片方に倒さない。
- 候補付きの入力欄（`SuggestBox`）は、**候補の一覧が開いているときだけ** Enter と Esc を受ける。
  閉じているときまで食べると、打ち終えた後の Enter で窓が決まらず、Esc でも窓が閉じられない。

## ボタン

- やめる側の名前は**「キャンセル」**で揃え、**右端**に置く（D3）。主のボタンはその左。
  知らせの窓（`Notice`。MessageBox と同じ並び）も OK が左・キャンセルが右なので、窓の種類で並びが変わらない。
- 押すと何が起きるかが分かる名前にする（[ui-writing.md](ui-writing.md)）。
- **中止の範囲を名前に入れる**（D11）。1件ずつ順に聞く窓では「この商品を飛ばす」（1件）と
  「残りすべてを中止」（残り全部）を並べる。「やめる」だけでは、1件なのか全部なのか読めない。
- 本文でボタンごとに説明するときは、ボタンの名前を「」で1行に書き、説明はその下の行に書く。選択肢の間は1行空ける
  （「……」「：」でつないで1行にしない。ユーザ判断 2026-09-24・[ui-terms-avoid.md](ui-terms-avoid.md)）。

## 取り返しがつくか

- 商品やデータを書き換える窓は、**押す前に取り返しがつくかを必ず1行で書く**（D4）。
  戻せるなら「同じ手順で戻せます」と書く。書かないと、戻せないものと見分けが付かない。
- 窓の本文は、1行目に何が起きるか、2行目に取り返しがつくか。理由や経緯は書かない（[ui-writing.md](ui-writing.md)「何を載せるか」）。
- **設定の「すべての設定を既定に戻す」**（2026-10-04・メモ29。データの節の末尾。「…」は付けない：確認だけの窓）は、窓で何が戻り何が戻らないかを言い、1行空けて「この操作は元に戻せません」と書く（メモ40。続けて読むと混ざる。既定はキャンセル）。
  戻さないのは使う人の環境に特有の物＝取り込み元・監視するフォルダ・アバター検出の見出し語など、画面に出していない欄すべて（settings.json を手で書いて調整する値を黙って消さない）（非表示・除外・外した記録と保存先は設定の外にあり、触れない）。ほかは既定に戻す（`AppSettings.ResetToDefaults`）。 窓では「取り込み元・監視するフォルダ・非表示にしたもの・保存先と、画面にない細かな調整は、そのままです。」と言い、1行空けて「この操作は元に戻せません。」（2026-10-05）。
  **窓は専用の窓**（`ResetSettingsDialog`。標準の知らせの窓にチェックを足せない。ユーザ判断 2026-11-10）：本文の後に「通知の保管に使う容量はそのままにする」のチェック（既定オン。通知の保管の容量だけ今の値で残す。オフで 50 に戻る。[notifications.md](notifications.md)「保管庫」）。戻す側は赤の「既定に戻す」、キャンセルが右端・Esc・既定（枠だけ青）。本文に「保管している通知も消えません。」を足した。試験の口は `ResetSettingsDialogViewModel.Intercept`。
  戻した結果はボタンの下の1行に出す
- 統合は戻せない（どちらに付いていたかを残していないので分け直せない）。
  名前の変更は戻せる。同じ窓でも、選んだ内容で答えが変わるなら文もそれに合わせる。

## 何回聞くか

- **戻せない操作だけ、窓の後にもう一度聞く**（D5）。統合（分類・属性）がこれにあたる。
  1つになった後は、どちらに付いていたかで分け直せない。
- 名前の変更・移動のように**同じ手順で戻せる**ものは、影響を示す窓の1回だけで済ませる。
  戻せるものまで2回聞くと、聞かれること自体が読み飛ばされる。

## どこに言うか

- **操作の結果は、押した欄・ボタン・行のすぐ下に出す。失敗もそこに出す**（D6 を 2026-10-03〜04 に直した。前は「うまくいったことは画面の1行、できなかったことは必ず窓」。決まりの全体は [ui-empty-and-errors.md](ui-empty-and-errors.md)「知らせの置き場の共通の決まり」、元は `docs/feedback/notice-placement-2026-10-03.md`）。
- **窓に残すのは `Notices.LineOrWindow` の失敗だけ**（Unityで選択・Unityへ送る。成功は1行）。窓を開くときは、途中の表示（「調べています…」）を消してから開く。
- 行を持たない所（カードの右クリック）は、うまくいったことも窓で知らせる。ただし戻せる操作（非表示にする）は、窓の代わりに下の帯に戻し方と解除を表示する（`MainViewModel.HiddenNotice`）。
- **見れば分かることは言わない**（D7）。Unity の取り込み画面が開く・画像が消える・フォルダが一覧に並ぶ、はそれ自体が結果。
- 呼ばれた側は `NoticeSink` に返し、**表示先は呼んだ画面が決める**（`Notices.LineOrWindow`）。

## 知らせの窓（`Services.Notice`）

知らせと確認の窓は、Windows の `MessageBox` ではなく自前の窓（`Views/NoticeWindow`）で出す（ユーザ指示 2026-09-29。MessageBox は暗い表でも白いまま残った）。
呼ぶ側は今まで通り `Notice.Show`（引数と返り値は MessageBox と同じ形）で、**動きも MessageBox に合わせる**。呼ぶ所は MessageBox の動きを前に書かれている。

- ボタンの組は OK・OK/キャンセル・はい/いいえ・はい/いいえ/キャンセルの4つ。語は Windows と同じ（[ui-terms.md](ui-terms.md)）。キャンセルは右端
- 既定のボタンは頼まれた答え、無ければ左端。フォーカスもそこに置く。OK・はいが既定なら主のボタンの見た目、キャンセル・いいえが既定なら枠だけ青くする
- Esc と × はキャンセル。キャンセルが無ければ OK。**「はい・いいえ」だけの窓は Esc も × も効かない**（「いいえ」が別の操作を選ぶ窓がある。展開先のファイルの窓の「いいえ」は、指定のファイルのまま取り込む）
- 並び・既定・Esc の答えは `Core/Services/NoticeLayout`（試験は `NoticeLayoutTests`）
- 持ち主を渡されなければ、今手前にあるこのアプリの窓が持ち主（その中央に出る）。無ければ持ち主なしで画面の中央に出し、タスクバーにも出す
- 本文は選んでコピーできる。Ctrl+C は MessageBox と同じ形で題・本文・ボタンを写す。長い本文は本文だけを縦に送り、ボタンの帯は見え続ける
- 表示の大きさ（`AppZoom`）と題の帯の色は、ほかの小窓と同じく `DialogFit.Prepare` が当てる
- 主の窓より前に出す窓（保存先の確かめ・既に起動している）は、出している間だけアプリの終わり方を止める。WPF の窓は閉じると「最後の窓が閉じた」とアプリを終えてしまう
- 選ぶ窓（`ChoiceDialog`）のように、ボタンの名前で何が起きるかを言う方がよい問いは、MessageBox の形に押し込まずに専用の窓にする

## 一覧から選ぶ窓と、Unityで選択の木

- 一覧から1つを選ぶ窓は `Services/ListChoice`（送り先の Unity・開くファイル・送る unitypackage）。候補が2つ以上のときだけ出す。
- **Unityで選択の木**（`Views/UnityPickDialog`・`ViewModels/UnityPickTree`。ユーザ判断 2026-11-13「フォルダツリーにする形」）：「Unityで画像を選択」の候補（見つかった画像と unitypackage）が**9件以上**なら、Unity の中のフォルダの木で選ばせる。
  **8件以下か画像が1つ以下は平らな `ListChoice` のまま**（2段の行で一覧の高さ360に流さず収まるのが8行。収まるなら木にしても行が増えるだけ）。画像が1つのフォルダに収まっていても9件以上なら木にする（頭のフォルダを1行にまとめ、行には名前だけを出す方が読める）。
  - 区切りは「/」で段ごとに分ける（`Foo` と `Foobar` は別）。子がフォルダ1つだけで画像の無い段は1行に畳む（全部に共通の頭 `Assets/作者/商品` は根の1行になる）。フォルダが先・画像が後、それぞれ名前の順。フォルダの行の右端に下の画像の数、吹き出しにフルパス。
  - 画像の行は名前と、右に小さく見つかり方（「同じ画像」「名前が同じ」）。吹き出しは平らな行と同じ文（見つかり方：Unity の中のパス）と商品の側の名前。
  - unitypackage は画像の木と分けて「unitypackage」の節に置く（両方あるときだけ「画像」「unitypackage」の2つの節。片方なら節の行は出さない）。行の右に入っている zip の名前。
  - 開いた時は幅優先で、見える行が16（行26・一覧の高さ420）に収まるフォルダだけ広げる。兄弟の無い行（根が1つ）は収まらなくても広げる。最初の画像の行を選んでおく。
  - 選べるのは画像と unitypackage の行だけ。フォルダの行では「これを選択」が押せない。キー：↑↓ で行・→ で広げる／最初の子へ・← で畳む／親へ・Enter は画像なら決める、フォルダなら畳む・広げる・Esc でやめる。ダブルクリックも同じ。三角でも畳む・広げる。
  - 行の読み上げの名前は「名前、見つかり方」「フォルダ名、n 件」。字下げした平らな一覧で描く（フォルダビューの木と同じ。三角の型 `FolderGlyph` も共用）。

## 知らせのアイコン

- **人が押した操作の確認は Question**（D9）。消す・統合するでアイコンが割れないようにする。
  取り返しのつかない操作は、アイコンではなく**既定のボタンをキャンセル側に倒して**止める。
- **できなかったことは Warning**（D8）。うまくいかなかったこと・壊れている状態を言う窓はこちら。
  結果を呼んだ側に返すときは `NoticeSink`（`failed` を添える）を通す。既定のまま表示していて、
  「送れませんでした」が ℹ のアイコンで表示されていた。
- Information は「済んだこと」だけに使う。

## 「…」の付け方

押すと**もう一度聞かれることがある**ものにだけ付ける（選ぶ窓・ファイルを選ぶ窓が開く。D10）。

- カードの右クリックの「エクスプローラで開く…」「Unityへ送る…」は、対象のファイルがまだ決まっていないので聞く。
- 商品ページのファイルの欄の同じ項目は、押した行で対象が決まるので聞かない。付けない。
- 確認だけの窓（「消しますか」）は聞き返しではないので付けない。
