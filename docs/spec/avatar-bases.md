# 共通素体と素体経由の対応（今の決め事）

[avatars.md](avatars.md) から分けた（2026-11-04：1ファイル200行の決まり）。アバターそのもの・検出・登録簿は avatars.md。

## 共通素体

- **名前をキーにしたグループ**（配布されていない素体がある）。配布されていれば `itemId` も持つ。ショップでは括れない（同じ作者＝同じ素体ではない）ので、ショップを理由に質問しない。
- 所属は「#MARUBODY」「（えも研素体）」「+Head」のような手掛かりから自動で埋め、手でも足せる。
  推すのは手で決めた所属（`baseName`）が無く、`noBase` が立っていないアバターだけ（`AvatarBaseKeys.InferBaseOf`。推す所はすべてここを通る）。推した所属は保存しない。
- **素体の詳細：足す・外すで一覧を作り直さない／開いたら履歴に積む／行に吹き出しを付けない**（メモ68・ユーザ判断 2026-10-05）：一覧は1つを持ち、足した行・外した行だけを足し引きする（作り直すと乗せた行のホバーが効かなくなる）。行を押してアバターを開くときは、素体の詳細を履歴に積み、戻る（Alt+←）で素体の詳細へ戻る。行の「このアバターを開きます」の吹き出しは付けない。「この素体から外す」は赤（「外す」も赤。`ui-rules.md` V4）。
- **素体の側から足す・外す**（メモ46・ユーザ判断 2026-10-05）：素体の詳細の「この素体を使っているアバター」の上に候補付きの欄（ほかのアバターの候補と同じ群・呼び方・絵。
  この素体に入っていないアバターだけ。扱わない物は出さない）。選ぶと `UiCommand.SetAvatarBase`。**ほかの素体に入っていた物は聞かずに移し、欄の下に「「A」を「B」から移しました。」**（アバターの側で選ぶと聞かずに入るのと揃える）。新しく入っただけなら知らせない。
  行の右クリック「この素体から外す」と、**行の右端の赤い「外す」ボタン**（メモ73-②。基本の操作は右クリックと画面の両方。同じ `RemoveMemberCommand`。`UiCommand.RemoveAvatarFromBase`）：手で決めた所属は `baseName` を空に、**推した仲間は `noBase` を立てる**（1-B。推しは保存しない値なので、人が「違う」と言える印が要る）。
  空にしても名前から同じ素体に推される物は印も立てる。どちらも錠の中で今の所属を見て決め、もうその素体に入っていなければ書かない。素体を選び直すと印を下ろす。
- **足した後は候補の窓を閉じ、欄を空にする**（メモ73-①）：選んで足すと読み直しで候補の元が差し替わり、フォーカスの残った欄の窓が開き直って画面の左上に残った。`SuggestBox` は閉じている窓を、元の差し替えでは開かない（開くのは欄を触ったときだけ。試験 `SuggestBoxSourceTests`）。
- **+Head は体の共通素体**（2026-09-11 に訂正）。`inferClothing`（衣装互換を広げるか）は仕組みとして残すが、実例は無い。画面のチェックは説明が無く何のことか分からないので隠している（2026-09-17）。
- グループの削除だけが取り返しのつかない操作：確認に**何件の商品が書き換わるか**を出す。改名で同名があれば統合（統合は戻らない）。
  **改名・削除は、商品の中で素体の名前を持つ欄を全部書き換える**（洗い出し 2026-11-10・D2。前は対応の宣言 `avatarBases` だけで、改名すると変換経由が黙って効かなくなった）：
  対応の宣言・バリエーションの対応（外した物も）・名前から見つけた対応・変換のつなぎ先・新しい版の向き先。どの欄かは `LocalReferences` の表（欄を足して表に載せないと試験が落ちる）。確認の数も同じ表で数える。
  削除では名前を消し、向き先が無くなったバリエーションの行と変換のつなぎ先の行は消す。**新しい版の向き先だけは、消すと空（全部向け）になるときは残す**（消えた素体だけ向けの更新が、どのアバターにも促す更新に変わるため）。
  統合で変換のつなぎ先が重なったときに残す行は `conversion.md`「統合で重なった行」（人が選んだ行が、外した行・推した行に勝つ）。
  商品の対応素体の欄（`avatarBases`）で同じ名前が2つになったときも同じ決め方で1行を残す（確かめた行＞外した行＞検出の行、同じなら統合先の行。Codex の点検 2026-11-13 の範囲の外で見つけた物・ユーザ判断「その形で進めましょう」。前は配列の先頭を残していた）。
  **統合になる改名は押す前に聞く**（ユーザ判断 2026-09-29。前は確認なしで統合された）：統合先・所属のアバターと宣言している商品の数・元に戻せないことを書いた窓（OKCancel・既定はキャンセル）。
  見分けは `AvatarBaseRename.MergeTarget`（Core の改名と同じく大文字小文字と前後の空白を見ない。大文字小文字だけの変更は統合ではない）。ただの名前の変更は戻せるので聞かない（タグの管理と同じ作法）。
- **消したグループは行を残して `rejected` の印を立てる**（ユーザ判断 2026-09-21・X1）。行ごと消すと、初期辞書が足し直し、検出が作り直すので次の検出で丸ごと戻っていた。
  **消したグループと同じ名前への改名は統合にしない**（ユーザ判断 2026-09-29）：消した行を片付けて名前を引き継ぐ。前は一覧に出ない行へ吸い込まれ、改名した素体が消えたように見えた。
  印の付いたグループは一覧にも照合にも出さない。同じ名前を手で付け直したら印を下ろす（別名の消し方と同じ作法）。
- **手で足す**（ユーザ判断 2026-09-28）：「共通素体」の一覧の上に欄と「追加」を置き、アバターを選ばずに素体だけを足せる（`UiCommand.AddBase`）。
  **素体の名前の候補は付けない**（メモ9-⑥ 2026-10-02。「入力欄には候補を付ける」の例外・`ui-input.md`）：新しい素体を名付ける欄なので、今ある名前を並べても重複を誘うだけだった。
  ［実装 2026-11-20・ユーザ判断⑤］欄は下の**探す欄と1本**（タグの管理の小分類の欄と同じ形。案内「素体・アバターを探す、または素体を追加」・右に「追加」）。
  候補は**素体に入ったアバターの名前**（探すための物。素体の名前の候補ではないので上の例外とぶつからない。所持アバター／未所持アバターの見出し・絵・呼び方は、素体の詳細のアバターを足す欄と同じ作り。［実装 2026-11-20・ユーザ判断⑤］同じ名前でもアバター（ID）が違えば分けて出す。欄は候補を字で引くので、重なる名前にはショップ名を添え（名前に付いていなければ）、それでも重なれば「（ID 123）」を添える）。
  Enter：アバターの候補を決めたら絞るだけ（書かない）。絞るのは**選んだアバターの ID が入った素体だけ**（同じ名前の別のアバターの素体は出さない。行には「アバター「A」」）で、欄の字が選んだ候補のままの間だけ続き、打ち直すと名前で当てる絞りに戻る、ほかの語は素体として足す。候補が開いている間の Enter は選ばれている候補（最初の行）を決めるので、アバターの名前を含む新しい名前は「追加」で足す（「追加」はいつも打った語を足す）。
  打ってすぐの Enter・「追加」は結び付けの待ち（200ms）を先に流し込む（`SearchAddBox` と同じ）。足せたら欄を空ける。一覧にある名前（大文字小文字の違いは同じ）なら書かずに「共通素体「…」は既にあります。」と言い、その素体を開く。消した素体と同じ名前なら戻す。
  **手で足した素体は `isManual: true` を持ち、検出し直しでは消さない**（検出は最新の登録簿の素体を残し、新しく見つけた物だけを足す）。消えるのは人が削除したときだけ（削除は上と同じく消した印）。
  アバターの詳細で新しい名前を打って作った素体・消した素体を付け直した物も手で足した物。既にある素体に後から印は立てない。欄が無ければ手で足していないと読む。
  足した素体は照合にも使うので、次の検出で商品の説明・タグに名前があれば商品の対応素体に入る。
- **探す欄**（2026-11-20・ユーザ「共通素体の画面にもアバター検索は付けましょう。」）：「共通素体」の一覧の上の、足す欄と1本の欄（上の「手で足す」）。
  ［実装 2026-11-20・ユーザ判断⑤］**当てるのは素体の名前**（大文字小文字は区別しない）**と、素体に入ったアバター**（「アバター」の見方の探す欄と同じ照らし：名前・商品ID・BOOTHでの正式名・呼び方。仲間は素体の人数と同じ数え方で、名前から推した仲間を含む）。
  名前で当たらずアバターで当たった行には、何で当たったかを添える（「アバター「A」」、2体以上なら「アバター「A」ほか n 体」。「アバター」の見方の行の呼び方の札と同じ色）。前は名前だけで、アバターで当てると行になぜ残ったかが出ないので当てなかった。
  絞るのは一覧に出す物だけで、切り替えの「共通素体（n）」・足す時の「既にあります」・改名の統合先・組の端へ移れるかは全部の素体で見る。選んでいた素体が当たらなくなったら当たる最初の素体を選び（「アバター」の見方と同じ）、0件なら「打ち込んだ言葉に当てはまる共通素体がありません。」と「絞り込みを消す」。絞りで外れた素体へ移る時（組の端・足した素体・戻る）は、そのときだけ絞りを外す
- 素体名（`+Head` `まめふれんず` `珍飯亭共通素体` など）は初期辞書として少数同梱。外部サイトの整理済みリストは取り込まない（他者の労力）。
- **素体そのものの商品の候補**（2026-09-17）：`itemId` が無い素体に、登録簿のうち名前に素体名（か消していない別名）を含み、3Dキャラクターではない商品を最大3件「素体の商品に設定」付きで出す（`AvatarBaseItemFinder`）。**自動では結ばない**（推定は候補として出し、押したら入る）。友人のデータでは11の素体のうち3つに1件ずつ出た。

## 共通素体の画像（ユーザ判断 2026-11-20・152 の案A）

配布されていない素体には商品の絵が無く、一覧で見分けられなかった。素体に画像を1枚付けられる。

- **持ち方**：グループの `image` にファイル名だけを書き、中身は `images/_bases/` に中身のハッシュの名前（`user-xxxxxxxx.webp`。商品に自分で足した画像と同じ名付け・同じ圧縮）で置く。
  素体は名前がキーで改名・統合で名前が変わるので、素体ごとのフォルダにせず平らに置く。同じ絵を2つの素体に付けると1つのファイルを分け合う。
  名前が `user-` で始まるので、「画像は入れない」の書き出しにも入る（BOOTH に無い絵）。引越し・書き出し・すべてを戻すは保存先の木ごとなので入る（試験 `BackupArchiveTests`・`StoreMoverTests`）。
- **表示**：付けた画像 → 素体の商品（`itemId`）の1枚目（持っていれば商品のサムネイル、無ければ控えの1枚）→ 頭の字。決め方は `AvatarBaseImage.IconPath` 1つ。
- **画面**：アバターの管理の共通素体の一覧の行の頭（アバターの行と同じ大きさ）と、素体の詳細の左（112）に出す。絵の下に「画像を設定…」（付けていれば「画像を変更…」）と、付けた画像があるときだけ赤い「画像を外す」。外すのに確かめの窓は出さない（選んだ元のファイルは手元に残る）。知らせは絵の下。右の欄が狭い（窓の幅 900 など）と絵を名前の上に置く（場面 `avatars-base-image`・幅 900 も撮る）。［実装 2026-11-20・ユーザ判断①］一覧の行の絵と詳細の絵、素体の探す欄・アバターの詳細の共通素体の欄・アバターを足す欄の候補の絵に乗せると、大きな絵（180）を出す（絵が無ければ出さない・`avatars.md`「左の一覧」）。
  素体を選ぶ・探す欄の候補の頭にも同じ絵を出す（open.md 73 行・ユーザ指示 2026-11-18「商品画面の対応アバターの追加を参考に」）：商品ページの「対応アバターを追加」・検索の条件「対応アバター」「プロファイル」・アバターの詳細の「共通素体」・変換のつなぎ先を選ぶ欄。
  商品ページの共通素体の札と変換のつなぎ先の札は、乗せたときに絵を出す（対応アバターの札と同じ 160。絵が無ければ吹き出しを出さない）。
  名前しか持たない所は `AvatarBaseIcons`（名前 → 消していないグループ → `IconPath`）を通し、登録簿は絵を引くその時の物を読む。グループの無い素体名（アバターの記録だけにある物）は頭の字。
  変換のつなぎ先の札は、前は素体の商品が無いと仲間のアバターの1体目の絵を出していたが、決め方を1つにするため出さなくした
- **命令**：`UiCommand.SetBaseImage`（付ける・差し替える）と `UiCommand.RemoveBaseImage`（外す）。ファイルを先に保存し、錠の中で素体がまだ在れば書く。無ければ書かずに保存した分を片付ける。
- **改名・統合・削除**：改名は画像ごと引き継ぐ。統合は統合先に画像が無ければ統合元の画像を引き継ぎ、両方にあれば統合先の画像を残す（統合元の絵は片付ける）。
  削除は画像を外して片付ける（消した行は一覧に出ないので見る所が無い。同じ名前で足し直しても画像は戻らない）。
- **片付け**：外す・差し替える・統合・削除で行き場の無くなったファイルは、書いた後の最新の登録簿で、どの素体（消した印の行も）も指していない物だけ消す。
  手で直した登録簿の名前は、ファイル名だけで `user-` で始まる物しか使わない（置き場の外を指させない）。古い版が登録簿を保存すると欄が消え、ファイルだけが残る（掃除する所は無い）。

## 相性（検索で使う）

1. **直接対応** … 商品がそのアバターを名指し
2. **素体経由** … 同じ素体グループ（素体を名指し／同じ素体の別アバターを名指し）。**素体の兄弟は対応として数える**（「共通素体はその為の概念なので」）
   素体の一員に数えるのは、アバターでないと分かっている物（「アバターとして扱わない」にした物・カテゴリが分かっていてアバターと判定されない物）を除いた記録（2026-10-03）。手で付けた素体名は扱いを変えても残り、アバターに戻せばまた一員になる
3. **未確認** … それ以外。**「非対応」とは呼ばない**（対応情報が無いのと、合わないと確かめたのは別）

既定は 1＋2。3 は「対応が確認できていないものも含める」で広げる。相性は保存しない。

## 商品ページの素体経由の札と、素体ごとのまとめ（2026-11-04・ユーザ指示）

検索では素体経由で当たるのに、商品ページには書かれていない食い違いを埋める。編集画面も同じ部品（`ItemAvatarsPanel`）。

- **素体経由の札**（設定「共通素体経由の対応アバターも表示する」・既定でオン・`ShowAvatarsViaBase`）：上の相性の 2 を、記録した対応の札と同じ欄に**点線の枠**で並べる（推定を確定と同じ顔で出さない）。
  計算は検索と同じ `AvatarCompatibilityIndex.Resolve`（名簿ごとに使い回す `For`）。保存しない。
  除く物：この商品の記録にあるアバター（**消したアバター**は素体の兄弟として計算に戻ってくるが、人が消した物を出し直さない・説明文のリンクの確認待ちは札がもうある）と、この商品そのもの。
  札は押すと開くだけ（外す・確認済みにするは無い）。吹き出しは「共通素体「A」経由です。押すとこのアバターを開きます」。
  見出しの件数は「（n 体・素体経由 m 体）」（変換経由があれば n の後に「+k」。`conversion.md`）、欄の説明に「点線は共通素体経由です。」を足す。
- **素体ごとのまとめ**（設定「対応アバターを共通素体ごとにまとめる」・既定でオン・`GroupAvatarsByBase`）：段は分けず、札の並びの中に素体の名前の見出しを差し込む（ユーザ判断「行まで分ける必要はないが、どの素体か分かるように」）。
  見出しは左に色の縦線・素体の名前を太字で、「共通素体」の語は付けない（素体の無いまとまりだけ「共通素体なし」）。前の「共通素体「A」」は灰色の字だけで札に埋もれ、下の共通素体の札「A 共通素体」と形が混ざっていた（ユーザ指示 2026-11-04）。
  見出しは次の札と同じ行に置く（`KeepWithNextWrapPanel`。行の末尾に見出しだけが残らない）。
  順は 持っているアバターを含む素体 → ほかの素体（名前の順）→「共通素体なし」。素体が1つも無い商品には見出しを出さない（全部の商品に「共通素体なし」が付くため）。
  見出しは数えない札（`ChipGroupLabel`・`ChipStrip.IsCounted`）で、「残り n 体」と最初の 40 体に数えない。まとまりの札が1枚も並んでいなければ（絞り込み・40 体で切った後）見出しも出さない。
  まとめないときは 記録した対応（持っている物が先・出品者の並び）→ 素体経由（持っている物が先→名前の順）。
- **素体の中の順**：人が並べた順（`AvatarBaseGroup.memberOrder`・商品IDの並び。並べていなければ書き出さない）→ 並べた後に入った・並べていない仲間を 持っている物が先→名前の順で後ろ。
  並べる関数は `AvatarBaseOrder.Arrange` 1つで、商品ページ・素体の詳細・検索の候補が使う（場所ごとに並べ方を持たない）。
  今は一員でない ID が残っていても無視する（外して入れ直したら元の位置に戻る）。命令は `UiCommand.SetBaseMemberOrder`（null で並べていない状態に戻す）。
- **並べる所**：アバターの管理の素体の詳細の「この素体を使っているアバター」。行の頭のつまみ（タグ・属性の管理と同じ `ReorderGrip`・`RowReorder`）でドラッグし、落とした時点で見えている全員の並びを書く（一覧は先に動かす）。
  並べた素体だけ一覧の上に「既定の順に戻す」を出す（ユーザ判断。手で崩した順を戻す道）。並べた順は商品ページの札と検索の対応アバターの候補が使うので、書いた後に候補を作り直す。
- **検索の対応アバターの候補**（設定「対応アバターを共通素体ごとにまとめる」のとき）：所持・未所持の群の中で、同じ素体の仲間を名前の順で最初の仲間の位置に寄せ、素体の中は上の並び（素体の無いアバターの名前の並びは崩さない）。改変の窓などほかの候補は名前の順のまま。
