# 共通素体と素体経由の対応（今の決め事）

[avatars.md](avatars.md) から分けた（2026-11-04：1ファイル200行の決まり）。アバターそのもの・検出・登録簿は avatars.md。

## 共通素体

- **名前をキーにしたグループ**（配布されていない素体がある）。配布されていれば `itemId` も持つ。ショップでは括れない（同じ作者＝同じ素体ではない）ので、ショップを理由に質問しない。
- 所属は「#MARUBODY」「（えも研素体）」「+Head」のような手掛かりから自動で埋め、手でも足せる。
  推すのは手で決めた所属（`baseName`）が無く、`noBase` が立っていないアバターだけ（`AvatarBaseKeys.InferBaseOf`。推す所はすべてここを通る）。推した所属は保存しない。
- **素体の詳細：足す・外すで一覧を作り直さない／開いたら履歴に積む／行に吹き出しを付けない**（メモ68・ユーザ判断 2026-10-05）：一覧は1つを持ち、足した行・外した行だけを足し引きする（作り直すと乗せた行のホバーが効かなくなる）。行を押してアバターを開くときは、素体の詳細を履歴に積み、戻る（Alt+←）で素体の詳細へ戻る。行の「このアバターを開きます」の吹き出しは付けない。「この素体から外す」は赤（「外す」も赤。`ui-rules.md` V4）。
- **素体の側から足す・外す**（メモ46・ユーザ判断 2026-10-05）：素体の詳細の「この素体を使っているアバター」の上に候補付きの欄（ほかのアバターの候補と同じ群・呼び方・絵。
  この素体に入っていないアバターだけ。扱わない物は出さない）。選ぶと `UiCommand.SetAvatarBase`。**ほかの素体に入っていた物は聞かずに移し、欄の下に「「A」を「B」から移しました。」**（アバターの側で選ぶと聞かずに入るのと揃える）。新しく入っただけなら知らせない。
  行の右クリック「この素体から外す」と、**行の右端の赤い「外す」ボタン**（メモ73-②。基本の操作は右クリックと画面の両方。同じ `RemoveMemberCommand`。`UiCommand.RemoveAvatarFromBase`）：手で決めた所属は `baseName` を空に、**推した仲間は `noBase` を立てる**（1-B。推しは保存しない値なので、人が「違う」と言える印が要る）。
  空にしても名前から同じ素体に推される物は印も立てる。どちらも錠の中で今の所属を見て決め、もうその素体に入っていなければ書かない。素体を選び直すと印を下ろす。
- **足した後は候補の窓を閉じ、欄を空にする**（メモ73-①）：選んで足すと読み直しで候補の元が差し替わり、フォーカスの残った欄の窓が開き直って画面の左上に残った。`SuggestBox` は閉じている窓を、元の差し替えでは開かない（開くのは欄を触ったときだけ。試験 `SuggestBoxSourceTests`）。
- **+Head は体の共通素体**（2026-09-11 に訂正）。`inferClothing`（衣装互換を広げるか）は仕組みとして残すが、実例は無い。画面のチェックは説明が無く何のことか分からないので隠している（2026-09-17）。
- グループの削除だけが取り返しのつかない操作：確認に**何件の商品が書き換わるか**を出す。改名で同名があれば統合（統合は戻らない）。
  **統合になる改名は押す前に聞く**（ユーザ判断 2026-09-29。前は確認なしで統合された）：統合先・所属のアバターと宣言している商品の数・元に戻せないことを書いた窓（OKCancel・既定はキャンセル）。
  見分けは `AvatarBaseRename.MergeTarget`（Core の改名と同じく大文字小文字と前後の空白を見ない。大文字小文字だけの変更は統合ではない）。ただの名前の変更は戻せるので聞かない（タグの管理と同じ作法）。
- **消したグループは行を残して `rejected` の印を立てる**（ユーザ判断 2026-09-21・X1）。行ごと消すと、初期辞書が足し直し、検出が作り直すので次の検出で丸ごと戻っていた。
  **消したグループと同じ名前への改名は統合にしない**（ユーザ判断 2026-09-29）：消した行を片付けて名前を引き継ぐ。前は一覧に出ない行へ吸い込まれ、改名した素体が消えたように見えた。
  印の付いたグループは一覧にも照合にも出さない。同じ名前を手で付け直したら印を下ろす（別名の消し方と同じ作法）。
- **手で足す**（ユーザ判断 2026-09-28）：「共通素体」の一覧の上に欄と「追加」を置き、アバターを選ばずに素体だけを足せる（`UiCommand.AddBase`）。
  **欄に候補は付けない**（メモ9-⑥ 2026-10-02。「入力欄には候補を付ける」の例外・`ui-input.md`）：新しい素体を名付ける欄なので、今ある名前を並べても重複を誘うだけだった。
  Enter か「追加」で足す。一覧にある名前（大文字小文字の違いは同じ）なら書かずに「共通素体「…」は既にあります。」と言い、その素体を開く。消した素体と同じ名前なら戻す。
  **手で足した素体は `isManual: true` を持ち、検出し直しでは消さない**（検出は最新の登録簿の素体を残し、新しく見つけた物だけを足す）。消えるのは人が削除したときだけ（削除は上と同じく消した印）。
  アバターの詳細で新しい名前を打って作った素体・消した素体を付け直した物も手で足した物。既にある素体に後から印は立てない。欄が無ければ手で足していないと読む。
  足した素体は照合にも使うので、次の検出で商品の説明・タグに名前があれば商品の対応素体に入る。
- 素体名（`+Head` `まめふれんず` `珍飯亭共通素体` など）は初期辞書として少数同梱。外部サイトの整理済みリストは取り込まない（他者の労力）。
- **素体そのものの商品の候補**（2026-09-17）：`itemId` が無い素体に、登録簿のうち名前に素体名（か消していない別名）を含み、3Dキャラクターではない商品を最大3件「素体の商品に設定」付きで出す（`AvatarBaseItemFinder`）。**自動では結ばない**（推定は候補として出し、押したら入る）。友人のデータでは11の素体のうち3つに1件ずつ出た。

## 相性（検索で使う）

1. **直接対応** … 商品がそのアバターを名指し
2. **素体経由** … 同じ素体グループ（素体を名指し／同じ素体の別アバターを名指し）。**素体の兄弟は対応として数える**（「共通素体はその為の概念なので」）
   素体の一員に数えるのは、アバターでないと分かっている物（「アバターとして扱わない」にした物・カテゴリが分かっていてアバターと判定されない物）を除いた記録（2026-10-03）。手で付けた素体名は扱いを変えても残り、アバターに戻せばまた一員になる
3. **未確認** … それ以外。**「非対応」とは呼ばない**（対応情報が無いのと、合わないと確かめたのは別）

既定は 1＋2。3 は「対応が確認できていないものも含める」で広げる。相性は保存しない。

## 商品ページの素体経由の札と、素体ごとのまとめ（2026-11-04・ユーザ指示）

検索では素体経由で当たるのに、商品ページには書かれていない食い違いを埋める。編集画面も同じ部品（`ItemAvatarsPanel`）。

- **素体経由の札**（設定「共通素体経由の対応アバターも表示する」・既定でオン・`ShowAvatarsViaBase`）：上の相性の 2 を、記録した対応の札と同じ欄に**点線の枠**で並べる（推定を確定と同じ顔で出さない）。
  計算は検索と同じ `AvatarCompatibilityIndex.Resolve`（名簿ごとに使い回す `For`）。保存しない。
  除く物：この商品の記録にあるアバター（**消したアバター**は素体の兄弟として計算に戻ってくるが、人が消した物を出し直さない・説明文のリンクの確認待ちは札がもうある）と、この商品そのもの。
  札は押すと開くだけ（外す・確認済みにするは無い）。吹き出しは「共通素体「A」経由です。押すとこのアバターを開きます」。
  見出しの件数は「（n 体・素体経由 m 体）」、欄の説明に「点線は共通素体経由です。」を足す。
- **素体ごとのまとめ**（設定「対応アバターを共通素体ごとにまとめる」・既定でオン・`GroupAvatarsByBase`）：段は分けず、札の並びの中に見出し「共通素体「A」」を差し込む（ユーザ判断「行まで分ける必要はないが、どの素体か分かるように」）。
  順は 持っているアバターを含む素体 → ほかの素体（名前の順）→「共通素体なし」。素体が1つも無い商品には見出しを出さない（全部の商品に「共通素体なし」が付くため）。
  見出しは数えない札（`ChipGroupLabel`・`ChipStrip.IsCounted`）で、「残り n 体」と最初の 40 体に数えない。まとまりの札が1枚も並んでいなければ（絞り込み・40 体で切った後）見出しも出さない。
  まとめないときは 記録した対応（持っている物が先・出品者の並び）→ 素体経由（持っている物が先→名前の順）。
- **素体の中の順**：人が並べた順（`AvatarBaseGroup.memberOrder`・商品IDの並び。並べていなければ書き出さない）→ 並べた後に入った・並べていない仲間を 持っている物が先→名前の順で後ろ。
  並べる関数は `AvatarBaseOrder.Arrange` 1つで、商品ページ・素体の詳細・検索の候補が使う（場所ごとに並べ方を持たない）。
  今は一員でない ID が残っていても無視する（外して入れ直したら元の位置に戻る）。命令は `UiCommand.SetBaseMemberOrder`（null で並べていない状態に戻す）。
- **並べる所**：アバターの管理の素体の詳細の「この素体を使っているアバター」。行の頭のつまみ（タグ・属性の管理と同じ `ReorderGrip`・`RowReorder`）でドラッグし、落とした時点で見えている全員の並びを書く（一覧は先に動かす）。
  並べた素体だけ一覧の上に「既定の順に戻す」を出す（ユーザ判断。手で崩した順を戻す道）。並べた順は商品ページの札と検索の対応アバターの候補が使うので、書いた後に候補を作り直す。
