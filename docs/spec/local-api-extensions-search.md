# 拡張データの検索とメモリ [採用]

> **要点**：ほかのソフトの欄は、宣言で `search: true` を付けた物だけをメモリに持ち、検索の条件にする。条件は「＋ 条件を追加」に欄ごとに並べ、今の部品（範囲・日付・候補から積む・三項）を型から当てはめる。
> 段階：[採用]（2026-11-27・ユーザ判断「OKです。それらのできないことは仕様とします」）。まだ作っていない。拡張データの全体は [local-api-extensions.md](local-api-extensions.md)、今の検索の条件は [search-filters.md](search-filters.md)。

## なぜ

ユーザの言葉（2026-11-27）：「メモリ削減案。検索条件に不要なものを宣言時に指定してもらい、検索に必要なもののみをメモリに置く仕組み。検索条件モジュールへの発展を議論しよう。」

検索と件数は、打つたびに全部の商品で数え直す（`SearchFilterPass`）ので、照らす値はメモリに要る。照らさない値まで持つと、件数とソフトの数に比例してメモリが増える。

## メモリに持つ欄 [決定]

- 欄の宣言に `search: true` を付けた欄だけを、API の写し（`QuerySnapshot`）と画面の検索に持つ。検索の条件・件数に使えるのはこの欄だけ。
- **既定は持たない**（付けない）。既定を持つ側にすると、検索を考えていないソフトの値が全部メモリに乗り、メモリを守るかが作り手の気遣いに任される。付け忘れても軽い側に倒れる。
  ユーザの案（要らない物に印を付ける）から向きだけ変えた。
- 付けない欄はファイルに置いたまま。読むのは商品ページを開いた時・1件の GET・`batch` の時だけ。メモ欄はいつも持たない。
- 一覧・検索の答えの `include=extensions` には、メモリにある欄だけを入れる（200件の答えのために200個のファイルを読まない）。全部の欄は1件の GET か `batch` で。
- `search` の付け外しは宣言の変更として受ける（値の意味は変わらない）。付けたら全件を読み込み、外したらメモリから捨てる。
- 上限は `search` を付けた欄と付けない欄で分ける（メモリに乗る前の方を小さく）。数は [local-api-extensions.md](local-api-extensions.md)「上限」の計測で一緒に決める。

## 検索の条件 [決定]

- 「＋ 条件を追加」に見出し「ほかのソフトの情報」を足し、その下にソフトごとのまとまりで欄を並べる（例「試着チェッカー：ポリゴン数」）。
  前に決めた「ソフト → 欄 と選ぶ」から、今の条件と同じ1段で選ぶ形に変えた。
- 型から部品を当てはめる：

  | 欄の型 | 条件の部品 | 今の似た条件 |
  |---|---|---|
  | 数 | 範囲（スライダ2本と分布の帯） | 価格・スキ数 |
  | 日付 | 日付（始まり・終わり） | 公開日 |
  | 真偽 | 三項（はい・いいえ・両方） | お気に入り |
  | 選択肢 | 候補から積む（件数つき・AND／OR） | カテゴリ |
  | 文字の一覧 | 候補から積む | BOOTH タグ |
  | `avatarList` | 候補から積む（アバターの名前） | 対応アバター |
  | 文字・URL | 「含む」の欄（新しい小さな部品） | — |
  | 表 | 後回し（「どれかの行が合う」の形を使い道が出たら決める） | — |

- 複数置く・除く・件数・保存した検索・履歴は、今の決まりにそのまま乗る。API の条件の種類 `extension` も同じ判定（Core の `SearchModuleConditions`）を使う。
- 宣言に足す物：
  - **選択肢の型**：値と表示名の並びを宣言する（決まっていれば件数を数えて候補から積める）
  - 数の型に `unit`・`min`・`max`（単位と範囲の目安。スライダの端と表示に使う）
- 保存した検索・画面の状態には名前空間と欄の名前を持たせる。条件の種類は文字列（`SearchModuleState.Kind`）なので形式の版は上げない見込み。古い版がこの条件をどう扱うかは作る時に確かめる [要確認]。
- 欄やソフトが無くなった条件は当たらないとし、「この条件の欄はありません」と出す（[local-api-extensions.md](local-api-extensions.md)「付け先の変化・守り・ほかの口」）。

## 仕様として出来ない事 [決定]

ユーザ判断 2026-11-27「それらのできないことは仕様とします」。

- **ソフトがその場で当たり外れを返す条件**（例：「今の Unity プロジェクトに合う物」をソフトに聞く）。件数は打つたびに全部の商品で数え直すので、毎回聞くと遅く、ソフトが止まると検索が止まる。Chmonos から外へつながない決まり（[plugins.md](plugins.md)）とも合わない。
  代わりに、ソフトが前もって計算して欄に書けば条件にできる（例：真偽の欄「今のプロジェクトに合う」）。
- **ソフトが条件の部品（見た目・照らし方）を持ち込む**：部品は Chmonos が型から決める。
- `search` を付けていない欄での検索・件数。
- 表の欄での検索（後回し）。
