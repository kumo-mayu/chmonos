# データの形と書き方（今の決め事）

> **要点**：保存するものは全部、人が開いて読めて直せる JSON。商品は1商品1ファイルで `booth`（取ってきた物）と `local`（人と取り込みが決めた物）に分ける。
> 書くときは「自分が持つ項目」だけを、読み直した最新に重ねる。計算で出せる値は書かない。配った版（v1.0.0〜）の形は、形式の版と移し替えで読む。それより前の形には合わせない。書き方の決まり（持ち主・錠・手で直した JSON・やりかけの記録）は [data-writing.md](data-writing.md)。
>
> **コード**：`Core/Models/`（`ItemRecord`・`LocalBlock`・`LocalFields.cs`・`AppSettings`・`UiState`）、`Core/Storage/`（`DataStore`・`ItemRepository`・`JsonStore`・`AppPaths`）
>
> **経緯**：`docs/history/grill-2-ui-and-data-model.md`（ファイル構成・item・LocalFile）、`docs/history/import-concurrency.md` §2（持ち主）、`docs/history/tech-debt-2026-09-14.md` 1-1〜1-5・3-2

## 商品（item）

- **1商品1ファイル**。全件を1ファイルにまとめない（壊れたときの被害・差分・手で直す）。
- **読んだ商品は `ItemRepository` が写しで持ち、ファイルの大きさと更新日時が同じ間は読み直さない**（2026-09-24）。全件の読み込みは約40か所から呼ばれ、2000件で1回0.3〜0.7秒・45MB を毎回払っていた（2回目から 3〜13ms・1.4MB）。
  返す `ItemRecord` は書き換えられない形なので、画面どうし・裏の作業で共有してよい。このアプリの書き込みは書き終えた直後から入り、手で直した物は日時か大きさが変わるので読み直す。
  画面は全件を抱えて差分を自分で追わず、要るたびに `LoadAllAsync` を呼べばよい。登録簿・ユーザータグ・属性も `JsonFileStore` が同じように読んだ物を共有する（一覧の入れ物は共有しない）。
- **`booth` と `local` を分ける**。再取得は `booth` を差し替えるだけで、人の入力を壊しようがない。
- **説明は2つに分ける**：JSON には検索・差分用の `h2Sections`（見出しと本文のテキスト）、表示用の HTML は別ファイル。
- **購入記録（`Purchases`）は自立した記録**：種類のID・買ったときの名前・価格・ギフトかどうか。BOOTH から種類が消えても消さず、`ExistsOnBooth=false` にする（支出には数える）。
  `ExistsOnBooth` は書く側が毎回 `Booth.Variations` から計算し直す（編集画面と再取得が同じ式で書くので食い違わない）。
- **価格とギフトは種類ごと**。商品の購入額はその合計。
- **バリエーションの向き先**（v1.3.0・`docs/spec/conversion.md`）：人が決めた `variationTargets` と、検出が書く `detectedVariationTargets`。1行は `variationId`（null＝バリエーションを選ばない購入。null でも欄を書き、欄が無い行も null と読む：11-07〜11-27 の開発版は欄を書かず、必須にしていたため商品の記録が読めなかった）・`avatars`（商品 ID）・`bases`（共通素体の名前）・`all`（対応アバター全部向け。立っていなければ書かない）・`rejectedAvatars`・`rejectedBases`（人が外した、名前から見つけた物。無ければ書かない）。同じバリエーションに両方あれば人が決めた方を使う。持っているバリエーションの分の見分けは保存せず、その場で計算する（`AvatarCompatibilityIndex.UnownedVariationAvatars`）。中身の更新の控え `contentUpdate` は `used-updates.md`
- **購入記録ごとの日付**（`purchasedAt`・`DateOnly?`。空なら書かない。メモ45・ユーザ判断 2026-10-05）。空のときは商品の日付（入手日）を使い、**空を推定で埋めない**。
  決まりは Core の `PurchaseDates` 1か所：購入1件の日付＝欄があればそれ・無ければ商品の日付（場面によって、入手日が空ならファイルの日付で代える／代えない）。
  商品を1つの日付で並べる場面の**代表の日付＝購入1件の日付のうち最も早い物**（購入記録が無ければ商品の日付。入手日は「最初に手に入れた日」の意味で使ってきた）。

  | 場面 | 見る日付 |
  |---|---|
  | 統計：月ごと・年ごとの支出 | **購入1件ごと**にその購入の日付（代える）の月へその額。贈った分は自分用の支出に入れないので月も決めない。月の商品の数は同じ月に2回買っても1件 |
  | 統計：日付の分からない支出・「ファイルの日付で代えた」の数 | 額は購入1件ごと、数は商品。買った日を入れた購入は、入手日が空でもファイルの日付を使わない |
  | 統計：月ごとのカテゴリ構成 | 代表の日付（代える）の月に1回 |
  | 統計：期間で変わる欄（open.md 104） | 自分用・貰った購入の日付（代える）が期間に1件でもある商品を、その購入だけに削って数える。そういう購入が無い商品は商品の日付（代える）。贈った分は贈った購入の日付で、所持していない商品も数える。日付の分からない商品は全期間にだけ入る（`StatsPeriods`） |
  | 検索の並べ替え「入手日」・区切りの札・2つ目の鍵 | 代表の日付（代えない） |
  | 検索の条件「入手日」 | 既定は**最初の購入の日付**で見る。「すべての購入」を選んだときは、**どれか1件の日付が範囲に入れば当たる**（`search-filters.md`。代えない） |
  | ショップの商品の入手日／最後に買った日 | 代表の日付（代える）／購入1件の日付の最も遅い物（代える） |
  | 商品ページの入手日・編集の「未入力」 | 商品の入手日のまま（購入の日付は任意の欄で、未入力に数えない） |
- BOOTH に無い商品は仮ID（`local-…`。ファイルから作ればハッシュの先頭8桁、名前だけで作れば乱数12桁）で作る（`docs/spec/private-items.md`）。

## 手元のファイル（`LocalFiles`）

- **同一性はハッシュ**。1件が `paths[]` を持つ（同じ zip が2か所なら1件に2パス。移したらパスが差し替わる。版違いは別の件）。
- **外した印 `Detached`**：「この商品のものではない」と外した行は消さずに残す（次の取り込みで同じ商品へ戻らないようにするため）。所持には数えない。
- **容量は2つ**：商品ページは論理値（重複を1回）、統計のディスク使用量は実占有（重複コピーも数える。内訳に1行）。
  実占有は在る場所だけを数え、場所が空・`missingSince` の付いた記録・無いと見たフォルダは0（2026-10-05・ユーザ判断 7-A。`ItemRecord.ActualDiskBytes`）。商品の容量は見つからなくても数える。1つのファイルは2つ以上の商品に付けられ、商品をまたいだ合計は同じ中身・同じ場所を1回だけ数える（`LibrarySizes`・[shared-files.md](shared-files.md)）。
- **開けなかった印 `archiveBroken`**（ユーザ判断 2026-09-30）：取り込みで zip として開けなかった事実。未確定の記録（`unresolved.json`）の同じ欄を、商品に結び付いた後も持つ。
  開いてみないと分からないので記録に書く。壊れていない物には書き出さない。古い記録に合わせる救済は無く、取り込み直すと付く（`docs/spec/import.md`）。
- **場所の無い記録は残す**：移した・消した・同じ名前で上書きされた（ユーザ判断 2026-09-30）物は、`paths` が空のまま残り、商品ページで「見つかりません」になる。
  ただし上書きで場所が残らなかった物には**古い版の印 `replaced`**（`{ "path": 置き換わった場所, "at": 日時 }`）を付け、「見つかりません」に数えない（`HasMissingFile`・見回りの日時・「探す」の対象から外す。2026-10-05・点検の8・ユーザ判断 8-A）。
  上書きを見た回にしか分からないので記録に書く。古い版の中身をまた取り込んで場所が付いたら印を消す。商品ページの「古い版の記録を片付ける」で行ごと消せる。
  古い版は**所持・容量にも数えない**（`OwnedFiles`・`HasOwnedFiles` から外す。古い版だけの商品は未所持。ユーザ判断 2026-10-05 ⑤-B）。行は商品ページに残る（行の一覧は `LocalFiles`）。
  同じ場所に別の中身が来たら、古い中身の記録からその場所を外す（取り込みがその場所のハッシュを取ったときだけ。`docs/spec/import.md`）。記録ごと落とすのは、落とし直された壊れた zip だけ。
- **見つからなくなった日時 `missingSince`**（ユーザ判断 2026-10-04）：記録のどの場所にも無いと見た日時。また見つかったら消す。無い間は最初に見た日時のまま。無ければ書き出さない。
  書くのは、取り込みのたびに記録の場所を全部見たとき（`import.md`）・起動時の裏の見回り（`MissingMarksSweep`）・「見つからないファイルを探す」で見つからなかったとき（`MissingFileFinder`）・使おうとして無い・在ると分かったとき（商品ページ・開く・展開・Unityへ送る。`item-page.md`）（2026-10-05）。
  どれも `FileMissingMarks` の1つの決まり。外したファイルにも書く。
  つながっていないドライブ（控えた文字に別のディスクが来ている場合を含む）・権限が無く確かめられない場所にしか無ければ書かない。場所が複数あれば、どれか1つ在れば見つかっている。**この欄のために場所は外さない**（覚えている場所を黙って消さない）。
  ただし見回りは、同じ中身のほかの場所に在ると確かめたとき、無いと確かめた場所を外す（2026-10-05。`import.md`）。
  前は「無い」が記録に残るのが取り込みが場所を外したときだけで、手で zip を消してもカードの印・検索の条件・統計に出ず、商品ページとだけ食い違っていた。
  場所を外す今の作り（`LocalFileMerger`）はそのまま残し、印・条件・統計（`ItemRecord.HasMissingFile`）は「場所が空」と「日時が付いた」の両方を数える（1ファイルの式は計算の欄 `LocalFileRecord.IsRecordedMissing`。JSON に書かない）。
  「見つからないファイルを探す」は両方を探す（記録の場所がディスクに無い物・場所が空の物）。見つけて結び直したら日時を消す。
  場所の1つでもつながっていないドライブの上にある物は探さず、その場所も外さない（取り込みと同じ判定・2026-10-05）。
  書くのは商品ごとの錠の中で今の値に当て、持ち主は取り込み（`LocalOwners.Import`）と画面（`LocalOwners.FilePresence`）。見たときと場所が変わったファイルには当てない（見ている間に取り込みが結び直した物に、古い答えで「無い」と書かない）。
- **場所ごとのディスクの通し番号 `volumes`**（2026-10-05・ユーザ判断 3-A）：`{ "E:\\Booth\\a.zip": "1234ABCD" }` のように場所 → ボリュームの通し番号。
  2台の外付けが日によって同じ文字を使っても、別のディスクの上の場所を「無い」と見ない・外さない・別のディスクで探さない（`folder-view.md`・`import.md`）。
  場所ごとにするのは、同じ中身を2台に置くと1件の場所がディスクをまたぐため。書くのは在ると確かめたときだけ（取り込みが見つけた場所・見回りや取り込みが在ると見た番号の無い場所）で、
  欄の無い記録はこうして埋まる。番号の分からない場所（ネットワークの共有など）は載らず、今までどおり文字の控え（`volumes.json`）で見る。無ければ書き出さない。
  同じ場所が2台に同じ名前である（丸ごと写した控えのディスク）と、最後に取り込んだ方の番号になる。登録したフォルダは1つの `volume`（同じ決まり）。
- **未確定の記録の `samePathItemIds`**（ユーザ判断 2026-09-30）：同じ場所に前にあった別の中身を持っていた商品のID。候補として見せるだけで、結ぶのは人が選んだとき。
  上書きを見つけた回にしか分からない事実なので記録に書く（計算では出せない）。この欄の無い記録は空として読む（取り込み直しても遡っては付かない）。
- **記録した日時 `registeredAt`**（ユーザ判断 2026-11-10・v1.3.0 から）：その商品のファイルとして行が新しくできた日時（取り込み・未確定から選ぶ・手で足す・落とす）。場所を足す・外す・戻す・ID の付け替えとまとめ（移す元の日時。両方にあれば早い方）では保つ。前からの行は空（分からない）のまま、ファイルの日付で埋めない。画面には出さない（`LocalFileMerger`）。API の商品の答えには `files[].registeredAt`・`folders[].registeredAt` で出す（2026-11-11・plan 32）。ダウンロード元 `downloadSource`（BOOTH のダウンロードの ID・商品ページ）は `id-resolution.md`。
- `unityPackages`：zip の中の unitypackage の入る先の要約（取り込みの裏で1回だけ読む。`docs/spec/unity.md`）。
- フォルダごと登録した商品は `LocalFolders`（中身は記録しない）。取り込みと起動時の裏の見回りがフォルダを「無い」と見たら `missingSince`（見つからなくなった日時）を書き、また見つかったら消す
  （ユーザ判断 2026-10-04。無い間は最初に見た日時のまま。ドライブごと見えないときは書かない。書くのは商品ごとの錠の中で今の値に当てる）。
  フォルダは場所が同一性なのでファイルのように場所を外せず、前は「無い」が記録に残らなかった。カードの印・検索の条件・統計はこの記録だけを見る。所持の定義は変えない。
  移したフォルダは「見つからないファイルを探す」が名前・ファイル数・大きさで候補を見せ、人が選んだときだけ場所を差し替える（2026-10-05・点検 10-A。`missing-search.md`）。

## ショップ

- 商品の `booth.shop`（取得したときの BOOTH の姿）と `local.shop`（人が入れたその商品のショップ）は**商品の記録の一部で、動かさない**。
  ショップの記録を1か所にまとめて商品から鍵で指す形にすると、商品の JSON を開いてもどのショップか読めなくなる（2026-09-16）。
- ショップそのものの記録は持たず、ショップ一覧は商品を鍵で束ねて毎回計算する。**人が付けた星とメモだけを `shops.json` に置く**。
  商品に持たせると同じショップの全商品に写すことになり、直すたびに食い違う。`shop-banners.json`（機械の記録）とは混ぜない。
- 気を付けること（未対応）：BOOTH 側でサブドメインが変わると星とメモが宙に浮く（控えた ID でつなぎ直せる）。
  BOOTH に無いショップの鍵は名前から作るので、名前を直すと記録が付いてこない。

## 参照の持ち方

ユーザータグと属性は**名前**で参照（改名・統合はアプリが全商品を書き換える）。アバターは**BOOTHの商品ID**で参照（実在する安定したキー）。
属性の値（0〜100）は商品の側に持つ。共通素体は登録簿の関係として持ち、商品の対応アバターは出品者の宣言のまま触らない。アバターの所属は登録簿の行の `baseName`（手で決めた素体）。無ければ名前から毎回推し、推した所属は書かない。推した素体に入れないと人が決めたら `noBase: true`（立っているときだけ書く。素体を選び直すと消える。メモ46・`avatar-bases.md`「共通素体」）。 素体の中の並びは素体のグループの `memberOrder`（人が並べたときだけ書く。`avatar-bases.md`）。素体に人が付けた画像は `image`（`images/_bases/` の中のファイル名だけ。付けたときだけ書き、欄が無ければ画像なし。省略できる欄なので形式の版は上げない。`avatar-bases.md`「共通素体の画像」）。

## 属性

商品の属性は3つの状態を持つ：**付いていない**（どちらの欄にも無い）・**付いているが値はまだ**（`local.pendingAttributes`：名前の並び）・**値がある**（`local.attributes`：名前 → 0〜100。0% も値）。
値はまだは選択の帯の「属性を追加…」で足した物（ユーザ判断 2026-11-20・形式の版 3）。`attributes` の意味（値のある物だけ）は変えず別の欄に持つ（値の表に `null` を入れる形は、表を読む約100か所を全部直すことになるので取らない）。
空なら書かない。手で両方に書いた名前は値が勝つ（こちらからは直さない）。足す・値を付ける（値はまだから外れる）・外す（両方から消す）は `Models/ItemAttributes` 1か所。持ち主の項目は `Attributes` 1つで2つの欄を一緒に書く。

| 場所 | 値はまだの扱い |
|---|---|
| 検索の属性の条件（範囲・除く）・並べ替え・カードの札・統計・API の答えの `attributes` と件数・属性の管理の平均 | 値の無い物（未評価）と同じ。どの範囲にも当たらず、並べ替えでは末尾 |
| 検索の「編集状況」の「属性」 | 未入力に数える（値を付けに探せるように） |
| 編集の画面 | 値の行の下に「未評価」の行で出す（既定で並べるだけの行と同じ見た目）。触らずに保存すれば残し、動かすと値へ移り、「外す」で両方から消す（`AttributeRow.IsPendingOnItem`） |
| 商品ページ | 値のある属性（高い順）の後ろに、値はまだを「—」で出す。棒の枠を薄くして、0% の行（枠は普通の濃さで「0」）と見分ける。見出しの件数にも数える（`AttributeBar.Build`） |
| 属性の改名・統合・削除、使われていない属性・参照切れの知らせ | 名前として扱う（付け替える・外す・知らせる）。統合先に値があれば値が残る |
| ID の付け替えでまとめる | 値と値はまだを1組で、移す先に1つでも付いていれば移す先の組 |
| 属性の管理 | 一覧の件数・選んだ属性の「n 件の商品に付いています」・削除の確かめの件数に、値はまだの商品も数える（`AttributeUsage.PendingCount`）。「この属性を持つ商品」の一覧と平均は値のある物だけ。値はまだだけなら削除の確かめで「評価は戻りません」と言わない |
| API の商品の答え | 値はまだの名前を `pendingAttributes` に分けて返す（`attributes` には入れない。持たない商品には欄ごと出さない）。属性の一覧の件数は値のある物だけ |
| API の書き込み | 値を書けば値はまだから外れ、`null` は値はまだも外す |
| 書き出し・引越し・形式の控え | 商品の JSON のまま入る |

## 数え方（全画面で同じ）

- **所持**＝手元のファイルかフォルダを1つ以上持つ（外したファイル・上書きで残った古い版は数えない）。ファイルの無い商品は検索には出る（印なし）が、統計・ショップの件数・支出には入れない。
  答えは `LocalBlock.IsOwned`（`ItemRecord.IsOwned`）1か所で、検索のカード・絞り込み・改変・統計・ショップ・アバターが同じ物を使う（2026-10-05。前は `IsDownloaded` がフォルダを数えず、フォルダだけの商品が検索で「未取得」・改変で「無い」になった）。容量は `OwnedSizeBytes`（ファイル＋登録したフォルダ）。Unity へ送る・中身を読むなどファイルが要る場面は `HasOwnedFiles`（フォルダだけの商品は false）。中身がどの商品のものか（取り込みの結び直し・未確定の均し・ほかの商品が持つか）は古い版も含む `AttachedFiles`。
- **非表示**：検索とショップの件数から外し、統計には入れる（見えなくしたいだけで、持っていないことにはしない）。
- **R-18を表示しない設定**：検索とショップの件数から外し、統計の金額には入れる。通知には出す。
- **所有アバター**＝登録簿のIDが所持している商品に含まれるか（手で「持っている」にもできる）。フラグとしては持たない。
