# データの形と書き方（今の決め事）

> **要点**：保存するものは全部、人が開いて読めて直せる JSON。商品は1商品1ファイルで `booth`（取ってきた物）と `local`（人と取り込みが決めた物）に分ける。
> 書くときは「自分が持つ項目」だけを、読み直した最新に重ねる。計算で出せる値は書かない。公開前なので古い形のデータに合わせる変更はしない。
>
> **コード**：`Core/Models/`（`ItemRecord`・`LocalBlock`・`LocalFields.cs`・`AppSettings`・`UiState`）、`Core/Storage/`（`DataStore`・`ItemRepository`・`JsonStore`・`AppPaths`）
>
> **経緯**：`docs/history/grill-2-ui-and-data-model.md`（ファイル構成・item・LocalFile）、`docs/history/import-concurrency.md` §2（持ち主）、`docs/history/tech-debt-2026-09-14.md` 1-1〜1-5・3-2

## 保存先

既定は `%LOCALAPPDATA%\Chmonos`（2026-09-14 に `BoothAssetManager` から改名。古い名前は読み替えない）。環境変数 `CHMONOS_HOME` ＞ 設定した場所 ＞ 既定（`StoreLocation`）。多重起動はロックファイルで止める。

## 商品（item）

- **1商品1ファイル**。全件を1ファイルにまとめない（壊れたときの被害・差分・手で直す）。
- **読んだ商品は `ItemRepository` が写しで持ち、ファイルの大きさと更新日時が同じ間は読み直さない**（2026-09-24）。全件の読み込みは約40か所から呼ばれ、2000件で1回0.3〜0.7秒・45MB を毎回払っていた（2回目から 3〜13ms・1.4MB）。
  返す `ItemRecord` は書き換えられない形なので、画面どうし・裏の作業で共有してよい。このアプリの書き込みは書き終えた直後から入り、手で直した物は日時か大きさが変わるので読み直す。
  画面は全件を抱えて差分を自分で追わず、要るたびに `LoadAllAsync` を呼べばよい。登録簿・ユーザータグ・属性も `JsonFileStore` が同じように読んだ物を共有する（一覧の入れ物は共有しない）。
- **`booth` と `local` を分ける**。再取得は `booth` を差し替えるだけで、人の入力を壊しようがない。
- **説明は2つに分ける**：JSON には検索・差分用の `h2Sections`（見出しと本文のテキスト）、表示用の HTML は別ファイル。
- **購入記録（`Purchases`）は自立した記録**：種類のID・買ったときの名前・価格・ギフトかどうか。BOOTH から種類が消えても消さず、`ExistsOnBooth=false` にする（支出には数える）。
  `ExistsOnBooth` は書く側が毎回 `Booth.Variations` から計算し直す（編集画面と再取得が同じ式で書くので食い違わない）。
- **価格とギフトは種類ごと**。商品の購入額はその合計。統計の時系列は**入手日**（購入日という欄は作らない。無ければファイルの日付）。
- BOOTH に無い商品は仮ID（`local-…`）で作る（`docs/spec/private-items.md`）。

## 手元のファイル（`LocalFiles`）

- **同一性はハッシュ**。1件が `paths[]` を持つ（同じ zip が2か所なら1件に2パス。移したらパスが差し替わる。版違いは別の件）。
- **外した印 `Detached`**：「この商品のものではない」と外した行は消さずに残す（次の取り込みで同じ商品へ戻らないようにするため）。所持には数えない。
- **容量は2つ**：商品ページは論理値（重複を1回）、統計のディスク使用量は実占有（重複コピーも数える。内訳に1行）。
- **開けなかった印 `archiveBroken`**（ユーザ判断 2026-09-30）：取り込みで zip として開けなかった事実。未確定の記録（`unresolved.json`）の同じ欄を、商品に結び付いた後も持つ。
  開いてみないと分からないので記録に書く。壊れていない物には書き出さない。古い記録に合わせる救済は無く、取り込み直すと付く（`docs/spec/import.md`）。
- **場所の無い記録は残す**：移した・消した・同じ名前で上書きされた（ユーザ判断 2026-09-30）物は、`paths` が空のまま残り、商品ページで「見つかりません」になる。
  同じ場所に別の中身が来たら、古い中身の記録からその場所を外す（取り込みがその場所のハッシュを取ったときだけ。`docs/spec/import.md`）。記録ごと落とすのは、落とし直された壊れた zip だけ。
- **未確定の記録の `samePathItemIds`**（ユーザ判断 2026-09-30）：同じ場所に前にあった別の中身を持っていた商品のID。候補として見せるだけで、結ぶのは人が選んだとき。
  上書きを見つけた回にしか分からない事実なので記録に書く（計算では出せない）。この欄の無い記録は空として読む（取り込み直しても遡っては付かない）。
- `unityPackages`：zip の中の unitypackage の入る先の要約（取り込みの裏で1回だけ読む。`docs/spec/unity.md`）。
- フォルダごと登録した商品は `LocalFolders`（中身は記録しない）。取り込みがフォルダを「無い」と見たら `missingSince`（見つからなくなった日時）を書き、また見つかったら消す
  （ユーザ判断 2026-10-04。無い間は最初に見た日時のまま。ドライブごと見えないときは書かない。書くのは商品ごとの錠の中で今の値に当てる）。
  フォルダは場所が同一性なのでファイルのように場所を外せず、前は「無い」が記録に残らなかった。カードの印・検索の条件・統計はこの記録だけを見る。所持の定義は変えない。

## ショップ

- 商品の `booth.shop`（取得したときの BOOTH の姿）と `local.shop`（人が入れたその商品のショップ）は**商品の記録の一部で、動かさない**。
  ショップの記録を1か所にまとめて商品から鍵で指す形にすると、商品の JSON を開いてもどのショップか読めなくなる（2026-09-16）。
- ショップそのものの記録は持たず、ショップ一覧は商品を鍵で束ねて毎回計算する。**人が付けた星とメモだけを `shops.json` に置く**。
  商品に持たせると同じショップの全商品に写すことになり、直すたびに食い違う。`shop-banners.json`（機械の記録）とは混ぜない。
- 気を付けること（未対応）：BOOTH 側でサブドメインが変わると星とメモが宙に浮く（控えた ID でつなぎ直せる）。
  BOOTH に無いショップの鍵は名前から作るので、名前を直すと記録が付いてこない。

## 参照の持ち方

ユーザータグと属性は**名前**で参照（改名・統合はアプリが全商品を書き換える）。アバターは**BOOTHの商品ID**で参照（実在する安定したキー）。
属性の値（0〜100）は商品の側に持つ。共通素体は登録簿の関係として持ち、商品の対応アバターは出品者の宣言のまま触らない。

## 書き方

1. **商品の `local` は `ItemRepository.SaveLocalAsync(itemId, local, owns)` で書く。**`owns` に名指しした項目だけを、保存の直前に読み直した最新へ重ねる。
   持ち主は `LocalOwners` に宣言（編集画面＝タグ・属性・メモ・購入・入手日など／取り込み＝`LocalFiles` `LocalFolders`／検出＝`Avatars` `AvatarBases` …）。
   `Items.SaveAsync`（丸ごと）は**新しく作るときだけ**。商品番号の付け替えも、既にある先へは `SaveLocalAsync`。
   - **変えていない項目を名乗らない。**名乗った項目は必ず上書きされるので、持ち主が2人いる項目（`Memo` など）で
     相手の書いた値を古い写しで戻す。編集画面は `LocalFields.Changed` で**人が変えた項目だけ**を名乗る。
   - **時間のかかる処理を挟んでから書くなら `ChangeLocalAsync(itemId, change, owns)`。**名指しは他の項目を守るだけで、
     名指しした項目そのものは守らない。変え方を関数で渡し、**錠の中で読み直した今の値に当てる**
     （検出・タグや属性の一括書き換え・取り込みのフォルダの測り直しが、古い写しに当てて人の操作を潰していた）。
     関数が `null` を返せば書かない。
     フォルダの登録・ファイルを外す／戻す・unitypackage の入り先・IDの付け替えもこれで書く（2026-09-23。どれも測る・全件を読む・BOOTH から取る間に取り込みが足した物を消していた）。
   - `booth` を時間のかかる処理の後で書き換えるなら `ChangeBoothAsync(itemId, change)`（取り込みの②。`local` には触らない）。
2. **書き手が複数いるファイルは `JsonFileStore.UpdateAsync`（錠の中で読んで直して書く）。**画面の写しを丸ごと書き戻さない（取り込み元・未確定が消えていた）。
   変える物が無ければ `TryUpdateAsync` で書かずに済ませる（未確定から外す所は、一覧に無ければ書かない）。
   今の値を見て別の物を先に保存してから書くなら `TryUpdateAwaitingAsync`（錠を持ったまま待つ。未確定の1件を商品にする所）。
3. **設定・画面の状態・検索の履歴は、変え方を関数で渡す**（`UiCommand.ChangeSettings` など）。持つのは `SettingsService` だけで、画面は写しを持たない。
4. 書き込みは一時ファイル（`〜.tmp`）に書いてから置き換える。**名前は毎回変え、同じファイルへの書き込みは1本ずつ**
   （固定名だと2本重なったときに保存そのものが例外で落ち、投げっぱなしなので画面には何も出ない）。
   失敗したら `.tmp` を消す。起動時に、保存先の下にある10分より古い `.tmp` を消す。
5. 保存の直前に商品がまだあるかを見て、無ければ書かずに飛ばす（塞がない）。
   **組み直した結果が今の中身（保存する JSON の形）と同じなら書かない**（2026-09-24。取り込み直すたびに変わっていない商品を1件ずつ書き直していた）。呼んだ側への答え（書いたか・在ったか）は変えない。
6. **計算で出せる値は書かない**（`[JsonIgnore]`）。説明の節の `normalizedHeading` も見出しから計算する（2026-09-24。前に書かれたファイルに残っていても読むときに無視される）。
7. **手で書いた `null` の配列は空として受ける**（`Storage/EmptyForNull`。保存の設定1か所で全部の欄に効かせる）。
   落ちるのは読んだ瞬間ではなく、後から一覧・検索・統計が触ったときなので、原因の商品も分からない。
   `?` を付けて宣言した欄は別（「まだ調べていない」と「調べて0件だった」を区別している）。
8. **公開前は古い形のデータに合わせる変更をしない**。合わない物は「どの保存先の何件がどう合わないか」を報告して直し方を聞く。
9. **手で直した JSON の食い違いは、落ちずに知らせる**（`Services/HandEditCheck`・ユーザ判断 2026-09-21）。
   - 同じ鍵が2つあっても索引を作る所で落ちない（`FirstWins.Map`。**先に書いてある方**を残す）。
   - 起動時の裏の作業で、同じ名前の大分類・小分類・属性・登録簿の商品ID・素体の名前・別名と、
     **ファイル名と中の商品IDのずれ**（L6）を見て、要確認に1件出す。直ったら解消済みにする。
   - **こちらから直さない。**直し方（片方を消す・名前を分ける・IDを揃える）は人が決める。

## 数え方（全画面で同じ）

- **所持**＝手元のファイルかフォルダを1つ以上持つ。ファイルの無い商品は検索には出る（印なし）が、統計・ショップの件数・支出には入れない。
- **非表示**：検索とショップの件数から外し、統計には入れる（見えなくしたいだけで、持っていないことにはしない）。
- **R-18を表示しない設定**：検索とショップの件数から外し、統計の金額には入れる。要確認には出す。
- **所有アバター**＝登録簿のIDが所持している商品に含まれるか（手で「持っている」にもできる）。フラグとしては持たない。
