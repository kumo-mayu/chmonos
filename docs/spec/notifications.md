> **要点**：通知の画面（旧「要確認」）の束・行・既読の決め事。知らせをどこに出すかの共通の決まりは [ui-empty-and-errors.md](ui-empty-and-errors.md)。

> **コード**：`App/ViewModels/InboxViewModel.cs`（束の見出し `KindLabel`・説明 `KindDescription`・並び）・`NotificationRow`・`Core/Services/NotificationService.cs`・`BrokenItemRepair.cs`・`App/MainWindow.xaml`（形式の変化の帯）

## 束（種類ごとのまとまり）

- **束は9つ**：商品ページの変更・タグの参照切れ・消えたバリエーション・復活したバリエーション・zipを入手した・非公開商品の復活・展開先のファイルを取り込んだ・手で直したJSONの食い違い・読めない商品の記録（2026-10-05）。
  見出しの言葉はユーザ指定（2026-09-18。のちに「消えた種類」を「消えたバリエーション」へ直した）。説明の文はコード（`KindDescription`）が正。
- **「対応アバター確認」「同じ内容のファイル」は通知に出さない**（ユーザ判断 2026-09-18：件数が多く、かつ「起きたこと」ではなく「今の状態」なので、別の場所で見る）。
  - 確かめていない対応アバター（説明文のその他のリンク＝対応と数えない推定）は、**商品ページの見出しに「確認待ち n」**、**検索の条件「編集状況」の項目「対応アバターの確認」**（未入力のみ＝確認待ちあり。2026-10-06 に条件から項目へ）で見る。
  - 同じ内容のファイルは**統計**（「ディスク使用量の内訳」の「うち重複コピー」と「空けられる場所」）で見る。
- 種類ごとに束ね、**束は畳める**（見出しのどこを押しても開閉。畳んだ状態は種類ごとにアプリを閉じるまで覚える）。件数は畳んでいる間も出す。
- 束の並びは、重要な未読がある種類を先に、その次は新しい知らせがある種類から（種類の宣言順では何から読めばよいか伝わらない）。
- 束の幅は中身の長さで変えない（畳むと札の幅が縮んで目が泳ぐ）。
- 束の見出しと行は**平らな1本の一覧にして仮想化する**（束の中に行を入れ子にしていた頃は、知らせ1000件で開くのに約7秒固まった。2026-09-24）。束の枠は行ごとに描き分け、見た目は1枚の札のまま。
- 束の件数は札にして、行に出る札と同じ色・同じ言葉で出す（重要＝注意の色、未読＝ナビのバッジと同じ色、解消済み＝灰。最後に全件数）。畳んでいる間もここだけで「何件あって何を先に読むか」が分かるようにする。
  件数の札は説明の右に上端を揃えて並べ、入り切らなければ次の段の右へ送る（`SplitRowPanel`。説明は幅いっぱいで折り返す。前は右の 400px を常に空けていて、狭い窓で説明が改行だらけになった。メモ13-①）。
- まとめて既読にするのは、全体と**束ごと**の2つ（選んで既読にする仕組みは持たない）。束の見出しの右に、未読がある束だけ出す。

## 種別ごとの「ここを直す」ボタン

種別ごとに1つ出す。タグの参照切れ→タグの管理を開く、zipを入手した→展開フォルダの登録を外す、消えた／復活したバリエーション・非公開商品の復活→商品情報を取り直す。

- 「zipで登録しなおす」は、押すとzipをその場で商品に付け、展開フォルダの登録を外す（ディスクのファイルには触らない）。結果で、zipで数えるようになったことを言う。
  zip に人が決めた事情があるときは黙って上書きしない（ユーザ判断 2026-10-05。`ItemService.SwapFolderForArchiveAsync`・`InboxViewModel`）：
  - 前にこの商品から**外した** zip：押した方が新しい判断なので、外した印を下ろして付け、フォルダを外す（前は「登録済み」と読んでフォルダだけ外し、所持が無くなっていた）。
  - **除外した** zip：確かめの窓（「除外を解除して、この商品に登録しますか？」。既定はキャンセル）。OK なら除外を解いて付ける。
  - **ほかの商品が持つ** zip：選ぶ窓で「その商品を開く」（何も変えずにその商品ページへ）と「この商品に付け直す」（向こうに外した印を付け、こちらに付ける。それぞれの商品の錠の中で書く。向こうの手元の物が無くなるなら窓で言う。商品は消さない）。
- 結果の置き場は [ui-empty-and-errors.md](ui-empty-and-errors.md) の「通知：行のボタンの結果の置き場」。
- 宛先の商品が無くなっていた通知は、押したときに理由を出して解消済みにする。

## 読めない商品の記録（ユーザ判断 2026-10-05「前提と 1 と 3 の案を採用する」）

- 読めない記録は全件の読み込みが飛ばすので、その商品は検索・統計・ショップのどこにも出ない。**1商品1件**の知らせにする（ID は `unreadable-item:{商品ID}`・重要）。
  行の題は、控え（`items/.prev`）が読めればその商品名（画面の名前と同じ決め方：表示名、無ければBOOTHの名前）。控えが無い・読めないときだけ `{商品ID}.json`（ID は使う人が扱う第一の情報にしない。ユーザ判断 2026-10-05）。題が商品名のときは、札に「壊れている場所：n 行目」と「ファイル：{商品ID}.json」を並べる（手で直す人がファイルを探すため）。題が `{商品ID}.json` のときは札は「壊れている場所：n 行目」（JSON の読み取りが止まった行。中身が `null` だけなら「壊れている内容：中身が空です」）。商品は開けないので行から商品ページへは行かない。
- **見るのは起動したときと、通知の画面を開いたとき**（`UiCommand.DetectUnreadableItems`）。BOOTH に問い合わせないので、設定「起動したとき、裏で取得を始める」を切っていても見る。
  同じ所で読めないままなら書き直さない（既読を未読に戻さない）。読めるようになった・無くなった物は解消済みにする。ほかのアプリが開いていて読めなかっただけの物は出さない。
- 行のボタンは1つで、状態で変わる：
  - **「1つ前の版に戻す」**（控え `items/.prev/{id}.json` が読めて、中の商品IDが同じとき。`UiCommand.RestoreItemCopy`）。控えはアプリが最後に書いた版なので、タグ・メモまで戻る。BOOTH へは行かない。
  - **「BOOTHから作り直す」**（控えが無い・読めないとき。`UiCommand.RebuildItemFromBooth`）。壊れた記録をよけてから「商品IDで登録」と同じ道で取り直す（人が押した優先度で門を通る）。
    取れなければ（見つからない・通信）よけた記録を元へ戻し、行に理由を言う。手元のファイルの記録は作り直した記録に無いので、取り込み直すと手掛かり（zip の中の URL・ダウンロード元の記録）で付き直し、決まらない物は未確定に出る（試験で確かめた）。
  - BOOTH に無い商品（仮ID）で控えも使えなければ出さない（JSONを開いて直すと説明の文が言う）。解消済みの行にも出さない。
- どちらも押すと確認の窓を出す（1行目に何が起きるか・続けて取り返し）。作り直しの窓は「タグ・メモ・購入記録などは戻りません」「手元のファイルは、そのフォルダを取り込み直すと付け直します」と言う。
- **壊れた記録は消さずに `items/_broken/{ID}-{日時}.json` へよける**（壊れた中にしか無い入力を手で救えるように）。押すまでに手で直していれば何も動かさない。
- 成功は一覧の見出しの下に出し、検索を読み直す（読めなかった商品は検索の写しに居ないので、1件の差し替えでは並ばない）。
- 「展開先フォルダの削除」が読めない記録で止まるときは、文に「通知の画面から直せます」を添える。

## 行

- 行のタイトルは商品名だけ。何が起きたかは束の見出しが言う。行の本文はその行だけの事実（「消えたバリエーション：旧・支援版・旧・通常版」「ユーザータグ：衣装／夏」）にして、束の説明と同じことを書かない。
  消えたバリエーションは**名前で言う**。名前はBOOTHにもう無いので、取り直す前の `booth` と購入時に写した名前（`NameSnapshot`）から引き、どちらも無ければIDで言う。3件を超えたら「ほか n 件」。
- 行の中身は**どの種別も同じ札**で出す。変化を持つ知らせは変わったところを1つずつ（「前 → 後」。価格・商品名・バリエーション数は変化なので、後の値だけでは何が起きたか分からない）、持たない知らせは本文の「見出し：中身」を1枚の札にする。
  説明文の見出しの変更は**変わった行だけ**を「追加」（緑）・「削除」（赤）の札を付けて並べ、4行を超えたら「ほか n 行」（メモ13-②。行の差を持たない前の形の知らせは頭の抜き出しの「前 → 後」のまま）。
- 行の要約の1行は、変わった項目の札が下に並ぶときは出さない（同じことを2回書かない）。
- **行の頭に商品のサムネイル**（ユーザ指示 2026-10-06「通知画面にもアイコンが必要だろう」。名前だけで大量に見分けると疲れる）。作りは取り込みの探した結果の行と同じ（[missing-search.md](missing-search.md)「行の左に商品のサムネイル」・`ResultThumbnail.ForItem`）：
  - 一辺 56 の四角を既読の丸と題の間に置き、**題の1行目に上をそろえて固定する**（行は札の数と題の折り返しで高さが変わる。丸の位置は全部の行で同じ）。
  - 絵の決め方は検索のカードと同じ。絵が無い・商品が消えていれば頭文字。読めない商品の記録は本体が読めないので控え（`items/.prev`）から決め、控えも無い（題が `{商品ID}.json`）なら名前が分からないので「?」。
  - **商品を指さない知らせ**（手で直したJSONの食い違い・展開先のファイルを取り込んだ）は絵の列ごと出さない。束は種類ごとなので同じ束の中で頭はずれず、種類の絵は束の見出しと同じことを言うだけなので置かない。
  - **絵は見えた行だけ読む**：行が作られて絵が読まれたときに初めて、裏で商品の記録から場所を決め、枠の大きさに縮めて読む（`PeekForFill`）。知らせ500件（全部に絵）の場面で、開く約0.15秒・流す1歩の最長 8ms・止まったコマ 0、開く速さ・流す速さ・メモリとも絵を足す前と差が見えない（3巡。撮影台 `perf-inbox-500`。見た目は `inbox-pictures`）。
- 題は折り返す（「重要」「解消済み」の印は1行目に上をそろえる。前は狭い窓で長い商品名が右で切れていた。2026-10-06）。
- 既読の印は行の左の丸で、右の「何かをする」ボタンとは分ける。読んだ行は薄くする（ユーザ判断 2026-09-18）。
- 操作のボタンは**本文のすぐ下、日時と同じ行**に、**指した行にだけ**出す。日時の行をボタンの高さ（28）で確保しておき、**行の高さは変えない**——出し入れで伸び縮みすると、境目にマウスがあるときに出たり消えたりして画面が揺れる。右端に置くと、行を読んでから押すまでに視線が大きく往復する。
- 日時は「3時間前」のように相対で出し、正確な日時はツールチップに置く（1週間より前は日付）。
- 通知どうしの区切り線は薄くしない（`Border`）。行の高さも上下15pxにする（ユーザ指摘 2026-09-18：区切りが見えない）。

## 未読・解消済み

- 未読の数え方は**未読かつ未解消**（ナビのバッジと画面で必ず揃える）。既読にしたら、保存を待ってから数え直す。
- 「未読のみ」の状態は覚える（`ui-state.json` の `inboxUnreadOnly`）。
- 状況が解消したものは消さずに「解消済み」の札を付ける（未読のみの表示には出さない）。上限を超えたら既読と同じく古い方から捨てる。上限の適用は起動時にも1回走る。

## 取得できる情報の形式の変化（束に出さない）

- 束には出さず（`InboxViewModel` が一覧から除く）、ナビの「設定」の上の帯で知らせる（アプリ全体の話）。押すと詳しい説明の窓（`MainViewModel.ShowStructureAlertCommand`）。読み取りが戻れば自分で消える。
- 帯の文は「BOOTHの情報の形式が変わったかもしれません」。窓には「対応アバターの検出と検索に使える情報が減りますが、手元のデータはそのままです。BOOTHの商品ページの作りが元に戻れば、この知らせは消えます。」と添える。
  説明の文（`KindDescription`）は「BOOTHの情報の形式が変わったかもしれません。対応アバターの検出と検索に使える情報が減ります。」。見出しの言葉は「取得できる情報の形式の変化」（ユーザ指定 2026-09-18）。
- 帯の配色はナビと同系の暗い色で、注意の色は左の縦線と文字だけに使う（ユーザ指摘 2026-09-18：明るいクリーム色は暗い帯から浮く）。

## 商品を指して開いたとき（メモ51・ユーザ決定 2026-10-05）

カード・ショップの「更新の通知を開く」（`MainViewModel.ShowInboxFor`）で来たとき。ナビから開いたときは何も変わらない。

- **指した商品を、画面にいる間ずっと持つ**（`InboxViewModel._targetItemId`）。読み直し・「未読のみ」の切り替えで行が作り直されても外れない。数秒で消す案は、目を離した人がまた探すことになるので採らなかった。画面を離れれば消える（画面ごと作り直されるので持ち越さない）。
- **強調**：その商品の行（`NotificationRow.IsTarget`）を、地の色（鍵 `TargetBand`）と左の縦線（`Accent`）で描く。アニメーションは付けない。
- **束の中の並び**：どの束でも、その商品の行を先頭に寄せる（未読を先、あとは新しい順のまま）。「商品ページの変更」の束にも当てる。束を開いたときにその商品の行がいちばん上になる。
- **自動で送る先**：「商品ページの変更」の束の**見出しを画面のいちばん上**に合わせる（束が畳まれていれば開く）。行は見出しのすぐ下にあるので、見出しと行が一緒に見える。行を送ると画面の端に来て、周りが見えなかった。
  その束にその商品の行が無いときは、「この商品 n」の印のある最初の束を開いて、その見出しへ送る（印だけ見えて送り先に何も無い、を作らない。ユーザ判断 2026-10-05）。どの束にも無ければ送らない。
- **ほかの束の見出し**：その商品の行があれば、件数の札の並びに「この商品 n」を出す（畳んでいても見える。吹き出しは「開いた商品の通知が、この束に n 件あります。」）。
  「未読のみ」のときは出ている行だけで数える（出ない行を数えると、開いても何も無い）。「商品ページの変更」の束には出さない（送る先なので）。
- 平らな一覧の仮想化はそのまま。見出しの上合わせは、送った後に行の位置を測って流す（`InboxView.AlignToTop`。`ScrollUnit=Pixel`）。
