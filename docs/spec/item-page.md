# 商品ページと編集画面（今の決め事）

> **要点**：商品ページは主に見る場所、入力は編集画面に寄せる（保存経路を少なく保つ）。画像は「BOOTH で観測した物 → 自分で足した物 → BOOTH から消えた物」の順。
> 手元のファイルはファイル単位で扱い（外す・戻す・Unity へ送る・展開して開く）、商品ごとの移し替えは「IDを変える」。編集画面は複数の商品を順に埋める画面。
>
> **コード**：`App/ViewModels/ItemViewModel*.cs`・`ItemRows.cs`・`Views/ItemView.xaml`・`ItemFilesPanel.xaml`、`App/ViewModels/EditViewModel*.cs`、
> `Core/Services/ItemImageOrder`・`ImagePipeline`・`ItemService`、`Core/Models/LocalFields.cs`（持ち主）
>
> **経緯**：`docs/history/user-images.md`（自分で足す画像）、`docs/history/ui-revision.md` §5（購入記録）・§8.5（外す）、`docs/history/private-items.md` §9（IDを変える）、`docs/feedback/`（U番号）

## 商品ページ

- 説明は保存した HTML（`items/{id}.h2.html`・script などは保存時に削る）。h2 を畳める（全体とセクションごと・既定は全開）。
  「商品説明」の欄ごとも畳める（ユーザ指示 2026-09-14）。畳んだかどうかは「BOOTHのタグ」と同じく商品を移っても保つ（アプリを閉じるまで）。
- **説明の見出しは、画面に見えている分までを最初の1コマで作り、画面の外の分は後から1行ずつ足す**（ユーザ判断 2026-09-30。`Controls/ProgressiveItems`）。
  見出しごとに選べる文字の箱が1つあり、見出し21個の商品では開くのに約340ms かかっていた（短い商品は約60ms。`docs/research/item-page-open-2026-09-30.md`）。
  - 最初に出るコマは、全部を1回で作ったときと同じ。見えている物は動かさない（足すのは一覧の末尾だけ。先読みは 300px）。
  - **説明の全部が在ることを当てにする処理は、先に足し切る**（`ProgressiveItems.FeedAllNow` → 並べ直す）。今は画面内検索（Ctrl+F）だけ。
    説明をまとめて読む処理（書き出し・印刷など）を足すときは、同じに足し切ってから読む。
  - 分けずに全部その場で足すとき：説明の欄を畳んでいる・流せる画面の中に無い・使い回された画面で流した位置が残る（同じ商品の開き直し）。
    戻る・進むで途中の位置へ戻すときは、位置を当てる前に足し切る（戻す先まで中身が要る）。
  - 読み上げ・自動操作から見ると、開いた直後の約0.3秒は画面の外の見出しがまだ無い（足し終えると全部出る）。
- **動画の欄**（ユーザ指示 2026-09-14）：埋め込み（`booth.embeds`）・短い説明・見出しの本文に載っている YouTube の動画を拾い（`VideoLinks`・試験付き）、
  絵とタイトル付きのリンクで出す。押すとブラウザで YouTube を開く（アプリの中では再生しない）。
  - **既定は畳む**。商品ごとに畳んだ状態で始め、開いたときだけ YouTube へ絵とタイトルを取りに行く（`docs/spec/background-and-network.md`）。
  - 動画が無ければ見出しに「この商品の説明に YouTube の動画はありません」と出し、開けない。
  - タイトルが取れなければ（非公開・削除・通信の失敗）その旨を出し、リンクは残す。
- 本文中の BOOTH 商品リンクは、所持していればアプリ内の商品ページへ。作者名はアプリ内のショップ画面へ（外の BOOTH へ飛ばさない）。
- タグは上部（切り替えられる）。右の列の枠の中は「商品名（星と一緒）→ ショップ・ID → ユーザータグ → BOOTHのタグ」の順（ユーザ判断 2026-10-02：タグは商品名の下）。
- **ユーザータグは小分類まで全部出す**（ユーザ判断 2026-10-02。前は大分類だけ）。札は「大分類 / 小分類」の1枚、小分類の無い大分類は大分類だけ。
  BOOTHのタグと同じ三角で畳め、既定は開く。開け閉めは BOOTHのタグと別に、商品を移っても保つ（アプリを閉じるまで。`SectionFolds.UserTagsExpanded`）。
- **上の帯**（左に戻る・カテゴリ、右に状態の文とボタン3つ）は、入り切らなければ右の塊を次の段へ送る（`SplitRowPanel`）。右の塊だけでも欄を超えるときは塊の中で折り返す。
  カテゴリは「…」で切る。前は右寄せで重ねて置いていて、フォルダビューの狭い欄でボタンがカテゴリの上に重なった（2026-10-02）。
- 対応アバターを手で足す・消す（`docs/spec/avatars.md`。消した印は再検出をまたいで残る）。「＋ 追加」の候補には「〇〇（共通素体）」も混ぜ、選ぶと対応素体に入る（2026-09-28）。
- 持っているのに出していなかった内部情報（メモなど）も出す。
- 「BOOTHから取り直す」（何が起きるかを名乗る）。BOOTH に無い商品では押せない（理由をツールチップ）。
- 右の列に「この商品を使った改変」と「改変に追加」、何回入っているか（`docs/spec/modifications.md`）。
- フォルダビューに組み込むときは戻るを隠す（`IsEmbedded`）。境目のドラッグも出さない。
- **組み込んだ商品ページは、幅 720 より狭い欄では横に送れる**（2026-09-30）。720 は左の列の最小 360＋右の列の最小 320＋本文の左右の余白 20×2。
  前は下限が無く、列は最小の幅のまま欄からはみ出して、右の列（名前・価格・ローカルファイル）が切れたまま届かなかった。主の窓の商品ページの下限は変えていない。
- **組み込んだ商品ページ（フォルダビュー・改変の画面）で別の商品を選び直したら、流した位置を先頭へ戻す**（ユーザ判断 2026-09-30）。
  画面は使い回されるので、戻さないと前の商品の位置のまま次が出る。同じ商品を開き直したとき（取り直した後・ファイルを外した後）は戻さない。
- **主の窓の商品ページの流した位置は、ショップの画面と同じ決まり**（ユーザ判断 2026-09-30。`ItemViewModel.Scroll.cs`・`ItemView.xaml.cs`）。
  - **進むとき**（検索・一覧・説明の中のリンク・対応アバターから開く）は先頭から。
  - **戻る・進む**（Alt+←／→・マウスの戻るボタン）で来たときは、その商品を離れたときの位置へ。間に別の種類の画面を挟んでも戻す。
  - **同じ商品の開き直し**（取り直した後・ファイルを外した後・IDを変えた後）は、今の位置を保つ。
  - 位置は画面の履歴の1件ごとに持ち、保存先には書かない（アプリを閉じれば消える。履歴から控えが消えれば位置も消える）。
    流した量（px）で覚える——商品ページは仮想化していない1枚で、ショップの一覧のように列の数が幅で変わらない。窓の幅を変えてから戻ると、折り返しの分だけずれる。
  - 右の列の行（zip の中の Unity へ送れる物・この商品を使った改変）は裏で読んで後から届く。戻した時点で流せる長さが足りなければ、伸びるたびに送り直す。
    人が触ったら（クリック・ホイール・キー・自分で流した）追うのをやめる。

## 変わった所の印（ユーザ判断 2026-10-02・メモ7）

- その商品に未読の更新の知らせ（`ItemUpdated`・未読かつ未解消。ショップの「変更あり」と同じ数え方）があれば、差の欄ごとに印を付ける（`ItemChanges`）。
  印は欄の左の色の線と札。札に乗せると前の値（前が無い物は「前回の取得の後に追加されました。」）。線はカードの内側の余白に置き、中身は動かさない。
- 色と札（色だけに頼らず、札の文字も分ける。明暗とも WCAG AA）：変わった＝橙「変更」（`Warn`。商品名など行を持たない変化）・足された＝緑「追加」「販売再開」（`Good`）・
  消えた＝赤「削除」「販売終了」（`Bad`）・価格＝橙「価格変更」（`Warn`。変わったと同じ色。2026-10-04 に青から変えた）。数（バリエーション・画像）は増えたら追加、減ったら削除。
  **見出しの「変更」の札は中身で分ける**（ユーザ判断 2026-10-05・メモ53②）：足した行があれば「追加 n」（緑）、消した行があれば「削除 n」（赤）の札にし、両方あれば2枚並べる。
  欄の左の線・上の帯の左の線は、足しただけなら緑・消しただけなら赤・両方あるか値段・名前などほかの変化が混ざれば橙（`ChangeSlot.Edge`・`ItemViewModel.ChangesBarTone`）。
  説明文の欄の見出しの札は、全部の見出しの足した行・消した行の合計。通知の画面の札は、行ごとに「追加」「削除」の札を付けているので同じ決まりのまま。
  **購入の札は灰色**（`PurchasedText`・`PurchasedSoft`・`PurchasedBorder`）：緑と赤は BOOTH で変わった所だけの意味にする。検索のカードの「所持」と持っている商品へのリンクの緑（`Good`）はそのまま。
- 欄の対応：商品名→名前、価格とバリエーションの数→バリエーションの欄の見出し（値段が出ているのはここだけ）、画像→画像の欄（線は左の縁・札は大きい絵の左上）、
  販売状況→「記録していること」の「BOOTHでの販売」、説明文の見出し→その見出し（正規化した見出しで突き合わせる）と「商品説明」の見出し（畳んでも分かるように）、
  見出しの無い商品の説明文→「商品説明」の見出し。消えた見出しは元の位置に見出しごと並べる（下の帯）。
- **足した・消えた物は帯（地と左の線）で示す**（ユーザ指示 2026-10-03・メモ17。前は消えた行だけ見出しの下に「削除」の札で並べていた）：
  足した＝緑（地 `AddedBand`・線 `Good`）、消えた＝赤（地 `RemovedBand`・線 `Bad`）。地は札の地より薄い専用の色（帯が多い商品で強すぎないように。文字は明暗とも AA）。
  帯に乗せると「BOOTHで追加／削除された〇〇です。」。帯を付ける物：
  - **本文の行**（メモ13-②）：知らせが行の差（`NotificationDiff.Lines`）を持つ見出しは、足した行に緑、**消えた行は元の位置に差し込んで赤**（`SelectableText.MarkedLines`）。
    位置は知らせの `follows`（今の本文で直前にあった行の文）で探す。知らせに残さなかった消えた行（上限の30行を超えた分）は本文の下に「ほかに消えた行が n 行あります。」。
    行は差の並びの順に本文を上から辿って当てる。行の差を持たない前の形の知らせでは本文に何も付けない。
  - **見出しごと**足された・消えた物は、見出しの行から帯（メモ17②）。消えた見出しは前のページで直前にあった見出し（`follows`）の後ろに、見出しと知らせに残した行だけで並べる。
  - **バリエーション**：足された物は緑、消えた物は元の位置（`follows`）に行として残して赤（ユーザ判断 2026-10-03）。買っていて「BOOTHに現存しない」行が既にあれば、その行に赤を付ける（2行に出さない）。
    差し込んだ行は欄の件数に数えない。
  - **商品名**：前の名前を赤の帯の行、今の名前を緑の帯で上下に並べる。札と、乗せると前の値が出る吹き出しは残す。
  - **値段の変わったバリエーション**（ユーザ判断 2026-10-04・メモ27-⑤）：行に橙の帯（地 `ChangedBand`・線 `Warn`。ユーザ判断 2026-10-04 で青から橙へ。見出しの札「価格変更」と同じ色）を付け、行の中に「¥前 → ¥今」を出す。
    買っていない行は値段の欄をそのまま「¥1,000 → ¥1,500」に、どの行も右端の BOOTH の価格が「¥1,000 → ¥1,500」になる（買った記録の札はそのまま）。行は知らせの `prices` の ID で当てる。
    種類ごとの値段を持たない前の形の知らせでは行に何も付けない（札だけ）。通知の札も「名前 ¥前 → ¥今」を1行ずつ並べる。
- **ページの上の帯**（流す本文の外）：「BOOTHで変わったところ：」の後に変わった所を並べ（商品名・バリエーション〈価格だけなら「価格」〉・販売状況・画像・「説明文：見出し」を
  ページの上から）、押すとそこまで流す。畳んだ欄（商品説明・見出し・バリエーション）は開いて、並べ直してから位置を測る（開く前に測ると伸びた分だけずれる）。
  並びの左の短い線は印と同じ種類の色。**帯は1行の高さに決める**：入り切らない分は「ほか n 件 ▾」の一覧へ（`OneLinePanel`）。
  ページに無いのに「変わった」とある見出しは押せない語として並べる。右端に「既読にする」（主のボタン）。
- **本文を跳ねさせない**（ユーザ指示 2026-10-03「画面が一瞬で大きくズレるような動作は避ける」）：知らせは開く時点で同期で読む（後から読むと帯が後から現れて本文を押し下げた）。
  既読にした後も、そのページを開いている間は帯を同じ高さで残し「既読にしました。」と出す。消えた見出しの行は一覧から抜かずに隠す。
  既読で消える帯のうち、見ている所より上にある分（左の列＝説明文）の高さだけ流した位置を戻す（右の列は高さが別なので保たない）。
- **印は「既読にする」を押すまで残す**（開いただけでは既読にしない。読み終える前に別の画面へ移ると消えてしまう）。ボタンは未読があるときだけ出す。
  押すと通知の「この束を既読にする」と同じ命令（`MarkNotificationsRead`）でその商品の知らせを既読にし、ナビの通知の数も数え直す。
- 編集画面の中の商品ページには出さない（入力の場で、既読の操作を混ぜない）。

## 画像

- 保存先 `images/{id}/{URLのハッシュ}.webp`（長辺・画質は設定。既定 384px・WebP 80）。**再取得は画像ファイルを消さない**（消すのは取れなかった印だけ）。
- **並び**：`Booth.Images` の順 → 自分で足した物（`Local.UserImages` の順・足すと末尾）→ BOOTH から消えた物（「削除済」のかぶせ）。BOOTH の画像は並べ替えない。
- **自分で足す**：ファイル選択・ドロップ・貼り付け。ライブラリへコピーして同じ圧縮をかけ、`user-{中身のハッシュ8桁}.webp`（同じ絵は1枚にまとまる）。印は左下の小さな札。
- **サムネイルの指名**：`Local.ThumbnailImage` にファイル名を1つ（BOOTH の画像も指名できる）。指名先が消えたら黙って1枚目に戻す（BOOTH の画像なら指名は残す。自分で消した画像なら指名も外す）。★は右上。
- BOOTH 由来の画像（URL に商品ID）を商品ページに落としたら「この画像をどうしますか？」［キャンセル］［商品を開く］［画像として足す］。既定のボタンは置かない。商品ページ以外では今まで通り。
- 見る：矢印はマウスが絵の端に来たときだけ出し、最初と最後をつなぐ（1枚なら出さない）。帯そのものがボタン。左右キーでも送る（入力欄・並びの中・ショップ名と ID のリンクの上では効かせない。`ui-keyboard.md`）。操作は右クリックに集める。
- 「この商品の画像取得を優先」は未取得があるときだけ。取れなかった物（`.missing`）は「n 枚は取得できませんでした」。裏で取った画像はその場で出る（見ていた絵は選んだまま）。
- 画像の削除の確認：公開中の商品は1回、非公開・削除済みの商品は「二度と取得できません」と理由を添える。

## 手元のファイル

- 欄は見出しの三角で畳める（ユーザ指示 2026-09-19）。既定は開く。商品を移っても同じ開き方のまま（アプリを閉じるまで）。件数と容量は畳んでも見出しに出す。
- ファイル単位で並べる。容量は論理値（重複を1回）。
- **名前を押すとエクスプローラで開き、場所は名前に乗せたときに出す**（ユーザ指示 2026-09-19：名前の下に場所の行が続き、同じ名前が2回並んで読みにくかった）。
  フォルダの行も同じ。見つからないファイルは開く先が無いので名前を押せない。
  同じ中身が別の場所にもあるときは、名前の横に「同じ中身が n 箇所に」の札（「実体」は内部の言葉に読めたので改めた・2026-09-19）、下に**2つめ以降の場所**を「同じ中身がある、ほかの場所」として行に出し、場所のすぐ横の［エクスプローラで開く］から開ける（ツールチップは押せないので入口が要る）。
- **ボタンは名前のすぐ横**（ユーザ判断 2026-09-19：右端に並ぶと、名前を読んでから押すまでに視線が画面の幅ぶん往復した）。
  - ［開く ▾］：「エクスプローラで開く」「一時的に展開して開く」（zip のときだけ）を下に出す（`Controls/MenuButton`・改変の「Unity ▾」と同じ開き方）。外したファイルでも薄くしない。
  - unitypackage の行：名前の横に［Unity ▾］で「Unityへ送る」「改変に追加して送る」「Unityで選択」。送り方を2つに分けたまま選ばせる（送る前に記録するか聞くと、記録を使わない人の邪魔になる）。
    「選択」は改変の画面と同じ道（`UnityMemberSelect.ShowIfPresentAsync`）で、相手は送り先と同じいま開いている Unity。**入っていなければ言うだけで、取り込みには進まない**（「示す」つもりが「取り込む」にすり替わらないように）。結果は欄の下の1行。
  - 商品の中身を変える「この商品から外す」「この商品に戻す」「登録を解除」だけは右端に離す（開く・送るの隣で押し間違えないように）。
- **行の中身（名前・札・容量・リンク・［開く ▾］）は、入り切らなければ次の段へ送る**（ユーザ判断 2026-09-30）。札とボタンは切らず、名前は1つで幅を超えるときだけ「…」で切る。
  前は横に並べるだけで、狭い幅では右の「この商品から外す」の下へ潜り、「見つかりません」の札が丸ごと見えなかった。右のボタンは名前の段に並べる。
  札は文字の高さの箱にして、段の上下の中央に置く（行の高さまで伸びて、文字が上に寄っていた）。フォルダの行も同じ。
- ファイルごとに：「この商品から外す」（灰色の行で残る・`docs/spec/id-resolution.md`）／「一時的に展開して開く」／zip の中の unitypackage ごとに「Unityへ送る」「改変に追加して送る」と入り先（`docs/spec/unity.md`）。
- 最後のファイルを外すときは、商品を「非表示にして残す（おすすめ）」「残す」「完全に削除」の3択で聞く（ユーザ判断 2026-09-12）。
  残す2つは外した印も残るので、次の取り込みでこのファイルがこの商品に戻らない。非表示は検索とショップの件数から除き、統計の支出には入れる。
  完全に削除は印も消えるので、次の取り込みで読み取った情報がこの商品を指せば作り直される。窓には選ぶのに要ることだけを書く（2026-09-24）。
- 在るか・中の unitypackage は画面のスレッドの外で調べ、行を先に出して後から印を付ける（`DiskCheck`）。
- 見つからないファイルは「見つかりません」（記録のどの場所にも無い。移した・消した）。名前も［開く ▾］も押せない。**［開く ▾］・［Unity ▾］は消さずに薄くし、吹き出しで理由を言う**（「ファイルが見つかりません。」「ドライブをつなぐと開けます。」。ユーザ判断 2026-10-04。右クリックのメニューと同じ形で、行の形がいつも同じになる。前はボタンごと消していた）。在るかは商品ページを開くたびに画面のスレッドの外で確かめる（`LocalFilePresence`。前は記録のパスが空のときだけ出していて、移したファイルも普通の行で出ていた・点検 2026-09-30 の B）。
  権限が無い・ドライブが答えないで確かめられないファイルは「確かめられません」（吹き出し「フォルダを読む権限があるか確かめてください。」）。記録には「無い」と書かず、カードの印とも揃う（2026-10-05・MB-B。前は「見つかりません」と出ていた）。
  同じ場所で新しい版に置き換わった古い版（`replaced`）は、置き換わった場所の名前で「古い版」の札を出し、「この商品から外す」の代わりに「古い版の記録を片付ける」（行を記録から消す。ディスクには触らず、窓で聞かない）を出す（2026-10-05・点検の8）。
  **見た結果は記録にも書く**（ユーザ判断 2026-10-04）：無ければ見つからなくなった日時（`missingSince`）を付け、在れば消し、検索の写しへ知らせる（前は書かず、ここで「見つかりません」の商品がカードの印・検索の条件・統計に出なかった）。
  ［開く ▾］の「エクスプローラで開く」「一時的に展開して開く」・Unityへ送る・カードの右クリックの開く／展開で無かったときも、そのファイルを見直して同じく書く。Unityへ送る道は商品ページの1件・検索とフォルダビューの複数選択・改変の画面（順に送る・「Unityで選択」）のどれも同じ（`FilePresenceNotes.NoteFailedSendsAsync`。人が止めた分は見ない）。
  書くのは日時だけで、場所・メモなど人が入れた値に触れない。記録と同じなら命令も出さない。命令は `UiCommand.NoteFilePresence`（`FilePresenceNotes`）。
  つながっていないドライブの上にしか場所が無いファイルは「取り外しているドライブ」（取り込みがそこのパスを残すのと同じ考えで、無くなったとは言わない。フォルダの表示と同じ語）。フォルダとして登録した商品はフォルダの行。
- **壊れていて開けない zip は、名前のすぐ横に札「壊れたzip」**（ユーザ判断 2026-09-30。記録の `archiveBroken`・`docs/spec/import.md`）。未確定の行と同じ色（赤：`BadSoft`・`BadBorder`・`Bad`）、同じ吹き出し「zipを開けませんでした。ダウンロードし直してください。」。
  前は中身の一覧が空なだけで、「一時的に展開して開く」を押して初めて分かった。商品ページを開くたびに zip を開き直さず、取り込みが書いた事実を見せる。編集画面も同じ部品なので同じ札が出る。
  - **在る物にだけ出す。**「見つかりません」「取り外しているドライブ」の行には出さない（無い物は壊れているかを見られない。次の手が「取り込み直す」「つなぐ」と「ダウンロードし直す」で並ぶと、どちらを先にするのか分からない）。
  - 外したファイルの行にも出る（事実は変わらない）。［開く ▾］の「一時的に展開して開く」と Unity へ送るは、壊れていない物と同じに出す（押すと失敗の文が出る）。

## 購入記録

- 商品ページのバリエーションの欄は畳める。見出しに三角と件数を置き（ローカルファイルの欄と同じ形）、畳んだ状態はアプリを閉じるまで覚える（ユーザ判断 2026-09-27）。
- 畳む印は全画面で三角に揃える（商品ページ・編集画面のあと、アバターの管理・改変の画面・未確定・設定にも広げた。ユーザ判断 2026-09-29。`ManageResources.xaml` の `TriangleExpander`・`TagToggle`。見出しの文字を押しても開閉する。ユーザ判断 2026-09-27）。
- **バリエーションの行の価格は、BOOTH の価格を右端に固定し、購入は札で並べる**（ユーザ判断 2026-10-05・メモ39・54。絵を見て決めた）。
  BOOTH の価格は1つなので、行の右端に13ptで固定する（変わった行は「¥前 → ¥今」。BOOTH に無い行・消えた版は空）。
  買った記録は名前の下に札で**全部**並べる（入り切らなければ折り返す）。同じバリエーションを何度買っても1件ずつ出す（前は1件目だけ「ほか n 件」）。
  札の文は動詞で種類を分ける：「¥1,200 で買った」「¥1,500 で贈った」「¥800 で貰った」。価格の無い貰った物（空欄か0円）は自分の支出ではないので「貰った」だけ。価格の無い買った・贈った物は「価格未入力（贈った）」。
  購入の日付を入れた札だけ頭に日付を添える（「2025-12-24 に ¥1,500 で贈った」。空の札は入手日と同じ日なので添えない。メモ45）。
  札は灰色にする（購入を緑にすると足した行の緑と区別できない）。前の「購入済み」の札は、買った札が並ぶので外した。
  比べた案：上下2行の小さな文字（前）／行で並べる／札で並べる（採用）。購入の色は青・灰を比べて灰。
- 「記録していること」の「検索から除く」のチェックで、非表示にする・解除する（状態の横で戻せるので「元に戻す」の帯は出さない。ユーザ判断 2026-09-27）。
  隣の「更新通知」と同じチェック1つにする（状態の文字と［非表示にする］［非表示を解除］は分かりにくかった。ユーザ判断 2026-09-28）。
- 「更新通知」のチェックも押して切り替える（ユーザ判断 2026-10-04・メモ27-④。前は見せるだけで、変えるには編集画面を開いた）。書くのは編集画面と同じ命令で、持ち主は `NotifyOnUpdate` だけ（`LocalOwners.UpdateNotice`）。押した結果の知らせは出さない（チェックの状態で分かる）。

- **買った1回＝1レコード**（`purchases[]`：`variationId`（`long?`）・`price`・`kind`＝自分用／贈った／貰った・`note`・`purchasedAt`）。同じ種類が複数行あってよい（3人に贈れば3行）。
- 2件目以降は種類の行の下に独立した行で足す（既定は「贈った」）。行ごと消す。種類を指さない購入もいつでも足せる。
- **購入1件ごとの日付の欄**（メモ45・ユーザ判断 2026-10-05）：1件目（種類の行）にも2件目以降にも出す（1件目だけ入手日と違う日に買うこともある）。
  欄の名前は行の種類に合わせる（買った日／贈った日／貰った日）。空欄は入手日を使い（薄い字で「入手日と同じ」）、保存は null（推定で埋めない）。
  書き方と読めないときの知らせは入手日の欄と同じ（`DateText`。「買った日「…」は読めなかったので、空のまま保存しました」）。足した2件目は日付を写さない。
  行は2段：値段・現在の値段・種類の上の段と、日付・［＋ 追加購入］（2件目は［この記録を削除］）の下の段（日付を足すと右の欄の幅に1行で収まらない）。
  日付をどこで使うかは `data-model.md`「購入記録ごとの日付」。
- 所持の定義は変えない（贈った物はファイルが来ないので所持ではないが、支出には入る）。貰った物は支出に数えない。
- 価格の空欄は **0円として記録する**（ユーザ判断 2026-09-29：未入力を無くす。前は空欄を未入力、0 を無料配布と分けていたが、未入力は検索の「払った額」「有料・無料」で値の無い物として抜け落ちた）。欄は空欄のとき薄い 0 を出す。BOOTH の値段が無い行（種類を指さない購入・消えた版）では横の「現在 -」を出さない。読めない文字だけは保存せず知らせる。
- ファイルに「どの種類か」を付ける：購入した種類の行の横のプルダウン（名前に種類名が入っているファイルを先に並べる。自動では付けない）。書くのは編集画面の保存とは別の命令（`LocalFiles` は取り込みも書く）。

## 編集画面

- 複数の商品を順に埋める。「保存して次へ」を上にも下にも置く。無くなったら3秒後に検索へ戻る（切れる・止められる）。
- 商品名・ショップ・カテゴリは左の商品表示の「編集」で開く（BOOTH から取れている商品では普段変えない）。右の入力はユーザータグから始まる。
- 既定の属性を並べておき、触るまで保存しない（触っていないのに書くと「決めた」と区別できない）。
- 入力欄には候補（`SuggestBox`）。全部並べず候補から積む。Enter で確定・↑↓で候補・Tab は次の欄。候補に無い語は「新しく足す」と明示。
- ユーザータグ・属性は名前で参照、トップレベルは複数選べ、サブはトップレベルごと（外すと配下のサブも外れる）。
- 非表示にする（統計には含める）。
- **左の「商品説明」の欄の高さは人が変える**（ユーザ指摘 2026-10-02：決め打ちの 360 では、説明を読みたい人と入力を見たい人で合わない）。欄の下の縁のつまみ（`Controls/HeightGrip`）をドラッグし、ダブルクリックで既定の 360 に戻す（画面の幅の境目と同じ作法）。
  値は高さの上限で、短い説明は中身の高さで止まる。覚えるのは `ui-state.json` の `paneWidths` の `edit.description`（範囲 120〜1600）。設定画面の「すべて元の幅に戻す」でも戻る。伸ばしてつまみが左の列の見える範囲の下へ出たら、出た分だけ列を流して追従する（メモ18。縮めるときは流さない）。
- ショートカット：保存して次へ＝Ctrl+Enter・スキップ＝Ctrl+N・前へ＝Ctrl+P（どちらも入力欄の中でも効く。ボタンの吹き出しにキーを出す。`ui-keyboard.md` のキー）・画面の中を探す＝Ctrl+F・戻る＝Alt+←。設定画面でキーを押して変えられる（同じキーは先の方を外して知らせる）。文字の欄では文字を打つ・カーソルを動かすキーは働かせない。
- 編集キューの位置は `edit-session.json`（`UiCommand` の編集キュー5種）。**5種とも錠の中で書く**（`JsonFileStore.UpdateAsync`。2026-10-04）。
  積み直し・終える（消す）は今の記録を使わないが、錠の外で書くと、古い記録を読んだ位置・保存した印・IDの付け替えが後から書き戻し、積み直した順番が消える／終えた順番が戻る。
  入り直して順番を詰めたときは、順番と位置を1回で書く（`StartEditSession(順番, 位置)`）。
- 一括操作は ユーザータグの追加・削除／属性の一括設定／非表示 だけ（メモや価格のような1件ずつ違って当然の物は対象にしない）。
- 保存は `SaveLocalAsync` で編集画面が持つ項目のうち、開いた後に人が変えた項目だけ（`LocalOwners.EditScreen` と `LocalFields.Changed`）。
  ファイルの種類は別の命令で、商品の錠の中で今の一覧の種類だけを書き換える（`ChangeLocalAsync`。前は錠の外で読んだ一覧ごと書き、間に取り込みが足したファイルが消えた。2026-10-04）。

## 取り消し

1. 取り消せる操作（非表示。未確定の「管理対象から除外」も）は確認なしで、直後に「元に戻す」。
2. ファイル削除・公開中の商品の画像削除は確認1回。
3. 取り返しがつかない物は理由を添えて確認（非公開商品の画像・共通素体の削除・改変の削除）。

## 操作の結果の知らせは押した欄の下に出す（2026-10-04・メモ20-③）

上の段の1行（`RefreshStatus`）は「商品情報を取り直す」の結果だけ（ボタンと同じ段）。ほかは `AreaNotice`（`Controls/AreaNoticeLine` が App.xaml の `FieldNotice`／`FieldWarning` で出す）に分ける：
IDのコピー・IDを変えるの失敗＝IDの行の下（`IdNotice`）／外したファイルを戻すの失敗＝ファイルの欄の上（`FilesNotice`）／共通素体を足す・対応アバターの保存の失敗＝対応アバターの欄（`AvatarsNotice`）／
画像の追加・動かす・サムネイル・削除の結果＝ギャラリーの下（`GalleryNotice`。改変の写真の欄は持たないので場所も取らない）／「検索から除く」の保存の失敗＝そのチェックの下（`VisibilityNotice`）。
どれも出ていない間も1行の高さを取り、出入りで下が動かない。保存できたときは何も出さない。編集画面も同じ部品を使うので同じ場所に出る。
