# 1つのファイルを2つ以上の商品に付ける（今の決め事）

> **要点**：1つのファイル（同じハッシュ）を2つ以上の商品の持ち物にできる。人がファイルを付けるとき、ほかの商品が持っていれば窓で「その商品を開く」「この商品に付け直す」「両方に付ける」を選ぶ。
> 片方への操作は、その商品の記録だけを変える。ファイルそのもの（場所が増えた・無くなった）と除外の一覧は全体に効く。容量の合計は同じ中身・同じ場所を1回だけ数える。
>
> **コード**：`Core/Services/LocalFileEditor.cs`（`AttachFileAsync`・`SwapFolderForArchiveAsync`・`DetachFileAsync`）・`ArchiveSwapOutcome.cs` の `OtherHolders`・`LibrarySizes`・`FilePool`、`App/ViewModels/ChoiceQuestion.cs`
>
> **経緯**：`docs/plan.md` 27（ユーザ判断 2026-11-11「一つのファイルを複数の商品に紐付け出来るようにしましょうか。」）。使い道はセット商品（買った記録を持つ）と中身の各商品の両方を「持っている」にすること（plan 26 の続き）。
> 2026-10-05 に、人が付けるときは「付け直す」だけにした（前は聞かずに2つの商品の持ち物にし、容量を二重に数えていた）。容量を1回だけ数えるようにしたので、両方に付ける道を足した。

## データ

- 形は変えていない（形式の版は上げない）。前から、2つ以上の商品の `localFiles` に同じハッシュの行があってよかった（取り込みは同じ中身を持つ商品の全部へ場所を足す。`import.md`）。
- 商品ごとの行の欄（種類 `variationId`・外した印 `detached`・記録した日時 `registeredAt`）は商品ごとに持つ。片方を変えてももう片方は変わらない。
- フォルダの画面は、同じファイルを商品ごとに1行ずつ並べる（`folder-view.md`）。

## 付けるとき

- 命令は `UiCommand.AttachFile`（商品ページの［追加…］・落とす）と `UiCommand.SwapFolderForArchive`（通知の「zipで登録しなおす」）。ほかの商品の扱いは `OtherHolders` の1つの値で渡す（2つの真偽にすると「付け直す」と「残す」を両方立てられる）。
  - `Ask`（既定）：ほかの商品が持てば何も書かずに `OwnedElsewhere` と持ち主を返す。画面が窓で聞いて、答えを決めて呼び直す。
  - `TakeOver`：持ち主の全員に外した印を付け、この商品に付ける（「この商品に付け直す」）。
  - `Share`：持ち主の記録に触れず、この商品にも付ける（「両方に付ける」）。
  - どれでも、除外していれば先に除外として返る（除外の窓が先）。付けた後は未確定から消す。
- 窓（`ChoiceQuestion.OwnedElsewhere`・`ChoiceDialog` の3択）：ボタンは「その商品を開く」「この商品に付け直す」「両方に付ける」「キャンセル」。既定のボタンは置かない（`ui-dialogs.md`）。
  持ち主が2件以上なら「両方」ではないので、3つ目は「すべてに付ける」。本文の3つ目の説明は「（持ち主）にも残したまま、この商品にも登録します。」「あとでこの商品から外せます。」。撮る場面は ViewShot の `catalog-dialog-owned-elsewhere`・`-many`。
- **決まった組でも、付けるたびに聞く**（plan 27「最初は残す」）。両方に付けた後で3つ目の商品に付けるときは、2つの持ち主を返して聞く。
- **新しい版は1つの商品にだけ付く**（ユーザ判断 2026-11-11）：作者が更新した zip は中身が違う（別のハッシュ）ので、取り込みはダウンロード元の記録（Zone.Identifier）の指す1つの商品へ付ける。古い版を共有していたもう片方には付かない。要るときは人が商品ページの［追加…］で付け、窓で「両方に付ける」を選ぶ。同じ中身の場所が増えたときに全部の持ち主へ足すのは、前から（`import.md`）。

## もう片方への効き方

| 操作 | 操作した商品 | もう片方の商品 | 全体 |
|---|---|---|---|
| 外す（「この商品から外す」） | 外した印 | そのまま持つ | **未確定に出さない**（行き先が決まっているため。最後の持ち主から外したときだけ、今までどおり未確定へ） |
| この商品に戻す | もう片方が持っていれば戻さない（今は「先にそちらの商品から外してください」） | そのまま | — |
| 付け直す | 付く | 全員に外した印 | 未確定から消す |
| 管理対象から除外 | 記録はそのまま | 記録はそのまま | 除外の一覧に入る。次に付ける商品では除外の窓が出る。取り込みは新しい場所をどの持ち主にも足さない |
| 見つからないファイルの掃除 | 記録を消す | 記録を消す（ファイルが無いのは全体の事実） | 窓の件数は商品ごとの記録の数（同じファイルでも2件） |
| 移した先の取り込み | 新しい場所 | 新しい場所 | — |
| 引越し・バックアップと戻す | 保存先を丸ごと運ぶので、両方の記録が残る | 同じ | — |
| 外から使う API の読み取り | 両方の商品の答えに同じファイルが出る。外した方は既定の答えに出ない（`include=allFiles` で「外した」） | 同じ | — |

試験は `Core.Tests/SharedFileTests`・`Query.Tests/SharedFileAnswerTests`・`App.Tests/InboxArchiveSwapTests`。

## 数え方

- **合計は1回**（`LibrarySizes`）：統計の「持っているアセットの大きさ」（`Owned`：同じハッシュを1回、同じ場所の登録フォルダを1回）・「ディスク使用量」（`OnDisk`：在る場所を1回ずつ）・「うち重複コピー」（`DuplicateOnDisk`：同じ中身の在る場所の2つ目から。商品をまたいだ別の場所の写しも数える。前は商品の中だけ）、カテゴリの棒（カテゴリの中で1回）、ショップの中の合計。
- **商品1つの値は今までどおり**（カード・並べ替え「容量」・商品ページ・重い商品の順位）：その商品が持つ物の大きさなので、共有したファイルも数える。
  そのため、商品ごと・カテゴリごと・ショップごとの値を足すと全体の合計より大きくなることがある（両方のカテゴリに入っている物なので、カテゴリどうしでは重なる）。
- 件数（所持の数・ショップの件数）は商品の数なので、共有で変わらない。重複の一覧（`DuplicateFinder`）は場所で数えるので、同じ場所を2つの商品が持つだけなら出ない。

## 30（選んだ商品の間でファイルを割り振る画面）のための口

- `FilePool.Of(選んだ商品)`：選んだ商品が持つファイルを中身ごとに1行にし、名前・大きさ・場所・持ち主・重複回数（選んだ商品の中で数える）を返す。読むだけ。組分け（頭文字）はまだ持たない。
- 付けるのは窓を出さずに `UiCommand.AttachFile(商品, 場所, OtherHolders: Share)`、外すのは `UiCommand.DetachFile`。
  [要確認] `AttachFile` は場所を受けてハッシュを取り直し、ファイルが在ることを求める。溜まりの記録から付ける（見つからない物・大きい zip を何度も読まない）には、ハッシュで付ける命令が要るかもしれない。30 を作るときに決める。

## 気になっていること

- Unity のプロジェクトから使った商品を探す（`UnityProjectMatcher`）は、2つ以上の商品に同じパスで入っているファイルを「共有の部品」として数えない。同じ zip をセットと単品が持つと、両方とも候補から落ちる見込み（直していない）。
