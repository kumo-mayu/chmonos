# Unity プロジェクトの VPM（今の決め事）

> **要点**：Unity プロジェクトに VPM（VCC・ALCOM）で入っているパッケージを**読むだけで控え**、同じ GUID の物を unitypackage で送る前に窓で言う（入れる・消す・版を変えるはしない。plan 40・ユーザ判断 2026-11-11「作りましょう」）。
> きっかけは、VPM で入っている物と同じ GUID・違う中身の物を unitypackage で取り込むと、Unity が `Assets/` に作らず `Packages/` の中の VPM のファイルを黙って上書きすること（[実測]・`docs/research/vpm-duplicate-guid.md`）。
>
> **コード**：`Core/Services/VpmPackages.cs`（読む）・`VpmOverlaps.cs`（照らす）・`UnityProjectScan.Vpm`・`Storage/UnityScanStore`（控え）、`App/Services/UnityVpmGuard.cs`（聞く）・`UnityImportQueue`・`ApiUnitySender`（409）・`ViewModels/ModificationHubRows.cs`（`HubProjectDetail.VpmText`）
>
> 送る前の決め事（Unity への受け渡しの全体）は [unity.md](unity.md)、改変の画面は [modifications.md](modifications.md)。

## 読む物

- `Packages/vpm-manifest.json` の `dependencies`（人が入れた物）と **`locked`**（それが連れてきた物）。版は `locked` が先（実際に解決した版）。
  `locked` も読むのは、確かめ用のプロジェクトで Modular Avatar が連れてきた NDMF が `locked` にだけ書かれていたため（`dependencies` だけ見ると手で置いた物と取り違える）。
- `Packages/*/package.json`（`name`・`displayName`・`version`）。manifest に無い、手で置いた埋め込みの物も拾う（unitypackage で上書きされるのは同じ）。
  名前は `package.json` の `name` が正（フォルダの名前と違うことがある）。`package.json` の無いフォルダ・隠しフォルダ（`.git` など）はパッケージと見ない（Unity も読まない）。
- 1つの行は「名前・表示名・版・フォルダ・manifest にあるか」（`VpmPackage`）。版はフォルダがあれば `package.json`、無ければ manifest の物。
- 壊れた JSON・欠けた欄・形の違う欄は無いのと同じにし、読めた分だけ返す。1MB を超える物は読まない（手元の manifest は 1.4KB）。
- 確かめ用のプロジェクトで9本・27ms（JIT を含む。2026-11-11）。

## いつ読み、どこに控えるか

- **プロジェクトの中を調べる時と同じ時**（`AppServiceContainer.ScanUnityProject`。検索の条件「Unityプロジェクト」・使っている商品の見張り）に読み、調べた結果の控え（`unityscans/`）の `vpm` に書く。
- **形式の版は上げない**：控えは消しても調べ直すだけの写しで、欄の無い前の控えは「まだ読んでいない」（`Vpm` が null）と読めば足りる。空の配列は「読んだが1つも無い」。
- 照合の結果ではないので、`FindsSameAs`（一覧を組み直すか）には入れない。場所の付け替えでは、控えごと新しい場所へ写る（[modifications.md](modifications.md)「場所を付け替える」）。

## 見せる所

- **改変の画面のプロジェクトの右の欄**の「VPM」の行。1つ1行で「表示名 版」（表示名が無ければ名前）。並びは見せる名前の順。
  manifest にあってフォルダが無い物には「：フォルダが見つかりません」、manifest に無い物には「：手で置いたもの」と添える（どちらも VCC・ALCOM の一覧と見比べたときに食い違って見える）。
  行は多くても十数本なので畳まない。見出しは値の1行目にそろえる。
- 控えが無い（改変に紐付けておらず、開いてもいないプロジェクトは調べない）ときは「Unityで開くと表示されます。」、1つも無ければ「ありません。」。
- 読むのは右の欄を出す時（控えの小さなファイルを画面のスレッドで読む）。出している間に調べ直しが終わっても差し替えない（選び直すと新しい物）。

## 送る前に重なりを言う（`Core/Services/VpmOverlaps`・`App/Services/UnityVpmGuard`）

- 「Unityへ送る」のどの入口（商品ページ・カードの右クリック・検索の複数選択・改変の「使ったものを順に」と「Unity ▾」・「Unityで選択」から送る・API）でも、送り始める前に1回だけ照らす。
  画面の送りは送る列（`UnityImportQueue.RunAsync`）の頭で、送り先の場所を引いた後に照らし、重なる包みだけを聞き終えてから1件目を送る（取り込み画面の合間に聞くと Unity の窓と入れ替わりに出て読みにくい）。
- **照らし方**：送る unitypackage の GUID（中身の控え `unitypackages/` から読むだけ。`UnityPackageReads.StoredOnly`。zip は解かない・控えに書き足さない）と、
  送り先のプロジェクトの `.meta` の GUID（「Unityで選択」と同じ表 `UnityProjectGuids.ForProject`）を当てる。VPM の一覧はその場で manifest から読む（27ms ほどで、控えより新しい）。
  数えるのは **manifest にある VPM のフォルダ**（`package.json` を持ち、`dependencies` か `locked` に書かれた物）の中だけ。数えない物は2つで、どちらも入れ直すたびに「上書きされます」と言い、入れたい物そのもののチェックを外させてしまう：
  - `Packages/` の下でも manifest に無い物（`package.json` の無い実フォルダ・手で置いた埋め込みの物。unitypackage が自分で入れた BlendShare などで、`package.json` を同梱する物もある）
  - VPM のフォルダでも、unitypackage の中の置き場が同じ `Packages/<フォルダ>/` の物（その包み自身の入れ直し。配布元が出す unitypackage 版など）
  unitypackage の中のフォルダの項目は数えない（「ファイルが n 個」と言う）。照らす包みも VPM のフォルダも無ければ、`.meta` の表を作らない。
- **照らせない物は黙って送る**：中身の控えが無い包み（単体の unitypackage・登録したフォルダの中の物はハッシュが無く控えを作らない。zip でも取り込みの裏がまだ読んでいない物）と、送り先の場所が分からないエディタ（題から言い当てられない）。照らすのに失敗したときも送る（取り込み画面は人が見る）。
- **`.meta` は送る時に読む（控えない）**。2026-11-11 に確かめ用のプロジェクト（`Packages/` の `.meta` 2,588・`Assets/` 996）で測った [実測]：
  - 1本ずつ読むと、冷えた `Packages/` の 2,588 個で約16秒（PowerShell・別の担当の試験と並行）。温まった後は 417ms。一覧だけなら 37〜58ms
  - アプリと同じ道（8本並べて読む・更新時刻で使い回す）で表を作ると、最初の1回が約2.0秒（`Packages/` は直前の1本ずつの読みで OS に温まっていて、`Assets/` だけ冷えていた。全部が冷えた値は測っていない）、OS が温まった後の新しいプロセスで 133ms、同じプロセスの2回目は 37ms
  - 表はアプリを開いている間プロジェクトごとに覚え、2回目からは更新時刻の変わった物だけ読むので、控えても速くなるのは「アプリを開いて最初の1回」だけ。控えると1プロジェクト約 2,600 行の GUID とパスを書き、古くないかを見るには結局一覧を取り直す。
    同じ表は「既に全部入っているか」の照合（パスで見つからない物があると作る）でも使うので、重なる物を送るときは照らさなくても同じ時間が掛かっていた。
  - 照らしている間は送る帯に「送る前に、VPMとの重なりを確かめています…」を出す（裏のスレッドで読む）
- **窓**（選ぶ窓 `ChoiceDialog`。題「Unityへ送る」、連続で2つ以上重なれば「（1/2）」）：
  - 1行目「「{包み}」の中に、VPMで入っている{VPM}と同じファイルが {n} 個あります。」、2行目「取り込むと、VPMの{VPM}が上書きされます。Unityの取り込み画面で「{場所}」のチェックを外してください。」
    場所は、重なるファイルが unitypackage の中で入る場所の共通の頭。`Assets` だけ・共通の頭が無いときは場所の代わりに「{VPM}のファイルのチェックを外してください。」（「Assets のチェックを外す」は全部を外させる文になる）。VPM が2つ重なれば「・」で並べる。
  - 送る物が1つなら［送る］［やめる］、2つ以上なら重なる包みごとに［送る］［これを飛ばす］［残りすべてを中止］（1件ずつ聞く窓の決まり。[ui-dialogs.md](ui-dialogs.md) D11）。キャンセルのボタンは並べず、やめる側が Esc と ×。
  - **既定のボタンは置かない**（Enter で送らない。選ぶ窓の決まりのまま）。止めはしない：取り込み画面でチェックを外せば避けられ、中身が同じなら何も起きない。
  - **静かにする設定（`QuietUnitySend`）でも窓で聞く**（取り込みの後に何も出ず、通知では押す前に読めない）。「送ります」の確認と2枚続くことがある（確認を減らすより、上書きを言う方を取った）。
- 答えの扱い：飛ばした物は「VPMと同じファイルがあるので、飛ばしました。」、やめた物は「送るのをやめました。」を理由に持ち、人が止めた物と同じに数える（失敗の ⚠ にしない。`UnityImportQueue.IsStopped`）。
  終わりの知らせ（`UnityQueueOutcome.Describe`）は飛ばした数を「{n} 件はVPMと同じファイルがあるので飛ばしました。」と別に言い、止めた・送れなかった物の文と混ぜない（飛ばした後に「中止」を押したとき、取り込み画面の閉じ方が隠れないように）。送れなかった一覧（`FailedNotChosen`）にも入れない。
  **何も送らずにやめたとき（`AllDeclined`）は何も言わない**：窓で選んだ直後で、何も起きていないのは見れば分かる（どの入口でも。「やめました」の窓をもう1枚出さない）。
- **「改変に追加して送る」は記録の前に聞く**（記録してから送る決まりなので、送る列の中で聞くと、やめても記録だけ残る）。やめたら何もしない。飛ばした物は記録にも入れない。送る列ではもう聞かない（`askVpm: false`）。
  改変の「使ったものを順に」で選んだ物を行に記録する分（`RecordModificationMemberFiles`）は、送る列の中で聞く（選んだことの記録で、送ったことの記録ではない）。
- 外から使う API は窓を出せないので、**送らずに 409 `vpmOverlap`** で返す（文にどの包みが・どの VPM と・何個・どの場所で重なるかを書く）。承知で送るときは要求に `allowVpmOverlap: true`（1件の送りも改変から送るときも）。
  答えに重なりを添えて送る案は採らなかった：202 を返した時点で取り込み画面が出ており、頼んだ側が読んで止める前に人が Import を押せば上書きされる。照らすのは 202 を返す前（送りの錠の中）。
- 確かめていない：Unity の取り込み画面で、重なる物がどう並ぶか（「変わった物」の印が付くか）[要確認]。実際の Unity では送っていない（試験と作り物のプロジェクトのフォルダで確かめた）。

## 外から使う API

- `GET /v1/unity-scans` の答えに `vpm: [{ name, displayName, version, folder, inManifest }] | null` を足した（[local-api-stored.md](local-api-stored.md)）。null は読んでいない。API は読み直さない。
