# 改変の記録（今の決め事）

> **要点**：改変＝**アバター1体＋名前**（1体に複数持てる）。構成物（使った商品・種類・zip・unitypackage）を**導入の順**に並べ、写真・Unityプロジェクト・メモを持つ。
> 目的は「再現できる」と「思い出せる」。1改変1ファイル。どのファイルを使ったかは推定で埋めない。ナビの「改変」で3つの見方（プロジェクト・アバター・改変）から辿る。
>
> **コード**：`Core/Models/Modification.cs`（`ModificationRecord`）・`Core/Services/ModificationService.cs`・`ModificationUsage`・`UnityProjectMatcher`・`UnityProjects`、
> `App/ViewModels/ModificationViewModel*.cs`（詳細）・`ModificationHubViewModel*.cs`（改変の画面）
>
> **経緯**：`docs/history/modifications.md`（30問のgrill・刷新 §9）、`docs/research/modification-canvas.md`（キャンバス・未実装）

## 持ち方

- `modifications/mod-{hash8}.json`。ID は `avatarItemId＋name＋createdAt` から作って以後変えない（名前を変えてもファイルが動かない）。**1ファイルにまとめない**（壊れたときに全部失う）。
- 項目：`avatarItemId`・`name`・`createdAt`・`updatedAt`・`unityProject`（0か1。消えていても黙って外さない）・`memo`・`images`・`members`。
- `blueprintId`（2026-09-19）：VRChat にアップロードしたアバターの ID（`avtr_…`）。改変の詳細の名前の下に欄と「VRChatで着替える」。
  押すと VRChat の OSC（`127.0.0.1:9000`）へ `/avatar/change` を UDP で送る（`Core/Services/VrcOsc`・形の試験あり）。送りっぱなしなので着替えたかは分からず、送ったことと確かめ方（OSC を有効にする・着られるアバターか）を言う。
  形（`avtr_` ＋ GUID）が違えば欄の下で知らせるが、保存は止めない。
  送る形は隣のリポジトリ `avatar-image-pad` の `measure/osc/local-probe.js avatar` と同じバイト列（2026-09-19 に照らした）。着替えたかを知るには、そちらの `Paramroom.Core/VrcConnection.cs` のように OSCQuery で `/avatar/change` を受ける道があるが、**入れない**（ユーザ判断 2026-09-19：「送信だけなのでOSCQueryを入れる必要は無い」。ライブラリと受け口が増える）。
- 改変の詳細の**名前・メモ・blueprint ID は押さずに残す**（打ち止めて 0.8 秒で書く。ユーザ指示 2026-09-19：タグ・属性・アバターのメモと揃える）。名前は空なら書かない。
- **状態（作りかけ・完成）は持たない**（増えると使われなくなる。`usedOn` が0件だったのと同じ道）。
- 同じ名前を許す（作るときに知らせる。一覧に日付も出す）。アバターが登録簿に無ければその場で足す。
- ワールドの改変は別の構造にする（ここでは扱わない）。
- **改変を選ぶ窓の「どのアバターの改変か」の候補は、持っているアバター → 区切り線 → ほかのアバターの順**（メモ32-② 2026-10-04。それぞれ名前順。区切りは `SuggestBox.PrimaryCount`。
  絞り込んでも群の順は崩さず、片方しか残らなければ線は出ない）。持っているは所持の定義（ファイルかフォルダを1つ以上）か、アバターの管理で「所有している」と手で指定した物。
- **改変を選ぶ窓の「今ある改変に追加」は、一覧の上の探す欄で絞れる**（ユーザ指示 2026-10-05・メモ41）。語を空白で区切り、全部の語が、改変の名前・アバターの名前・Unity プロジェクトの名前（場所の最後の部分）のどれかに入っている改変だけを出す（部分一致。大文字小文字・かなの種類・全角半角は区別しない）。
  当たった行は、名前以外で当たったときだけ小さく「アバター：〇〇　プロジェクト：〇〇」と出す（名前は行に出ているので言わない。タグの管理の「何で当たったか」と同じ考え）。絞って選んでいた改変が外れたら選びを解く。0件なら「当たる改変がありません。」。
  検索画面の書き方（`-語`・`OR`・`name:`）は載せていない（商品を探す書き方で、改変の名前3つを探すには重い）。「どのアバターの改変か」の候補には絵（商品の1枚目・無ければ控え・それも無ければ頭文字）を付けた（`SuggestBox.IconSelector`）。
- **改変の画面の折り畳みの三角は、行の高さいっぱいが押せる**（メモ32-① 2026-10-04。幅は 18 のまま：中身の縦線を三角の真下に下ろしている）。
  改変の行は、三角を行の頭に寄せるために枠が三角の大きさ（18×6〜9）しか無く、押せる所が小さかった。見出しの文字・行のほかの所を押すと、これまでどおりその行を右に出す。

## 構成物（`members`）

| 項目 | 何のため | 埋まり方 |
|---|---|---|
| `itemId` | どの商品か | 常に |
| `variationId` | どの種類か | 分かれば（送ったファイルに種類が付いていれば） |
| `fileHash` | どの zip か＝版 | Unity へ送ったときと、手で足すときに窓で選んだとき |
| `package` | zip の中のどの unitypackage か（依存物と本体が同じ zip にある） | 同上（unitypackage の無いファイルを選んだときは空） |
| `addedAt` | いつ積んだか | 常に |

- **並びが導入の順**（送った順に入る。手でも並べ替えられる：再現が目的なので順番が違うと役に立たない）。
- **手で足すときは、使ったファイルを窓で選べる**（メモ26-②・ユーザ判断 2026-10-04）。入口は改変の詳細の名前で足す（小さな窓「使ったものを追加」）・商品ページと右クリックの「改変に追加…」・選んだ物をまとめて足す（どれも改変を選ぶ窓の中に「使ったファイル」の欄）。
  - 選べるのは手元のファイル（外した物を除く）：zip の中に unitypackage があれば unitypackage ごと、無ければファイルごと。中の一覧は記録の `contents` から引き、zip を開かない。**フォルダは選べない**（中身のハッシュを持たない）。
  - **最初は何も選ばない。選べる物が1つだけならそれを選んでおく**（窓の中で「選ばない」に戻せる）。選ばずに「追加」で今までどおり空。窓を出さずに黙って入れることはしない。選べる物が無い商品は欄を出さない（名前で足すときは窓も出さない）。
  - まとめて足すときは**窓は1つ**で、商品ごとに名前と選ぶ欄を並べる（商品ごとに窓を出すと数十回聞かれる）。既に入っている商品は今までどおり重ねて足さない。
  - 選んだ物は `fileHash`・`package`・分かれば `variationId` に入る。Unityへ送って入った記録とは**言い分けない**（どちらも人が選んだファイルで、送るときも同じに使う）。行には unitypackage の名前、無ければファイルの名前を出す。
- 選ばなかった行は `fileHash` と `package` が空のまま「どのファイルを使ったかは分かりません」と出す。ただしその行を Unity へ送るときに**人が選んだ物は記録する**（選んだ物で行を置き換え、2つ選べば2行。`addedAt` は元のまま）。
- 構成物が手元から消えても記録は残す（過去の事実。「手元に無い」と出すだけ）。
- 商品の「IDを変更」では改変の記録も読み替える。
- 同じ商品は何回でも入る（別の版で2回）。商品ページには何回入っているかを出す。
- **外す（`detached`）と削除の二段**（ユーザ指示 2026-09-19：商品の手元のファイルと同じく戻せるように）。「外す」は印を付けるだけで、行・使ったファイルの記録・並びの位置は残り、薄くして「外した」の札を出す（確かめない・戻せる）。
  外した行には「戻す」と「削除」。**削除は完全に紐付けを解く**（聞いてから。使ったファイルの記録も消え、足し直しても送るまで戻らない）。
  外した行は使った数・送る（順に送る・Unity ▾）・候補・絞り込み・「この商品を使った改変」・改変の画面の一覧に入れない（`ModificationRecord.UsedMembers`）。商品の「IDを変更」の読み替えは外した行も含む。
  前は「外す」で確かめずに行ごと消え、記録も戻らなかった（動線の洗い出し B1）。

## 画像

- `images/_mods/{改変ID}/`（`images/` の外に出すと容量の集計や掃除から漏れる。`_` で商品IDと避ける）。
- 改変が自分の画像を持つ（商品の画像とは別）。何枚でも、まとめて足せる（ファイル選択・ドロップ・貼り付け）。並べ替えと削除は商品と同じ。
- 長辺 768px（原寸も選べる、既定は切）。見て思い出すためのもので細部が要る。
- 写真の欄は商品と同じ部品（`ItemGalleryPanel`）。「何枚目」は2枚以上のときだけ出す。**0枚なら大きい絵の所に「この改変の写真はまだありません」と貼り方を出す**（ユーザ指示 2026-09-14：意味の分からない黒い丸はストレス）。
- 改変の一覧の行の頭の絵は、写真の1枚目。無ければアバターの絵。

## Unity プロジェクト

- 改変1つにプロジェクトは0か1。プロジェクトから見ると多対1。**プロジェクトは同一性ではない**（消しても改変は残す）。
- 紐付ける入口は候補一覧（Hub の `projects-v1.json`・VCC の `userProjects`）。**今開いているものには目印を付けて先に並べる**（`Temp/UnityLockfile` で見分ける。紐付けたいのは大抵これ）。候補は開くたびに読み直し、こちらで持たない。
  （設計の時点では別のボタン「今開いているUnityを登録」も考えたが、候補一覧の目印と並び順に吸収した。2026-09-23 の点検で spec だけ残っていたのを直した）
- 既に紐付いている先を**替える・外すときは聞く**（点検 2026-09-23・B3）。今の紐付け先の名前と場所、残らないこと、戻し方を出す。前の先が候補の一覧に無ければこの画面から付け直せないので、そう書いて既定のボタンをキャンセルにする。まだ紐付いていないとき・同じ先を選び直したときは聞かない。
- 「開いている」は、印（`Temp/UnityLockfile`）があり、**Unity が1つでも起動しているとき**だけ（ユーザ指摘 2026-09-14：落ちて残った印で「開いています」と出ていた・`UnityProjects.IsProjectOpen`）。
- 「Unityで開く」：開いていれば手前に出す（「既に開いています。手前に出しました」と言う）。版が無ければ Hub に任せる。Hub も無ければ渡さない（受け手の無い `unityhub://` を開くと嘘になる）。
  エディタの探し方は `docs/spec/unity.md`。
- **プロジェクトの中を調べる**：手元の zip の中の unitypackage のパスがプロジェクトに実在するかを数える（`UnityProjectMatcher`）。ファイルだけ数え、2つ以上の商品に同じパスで入っているファイル（同梱の lilToon など）は数えない。
  1つでもあれば割合で並べて出し、**自動では足さない**（候補ごとの「追加」）。

## Unity へ送るときに積む

- unitypackage ごとに「Unityへ送る」（記録しない）と「**改変に追加して送る**」の2つ。送る前に「記録しますか」とは聞かない。
- 「改変に追加して送る」：送り先のプロジェクトに紐づく改変が0なら「作りますか」、**1個以上ならダイアログで選ぶ**（1個でも出す。「新しく作る」が答えかもしれない）。
  送り先が引けないプロジェクトなら絞らずに全部出し、絞れなかったと書く。新しく作った改変にはその場でプロジェクトを紐付ける。
- **記録は送る前に確定させる**（送った結果は返らない）。商品ページに「『普段着』に足して、Unityへ送りました。」を1行。
- 検索の複数選択「改変に追加」・商品ページの「改変に追加」は送らないので、どのファイルかは窓で選んだときだけ残る（「構成物」の手で足すとき）。既に入っている物は重ねて足さない。

## 「Unityで選択」

入っているかは、そのファイル（手で足した分は今ある zip の中身）のパスがプロジェクトにあるかで見る。

| 状態 | どうするか |
|---|---|
| 入っていて開いている | 最後に選んでいたプロジェクトタブで入り先のルートフォルダを開き、Unity を手前に出す。**結果が1件と言い切れなければ開かずに検索の結果で止める**。Packages の下は探さず場所の名前を伝える |
| 閉じている | 中を調べずに「プロジェクト『〇〇』がまだ開かれていません」とだけ言う（ユーザ判断 2026-09-19：入っているかより先に、開いていないことが要る） |
| 入っていなくて開いている | 取り込むか聞き、連続送りと同じ道で送る（改変に入っている時点で使う・使ったと分かっているので、このままでよい・同日） |
| 紐付けていない | 紐付けるよう言う |

商品ページとカードの「選択」（2026-09-19）は、改変に入っていない物も押せるので、入っていなければ言うだけで取り込みには進まない（`docs/spec/item-page.md`）。

## 操作の結果の知らせの置き場（メモ20-③・2026-10-04）

共通の決まりは `ui-empty-and-errors.md`「知らせの置き場」。

方針は `docs/feedback/notice-placement-2026-10-03.md`。欄やボタンのすぐ下の1行は `FieldNotice`／`FieldWarning`（`App.xaml`）で、改変の画面と詳細は `AreaNotice`（`AreaNoticeText`。文と警告の色）を持つ。

- **改変の画面**：VCC・ALCOM を開く（ボタンの下。見方の切り替えでも高さを変えない）、プロジェクトを開く（行と右の詳細の「Unityを開く」の下）、Unityで選択（使ったものの行と右の帯の下）、「改変を作る」の案内と失敗（アバターの右の「新しい改変」の欄の下）。
  行の下は出ているときだけ1行を足す（行は数が多い）。右の詳細は出ていない間も1行を取る。作れたことは言わない（右に作った改変が開く）。
  左の欄の下の帯（`Status`）に残すのは、読めなかった記録・開いていた改変や使ったものがもう無い・改変を消した。
- **改変の詳細**：名前・メモ・blueprint ID は自動で保存できたときは何も言わず、できなかったときだけ欄の下。
  着替える・プロジェクトを開く／紐付ける・足す・写真は押した欄の下、外す／戻す／削除／Unityで選択は使ったものの一覧の見出しの下、写真の追加と削除はギャラリーの下。
  上の帯の `Status` は「この改変を削除」の失敗だけ。
- 紐付ける先の候補の行は、版（`Caption`）と置き場所（`PathLine`）を分ける。置き場所を日本語の字体で出すと「\」が「¥」に見える。
- 右に組み込んだ商品ページ（使ったものを選んだとき）も、改変の詳細と同じく、横に送らずに済む幅を先に残して一覧を縮める。

- 「Unityで選択」の取り込む側は押して確かめていない。改変やプロジェクトが何十件になったときの一覧は見ていない。
- 改変とアセットを1枚に並べるキャンバス（調査済み・未実装）。
