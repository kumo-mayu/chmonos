# 保存データの形式の版と、新しい版の確認（今の決め事）

> **要点**：保存するファイルに**形式の版**を持たせる（ユーザ判断 2026-10-08）。アプリの版ごとに「読める形式の範囲」と「書く形式」を決め、
> 範囲内なら読み、**書くときは最新の形式で書く**。範囲より新しい形式を見つけたら、書き込まずに新しい版の Chmonos を案内する。
> 形式を上げる前の保存先は**控え**に写し、設定の「データ」で量を見て消せる。新しい版は GitHub の Releases に1日1回まで確かめる（設定で切れる）。
>
> **コード**：`Core/Storage/StoreFormat.cs`（版の決まり・保存先の印・控え）・`JsonStore`（ファイルごとの版を書く・見る）・`Core/Services/UpdateCheck.cs`、
> 起動の確かめは `App.xaml.cs`（保存先を確かめた後、サービス一式を作る前）
>
> **経緯**：点検22（2026-10-08 の夜間の点検）の [大] 2件「形式の版と移し替えの入口が無い」「新しい版で書いたデータを古い版で開くと欄が消える」。
> `docs/feedback/done-2026-10.md`。

## 版を2か所に持つ

- **ファイルごと**：オブジェクトの JSON は、いちばん外側の最初の欄に `"formatVersion": N` を書く。
  使う人が1件の JSON を手で直したり、別の保存先へ写したりしても、版が一緒に付いて行くように（ユーザ判断「ファイルごとが妥当」）。
  - **欄が無ければ 1**（v1.0.0 の形）。今あるデータは書き換えずにそのまま読める
  - いちばん外側が配列のファイル（`unresolved.json` など）は版を書けないので 1 とみなす。配列の形を変えるときは、外側を `{ "formatVersion", "items" }` に包む移し替えを書く
- **保存先ごと**：`format.json` に「この保存先を最後に使った形式の版」を書く（`{ "formatVersion": N, "writtenBy": "1.1.0" }`）。
  起動のたびに書き込む裏の作業（期限の来た商品の取り直し・検出など）が、ファイルを1つずつ読む前に、保存先ぐるみで止めるため。
  ファイルごとに見て「そのファイルだけ書かない」は、裏の作業が中途半端に止まるので合わない（ユーザ判断 2026-10-08）
  - 無ければ 1（v1.0.0 が使った保存先、または初めて開く保存先）

## アプリの版ごとの決まり

- `StoreFormat.Current`（書く版）と `StoreFormat.OldestReadable`（読める最も古い版）。v1.0.0 の次の版は両方 1
- **形式を上げる変更**：欄の名前・意味・型を変える、欄を消す、保存する列挙に値を足す（`JsonStringEnumConverter` は知らない値で例外を出すので、
  古い版がそのファイルを丸ごと読めなくなる）、配列を包む
- **上げない変更**：省略できる欄を足す。ただし古い版がそのファイルを保存すると、その欄は消える（下の「古い版に戻したとき」）
- 上げるときは、1つ前の版から今の版へ直す関数を書き（`StoreFormat` の移し替えの表）、**読むときに当てる**。書くときは今の版で書く。
  移し替えは読むたびに当たるので、書き直されなかったファイルも毎回正しく読める

## 起動したとき

順序は **保存先が見つかるか → 初回の窓 → 版を読む（読むだけ） → サービス一式（多重起動の錠） → 控えと印を書く → 主の画面（裏の作業）**。
版を読むのはサービス一式より前：新しい版の保存先だと、組み立てが設定を読む所で「読めない」と止まり、何が起きたかを言えないため。
控えと印を書くのは錠を取った後：錠より先に書くと、開いている古いバージョンの横で印だけ上がり、古いバージョンが前の形式で書き続ける。

| 保存先の版 | すること |
|---|---|
| 書く版と同じ | そのまま開く |
| 書く版より古い（読める範囲） | 控えを取ってから `format.json` を今の版にして開く。ファイルは読むときに移し替え、書くときに今の版になる |
| 読める範囲より古い | 開かない（今は起こらない。読める範囲を縮めるときに窓を決める） |
| 印が在るのに読めない | **開かない。**読めない印を今の版とみなすと、新しいバージョンの保存先を止められない（点検26） |
| 書く版より新しい | **開かない。**窓「このデータは、新しいバージョンの Chmonos で使われています。」［ダウンロードページを開く］［閉じる］。どちらでも終わる |

- 控えが取れなかったら（容量が足りないなど）開かずに終わる。移し替えた後で戻せないのを避ける
- **印が無い保存先は版 1 として比べる**（v1.0.0 の保存先）。今の版が 2 以上なら、控えを取ってから印を書く（点検26：前は印を書くだけで控えを取らなかった）
- 錠を取った後に版を**読み直してから**控えと印を書く（錠を取るまでの間に、別のバージョンが形式を上げて終わることがある）
- unitypackage の控えは、新しすぎる物を書き直さず、zip も解き直さない（点検26。読めない控えは捨てて書き直すが、新しすぎる物は壊れていない）
- メモ帳で付く UTF-8 の印（BOM）は除いてから読む（点検26：版を読むためにバイト列で読むようにして、読めなくなっていた）
- 引越し・戻すで別の保存先へ切り替えるときも、開き直す前に同じ確かめをする

## 形式を 2 に上げるときに足りない所（点検26）

今の入口は、オブジェクトの欄を直すだけなら足りる。次の物は、上げる前に足す。

- **配列・辞書のファイルは移し替えを通らない**（`JsonStore` は版を持てない型を、版を見ずにそのまま読む）。配列を `{ formatVersion, items }` に包む直し方と、
  包む前・後の両方を読める読み口を、ファイルごとに作る。未確定の一覧が在るかを頭だけで見る `ArrayHasItems` も合わせる
- 型だけでは、どのファイルかを見分けられないことがある（同じ `List<T>` の形）。直し方はファイルごとに結び付ける
- 配列の中に保存される列挙（知らせの種類・途中の操作）に値を足すときも、形式を上げる
- 途中の操作の記録に保存した商品の指紋（`OperationFingerprint`）と、移し替えた後の商品の指紋の関係を決める（再開の判定が変わる）
- 控えを取った後・印を上げる前・上げた後・ファイルを書いている途中で止まったときの試験
- 初回の窓は版を確かめる前に設定を書く。既にある新しいバージョンの保存先を選んだときに、確かめる前に書き込まないよう順序を見直す

## ファイルが新しい版だったとき

保存先の版は合っていても、1件だけ新しい版のファイルがある（新しい版の保存先から JSON を手で写した）ことはある。
そのファイルは読まずに `FormatTooNewException` で止め、**書かない**（読めない記録として扱い、上書きしない）。
商品の記録なら通知の「読めない記録」に出る。壊れた記録と同じく、自動ではよけない（よけるのは人が通知から選んだときだけ）。

## 古い版に戻したとき

- この仕組みを持つ版どうしなら、保存先の版で止まる（上の表の「新しい」）
- **v1.0.0 はこの仕組みを知らない**。v1.0.0 で新しい版のデータを開くと、今までどおり知らない欄が消え、知らない列挙の値のファイルは読めない。
  止める方法は無いので、形式を上げる前の**控え**で戻せるようにする

## 控え

- 形式を上げる前に、保存先の JSON を `format-backups/v{古い版}-{日時}/` へ写す（同じ相対の場所に）。
  写すのは保存先の直下の `*.json`、`items/`・`modifications/`・`unitypackages/` の `*.json`。画像・`.cache`・`logs`・`items/.prev` は写さない
  （画像は形式を持たない。控えの控えは要らない）
- 自動では消さない。戻したくなったときに無いと困るため。消すのは設定の「データ」から
- **設定の「データ」に「控え」の行**：他の行と同じく、容量とファイル数を最初から出す（ユーザ判断 2026-10-08）。消すのは `UiCommand.DeleteFormatBackups`。［控えを削除…］で確かめの窓
  （何件・何 MB か、元に戻せないこと）を出して消す。控えが無ければ「控えはありません」でボタンは押せない
- NullPriceFix の控え（`backup-null-price-*`）は入れない。テスターの1人のための道具で、今の版以降は作られない（ユーザ判断 2026-10-08）
- `items/.prev`（1つ前の版に戻す）・`items/_broken`（よけた記録）は入れない。アプリの仕組みの一部で、まとめて消すと「戻す」「救う」ができなくなる
- 引越しでは保存先ごと運ぶ。書き出し（`BackupArchive`）には入れない（戻したい時点のデータそのものではなく、書き出しが倍に膨らむ）

## 新しい版の確認

- 起動の後、裏で GitHub の Releases の最新（`/repos/kumo-mayu/chmonos/releases/latest`。下書きとプレリリースは返らない）を聞き、
  自分の版より新しければ主の窓の下に帯を出す（登録し終えた知らせの帯と同じ場所・同じ見た目）：「新しいバージョン（v1.1.0）があります。」［ダウンロードページを開く］［×］
- **1日1回まで**。最後に確かめた日時と、×で閉じた版は `update-check.json` に書く（`notifications.json` に知らせの種類を足すと、
  v1.0.0 が知らせのファイルを丸ごと読めなくなるため、別のファイルにする）。×で閉じた版は、次の版が出るまで出さない
- **設定で切れる**（「新しいバージョンを確かめる」・既定は入）。画面とマニュアルでは「バージョン」と書く（`ui-terms.md`）。切ったら通信しない
- BOOTH ではないので `BoothClient` の門は通さない。短く待って（10秒）、失敗はログだけ（画面には出さない）
- 試験では通信しない（確かめる口を差し替え、`TestApp` は何もしない物を入れる）。写しで起動したアプリは、1日1回 GitHub へ聞きに行く
- 通信する先が増えたので、README・マニュアル・BOOTH の原稿・zip の README の「通信する先」に GitHub を足す
- 自動で入れ替える機能は作らない（ユーザ判断 2026-10-08）。署名が無く、落とした物が本物かを確かめる手段と、止められたときに戻す道が要るため
