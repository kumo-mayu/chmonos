# 対応アバターと共通素体（今の決め事）

> **要点**：対応アバターは保存済みの説明（`items/{id}.h2.html`）・タグ・種類名から検出する（取り込み済みなら通信ゼロ）。照合は完全一致、別名は毎回事実から導き直す。
> 共通素体は**名前**をキーにしたグループで、配布されていれば商品IDも持つ。商品は素体への宣言だけを持ち、アバターとは検索の側でつなぐ。
> 判定結果・相性・所有は保存せず毎回計算する。正解付きの試験データで適合率 99.7%・再現率 99.1%（素体経由を含む）。
>
> **コード**：`Core/Services/AvatarDetector.cs`・`AvatarService*.cs`・`AvatarNameIndex`・`AvatarCompatibilityIndex`・`AvatarText`・`AvatarNames`・`AvatarBaseSeed`、
> `Core/Models/AvatarRegistryEntry`・`AvatarBaseGroup`・`AvatarLink`・`AvatarBaseLink`、`App/ViewModels/AvatarsViewModel*.cs`、`experiments/AvatarEvalBench`・`AvatarNameBench`
>
> **経緯**：`docs/history/avatars.md`（BOOTH 約1,300件の実測・操作の一覧・再測定・採用した案）、`docs/history/grill-2-ui-and-data-model.md`

## アバターかどうか（⓪）

- category が「3Dキャラクター」なら常に。`Booth.Category` か `Local.Category` のどちらか（`docs/spec/private-items.md`）。
- **「3Dモデル（その他）」「VRoid」は対応アバター節（見出し「検索用」なども含む）から挙がったときだけ受け入れる**（`SupportOnlyCategories`。素体はパーツとして出品されがち。無条件だと大鎌やテクスチャが入る）。
- ツール・テクスチャ・衣装・髪型・装飾品・素材は除く。登録簿は `IsAvatar=false` の負のキャッシュも持つ（lilToon など）。
- `AvatarOverride`（`null`＝規則／`true`・`false`＝人の上書き）が最優先。判定結果は保存しない（規則を直せば手元の JSON だけで全件計算し直せる）。
- 404 で category が引けない物は `category: null` で残し、勝手にどちらにも扱わない。

## 検出

- 読む所：h2「対応アバター」節（見出しの語は設定で足せる。「検索用」「プリセット」「位置設定済」「設定済みアバター」「セットアップ済」を含む）、
  平文の説明の対応リスト、h2 でない見出し行（「🌙 【対応アバター】」）の下、アバターの行が5行以上続く一覧、タグ、種類名、購入した種類。
- **読まない節**：クレジット・Special Thanks・使用素材・利用規約・注意・更新履歴・導入・同梱・内容物（クレジット節のリンクは34件中0件がアバター）。
- 対応節は `<a>` ではなく平文の「名前＋URL」なので、節のテキストに正規表現をかける。名前とIDが同じ行にあるので別名も取れる。
- **タグ・種類名は完全一致**（接尾辞・敬称を落として比べる）。英字の名前は語境界、カタカナだけの名前は前後がカタカナでないときだけ当てる（「リース」が「先行リリース」に当たった）。
- **別名は毎回、事実（そのアバター自身の正式名・タグ・対応節の呼び名）から導き直す**。当たったタグを積み上げない（「ティナ」が「ミルティナ」を覚えて誤りが固定された）。
- 説明文のその他のリンク（`H2Link`）は要確認に回し、**絞り込みでは数えない**（サムネやクレジットのアバターが「対応」に出ていた）。
- 文字列は NFKC ＋ 許可リスト（漢字・かな・カナ・ラテン・数字・長音符「ー」）で正規化する。
- 見送った物：「〇〇をベースに制作」などの言い回し（誤りのもとの言い回しと近すぎる）。
- 取り込みの③で走る。未知のアバターIDだけ category を問い合わせ、まず `items/{ID}.json` を見る。

## 商品に持つ物（`Local`）

| 欄 | 中身 | 書き手 |
|---|---|---|
| `avatars` | 出品者の宣言（`avatarItemId`・`source`・`confirmed`・`rejected`） | 検出（`Manual` 以外を作り直す）と人（`Manual`） |
| `avatarBases` | 素体を名指しした宣言（キーは名前） | 同上 |
| `avatarsDetectedAt` | 検出した日時 | 検出 |

- **再検出は `Source != Manual` だけを置き換える**。人が消した誤検出は `Rejected=true` ＋ `Source=Manual` にする（`Source` を変えないと次の検出で復活する）。
  **共通素体（`avatarBases`）も同じ**（ユーザ判断 2026-09-21・X3/X4：商品ごとの判断は数が多く人がやる物ではないので検出のままでよいが、誤検出を消す道は要る）。
- **商品に素体を手で付ける**（ユーザ判断 2026-09-28）：商品ページ・編集画面の対応アバターの「＋ 追加」の候補に「〇〇（共通素体）」を混ぜ、選ぶと `avatarBases` に `Manual`・確定で入る。
  候補は登録簿の素体のうち削除していない物で、その商品に付いていない物（`AvatarService.ItemBaseCandidates`。初期辞書だけの素体は出さない——付けてもつなぐ先が無い）。
  外した素体を選び直すと、行を増やさず消した印を下ろす（［戻す］と同じ）。アバターと同じ名前の素体があっても、添え書きの行で見分けて取り違えない。
- `source`：`SupportSection`・`Tag`・`Variation`・`SupportList`（confirmed）、`H2Link`（要確認）、`Manual`。
  **タグ・種類名・本文中の平文の一覧から拾った物も「確定」で入れる**（ユーザ判断 2026-09-21・X2）。
  商品ごとの対応アバターの登録は膨大で、人が1件ずつ選ぶ物ではない。誤りは上の「消す」で直す。
- 自分が使った記録は商品には持たない（`UsedOn` は外した。改変に持つ：`docs/spec/modifications.md`）。

## 登録簿（`avatar-registry.json`）

- 項目：商品ID・`displayName`（人が付けたときだけ）・`boothName`・category・ショップ名・`seenAs`（どの文脈で何回挙がったか）・`avatarOverride`・`baseName`・`isOwnedManually`・メモ・別名（`rejected` の印つき）。
  共通素体（`baseGroups`）は名前・`itemId`・`inferClothing`・メモ・`rejected`・`isManual`（手で足した）・別名。
- 検出は項目を作り直さない（部分的に書き換えるだけ）。書き込みは錠つき（`IAvatarRegistryEditor` を `UiCommand` から）。
- `detectedAt`：ライブラリ全体の検出を最後に終えた時刻（起動時の検出し直しの目安）。**登録簿を書き直す所はすべて引き継ぐ**（落とすと起動のたびに検出し直す）。
- **表示名**：`displayName` が `null` でなければ人の名前。自動の名前は保存せず、正式名の形から切り出す（`AvatarText.DisplayNameFrom`：タグと版を落とす → 括られた名前 → 区切りで割り、名前ではない語でない最初の部分 → 読みを括弧に）。
  名前が2通りなら「Ciel（シエル）」、同じ名前のアバターが2体以上ならショップ名を付ける（アバターでないと確かめた物は数えない）。「BOOTHの名前に戻す」ボタンで外せる。
- 別名を消すと：自動の別名は印を付けて残す（行を消すと次の検出で戻る）、手で足した別名はそのまま消す。印の付いた別名は照合にも一覧にも出さない。

## 共通素体

- **名前をキーにしたグループ**（配布されていない素体がある）。配布されていれば `itemId` も持つ。ショップでは括れない（同じ作者＝同じ素体ではない）ので、ショップを理由に質問しない。
- 所属は「#MARUBODY」「（えも研素体）」「+Head」のような手掛かりから自動で埋め、手でも足せる。
- **+Head は体の共通素体**（2026-09-11 に訂正）。`inferClothing`（衣装互換を広げるか）は仕組みとして残すが、実例は無い。画面のチェックは説明が無く何のことか分からないので隠している（2026-09-17）。
- グループの削除だけが取り返しのつかない操作：確認に**何件の商品が書き換わるか**を出す。改名で同名があれば統合（統合は戻らない）。
- **消したグループは行を残して `rejected` の印を立てる**（ユーザ判断 2026-09-21・X1）。行ごと消すと、初期辞書が足し直し、検出が作り直すので次の検出で丸ごと戻っていた。
  印の付いたグループは一覧にも照合にも出さない。同じ名前を手で付け直したら印を下ろす（別名の消し方と同じ作法）。
- **手で足す**（ユーザ判断 2026-09-28）：「共通素体」の一覧の上に候補付きの欄を置き、アバターを選ばずに素体だけを足せる（`UiCommand.AddBase`）。
  候補は一覧の素体（選ぶとその素体を開く）・消した素体（選ぶと戻す）・初期辞書の素体。別名は出さない（同じ素体が2つに割れる）。候補に無い名前は「（新規）」の行で選ぶ。
  **手で足した素体は `isManual: true` を持ち、検出し直しでは消さない**（検出は最新の登録簿の素体を残し、新しく見つけた物だけを足す）。消えるのは人が削除したときだけ（削除は上と同じく消した印）。
  アバターの詳細で新しい名前を打って作った素体・消した素体を付け直した物も手で足した物。既にある素体に後から印は立てない。欄が無ければ手で足していないと読む。
  足した素体は照合にも使うので、次の検出で商品の説明・タグに名前があれば商品の対応素体に入る。
- 素体名（`+Head` `まめふれんず` `珍飯亭共通素体` など）は初期辞書として少数同梱。外部サイトの整理済みリストは取り込まない（他者の労力）。
- **素体そのものの商品の候補**（2026-09-17）：`itemId` が無い素体に、登録簿のうち名前に素体名（か消していない別名）を含み、3Dキャラクターではない商品を最大3件「素体の商品に設定」付きで出す（`AvatarBaseItemFinder`）。**自動では結ばない**（推定は候補として出し、押したら入る）。友人のデータでは11の素体のうち3つに1件ずつ出た。

## 相性（検索で使う）

1. **直接対応** … 商品がそのアバターを名指し
2. **素体経由** … 同じ素体グループ（素体を名指し／同じ素体の別アバターを名指し）。**素体の兄弟は対応として数える**（「共通素体はその為の概念なので」）
3. **未確認** … それ以外。**「非対応」とは呼ばない**（対応情報が無いのと、合わないと確かめたのは別）

既定は 1＋2。3 は「対応が確認できていないものも含める」で広げる。相性は保存しない。

## 所有アバター

計算（登録簿のIDが所持している商品に含まれる）**∪** 手動指定。フラグとしては持たない。
並び順とまとまりの軸にはするが、絞り込みの既定にはしない。

## アバターの管理の画面（右の詳細）

2026-09-17 ユーザ指示で見直した。
- **所有**：取り込んだファイル（またはフォルダ）で持っていれば「所有している（ファイルあり）」で固定。持っていないときだけ「所有しているものとして扱う」を出す。
- **共通素体**：説明は置かない（使う人は分かっている）。基本は1つの素体にしか入らないので、一覧をマウスで押せばそのまま入る。矢印キーで候補を見ているだけでは入らず、Enter で入る（勝手に入らないように）。まだ無い名前も打って Enter で作る（押す前に「Enter で新しい素体『…』を作って入れます」）。ボタンは「素体から外す」だけ。
- **呼ばれ方**：畳む（件数を見出しに）。「対応アバターの検出に使うので、明らかに間違っている物以外は消さなくてかまいません」と書く。消した呼び方は末尾に取り消し線で出し、「戻す」で戻せる（足し直すと印を下ろすだけ）。
- **このアバターの改変**：改変の画面のアバターの項目と同じ行（絵・名前・Unityプロジェクト・畳んだ使ったもの。絵にホバーで大きめの絵。`ModificationRowBuilder` を共有）。右のビューが無いので、どれを押しても改変に入る。消すはここに置かない（改変の中で）。
- **アバターかどうか**：「今の扱い：アバター（自動の判定／手動で指定）」「今の扱い：アバターとして扱わない（…）」を文で出し、ボタン（自動の判定に任せる・アバターとして扱う・アバターとして扱わない）は繋がったボタン（並べ替えと同じ見た目）にし、今の扱いを塗って見せる。今の扱いを押し直しても何も書かない（点検 2026-09-23：押せなくするだけでは、どれが効いているか見た目で分からなかった）。
- **見出しのボタン**（この商品を検索で見る・商品ページを開く・BOOTHで開く）は名前の下の行に並べる。名前と同じ列に右寄せで重ねると「名前を保存」に乗った。
- **名前**：「名前を保存」は欄を今の名前から変えたときだけ出す。Enter でも保存する。名前は一覧の並びと見出しを変えるので、メモと違い押さずには書かない。
- **空の表示**：アバターが0件でも、商品を1件も取り込んでいなければ「まず商品を取り込んでください」と「取り込みを開く」を出す（検出しても何も見つからないため）。商品があれば検出を案内する。
- **検出の結果の1行**：数字は詰めて書く（「アバター6体 / 共通素体9グループ」）。更新が0件なら「n件を調べました。対応アバターに変わりはありませんでした」。
- **入力欄の案内**：改変の名前の欄に「新しい改変の名前（例：普段着）」、素体の商品の欄に「素体の商品のIDかURL」を内側に出す。
- **メモ**：保存ボタンは無い。打ち終えて0.8秒で書く。書くたびに一覧を読み直さない（打っている途中の欄が戻るため）。待っている間に別のアバターを選んだら、選ぶ前に元のアバターへ書く。
- **文言**（2026-09-17 ユーザ判断で提案18件を全部採用）：件数は「対応している商品 n件（ほかに共通素体経由 n件）」、根拠は「見つかった場所：…」（対応アバターの節は「説明文の「対応アバター」の見出し」）、「BOOTHで確認した日」。一覧の見出しは「対応商品で名前が挙がったアバター」。素体のカードは「この素体向けと書かれた商品 n件」「素体の商品：ID／なし」「素体の商品を設定」。「表記」「別名」は「呼び方」に揃える。

## アバターの管理の画面（左の一覧）

- リストとカードを選べる（2026-09-20・M4）。どちらで出すかはアバターの管理として覚える。
- **カードは検索画面の作り方（`Search.CardFor`）を通す。**自前で `ItemCardViewModel` を組むと、所持・容量・札の値が既定のままになり、
  所持している商品にまで「未所持」の襷が掛かった（2026-09-20）。
- **商品が手元に無いアバター（名前が挙がっただけ）には商品のカードを当てない。**中の結び付け先が全部外れて札が既定の「出す」になり、
  「所持」と「未所持」が同時に出ていた。代わりに絵（か頭文字）・名前・素体・「この名前の商品は手元にありません」だけの札を出す。
- カードでもリストの情報を落とさない：対応数は右上の札、素体名はその札のツールチップ、「アバターとして扱わない」は薄さで示す。
