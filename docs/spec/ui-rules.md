# 画面全体の決め事（今の決め事）

> **要点**：画面は同じウィンドウの中の差し替え。欠けや推定を隠さず、内部の言葉を画面に出さない。取り返しのつかない操作には取り返せるかを書き、空表示とエラーには次にやることを書く。
> 幅が決め打ちだった所は境目をドラッグで変えられ、画面ごとに覚える。画面の状態は設定ではなく `ui-state.json` に置く。
>
> **コード**：`App/MainWindow.xaml`（ナビ・常設の1行）・`App/Controls/PaneSplitter.cs`・`App/ViewModels/PaneColumn.cs`・`App/Services/PaneWidths.cs`・`Controls/SuggestBox`・`ChipStrip`・`ChoiceDialog`・`Shortcuts.cs`・`DropRouting`、`tools/wording.mjs`
>
> **経緯**：`docs/history/ui-revision.md`（ナビ・窓・ドロップ・文言）、`docs/research/ui-wording.md`（文言の総調査と用語）、`docs/feedback/done-2026-09.md`（U番号・画面の幅の範囲）

## 文言

- **否定に読める言い方をしない**（「既にライブラリにある商品です」は「登録できない」に読めた）。
- **内部の言葉を漏らさない**：item→商品、appTag→ユーザータグ（コード・JSON のキー・ファイル名まで揃えた）、BoothID→商品ID、variation→種類、マスタ→一覧、ハッシュ、実体→同じ中身（2026-09-19）。
- **破壊的な操作には取り返しがつくかを書く**。**空表示とエラーには次にやることを書く**（理由と戻し方・リンク）。
- ボタンは**何が起きるかを名乗る**（「今すぐ取り直す」→「BOOTHから取り直す」、「はい／いいえ」→「商品を開く」「画像として足す」）。確認は問いの形にし、どちらの意図か分からないから聞いているときは既定のボタンを置かない。
- 押しても何も起きないように見える物を作らない（結果は必ず言う。効かない選択肢は出さない・押せない理由を添える）。
- 新しい語を持ち込む前に `docs/research/ui-wording.md` を見る。抜き出しは `node tools/wording.mjs out.json`。

## 入力

- 入力欄には候補を付ける（`SuggestBox`）。候補に無い語は「新しく足す」と明示して選ばせる（表記揺れで名前でつないだ絞り込みが割れる）。
- **候補を全部並べて選ばせる画面は作らない**。候補付きの入力欄から1件ずつ積むか、畳めるようにする。
- 多い札（対応アバター・BOOTHのタグ）は50件までは全部、超えたら40件と「残り n を表示」。作った札は捨てずに隠す（`ChipStrip`：差し替えると全部作り直すため）。20体を超えたら「アバター名で絞る」欄。
- 探す語はひらがな・カタカナ／全角・半角／大文字小文字を区別しない。
- **保存のしかたが画面の中で分かれるときは、画面に書く。**編集画面の左（画像・星など）は押した時点で保存し、右は「保存して次へ」で保存する。
  この形のままにすると決めたので（ユーザ判断 2026-09-20・B7）、左の列の頭に「この列は押した時点で保存されます。右の欄は「保存して次へ」で保存します。」と出す。
- 名前を変えるのは**欄の中**（Enter か「名前を保存」。変えたときだけボタンを出す）。OS の入力窓は使わない（B10：共通素体だけ残っていた）。

## ナビ

- 208px ⇄ 56px に畳める（畳むとアイコンだけ、名前はツールチップ）。畳んでもアイコンの縦の位置は動かさない（見出しは同じ高さの小さなアイコン、区切りは同じ高さの細い線）。
- 並び：検索・改変・ショップ・フォルダ…／作業（取り込み→未確定→編集）／管理（要確認が先頭・アバター・タグ・属性）。
- バッジ：編集＝「未:n」（ユーザタグが無い商品のうち書きかけの無い物・茶）と「編:n」（書きかけのある商品・青）、未確定＝未確定の件数、要確認＝未読の件数。**0件のときは出さない**。操作の直後に数え直す。
- **戻るは行き先を名乗る。**上の「← ○○に戻る」も、編集を終えるボタンも、実際に戻る画面の名前を出す
  （B1：商品ページから編集へ入っても「検索へ戻る」と名乗っていた。行き先は `MainViewModel.LeaveEditLabel`）。
- 常設の1行（左下）：「何を n/N」（取り込み：画像を取得中 12/206、使っていない間の取得…）。応答待ちの再試行のときだけ通信の様子。作業が続いている間は合間でも畳まない（揺れる）。押すと取り込み画面へ。

## 言葉

- BOOTH の1商品の中の選択肢（DL版・色違いなど。コードとJSONでは `variation`）は、画面では**「バリエーション」**と呼ぶ（2026-09-18 ユーザ判断）。
  「種類」は分類（カテゴリ）の種類とも読めて紛れた。BOOTH の出品側が使っている語なので、外で調べても意味が一致する。コードの名前とJSONのキーは `variation` のまま。

- **アプリの中で開くのか、ブラウザでBOOTHへ出るのか**をボタンの名前で分ける。アプリ内は「商品ページを開く」「アバターの管理へ」、外へ出るものは「BOOTHで開く」。外へ出るボタンにはツールチップで「アプリの外へ出ます」と書く（ユーザ指摘 2026-09-18：どちらが開くのか分からない）。
  2026-09-20 に全部へ付けた（商品ページ・編集・カードの右クリック・ショップ・未確定の候補とブラウザで検索・商品ページの動画）。**行き先が無いときは押せなくし、理由をツールチップに出す**（BOOTHに無い商品として登録した物・店が分からない物）。
- 画面の名前は左上に太字で出す。**例外は検索画面**——左の「絞り込み」だけで検索だと伝わるので、画面を大きく使う方を採る（ユーザ判断 2026-09-20）。
- **BOOTHへ問い合わせて情報を更新する操作**は「商品情報を取り直す」と名乗る。「BOOTHから取り直す」はファイルをダウンロードするように読めた（同日）。ツールチップに「商品のファイルはダウンロードしません」と書く。

### 同じ操作は同じ動詞で呼ぶ（ユーザ判断 2026-09-20。W1〜W10・`docs/feedback/ui-consistency-2026-09-20.md`）

| 何を | 画面での言い方 | 使わない言い方 |
|---|---|---|
| Unity へ渡す | **送る**（「Unityへ送る」） | インポート・取り込み。**「取り込み」はこのアプリの画面の名前**なので、Unity 側の画面を指すときは「Unity の取り込み画面」と持ち主を付ける |
| 関係を切る（本体は残る） | **外す**（「商品から外す」「登録を外す」「紐付けを外す」） | 解除・（その意味の）消す |
| 未確定から片付ける | **管理対象から除外** | 管理から外す |
| さっきの操作を取り消す | **○○を解除**（「非表示を解除」「除外を解除」「紐付けを戻す」）——対象を名乗る | 裸の「解除」「元に戻す」「記録を消す」 |
| 永久に無くす | **削除** | 消す（入力欄を空にする × は「消す」のままでよい） |
| 2つを1つにする | **統合** | まとめる・寄せる |
| 結び付け | **紐付け** | 結び付け |
| 手元のフォルダを開く | **エクスプローラで開く** | フォルダを見る・フォルダを開く |
| 検索画面へ行く | **検索で開く**（「この商品を検索で開く」） | 検索で見る・絞り込んで検索 |
| 商品に付ける自分の語 | **ユーザータグ**（階層は**大分類／小分類**のまま） | 分類（BOOTH のカテゴリを指す「BOOTH分類」は別） |
| 見えている分を全部選ぶ | **全て選択** | 表示中を全て選択（どちらも見えている分に効くので言い分けない・B8） |
| 選んだ物を編集の画面へ | **○○を編集する**（未確定は「確定したものを編集する」） | 編集へ送る |

ナビの項目名は「タグの管理」のまま（長くなるため。ユーザ判断 2026-09-20）。画面の見出しは「ユーザータグの管理」。
要確認の束の見出し「タグの参照切れ」も変えない（ユーザが名指しで決めた語）。

### 並べ替えの出し方（ユーザ判断 2026-09-20・M5）

- **選択肢が3つまでは繋がったボタン、4つ以上はプルダウン。**見出しはどの画面も「表示順」で、一覧の上に置く。
- **検索は「使う項目」と「向き」を分ける**（項目はプルダウン、向きは2つなので繋がったボタン）。属性が増えるたびに選択肢が倍に増えるのを避ける。
- **向きの言い方は項目ごとに変える**：日付は「新しい順／古い順」、容量は「大きい順／小さい順」、数は「多い順／少ない順」、属性の値は「高い順／低い順」、名前は「あ→わ／わ→あ」。
  「昇順・降順」では、どちらが新しいのか・大きいのかが読み取れない。
- 項目を変えたら、その項目の既定の向きに戻す（「名前」を選んだのに「新しい順」のままにしない）。
- **検索の履歴に残るのは「入手日が新しい順」のような1つの言い方**。項目と向きに分けた後も、その言い方から戻せるようにしておく（前に残した履歴が効かなくなるのを避ける）。

## 要確認の画面

- 種別は6つ（商品ページの変更・消えたバリエーション・復活したバリエーション・タグの参照切れ・zipを入手した・非公開商品の復活）。「対応アバター確認」「同じ内容のファイル」は**要確認に出さない**（ユーザ判断 2026-09-18：件数が多く、かつ「起きたこと」ではなく「今の状態」なので、別の場所で「今の状態」として見る）。
  - 確かめていない対応アバター（説明文のその他のリンク＝対応と数えない推定）は、**商品ページの見出しに「確認待ち n」**、**検索の条件「対応アバターの確認」**で見る。
  - 同じ内容のファイルは**統計**（「ディスク使用量の内訳」の「うち重複コピー」と「空けられる場所」）で見る。以前からある。
- 束の件数は札にして、行に出る札と同じ色・同じ言葉で出す（重要＝注意の色、未読＝ナビのバッジと同じ色、解消済み＝灰。最後に全件数）。畳んでいる間もここだけで「何件あって何を先に読むか」が分かるようにする。
- 束の並びは、重要な未読がある種類を先に、その次は新しい知らせがある種類から（種類の宣言順では何から読めばよいか伝わらない）。
- 種別ごとに「ここを直す」ボタンを1つ出す（タグの参照切れ→タグの管理を開く、zipを入手した→展開フォルダの登録を外す、消えた／復活したバリエーション・非公開商品の復活→商品情報を取り直す）。
  「zipで登録しなおす」は、押すとzipをその場で商品に付け、展開フォルダの登録を外す（ディスクのファイルには触らない）。結果の1行で、zipで数えるようになったことを言う。
- 既読の印は行の左の丸で、右の「何かをする」ボタンとは分ける。読んだ行は薄くする（ユーザ判断 2026-09-18）。
- 操作のボタンは**本文のすぐ下、日時と同じ行**に、**指した行にだけ**出す。日時の行をボタンの高さ（28）で確保しておき、**行の高さは変えない**——出し入れで伸び縮みすると、境目にマウスがあるときに出たり消えたりして画面が揺れる。右端に置くと、行を読んでから押すまでに視線が大きく往復する。
- まとめて既読にするのは、全体と**束ごと**の2つ（選んで既読にする仕組みは持たない）。束の見出しの右に、未読がある束だけ出す。
- 行のタイトルは商品名だけ。何が起きたかは束の見出しが言う。行の本文はその行だけの事実（「消えたバリエーション：旧・支援版・旧・通常版」「ユーザータグ：衣装／夏」）にして、束の説明と同じことを書かない。
  消えたバリエーションは**名前で言う**。名前はBOOTHにもう無いので、取り直す前の `booth` と購入時に写した名前（`NameSnapshot`）から引き、どちらも無ければIDで言う。3件を超えたら「ほか n 件」。
- 行の中身は**どの種別も同じ札**で出す。変化を持つ知らせは変わったところを1つずつ（「前 → 後」。価格・商品名・バリエーション数は変化なので、後の値だけでは何が起きたか分からない）、持たない知らせは本文の「見出し：中身」を1枚の札にする。
- 日時は「3時間前」のように相対で出し、正確な日時はツールチップに置く（1週間より前は日付）。
- 未読の数え方は**未読かつ未解消**（ナビのバッジと画面で必ず揃える）。既読にしたら、保存を待ってから数え直す。
- 「未読のみ」の状態は覚える（`ui-state.json` の `inboxUnreadOnly`）。
- 行の要約の1行は、変わった項目の札が下に並ぶときは出さない（同じことを2回書かない）。
- 通知どうしの区切り線は薄くしない（`Border`）。行の高さも上下15pxにする（ユーザ指摘 2026-09-18：区切りが見えない）。
- 状況が解消したものは消さずに「解消済み」の札を付ける（未読のみの表示には出さない）。上限を超えたら既読と同じく古い方から捨てる。上限の適用は起動時にも1回走る。
- 宛先の商品が無くなっていた通知は、押したときに理由を出して解消済みにする。
- 「取得できる情報の形式の変化」は束に出さず、ナビの「設定」の上の帯で知らせる（アプリ全体の話）。押すと詳しい説明。読み取りが戻れば自分で消える。帯の配色はナビと同系の暗い色で、注意の色は左の縦線と文字だけに使う（ユーザ指摘 2026-09-18：明るいクリーム色は暗い帯から浮く）。
- 種類ごとに束ね、**束は畳める**（見出しのどこを押しても開閉。畳んだ状態は種類ごとにアプリを閉じるまで覚える）。件数は畳んでいる間も出す。
- 束の幅は中身の長さで変えない（畳むと札の幅が縮んで目が泳ぐ）。
- 見出しの言葉（ユーザ指定 2026-09-18）：商品ページの変更 / 対応アバター確認 / 同じ内容のファイル / タグの参照切れ / 消えた種類 / 取得できる情報の形式の変化 / zipを入手した / 非公開商品の復活。
  「取得できる情報の形式の変化」の説明は「BOOTHから取得できる情報の形式が変化した可能性があります。アプリの更新が必要かもしれません。」（BOOTH側の作りが変わったときに人が打てる手は、アプリの更新を待つことなので）。

## 窓と画面の状態

- 終了時の位置・大きさ・最大化（と解除したときの大きさ）を `ui-state.json` に。復元時に今のモニタのどれとも重ならなければ中央に戻す。
- ナビ・絞り込み欄の畳み方・積んだ条件の種類も `ui-state.json`。**設定画面には出さない**（アプリが覚える状態で、人が決める設定ではない）。
- 画面の中の畳み方（改変の画面の見出し・フォルダの木・購入した種類・タグの欄など）はアプリを閉じるまで覚える。
- 戻るは画面の履歴（`docs/spec/architecture.md`）。
- 別の窓（ダイアログ）のキー・ボタンの並び・確認のアイコンは [ui-dialogs.md](ui-dialogs.md)。

## 画面の幅

- 境目をドラッグで変える（`PaneSplitter`：GridSplitter。乗せると色が付く）。**境目のダブルクリックで1か所、設定画面の「全部を元の幅に戻す」で全部**を元の幅に戻す。
- 画面ごとに `ui-state.json` の `paneWidths` に覚える。ドラッグの間は手元で持ち、止まってから 0.4 秒で1回だけ書く。
- 組み込んだ画面（フォルダビューの右の商品ページ・改変の画面の右の改変）も境目を動かせる（ユーザ指示 2026-09-14）。単独の画面とは別の鍵で覚え、右側が狭いので既定と範囲を小さくしてある。
  未確定を組み込んだときは左の一覧を隠すので境目は無い。ナビと絞り込み欄は開いたときの幅だけ変わる（畳んだ幅は変えない）。
- 反対側の列には最小 360（商品ページ・改変の詳細の右は 320）を付けて潰れないようにする。

| 鍵 | 場所 | 既定 | 最小 | 最大 |
|---|---|---|---|---|
| `nav` | ナビ | 208 | 180 | 320 |
| `search.filter` | 検索の絞り込み | 286 | 240 | 480 |
| `folder.list` | フォルダビューの木 | 420 | 300 | 760 |
| `modifications.list` | 改変の画面の一覧 | 400 | 300 | 720 |
| `resolve.list` | 未確定の一覧 | 330 | 260 | 640 |
| `avatars.list` | アバターの一覧 | 360 | 280 | 640 |
| `tags.list`・`attributes.list` | タグ・属性の管理の一覧 | 340 | 260 | 600 |
| `item.left`・`modification.left` | 商品ページ・改変の詳細の左の列 | 660 | 460 | 1100 |
| `edit.right` | 編集画面の右 | 480 | 380 | 800 |
| `folder.item.left` | フォルダビューに組み込んだ商品ページの左の列 | 520 | 360 | 1000 |
| `modifications.modification.left` | 改変の画面に組み込んだ改変の左の列 | 560 | 360 | 1000 |

既定は分ける前の固定幅、最小は中身が崩れない幅、最大は反対側を潰さない幅。

### 商品のリストの列

- 商品をリストで出すとき（`docs/spec/search.md`「結果」）の列の幅も、見出しの境目をドラッグで変える（ユーザ指示 2026-09-14）。全部の行で同じ幅（GridView の列）。
- 画面ごと（`search`・`folder`）に同じ `paneWidths` へ `"{画面}.col.{列}"` の鍵で覚える（「全部を元の幅に戻す」でこれも戻る）。`ItemListColumns`・`PaneWidths.All`。

| 列 | 検索の既定 | フォルダビューの既定 | 最小 | 最大 |
|---|---|---|---|---|
| 選ぶ（`select`） | 36 | 36 | 28 | 60 |
| 絵（`icon`）。絵は列の幅−16 の正方形（最小28）で、行の高さもこれで決まる | 56 | 56 | 44 | 120 |
| 星（`fav`） | 36 | 36 | 28 | 60 |
| 名前（`name`） | 460 | 420 | 160 | 1000 |
| ショップ（`shop`。フォルダビューは「ショップ・場所」） | 200 | 260 | 80 | 500／600 |
| 状態（`chips`） | 220 | 220 | 100 | 420 |

- 改変の詳細の「使ったもの」（`modification`・ユーザ指示 2026-09-14）も同じ部品の列：順・絵（56）・星（36）・名前（160。2行目に使ったファイル）・操作（右端 200：▲▼・Unity ▾・外す）。
  左の列の中（既定で 500px ほど）に横に送らずに収まるよう、使ったファイルは列にせず名前の下に置く（列にすると右端の操作が画面の外に押し出された）。
- ボタンの文字はボタンの `Foreground` に従う（土台のボタンの見た目の中の `ContentPresenter` に置いた決まり）。
  アプリ全体の暗黙の TextBlock スタイルがボタンの作る文字にも効き、重要なボタンの白が濃い色になっていた（2026-09-14）。

## ドロップと貼り付け

- ウィンドウ全体で受け、中身で行き先を決める（`DropRouting`）。**勝手に処理を始めない**。
- **画面が自分で受けない。**取り込みの画面・改変の詳細・タグと属性の一覧・検索の条件の並びは、自分で受けていたせいで一部の物を落とせなかった（B5）。
  並べ替えの一覧は、外から来た物（ファイル・URL）なら印を付けず窓へ通す。改変の詳細は、画像だけが落ちたときに写真へ回す（`DecideOnModification`）。

| 落ちてきた物 | すること |
|---|---|
| ファイル・フォルダ | 取り込みの対象に積み、そのまま取り込みを始める（設定。既定は入）。フォルダなら監視対象に入れるか1回だけ聞く |
| BOOTH の商品 URL（持っている） | その商品を開く。**未確定でファイルを選んでいれば、持っていない商品でも開かず・尋ねずにそのファイルの商品IDとして入れて確かめる** |
| BOOTH の商品 URL（持っていない） | BOOTH から取って情報だけの商品として登録するか**尋ねる**（通信を伴う）。登録し終えても**画面を移さず**、通信の帯の上に「登録した商品を開く」を出す（続けて登録したうちの先頭の1件だけ。押すか閉じるまで残す。ユーザ指示 2026-09-15：登録を待つ間に検索を進めていると、画面が勝手に替わっていた） |
| ショップの URL | ショップ画面 |
| BOOTH 由来の画像（商品ページの上） | 開くか画像として足すかを聞く（`docs/spec/item-page.md`） |

- 読む形式：`UniformResourceLocatorW`（UTF-16）・`UniformResourceLocator`（ANSI）・`text/x-moz-url`・素のテキスト・CF_HTML（見出しの `SourceURL:` は掴んだ場所のページなので読まない）。貼り付け（Ctrl+V・入力欄では横取りしない）も同じ。
- 商品IDの入力欄は URL も受ける。

## エクスプローラで開く

- 開き方はアプリ全体で1つ（`Shell.Reveal`・ユーザ指示 2026-09-14）。
  - **フォルダ**：そのフォルダ自体を開く（A/B/C/D で B を開いたら C が見える）。
  - **zip**：中が見える状態で開く（アーカイブでも利用者の感覚ではフォルダ）。explorer に場所として渡すので、関連付け（7-Zip など）に左右されない。
  - **それ以外のファイル**：含んでいるフォルダを開き、そのファイルを選ぶ。
  - 消えていれば親フォルダを開く。在るかは画面のスレッドの外で見る。

## キー

- Ctrl+F：**どの画面でも画面内検索**（右上の帯・全部を薄い黄・今の1つを橙・Enter/Shift+Enter・Esc。畳んだ説明の中の一致は開いて見せる。仮想化した一覧の画面外は探せない）。検索とショップだけ検索欄へ移していたのをやめた（ユーザ判断 2026-09-20・B2：同じキーで見ていた画面を失うのは食い違い）。
- Ctrl+Shift+→（スキップ）と Alt+矢印（戻る・進む）は**入力欄の中でも効かせる**。譲ると、入力欄だらけの編集画面では一度も効かない（ユーザ判断 2026-09-20・B11。代償は欄の「1語ずつ選ぶ」で、Shift+矢印とマウスで足りる）。
- Alt+← とマウスの戻るボタン：画面の履歴を戻る（入力欄にいても）。左右キーの画像送りは入力欄では効かせない。
- 割り当ては設定画面で変えられる（`docs/spec/item-page.md` の編集画面）。

## 見た目の決まり

- どの画面にも左上に画面の名前を太字で出す（上の帯がある画面は帯の左端、改変とフォルダは左の欄の上）。
- 所持は緑（検索カードの「所持」・説明のリンク・持っているアバターの札）。色だけに頼らずツールチップでも言う。
- 押せる物は押せる見た目にする（リンクの絵もボタンで包む）。出る面と押せる面を一致させる。
- **行を押す意味は「選ぶ（右に出す）」か「開く（画面を移る）」の2つだけ**（ユーザ判断 2026-09-20・B3）。
  押せる行は乗せたときに色が変わり、手の形になる。押せない行にはどちらも出さない。名前の文字だけが押せる行は作らない（行全体で受ける）。
- 状態の文で一覧を動かさない（改変の画面の状態の1行は欄のいちばん下）。
- R-18 の表示の切り替えは設定画面の分かりやすい位置に。初期設定は保存先と画像を保存するかの2つだけ聞く。
- **設定画面は効く場所ごとに並べる**（2026-09-16 ユーザ判断）：一覧と検索／商品ページと編集／操作（画面の幅・ショートカット）／取り込み（取り込み元・監視）／取得と更新（更新・画像と通信）／隠したもの／データの保存先／このアプリについて（非公式の旨・辞書の出典）。
  **設定を足したら、読む所があるかを確かめる**（「一覧のカードに小分類のタグも出す」など3項目が、作ったときから保存されるだけだった）。
