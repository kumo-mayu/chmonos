## ナビ

- 208px ⇄ 56px に畳める（畳むとアイコンだけ、名前はツールチップ）。畳んでもアイコンの縦の位置は動かさない（見出しは同じ高さの小さなアイコン、区切りは同じ高さの細い線）。
  - 開く・畳むのボタンの印は、左に縦の帯の付いた四角（サイドバーの印。開いている間は広い帯、畳んでいる間は細い帯）で、矢印にしない。
  - **左右の矢印は画面の履歴（戻る・進む）だけに使う**（ユーザ指摘 2026-10-02：畳んだナビで「戻る ←」と開くの山形が並び紛らわしかった）。
- ナビのキー（↑↓・Tab で入る所）は [ui-keyboard.md](ui-keyboard.md)。
- 左上の戻る・進むは、畳んでいる間は**戻るだけ**を出す（幅56に2つは入らない。進むは Alt+→ とマウスのボタン。ユーザ判断 2026-09-27）。
- 取り込み元・監視フォルダを外したときは、確かめずに外し、下の帯に「何を外したか」と戻すボタン（「取り込み元に戻す」「監視を再開」）を出す（非表示の帯と同じ作法。ユーザ判断 2026-09-27）。
- **長い作業の帯（対応アバターの検出・候補の検索・保存先の移動・バックアップの書き出しと戻す）は1本**（`MainViewModel.BeginLongJob`。ユーザ判断 2026-10-01）。
  - 走っている間はほかの長い作業を始める口をすべて押せなくし、理由「{何をしているか}。終わるか、下の帯で中止してからお試しください。」を出す（検出・自動検索は吹き出し、設定の保存先は「場所を変える」の下の1行にまとめて）。
  - 帯には進み具合の棒（件数が分かるまでは流れる棒）と「中止」を出し、戻すも同じ（2026-10-02）。
  - 前は後から始めた作業が帯と「中止」の宛先を奪い、先に終わった方が帯ごと消していた。
- 並び：検索・改変・ショップ・フォルダ…／作業（取り込み→未確定→編集）／管理（通知が先頭・アバター・タグ・属性）。
- バッジ：編集＝「未:n」（ユーザータグが無い商品のうち書きかけの無い物・茶）と「編:n」（書きかけのある商品・青）、未確定＝未確定の件数、通知＝未読の件数。**0件のときは出さない**。操作の直後に数え直す。
- **戻るボタンには行き先を書く。**上の「← ○○に戻る」も、編集を終えるボタンも、実際に戻る画面の名前を表示する
  （B1：商品ページから編集へ入っても「検索へ戻る」と表示していた。行き先は `MainViewModel.LeaveEditLabel`）。
- **戻るはどの画面にも同じ形で出す**（ユーザ判断 2026-09-20・V2・V3）。上の帯の左端に、枠なし・透明のボタンで置く。
  出すのは**履歴があるとき**（ナビから入っても直前の画面が履歴に残るので出る）。組み込んだ画面（フォルダの右・改変の右）には出さない。
- 常設の1行（左下）：「何を n/N」（取り込み：画像を取得中 12/206、使っていない間の取得…）。応答待ちの再試行のときだけ通信の様子。作業が続いている間は合間でも畳まない（揺れる）。押すと取り込み画面へ。

## 並べ替えの出し方（ユーザ判断 2026-09-20・M5）

- **選択肢が3つまでは繋がったボタン、4つ以上はプルダウン。**見出しはどの画面も「表示順」で、一覧の上に置く。
- **検索は「使う項目」と「向き」を分ける**（項目はプルダウン、向きは2つなので繋がったボタン）。属性が増えるたびに選択肢が倍に増えるのを避ける。
  検索の項目は 2026-10-06 から、プルダウンと同じ顔の、押すとメニューが開くボタン（属性を「属性 ▸」の子に入れるため。[search.md](search.md)「絞り込み」）。
- **向きの言い方は項目ごとに変える**：日付は「新しい順／古い順」、容量は「大きい順／小さい順」、数は「多い順／少ない順」、属性の値は「高い順／低い順」、名前とショップは「昇順／降順」（英字・数字も混ざり、「あ→わ」ではそれらがどこに来るかが分からないため。2026-10-01）。
  「昇順・降順」では、どちらが新しいのか・大きいのかが読み取れない。
- 項目を変えたら、その項目の既定の向きに戻す（「名前」を選んだのに「新しい順」のままにしない）。
- **検索の履歴に残るのは「入手日が新しい順」のような1つの言い方**。項目と向きに分けた後も、その言い方から戻せるようにしておく（前に残した履歴が効かなくなるのを避ける）。

## 窓と画面の状態

- 終了時の位置・大きさ・最大化（と解除したときの大きさ）を `ui-state.json` に。復元時に今のモニタのどれとも重ならなければ中央に戻す。
  **位置と大きさは画面の画素で持つ**（2026-09-29）。モニターごとの拡大率（Per-Monitor V2・`app.manifest`）では DIP の座標がモニターの間で重なるため。
  拡大率の違うモニターへ窓を移すと、WPF が移った先の拡大率で描き直し、見えているカードの絵はその倍率で読み直す（`DisplayScale`・`CardMetrics.EdgePixels`）。
- ナビ・絞り込み欄の畳み方・積んだ条件の種類も `ui-state.json`。**設定画面には出さない**（アプリが覚える状態で、人が決める設定ではない）。
- 画面の中の畳み方（改変の画面の見出し・フォルダの木・購入した種類・タグの欄など）はアプリを閉じるまで覚える。
- **ショップの中**（バナーの畳み・1本のスクロール・1行の見出し・位置の戻し）→ [shops.md](shops.md)。
- 戻るは画面の履歴（`docs/spec/architecture.md`）。
- **ショップの一覧・ショップの中・商品ページは、戻る・進むで来たら離れたときの位置に戻す**（ユーザ判断 2026-09-28、商品ページは 2026-09-30。ほかの画面はまだ）。ショップは [shops.md](shops.md)、商品ページは [item-page.md](item-page.md)。
- 別の窓（ダイアログ）のキー・ボタンの並び・確認のアイコンは [ui-dialogs.md](ui-dialogs.md)。
- 空のとき・失敗したとき・押せないときに何を出すかは [ui-empty-and-errors.md](ui-empty-and-errors.md)。

## 画面の幅

- 境目をドラッグで変える（`PaneSplitter`：GridSplitter。乗せると色が付く）。**境目のダブルクリックで1か所、設定画面の「すべて元の幅に戻す」で全部**を元の幅に戻す。
- 画面ごとに `ui-state.json` の `paneWidths` に覚える。ドラッグの間は手元で持ち、止まってから 0.4 秒で1回だけ書く。
- 組み込んだ画面（フォルダビューの右の商品ページ・改変の画面の右の改変）も境目を動かせる（ユーザ指示 2026-09-14）。単独の画面とは別の鍵で覚え、右側が狭いので既定と範囲を小さくしてある。
  未確定を組み込んだときは左の一覧を隠すので境目は無い。ナビと絞り込み欄は開いたときの幅だけ変わる（畳んだ幅は変えない）。
- 反対側の列には最小 360（商品ページ・改変の詳細の右は 320）を付けて潰れないようにする。**覚えた幅は窓が狭いと「入れ物 − 反対側の最小」で頭打ちにする**（覚えた値は書き換えないので、窓を広げ直せば戻る。`PaneGrid`・点検 2026-09-23：広げた後に窓を狭めると商品ページの右が約130pxになった）。

- 画面の本文は見えている幅で並べ、左右の列の最小の合計が収まらないときだけ**横に送る**（`ViewportFitHost`。はみ出しうる `PaneGrid` が自分から知らせる。商品ページ・改変の詳細は自分で横に送る）。幅が足りる窓の並びは変えない。

- 改変の画面（一覧と詳細）は、詳細が横に送らずに済む幅（本文の下限＋縦のバー）を先に残して一覧の方を縮める（`PaneGrid.OppositeWidth`・`ModificationHubViewModel.DetailWidthWanted`。幅 1280 でも詳細が横に送られて右の列が切れていた。2026-10-03）。窓の最小の幅 900 では一覧を最小まで縮めても足りないので、詳細が自分で横に送る。

## ドロップと貼り付け

- ウィンドウ全体で受け、中身で行き先を決める（`DropRouting`）。**勝手に処理を始めない**。
- **画面が自分で受けない。**取り込みの画面・改変の詳細・タグと属性の一覧・検索の条件の並びは、自分で受けていたせいで一部の物を落とせなかった（B5）。
  並べ替えの一覧は、外から来た物（ファイル・URL）なら印を付けず窓へ通す。改変の詳細は、画像だけが落ちたときに写真へ回す（`DecideOnModification`）。

| 落ちてきた物 | すること |
|---|---|
| ファイル・フォルダ | 取り込みの対象に積み、そのまま取り込みを始める（設定。既定は入）。フォルダなら監視対象に入れるか1回だけ聞く。**画面は移さず**、通信の帯の上に進み具合と「取り込み画面を開く」を出す（注1） |
| BOOTH の商品 URL（持っている） | その商品を開く。**未確定でファイルを選んでいれば、持っていない商品でも開かず・尋ねずにそのファイルの商品IDとして入れて確かめる** |
| BOOTH の商品 URL（持っていない） | BOOTH から取って情報だけの商品として登録するか**尋ねる**（通信を伴う）。登録し終えても**画面を移さず**、通信の帯の上に「登録した商品を開く」を出す（注2） |
| ショップの URL | ショップ画面 |
| BOOTH 由来の画像（商品ページの上） | 開くか画像として足すかを聞く（`docs/spec/item-page.md`） |

- 注1（ファイル・フォルダ）：帯は取り込み画面にいるときは出さない。押すか閉じるまで残す（2026-09-23・動線の点検 A2：どの画面からでも取り込み画面へ移っていた）。落とした物が1つも見つからなければ始めず、帯を「始めませんでした」と次の一手に替える（「始めています…」で止まっていた）。立ち上げの途中に落とした分は、立ち上がったところで積む。
- 注2（持っていない商品URL）：「登録した商品を開く」は続けて登録したうちの先頭の1件だけ。押すか閉じるまで残す（ユーザ指示 2026-09-15：登録を待つ間に検索を進めていると、画面が勝手に替わっていた）。この帯は商品ページを離れた後に済んだ取り直しの知らせと共有し、**出ている間に来た別の知らせは順番に待たせて、押すか閉じたら次を出す**（待っている数は「ほか N 件」。ユーザ判断 2026-09-23：前は捨てていた）。

- 読む形式：`UniformResourceLocatorW`（UTF-16）・`UniformResourceLocator`（ANSI）・`text/x-moz-url`・素のテキスト・CF_HTML（見出しの `SourceURL:` は掴んだ場所のページなので読まない）。貼り付け（Ctrl+V・入力欄では横取りしない）も同じ。
- 商品IDの入力欄は URL も受ける。

## エクスプローラで開く

- 開き方はアプリ全体で1つ（`Shell.Reveal`・ユーザ指示 2026-09-14）。
  - **フォルダ**：そのフォルダ自体を開く（A/B/C/D で B を開いたら C が見える）。
  - **zip**：中が見える状態で開く（アーカイブでも利用者の感覚ではフォルダ）。explorer に場所として渡すので、関連付け（7-Zip など）に左右されない。
  - **それ以外のファイル**：含んでいるフォルダを開き、そのファイルを選ぶ。
  - 消えていれば親フォルダを開く。在るかは画面のスレッドの外で見る。

## キー

キーの割り当て・キーボードだけで進める決まりは [ui-keyboard.md](ui-keyboard.md)、読み上げの名前は [ui-input.md](ui-input.md)。

**操作できる部品には UI Automation の名前を付ける**（2026-09-30）。読み上げソフトがそのまま読む名前なので、画面の語（[ui-terms.md](ui-terms.md)）に揃え、内部の言葉と型の名前は読ませない。
行ごとに繰り返す部品は、どの行の物かを名前に入れる（「（商品名）をお気に入りに追加」）。名前で見分けられない物には、画面に出ない AutomationId を付ける。
押せるのに UI Automation に出ない作り（素の `Border`・文字に押す動きを付けただけの物・素の `ItemsControl` の行）を置かない。付け方の表と部品は [ui-input.md](ui-input.md)「読み上げの名前」。

**表示の大きさ**（ユーザ指示 2026-09-29）：設定の「操作」で 90・100・110・125・150%（既定 100%・`settings.json` の `displayZoomPercent`）。Ctrl＋プラス・Ctrl＋マイナス・Ctrl＋0 でも変え、**入力欄の中でも効く**（欄でこのキーを使う操作は無い）。テンキーの＋－0 と、Shift を足した Ctrl＋＋ も同じに扱う（`Shortcuts.Matches`）。
主の窓の中身・小窓・メニュー・吹き出しを丸ごと縮尺する（`AppZoom`）。窓の最小の大きさは倍率で変えない——最小は画面の大きさで決まるので、上げた分は中身が送る。絵は画面の拡大率×表示の大きさで読む。

## 見た目の決まり

- どの画面にも左上に画面の名前を太字で出す（上の帯がある画面は帯の左端、改変とフォルダは左の欄の上）。
- 所持は緑（検索カードの「所持」・説明のリンク・持っているアバターの札）。色だけに頼らずツールチップでも言う。
- 押せる物は押せる見た目にする（リンクの絵もボタンで包む）。出る面と押せる面を一致させる。
- **乗せたときだけ出すボタン（札の ×・通知の行の操作）は、その項目にキーボードのフォーカスがあるときにも出す**（ユーザ判断 2026-09-30）。マウスでしか届かない操作を作らない。
  新しく作るときは `RevealOnHoverOrFocusButton`（札の ×）か、行の `IsMouseOver`・`IsKeyboardFocusWithin` の両方で出す形にする。キーの動きは [ui-keyboard.md](ui-keyboard.md)「キーボードだけで進める」。
- **行を押す意味は「選ぶ（右に出す）」か「開く（画面を移る）」の2つだけ**（ユーザ判断 2026-09-20・B3）。
  押せる行は乗せたときに色が変わり、手の形になる。押せない行にはどちらも出さない。名前の文字だけが押せる行は作らない（行全体で受ける）。
- **消す・初期化する操作は、戻せるかに関わらず赤**（`DangerButton`・`DangerMenuItem`・赤い字の小さな ×。「続きを捨てる」（取り込み画面・主画面の帯）と設定の「すべて元の幅に戻す」も赤。V4。ユーザ判断 2026-10-05「消したり初期化したりする操作は赤色と統一した方がわかりやすいでしょう。」。前は「取り返しのつかない物だけ赤」）。対象は削除・消す・既定に戻す・ごみ箱へ移す・**外す**（登録や対応を外す。「この素体から外す」「商品から外す」「監視から外す」「取り込み対象から外す」など。ユーザ判断 2026-10-05 メモ68「B」で広げた）。赤にしないのは「非表示にする」・「除外」・入力欄を空にする「条件をクリア」・検索の条件の札の ×（「この条件を外す」。入力を外すだけ）・サムネイルの指名を外す・閉じる・キャンセル。赤は「消える・初期に戻る」の印で、戻せるかは吹き出しと確かめの窓に書く。**例外：検索の履歴の行の ✕ は赤にしない**（ユーザ判断 2026-10-05「重要度が高くない割に大量に並んでしまうからだ」。数多く並ぶ小さな × は目立たせない）。試験は `DeleteIsRedTests`。
- **主のボタン（青）は、その画面で今いちばんやってほしいこと1つだけ**（V1）。外のアプリやエクスプローラを開くのは補助なので、どの画面でも小さいボタン。既定の大きさは窓の中の確定と、画面の中で並ぶ同じ格の操作に使う。
- 状態の文で一覧を動かさない（改変の画面の状態の1行は欄のいちばん下）。
- **長いパスを1行に出すときは、間を「…」にして頭と最後の名前を残し、省いたら吹き出しで全文**（`Controls/PathLine`。公開前の点検 2026-10-01：初回の窓で最後の「\Chmonos」が切れていた）。吹き出しの全文も欄と同じ字体で出す（吹き出しの日本語の字体では「\」が「¥」に見えた。2026-10-01）。今は初回の窓と設定の保存先・取り込み元・監視対象・改変の詳細の Unity プロジェクトの場所。ほかの画面のパスはまだ末尾を切る。
- R-18 の表示の切り替えは設定画面の分かりやすい位置に。初期設定は保存先と画像を保存するかの2つだけ聞く。
- **設定画面は概念ごとの節に分け、各節は三角で畳める**（2026-10-02 ユーザ判断・案A。前は効く場所ごとの8つの枠）：
  表示（共通：色・大きさ・画面の幅・R-18／一覧と検索／商品ページと編集）・操作（共通：ショートカット・ドロップで取り込む／編集／改変）・取り込みと取得（取り込み／取得と更新／画像と通信）・隠したもの・データ（保存先・バックアップ）・このアプリについて（非公式の旨・辞書の出典・使っているライブラリと、その許諾文 `THIRD-PARTY-NOTICES.txt` をメモ帳で開くボタン）。節の中の小見出しは「共通」と画面の名前。
  既定は全部開き、開け閉めはアプリを閉じるまで覚える（`SettingsViewModel.Section*Open`。ファイルには書かない）。
- **設定を変えて保存できたときは何も出さない**（保存されるのは当然）。出すのは、保存に失敗したとき（理由と次にやること）と、範囲の外の値を丸めたとき（丸めた旨）だけ。
  **設定を足したら、読む所があるかを確かめる**（「一覧のカードに小分類のタグも表示」など3項目が、作ったときから保存されるだけだった）。
- **設定の取り込み元の履歴は畳める**（ユーザ判断 2026-09-28：取り込むたびに増えて膨大になる）。畳む印は商品ページ・編集画面と同じ三角（`TriangleExpander`）、見出しに件数を出して畳んでも見える。
  畳んだ状態はアプリを閉じるまで覚える（商品ページのバリエーションと同じ）。既定は開いた形。「フォルダを追加」で足したときは開く（足した行が見えないと何も起きなかったように見える）。
- **設定の「管理対象から除外したファイル」は、閉じている間は件数と三角だけ**（ユーザ判断 2026-10-01。除外は溜まる一方で、5,000 件で開くたびに 7 秒余り止まっていた）。既定は閉じる。開閉はアプリを閉じるまで覚える。0 件は三角を出さず1行。
  開いた一覧は新しい順（同じ日時は後から足した物が上）・高さの上限 360 で中だけが流れ、見える分だけ行を作る。行は開いている間だけ作り、解除した後は残った行を使い回す。記録は画面のスレッドの外で読む。
