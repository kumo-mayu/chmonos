## 保存する物

- 1件の形は検索の履歴と同じ `SearchHistoryEntry`（文字・効いている条件の状態・探す対象と区別・別表記・表示順）に、**名前**と**カードかリストか**（`view`）を足した物。
  同じ「条件一式」を2つの形で持つと、条件の種類を足すたびに両方を直すことになる。
- `view` は保存した検索だけが持つ。履歴は持たない（書かない）——履歴を押すたびに表示の形まで替わると、条件を戻したいだけのときに邪魔になる。
- **含める物を選べる**（ユーザ判断 2026-11-27・案1）：保存の小窓と上書きの窓のチェックで、検索文字列・表示順・カードかリストかを外せる。条件と探す対象と区別・別表記はいつも含める。
  - 検索文字列を外すと、文字を空で持つ（欄は足さない。呼び出すと文字を消す）。
  - 表示順・カードかリストかを外すと `keepSort`・`keepView`（true の時だけ書く）を立て、`sort`・`view` は書かない。表示順の null は「入手日が新しい順」の意味なので、「含めない」は null と別の欄で持つ（既存の欄の意味は変えない・[data-format.md](data-format.md)）。
  - [実測] v1.2.0（タグのコードで確かめた）はこの2つの欄を知らず、無視して読む。呼び出すと表示順は入手日が新しい順に戻し（`sort` が null）、カードで出す（`view` が null）。v1.2.0 が書き戻すと欄が落ち、新しい版でも「入手日が新しい順・カード」を含めた物になる。形式の版は上げない。
- 表示順は入手日が新しい順なら書かない（null）。書き方は履歴と同じ1つの言い方（「名前順」「かわいい が高い順」）。
  null の意味は、検索の既定をカテゴリにした後（2026-11-19）も入手日が新しい順のまま据え置く。それより前の記録は既定（入手日が新しい順）を null で書いたので、null を新しい既定で読むと、入手日で並べて保存した検索がカテゴリの順で開く（`SearchViewModel.RecordedNullSortLabel`）。
- 何も絞っていない検索も保存できる（「全部をリストで、名前順」のような物を残せる）。
- ファイルは保存先の `saved-searches.json`（[data-model.md](data-model.md)）。

## 一覧（「条件を追加」の隣のボタンから開く）

- 絞り込み欄の「＋ 条件を追加 ▾」の右に「保存した検索 ▾」のボタン。押すと下にポップアップが開く（外を押す・Esc・呼び出すと閉じる）。
  畳んだ状態の記憶は無い（`ui-state.json` の `savedSearchesCollapsed` は廃止。残っていても読まない）。
- 一覧の見出し：「保存した検索」・件数・右に「＋ 今の検索を保存」。
- 行は ✓ の場所と名前の1行（要約は吹き出し）。押すと呼び出して閉じる。**今の検索と同じ行は地の色を変え、✓ を出す**（同じ＝指紋〔文字・条件・表示順・探す対象と区別〕とカードかリストかが同じ。含めずに保存した表示順・カードかリストかは比べない〔`SavedSearches.SameAsCurrent`〕。
  呼び出しても何も変わらない物）。★は商品のお気に入りの印なので使わない。
  閉じているときは、同じ物があればボタンの末尾に小さな点を出し、ボタンの読み上げ（HelpText）に名前を載せる。
- 行の「…」（どの行にもいつも出す。ユーザ判断 2026-11-20：乗せた時だけ出す形では、1行目だけ出たままに見え、ほかの行の操作に気付きにくかった）と右クリック：条件を上書き／名前を変更…／フォルダへ移す ▸／上へ移動・下へ移動／削除（フォルダは下の「フォルダ」）。
  上書きは今の検索と同じ行では押せない（吹き出し「今の検索と同じです」）。端の行は外へ動かせない。
- **6件目から**は探す欄（名前か要約に含む行だけ。大文字小文字・全角半角・かなの種類は区別しない）を出し、一覧は5件ぶんの高さで中だけを流す。
  探して0件なら「見つかりません。探す語を変えてください。」。件数が5以下に戻ったら探す語を捨てる。
- 0件のときは「「＋ 今の検索を保存」で、今の検索に名前を付けて残せます。」。
- 小窓や確認の窓で一覧が閉じても、書いた後に開き直して行へ止まり直す（ほかの欄に移っていれば奪わない）。

## 保存の小窓・確認

- 「今の検索を保存」：名前の欄は**今の条件の要約**（60字まで）を全部選んだ状態で始まる（何も絞っていなければ空）。下に「保存に含める」のチェック（検索文字列〔文字を打っている時だけ〕・表示順・カードかリストか。既定はどれも入）と「条件と「対象」「オプション」は、いつも保存されます。」。
  今ある名前と同じなら欄の下に「既にあります」で、空欄と同じく「保存」を押せない（新しく名付ける欄なので候補は付けない）。名前は100字まで。
- 「名前を変更」も同じ小窓（ボタン「変更」・「名前は同じ手順で戻せます。」）。
- 名前は前後の空白を落とし、大文字小文字を区別せずに重ならない（`SavedSearches.SameName`）。同じ条件を別の名前で残すのは許す。
- 上書きは同じ小窓（題「条件を上書き」・本文「「名前」の条件を上書きします。上書きすると、前の内容には戻せません。」・名前の欄は無し・ボタン「上書き」）で、同じチェックを出す。チェックの初めの状態は元の行に合わせる（外して保存した物は外・文字の無い行は文字も外）。Enter で上書きしない（止まるのはキャンセル・D4）。
- 削除は前の内容が残らないので、知らせの窓で聞く（「削除すると元に戻せません。」・既定はキャンセル・D4）。名前の変更と並べ替えは聞かない。

## 呼び出す

- **今の検索を置き換える**：文字・条件の値・探す対象と区別・別表記・表示順・カードかリストか（含めずに保存した表示順・カードかリストかは今のまま）。条件の当て方は履歴と同じ
  （値を全部戻してから、同じ種類の n 番目の状態をパネルの同じ種類の n 番目の条件へ。足りなければ足す。足してある空の条件は残す）。
- 保存した表示順を書いていない（null）なら、入手日が新しい順に戻す（履歴は表示順を書いていなければ今の順のまま）。
- **今は無い値**（消したタグ・属性・カテゴリ・ショップ）は、履歴と同じく**そのまま条件に入れる**。黙って落とすと保存したときより広い結果が出る。
  入れておけば条件の欄にその値が見え、0件になる理由が読める。
- **表示順だけは無い項目で並べられない**（消した属性で並べていた）ので、既定の順で並べ、知らせの窓（Warning）で「表示順「…」は今は選べないため、カテゴリがBOOTHの並び順で並べています。」と言う。
- 呼び出しは履歴に積まない（履歴は今までどおり商品を開いたときだけ）。

## キーボード（行は条件の並びと同じ `FrameList`）

- Tab：「＋ 条件を追加」→「保存した検索」のボタン。**Enter・Space・↓ で開く**と、先頭の行（無ければ「今の検索を保存」）に止まる。一覧の中は Tab で巡る（外へは出ない）。
- 行の上：↑↓ で隣の行、Home・End で端。**Enter で呼び出す**（行には中へ入る部品が無いので、枠に付けた操作を押す。`FocusFrame.Command`）。
  行の操作は Shift+F10・アプリケーションキー（右クリックと同じメニュー）。「…」は Tab で止まらない。
- 探す欄で ↓ を押すと先頭の行へ。**Esc で閉じて、ボタンへ戻る**。
- 並べ替え・名前の変更・上書き・削除の後は、作り直した行（削除なら下の行、無ければ上、行が無くなれば「今の検索を保存」）に止まり直す。

## 書き込み

- 全部 `UiCommand.ChangeSavedSearches`（変え方を関数で渡し、錠の中で今の並びに当てる。規則は `SavedSearches` の純粋な関数）。
- 2つの所から同じ名前で同時に足されたら、2行にせずその場所で置き換える。上書き・名前の変更で名前が見つからなければ（別の所で消された）何もしない。
- 手で直した JSON の欠けた配列は空、並びの中の `null` は飛ばす。名前の無い行は要約を名前の代わりに出す。

## 名前の変更・統合に付いていく（ユーザ判断 2026-10-04）

- 保存した検索の条件は、ユーザータグ（大分類・小分類）・属性（幅と、その属性で並べた表示順「質感 が高い順」）・共通素体（対応アバターの条件の `base:名前`）を名前の文字で持つ。
  名前を変えると古い名前のまま0件になるので、**名前を変える・統合する命令の中で**、`UiCommand.ChangeSavedSearches` と同じ錠の中の書き方で条件の名前も書き換える
  （`RenameUserTag`・`RenameAttribute`・`RenameBase`。規則は `SavedSearches.RenameUserTagTop`／`RenameUserTagSub`／`RenameAttribute`／`RenameBase`）。
- 統合は、残る側の綴り（マスタにある名前）へ寄せ、同じ条件が2つになれば1つにする（大分類は小分類を合わせる。属性の幅は寄せ先のものを残す）。
- **消したときは今のまま残す**（0件の理由が条件の欄に見える。上の「今は無い値はそのまま条件に入れる」）。
- 場所が変わる命令にも付いていく（ユーザ判断 2026-10-05）。`MoveUserTagSub`（小分類を別の大分類へ）は「元の大分類の小分類 x」を「移動先の小分類 x」へ、`NestUserTagTop`（大分類を小分類に）は「大分類 X」を「入れ先の小分類 X」へ書き換える（`SavedSearches.MoveUserTagSub`／`NestUserTagTop`）。
  移動先に条件が既にあれば小分類を足して1つにする。ただし移動先が小分類を絞っていない条件（その大分類の全部）には足さない（足すと狭まる）。元の条件は、移した x を抜いて小分類が残らなければ消す（残すと「全部」へ広がる）。断られた・移せなかったときは触らない。
- Unity プロジェクトの場所の付け替え（改変の画面の「場所を付け替える…」・ユーザ判断 2026-11-10）にも付いていく。条件「Unityプロジェクト」「改変プロジェクト」の札の古い場所を新しい場所に書き換え、重なれば1つにする（`UiCommand.RelocateUnityProject` → `SavedSearches.RelocateUnityProject`。今の検索画面の条件も同じ関数。[modifications.md](modifications.md)「Unity プロジェクト」）。検索の履歴は過去の記録なので書き換えない。
- 対象外：検索の履歴（`search-history.json`）。

## 条件にする・フォルダ [実装]（2026-11-27）

ユーザの言葉（2026-11-27）：「今回のことで、検索モジュールに求められる挙動が複雑化したと考えます。保存した検索をモジュールとして追加する機能を作り、保存自体に1階層のフォルダ概念を追加するのはどうでしょうか？」
→ 案の5点に「3と5も含めてその形で良いと思う」。ほかのソフトの欄（[local-api-extensions-search.md](local-api-extensions-search.md)）で条件の種類が増えても、束ねて1つで選べるようにする。

**条件「保存した検索」**（種類 `SavedSearch`。判定は Core の `SavedSearchCondition`、画面は `SavedSearchModule`）
- 「＋ 条件を追加」の最後の見出し「保存した検索」に、一覧と同じ並び（フォルダの外 → フォルダごと）で名前が並ぶ。フォルダの間は区切り線で、フォルダの物は「フォルダ ／ 名前」（メニューは2段まで）。
  1件も無ければ押せない行「保存した検索はありません」。選ぶとその名前の条件を足す（欄は「「名前」に当てはまる商品」。別の保存した検索にするときは足し直す）。複数置ける・除ける。
- **今の中身で当てる**：元を上書きすると、それを使う条件も変わる（足した時の中身で固めない）。保存した検索が変わるたびに、使っていれば絞り直す。
- 使うのは**打った文字・条件・探す対象と区別・別表記だけ**。表示順・カードかリストかは使わない。中の条件は画面の絞り込みと同じ単位で照らす（範囲・日付の同じ種類は「どれかに当たる」の1つのまとまり。効かせていない条件は使わない。除くは除くを持つ種類だけ読む＝`SearchModuleConditions.SupportsExclude`、画面と揃うことを試験で確かめる）。
- **チェック「検索文字列も使う」**（ユーザ判断 2026-11-27 案2）：既定は入で、呼び出した結果と同じ。元に文字がある時だけ出す。外すと元の文字を照らさず条件だけで当てる。
  状態の `ignoreText`（外した時だけ true を書く。既定は書かない）。API は `useText`（既定 true）。
- **別表記**（ユーザ判断 2026-11-27 ①a）：元で別表記を入れていれば、**組めている索引だけで**広げる（`SearchBridge.WidenLoaded`。まだ組めていない変換は広げずに照らす。打つたびの数え直しの中で索引を組むと数秒止まるため）。API は広げない（API の text と同じ）。
  測らずに入れた：広げるのは数え直し1回につき名前ごとに1回（`SearchModuleContext` の中で組んだ物を使い回す。入れ子・同じ名前の条件が2つでも1回）で、増える手間は組めている索引を引く分だけ。商品ごとの手間は、今の検索で別表記を入れた時と同じ。
- **入れ子にできる**。**輪になる保存・上書きは書かずに断る**（錠の中の今の並びで判定。窓「条件の保存した検索をたどると「名前」に戻るため、保存できません。」）。
  手で直した JSON の輪は、輪の中の物は当たらないとし、欄に「保存した検索が輪になっています」。輪を指すだけの物（輪の外）は、中の条件が当たらないだけ。
- 名前で持ち（状態の `items` の1つ目）、**名前の変更に付いていく**（`SavedSearches.Rename` が中の条件も書き換える。今の条件の欄も付いていく）。**消したら当たらない**とし、欄に「この保存した検索はありません」（書き換えない。0件の理由が見える）。
- 元が無い・輪の時は「当たらない条件」として扱う（ユーザ判断 2026-11-27 ②a）。除くと全部の商品が通る（消したタグを条件に残した時と同じ）。
- API の条件の種類 `savedSearch`（`values` に名前を1つ・`useText`）。写しは `saved-searches.json` を見張って読み直す（`StorePart.SavedSearches`）。一覧は `GET /v1/saved-searches`（中身は API の検索の式に戻して出す。[local-api-internal.md](local-api-internal.md)）。
- [実測] v1.2.0（タグ `v1.2.0` のコードで確かめた）：知らない条件の種類は読み飛ばす（落ちない）ので、**この条件を入れた保存した検索は v1.2.0 では条件なしの分だけ広い結果になる**。
  書き戻しても種類の文字は残る（新しい版に戻れば元どおり）。`ignoreText` は `SearchModuleState` に知らない欄を残す仕組みが無いので、v1.2.0 が書くと落ち、「検索文字列も使う」が入に戻る。形式の版は上げない。

**フォルダ（1階層・作った 2026-11-27）**
- 1件ごとに `folder`（フォルダの名前。無ければフォルダの外で、書かない）。入れ子は作らない。**中身の無いフォルダは残らない**（フォルダの一覧は持たない）。指紋・要約には入れない。
  入れ子の形に変えると古い版が読めないため、欄を足す形にした（形式の版は上げない。[data-format.md](data-format.md)）。
  [実測] v1.2.0 の `JsonStore` は知らない欄を無視して読む。ただし v1.2.0 で保存した検索を1回でも書く（保存・上書き・名前の変更・並べ替え・タグの名前の変更に付いていく）と、**全部の行の `folder` が落ち**、フォルダの外に並ぶ（保存した検索は消えない）。
- 一覧はフォルダごとに見出しでまとめる（フォルダの外の物を先に、フォルダは並びに初めて出てきた順。同じフォルダの中は並びのまま。`SavedSearches.Grouped`）。
  見出しはフォルダの先頭の行の上に出す（行と別の項目にしないので、↑↓・Home・End と止まり直しは行だけを数える）。見出しの「…」（Tab で止まる）と右クリック：フォルダの名前を変更…／フォルダを削除。
- 行の「…」に「フォルダへ移す」：今あるほかのフォルダ・「新しいフォルダ…」・「フォルダの外」（フォルダに入っている時だけ）。移した行は、移した先の最後の行のすぐ後ろへ置く（置き場所を変えないと、フォルダの出る順まで変わる）。
  「新しいフォルダ…」は名前の小窓（題「新しいフォルダ」・ボタン「移動」・「フォルダを作って、この保存した検索を移します。」）。今あるフォルダと同じ名前なら「既にあります」。綴りは今あるフォルダへ寄せる（名前の比べ方は `SameName`）。
- 上へ・下へは**同じフォルダの中の隣**と入れ替え、フォルダの中の端では押せない。フォルダどうしの並べ替えは作っていない。
- フォルダの名前の変更は中身をまとめて移す（小窓の題「フォルダの名前を変更」。ほかのフォルダと同じ名前は「既にあります」。2つの所から同時に変えて重なったら1つにまとめる）。
  フォルダを消すと中身をフォルダの外へ出す（保存した検索は消さない。入れ直せば戻るので確かめの窓は出さない）。
- 上書き・同じ名前で足した時は、元の行のフォルダを残す。
- 探す欄（6件目から）はフォルダの名前にも当て、当たればそのフォルダの中身を全部出す。

作る順：予定の 59 の「内部の情報」⑤（API に保存した検索を出す）の前に作り、⑤ はこの形を出す。
