## 保存する物

- 1件の形は検索の履歴と同じ `SearchHistoryEntry`（文字・効いている条件の状態・探す対象と区別・別表記・表示順）に、**名前**と**カードかリストか**（`view`）を足した物。
  同じ「条件一式」を2つの形で持つと、条件の種類を足すたびに両方を直すことになる。
- `view` は保存した検索だけが持つ。履歴は持たない（書かない）——履歴を押すたびに表示の形まで替わると、条件を戻したいだけのときに邪魔になる。
- 表示順は既定（入手日が新しい順）なら書かない。書き方は履歴と同じ1つの言い方（「名前順」「かわいい が高い順」）。
- 何も絞っていない検索も保存できる（「全部をリストで、名前順」のような物を残せる）。
- ファイルは保存先の `saved-searches.json`（[data-model.md](data-model.md)）。

## 一覧（「条件を追加」の隣のボタンから開く）

- 絞り込み欄の「＋ 条件を追加 ▾」の右に「保存した条件 ▾」のボタン。押すと下にポップアップが開く（外を押す・Esc・呼び出すと閉じる）。
  畳んだ状態の記憶は無い（`ui-state.json` の `savedSearchesCollapsed` は廃止。残っていても読まない）。
- 一覧の見出し：「保存した条件」・件数・右に「＋ 今の検索を保存」。
- 行は ✓ の場所と名前の1行（要約は吹き出し）。押すと呼び出して閉じる。**今の検索と同じ行は地の色を変え、✓ を出す**（同じ＝指紋〔文字・条件・表示順・探す対象と区別〕とカードかリストかが同じ。
  呼び出しても何も変わらない物）。★は商品のお気に入りの印なので使わない。
  閉じているときは、同じ物があればボタンの末尾に小さな点を出し、ボタンの読み上げ（HelpText）に名前を載せる。
- 行の「…」（乗せる・止まると出る。条件の「…」と同じ）と右クリック：条件を上書き／名前を変更…／上へ移動・下へ移動／削除。
  上書きは今の検索と同じ行では押せない（吹き出し「今の検索と同じです」）。端の行は外へ動かせない。
- **6件目から**は探す欄（名前か要約に含む行だけ。大文字小文字・全角半角・かなの種類は区別しない）を出し、一覧は5件ぶんの高さで中だけを流す。
  探して0件なら「見つかりません。探す語を変えてください。」。件数が5以下に戻ったら探す語を捨てる。
- 0件のときは「「＋ 今の検索を保存」で、今の検索に名前を付けて残せます。」。
- 小窓や確認の窓で一覧が閉じても、書いた後に開き直して行へ止まり直す（ほかの欄に移っていれば奪わない）。

## 保存の小窓・確認

- 「今の検索を保存」：名前の欄は**今の条件の要約**（60字まで）を全部選んだ状態で始まる（何も絞っていなければ空）。下に「条件、検索文字列、表示順などが保存されます。」。
  今ある名前と同じなら欄の下に「既にあります」で、空欄と同じく「保存」を押せない（新しく名付ける欄なので候補は付けない）。名前は100字まで。
- 「名前を変更」も同じ小窓（ボタン「変更」・「名前は同じ手順で戻せます。」）。
- 名前は前後の空白を落とし、大文字小文字を区別せずに重ならない（`SavedSearches.SameName`）。同じ条件を別の名前で残すのは許す。
- 上書き・削除は前の内容が残らないので、知らせの窓で聞く（「…前の内容には戻せません。」（上書きの窓の題は「条件を上書き」）「削除すると元に戻せません。」・既定はキャンセル・D4）。名前の変更と並べ替えは聞かない。

## 呼び出す

- **今の検索を置き換える**：文字・条件の値・探す対象と区別・別表記・表示順・カードかリストか。条件の当て方は履歴と同じ
  （値を全部戻してから、同じ種類の n 番目の状態をパネルの同じ種類の n 番目の条件へ。足りなければ足す。足してある空の条件は残す）。
- 保存した表示順が既定（書いていない）なら既定に戻す（履歴は表示順を書いていなければ今の順のまま）。
- **今は無い値**（消したタグ・属性・カテゴリ・ショップ）は、履歴と同じく**そのまま条件に入れる**。黙って落とすと保存したときより広い結果が出る。
  入れておけば条件の欄にその値が見え、0件になる理由が読める。
- **表示順だけは無い項目で並べられない**（消した属性で並べていた）ので、既定の順で並べ、知らせの窓（Warning）で「表示順「…」は今は選べないため、入手日が新しい順で並べています。」と言う。
- 呼び出しは履歴に積まない（履歴は今までどおり商品を開いたときだけ）。

## キーボード（行は条件の並びと同じ `FrameList`）

- Tab：「＋ 条件を追加」→「保存した条件」のボタン。**Enter・Space・↓ で開く**と、先頭の行（無ければ「今の検索を保存」）に止まる。一覧の中は Tab で巡る（外へは出ない）。
- 行の上：↑↓ で隣の行、Home・End で端。**Enter で呼び出す**（行には中へ入る部品が無いので、枠に付けた操作を押す。`FocusFrame.Command`）。
  行の操作は Shift+F10・アプリケーションキー（右クリックと同じメニュー）。「…」は Tab で止まらない。
- 探す欄で ↓ を押すと先頭の行へ。**Esc で閉じて、ボタンへ戻る**。
- 並べ替え・名前の変更・上書き・削除の後は、作り直した行（削除なら下の行、無ければ上、行が無くなれば「今の検索を保存」）に止まり直す。

## 書き込み

- 全部 `UiCommand.ChangeSavedSearches`（変え方を関数で渡し、錠の中で今の並びに当てる。規則は `SavedSearches` の純粋な関数）。
- 2つの所から同じ名前で同時に足されたら、2行にせずその場所で置き換える。上書き・名前の変更で名前が見つからなければ（別の所で消された）何もしない。
- 手で直した JSON の欠けた配列は空、並びの中の `null` は飛ばす。名前の無い行は要約を名前の代わりに出す。

## 絞り込み欄を畳んでいるとき

- ボタンは絞り込み欄の中にあるので、畳んでいる間は出ない。呼ぶには欄を開く（畳んだ帯の開くつまみ1回）。新しい入口は足していない（判断待ち・報告 2026-10-04）。

## 名前の変更・統合に付いていく（ユーザ判断 2026-10-04）

- 保存した検索の条件は、ユーザータグ（大分類・小分類）・属性（幅と、その属性で並べた表示順「質感 が高い順」）・共通素体（対応アバターの条件の `base:名前`）を名前の文字で持つ。
  名前を変えると古い名前のまま0件になるので、**名前を変える・統合する命令の中で**、`UiCommand.ChangeSavedSearches` と同じ錠の中の書き方で条件の名前も書き換える
  （`RenameUserTag`・`RenameAttribute`・`RenameBase`。規則は `SavedSearches.RenameUserTagTop`／`RenameUserTagSub`／`RenameAttribute`／`RenameBase`）。
- 統合は、残る側の綴り（マスタにある名前）へ寄せ、同じ条件が2つになれば1つにする（大分類は小分類を合わせる。属性の幅は寄せ先のものを残す）。
- **消したときは今のまま残す**（0件の理由が条件の欄に見える。上の「今は無い値はそのまま条件に入れる」）。
- 対象外：検索の履歴（`search-history.json`）、小分類の移動・大分類を小分類にする命令（名前は変わらず場所が変わる）。
