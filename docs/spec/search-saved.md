# 保存した検索（今の決め事）

> **要点**：今の検索の**打った文字・条件・表示順・カードかリストか**を名前を付けて残し、呼び出すと今の検索を**置き換える**（ユーザ判断 2026-10-03）。
> 置き場は絞り込み欄のいちばん上の畳める節（ユーザ判断 2026-10-04・案A3。A1「検索欄の左のボタン」から変えた）。並びは人が決め、履歴のように古い物から押し出さない。
>
> **コード**：`App/ViewModels/SearchViewModel.Saved.cs`（節・保存・呼び出し）・`SavedSearchNameDialogViewModel`・`Views/SavedSearchNameDialog`・`Views/SearchView.xaml`（`SavedSearchSection`）・`SearchView.Saved.cs`（キーボード）、
> `Core/Services/SavedSearches.cs`（足す・上書き・名前の変更・削除・並べ替えの規則）・`Core/Models/SearchHistoryEntry`（1件の形）・`Controls/FrameList`（`FocusFrame.Command`）
>
> **経緯**：`docs/feedback/open.md`「今後の予定：今の検索条件に名前を付けて保存し、後から呼び出す」（2026-10-03 のメモ）、案の絵は担当SVD の案の枝 `mock/svd-saved-search-card-info`（master に入れない）。検索の履歴は [search-filters.md](search-filters.md)

## 保存する物

- 1件の形は検索の履歴と同じ `SearchHistoryEntry`（文字・効いている条件の状態・探す対象と区別・別表記・表示順）に、**名前**と**カードかリストか**（`view`）を足した物。
  同じ「条件一式」を2つの形で持つと、条件の種類を足すたびに両方を直すことになる。
- `view` は保存した検索だけが持つ。履歴は持たない（書かない）——履歴を押すたびに表示の形まで替わると、条件を戻したいだけのときに邪魔になる。
- 表示順は既定（入手日が新しい順）なら書かない。書き方は履歴と同じ1つの言い方（「名前順」「かわいい が高い順」）。
- 何も絞っていない検索も保存できる（「全部をリストで、名前順」のような物を残せる）。
- ファイルは保存先の `saved-searches.json`（[data-model.md](data-model.md)）。

## 節（絞り込み欄のいちばん上）

- 見出しの行：畳む山形・「保存した検索」・件数・右に「＋ 今の検索を保存」。畳んだ状態は `ui-state.json` の `savedSearchesCollapsed` に覚える。
- 行は名前と ★ の1行（要約は吹き出し）。押すと呼び出す。**今の検索と同じ行は地の色を変える**（同じ＝指紋〔文字・条件・表示順・探す対象と区別〕とカードかリストかが同じ。呼び出しても何も変わらない物）。
  畳んでいる間は行が見えないので、同じ物があれば見出しの下に「★ 名前」を1行出す。
- 行の「…」（乗せる・止まると出る。条件の「…」と同じ）と右クリック：今の検索で上書き／名前を変更…／上へ移動・下へ移動／削除。
  上書きは今の検索と同じ行では押せない（吹き出し「今の検索と同じです」）。端の行は外へ動かせない。
- **6件目から**は探す欄（名前か要約に含む行だけ。大文字小文字・全角半角・かなの種類は区別しない）を出し、節は5件ぶんの高さで中だけを流す。
  探して0件なら「見つかりません。探す語を変えてください。」。件数が5以下に戻ったら探す語を捨てる。
- 0件のときは「「＋ 今の検索を保存」で、今の検索に名前を付けて残せます。」。
- 保存したとき節を畳んでいれば開く（保存できたかが見えないため）。

## 保存の小窓・確認

- 「今の検索を保存」：名前の欄は**今の条件の要約**（60字まで）を全部選んだ状態で始まる（何も絞っていなければ空）。下に「打った文字・条件・表示順・カードかリストかを保存します。」。
  今ある名前と同じなら欄の下に「既にあります」で、空欄と同じく「保存」を押せない（新しく名付ける欄なので候補は付けない）。名前は100字まで。
- 「名前を変更」も同じ小窓（ボタン「変更」・「名前は同じ手順で戻せます。」）。
- 名前は前後の空白を落とし、大文字小文字を区別せずに重ならない（`SavedSearches.SameName`）。同じ条件を別の名前で残すのは許す。
- 上書き・削除は前の内容が残らないので、知らせの窓で聞く（「…前の内容には戻せません。」「削除すると元に戻せません。」・既定はキャンセル・D4）。名前の変更と並べ替えは聞かない。

## 呼び出す

- **今の検索を置き換える**：文字・条件の値・探す対象と区別・別表記・表示順・カードかリストか。条件の当て方は履歴と同じ
  （値を全部戻してから、同じ種類の n 番目の状態をパネルの同じ種類の n 番目の条件へ。足りなければ足す。足してある空の条件は残す）。
- 保存した表示順が既定（書いていない）なら既定に戻す（履歴は表示順を書いていなければ今の順のまま）。
- **今は無い値**（消したタグ・属性・カテゴリ・ショップ）は、履歴と同じく**そのまま条件に入れる**。黙って落とすと保存したときより広い結果が出る。
  入れておけば条件の欄にその値が見え、0件になる理由が読める。
- **表示順だけは無い項目で並べられない**（消した属性で並べていた）ので、既定の順で並べ、知らせの窓（Warning）で「表示順「…」は今は選べないため、入手日が新しい順で並べています。」と言う。
- 呼び出しは履歴に積まない（履歴は今までどおり商品を開いたときだけ）。

## キーボード（条件の並びと同じ `FrameList`）

- Tab：山形 → 「＋ 今の検索を保存」→（多いとき）探す欄 → 行の並び（1つの止まり。前にいた行、初めてなら先頭）→「＋ 条件を追加」。
- 行の上：↑↓ で隣の行、Home・End で端。**Enter で呼び出す**（行には中へ入る部品が無いので、枠に付けた操作を押す。`FocusFrame.Command`）。
  行の操作は Shift+F10・アプリケーションキー（右クリックと同じメニュー）。「…」は Tab で止まらない。
- 探す欄で ↓ を押すと先頭の行へ。
- 並べ替え・名前の変更・上書き・削除の後は、作り直した行（削除なら下の行、無ければ上、行が無くなれば「今の検索を保存」）に止まり直す。節の外に止まっていたら奪わない。

## 書き込み

- 全部 `UiCommand.ChangeSavedSearches`（変え方を関数で渡し、錠の中で今の並びに当てる。規則は `SavedSearches` の純粋な関数）。
- 2つの所から同じ名前で同時に足されたら、2行にせずその場所で置き換える。上書き・名前の変更で名前が見つからなければ（別の所で消された）何もしない。
- 手で直した JSON の欠けた配列は空、並びの中の `null` は飛ばす。名前の無い行は要約を名前の代わりに出す。

## 絞り込み欄を畳んでいるとき

- 節は絞り込み欄の中にあるので、畳んでいる間は出ない。呼ぶには欄を開く（畳んだ帯の開くつまみ1回）。新しい入口は足していない（判断待ち・報告 2026-10-04）。
