# 改変の詳細の「使ったもの」（今の決め事）

> **要点**：改変の詳細の左の列の「使ったもの」の見せ方と並べ替え。記録の形（`members` の1行＝商品とファイル1つの組）は [modifications.md](modifications.md)「構成物」。
>
> **コード**：`App/ViewModels/ModificationViewModel.cs`（`ShowRows`・`ModificationMemberGroupViewModel`）・`Core/Services/ModificationSendPlan.cs`（`InSendOrder`）・`Core/Services/ModificationService.cs`（`MoveItemAsync`・`MoveMemberInItemAsync`）
>
> **経緯**：[modifications.md](modifications.md)「画面」から分けた（2026-11-20）。

## 並べ方

- **検索と同じカード・リスト**（ユーザ指示 2026-09-14）。押す・星・右クリック・中クリックは検索と同じ。
  見出しの右のカード／リストの切り替えと「使ったものを順にUnityへ送る」は、左の列が狭いと見出しの下の段へ送る（重ねて置いていて、切り替えが見出しに乗った。2026-09-30）。
- 左の列は上から 写真 →「使ったものを追加」（商品名の欄と「紐付けたプロジェクトの中から探す」）→「使ったもの」（feedback 2026-11-18・ユーザ指示：前は追加が一覧の下で、多いと流した先になった）。
  「使ったもの」は見出しの山形で、見つかった商品は「見つかった商品 n 件」で畳める（畳んでも切り替え・送る間の行・結果の知らせは残す。アプリを閉じるまで覚える）。並べ替えと畳むだけで、一覧の仮想化と測定はまだ（同じ feedback の残り）。
- **1商品1欄**（ユーザ判断 2026-11-20「一つの商品が一つの欄を持つべき」）：同じ商品の行（別のファイル・別の版）を1つの欄にまとめ、欄の中にファイルを並べる。**記録の形は変えない**（画面でまとめるだけ。形式の版も移し替えも要らない）。
  欄の順は商品が記録に初めて出る順、欄の中は記録の順。外した行も欄に入れて決める（抜いてから決めると、画面の欄の順と送る順が食い違う）。全部の行を外した欄だけカードを薄くする。
  - カード：欄の上に欄の「移動 ▾」、カード（手元に無ければ名前と「手元にありません。」の枠）、その下にファイルの段（番号・外した・新しい版あり・使ったファイル・種類と、行の操作）。
  - リスト：1行＝1商品。列は 絵・星・名前・操作。名前の下にファイルの段を並べ、行の操作はファイルの右（入らない幅は下へ折り返す）。操作の列は欄の「移動 ▾」だけ。前の「順」の列はやめ、番号はファイルの段に付けた（1つの欄に番号が2つ以上ある）。
    名前の列は残りの幅を全部使い、左の列を広げれば伸びる（点検 2026-09-23：固定の 160 で見切れたままだった。切れた分はツールチップ）。
  - 行の操作：「移動 ▾」・「Unity ▾」・「更新 ▾」（新しい版のある行）・外す（外した行は戻す・削除）。操作は1行に収め、入らない幅だけ折り返す。どちらで出すかと列の幅はこの画面で覚える。
- 商品ページは、リストでは名前か絵を、カードではカードを押すと開く（「開く」ボタンはやめた）。欄のどのファイルからでも同じ商品。

## 番号と送る順

- 番号は**送る順**（1から）。送る順は設定の「使ったものを送る順」（[modifications.md](modifications.md)「構成物」）。
  - **商品ごと**（既定）：上の欄から、欄の中は上から。番号は上から 1, 2, 3…。説明の文は「上の商品から順に送ります。依存するものが先に来るように並べ替えられます。」。
  - **記録の順**：番号は記録の順なので、1つの欄の中で 1 と 4 のように離れ得る。説明の文は「番号の順に送ります。…」。
- 設定を変えたら、次に開いた改変から効く（改変の画面は開くたびに作り直す）。

## 並べ替え

- **商品ごと**：欄の「移動 ▾」（欄が2つ以上のとき）で欄を中のファイルごと動かし、行の「移動 ▾」（同じ商品のファイルが2つ以上のときだけ）で欄の中の順を替える。
  - 欄を動かすと、その商品の行だけを抜いて、行き先の欄の最初の行の前へ固めて入れる（`UiCommand.MoveModificationItem`）。記録の全部を商品ごとに並べ直すと、記録の順で送る人が手で挟んだ並びまで消えるので、ほかの商品の行は動かさない。
  - 欄の中では、同じ商品の隣の行と場所を入れ替える（`UiCommand.MoveModificationMemberInItem`）。抜いて差すと、間のほかの商品の行がずれて欄の順が変わり得る。
- **記録の順**：欄の「移動 ▾」は出さず、行の「移動 ▾」で記録の上を1つずつ動かす（`UiCommand.MoveModificationMember`。前からの動き）。
- メニューの項目はカードは前へ・後ろへ、リストは上へ・下へ。端では押せない方が灰色で、吹き出しで理由を言う（feedback 2026-11-18：前は ▲▼・◀ ▶ の2つで横幅を取った）。
- **見せる順［入れた順｜逆の順］**（メモ26-①・ユーザ判断 2026-10-04）：依存される物が上に来て、使ったと思っている衣装が下に沈むので逆にも見せる。**見せる順だけ**で、記録の並び・番号・送る順は変えない。逆の順では欄の並びも欄の中も逆にする。
  矢印は見えている向きで動く（逆の順の「前へ」は記録の上では後ろへ。吹き出しで「後に送られます」と言う）。説明の文は逆の順のとき「逆の順に並べています。Unityへは番号の順に送ります。」。
  どちらで見せるかは `ui-state.json` の `modificationMembersReversed`（全部の改変で同じ）。改変の画面の左の一覧の使ったものは入れた順のまま（1商品1欄にもしていない）。

## 行の操作

- **「Unity ▾」**：押すと「Unityへ送る」「Unityで選択」と、区切りの下に「使ったファイルを選び直す…」（2026-11-12。外した行は選び直しだけ）（2026-09-24 に「選択（Unityのプロジェクトタブで示す）」から改名。同じ機能を改変の画面のボタンと同じ名前にした・ユーザ判断）（ユーザ指示 2026-09-14：「開く」がエクスプローラなのか Unity なのか分かりにくかった）。
  インポートは「使ったものを順にUnityへ送る」と同じ道でその1件だけ、選択は改変の画面の「Unityで選択」と同じ道（`UnityMemberSelect`）。
- 「更新 ▾」・外す・戻す・削除は [modifications.md](modifications.md)「構成物」と [used-updates.md](used-updates.md)。
