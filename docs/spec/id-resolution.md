# 商品IDの決め方と未確定（今の決め事）

> **要点**：手元のファイルから BOOTH の商品IDを決める。確かな手掛かり（zip の中の商品URL・Zone.Identifier の配布URL）があれば即確定、無ければファイル名から BOOTH 内を検索して候補を点数付けする。
> ファイル名だけでは「確度が高い」に届かない設計（誤って確定しない）。決まらない物は未確定へ置き、人が ID 確定をまとめて片付けてから編集へ送る。
> **ログイン（cookie）は使わない**。
>
> **コード**：`BoothIdResolver`（手掛かり）・`BoothZipInspector`・`Core/Scanning/UnresolvedOrigin.cs`、`Core/Services/FallbackResolver.cs`・`FileNameQuery`・`AlternateQueries`・`RegistryCandidates`・`ExclusionFilter`、
> `App/ViewModels/ResolveViewModel*.cs`、`experiments/ResolveAccuracyProbe`・`QueryVariantProbe`・`ZipOriginProbe`
>
> **経緯**：`docs/research/id-resolution.md`（18本の実ZIP・319本での実測）、`docs/research/zip-linking.md`・`zip-linking-followup.md`（並行調査）、`docs/history/grill-2-ui-and-data-model.md`（Resolve → Edit）

## 手掛かり（強い順）

1. zip の中のテキストの BOOTH 商品URL（依存ツール lilToon などを指す物は除く）
2. Zone.Identifier の `HostUrl` の配布URL `s{n}.booth.pm/<shop>/f/<商品ID>/…`（Chrome/Edge は書く。**Brave はオリジンしか書かない**）
3. unitypackage の名前空間 `Assets/<作者>/…`・中の Readme の URL、PDF の本文
4. ファイル名の接頭辞・末尾がショップのサブドメイン
5. ファイル名からの BOOTH 内検索＋点数付け（下）

- 展開したファイルの Zone.Identifier は `ReferrerUrl=<親zipのフルパス>` を持つ（CP932・末尾 NUL）。**元zipで未確定を束ねる**（zip を消しても、別のドライブへ移しても残る）。ドライブ文字か `\\` で始まり書庫の拡張子で終わる物だけ使う。
- 手掛かりから商品IDが1つに決まるファイルは、未確定を通さずにその商品へ紐付く。**「この商品から外す」の印（`detached`）が付いた組は候補から落とす**。
- ブラウザの履歴DB・ログインしたライブラリは使わない（利用者主導の取り込みを優先。cookie の自動利用は規約・誤検知の点で配布ツールの機能にしない）。

## 自動検索（ファイル名から）

- **検索語を整える**（`FileNameQuery.Tokens`）：版番号・括弧の付け足し・#タグ・作者の略号・配布形態の語・ダウンロードの重複番号・英語の機能語（for・the・of）を落とす。「」の中身は残す。日本語と英字の続きは割る。
  BOOTH の検索はスペースを AND で読み、余計な1語で全滅する。
- 1ページ（最大60件）をファイル名との近さ（語・番号・ショップ名）で**並べ直す**（通信は増えない）。語に直接付いた番号（「ポーズ集13」）も使う。
- 裏付けが出なければ、特徴のある**1語だけ**で、次に**別の表記**（読み→漢字・隣り合う2語をつないだ英語→日本語。日本語の表記を先に）で引き直す。別表記が作れなければ何もしない。
- 候補ごとに商品 JSON を取って点数を付ける（無料の種類のファイル名一致・名前空間とショップ・商品名の語・番号の照合・種類名）。7点以上が「確度が高い」。
- **手元の登録簿からも候補を出す**（通信なし。非公開になった商品でも名前が残っている）。一般的な語・短い語・2項目以上が持つ表記では当てない。
- 実測（友人の正解の分かる319本）：上位3件に正解 54% → 76%。画面の1位が正解 13/30 → 19/30。

## 未確定の画面

- 束ね方：元zipで束ねて畳む（「このzipを選ぶ」で全件を1つの対象。検索語も zip 名）→ 分からなければフォルダで束ねる。展開物の中身は束で外せる（自動では外さない。自作の画像があり得る）。
- **束は2件以上のときだけ畳む**（ユーザ指摘 2026-09-17）：1件だけの束は畳まずに1行で出す。**zip自身は束に入れず**1行で出し、直後に「そのzipを展開した中身」を束にする（札「zipの中身」・「まとめて扱う」）。束を開いた中身は深く字下げして左に線を引く（束と中身が同じ密度で並び、どこを見ればよいか分からなかった）。
- **一覧を探す**（ユーザ指示 2026-09-17）：左の上に検索欄（ファイル名・フォルダ・zipの名前。大文字小文字・かなの種類・全角半角を区別しない。× で消す）。「全て選択」は見えている行だけ。選んでいた行が隠れたら見えている先頭の行を選ぶ（選択が外れると右側ごと消え、まとめて操作できなかった）。1行で出るzipの中身には「展開元：○○.zip」を添える（束の中では見出しにあるので出さない）。
- **元zipとして扱う**（ユーザ判断 2026-09-17）：元のzipが残っている中身の束の見出しと、1行で出ている中身に「元zipとして扱う」。押すと確認のうえ中身（束なら全件）を管理対象から外し、元のzipの行を選ぶ（そのままzipで登録できる）。zipが一覧に無ければ外すだけにして理由と次の一手を言う。
- **動線の直し**（ユーザ判断 2026-09-17）：zipを確定・登録した直後にそのzipの中身も一覧から外す（開いたときだけ見ていたので、残った中身を別の商品に登録できた）／「元zipとして扱う」は中身を外さずzipを選ぶだけ／選んだ行が検索で隠れていれば検索を消し、一覧をその行まで送る。確定後の次の行は見えている行から選ぶ／確定して編集へ送っていない商品は主画面が持つ（画面を離れても残る）／「エクスプローラで開く」／束の帯に検索で隠れている件数／フォルダ登録のボタンに対象のフォルダ名（zipの中身は同じzipの中身の共通フォルダ）／外した直後に上の帯で「外した n 件を戻す」（除外の記録を消し、外す前の未確定の記録を戻す）／空になったら「確定した分を編集へ送る」「取り込みを開く」／自動検索をするまで「候補がありません」を出さない／元zipが未確定にあるときの理由は入力欄の上に
- **zipを展開した中身は、元のzipを単位に登録する**（ユーザ判断 2026-09-17。基本は1zip＝1商品。`ResolveViewModel.ZipUnit.cs`）：
  - 元のzipが商品に登録済みで今もディスクにある：中身は未確定に出さず、上の帯に「登録済みのzipを展開したファイル n 件は出していません」。記録には書かず開くたびに決める（zipを消せば中身として戻り、後から紐付け直せる）。統計の容量は今まで通り登録した商品のファイルだけ
  - 元のzipが未確定にある：中身の「このIDで確定する」「BOOTHに無い商品として登録」は押せず、理由を出して「元zipで登録」へ案内。「フォルダのまま登録」はできる（同じzipの中身が共通して入っているフォルダ）
  - 元のzipが一覧に無い（消した・取り込んでいない）：同じzipの中身全件を1つの単位に（束を自動で立てる）。まとめて確定も同じzipの中身全件まで広げ、zipが未確定にある中身が混ざれば止める
  - **zipが無い展開物は「展開物の根」1つに揃える**（2026-09-17 ユーザ判断 案A）：目印（.unitypackage・.url）の一番外側から中身が1つだけの親を遡ったフォルダ。ドライブの直下や取り込み元（またはその上）になったら目印のフォルダ、それも駄目ならファイルのフォルダに戻す。左の束・まとめて扱う単位・フォルダのまま登録する先を全部これにし、サブフォルダで束が割れない。枠には「対象：パス（未確定 n 件）」と登録ボタンだけ（外すは「その他」）
  - 単位は確定・BOOTHに無い商品としての登録・管理対象から外すのどれにも効く（元のzipが未確定にある中身も、外すは中身全件）
  - 「このファイルだけを扱う」（商品IDを決めるの欄。1つのzipに複数の商品が入っているときなど）で単位を外す。選び直すと切れる
- **一覧の行**（ユーザ指示 2026-09-17）：上に確かな情報（1行目にファイル名と大きさ〔右寄せ〕、1行で出る中身は2行目に展開元）、その下に候補と操作（札：「自動候補:n件」＝取り込んだときに手掛かりから見つかった商品IDの数。自動検索の候補は数えない／「展開」＝zipの無い展開物、最後にボタン）。札まで名前の横に並べると、真ん中くらいの長さ（22文字）の名前でも切れる。
- 出口は3つ：**商品IDで確定**（URL も受ける）／**管理から外す**（除外）／**BOOTHに無い商品として登録**（`docs/spec/private-items.md`）。ほかにフォルダを商品として登録。
- zip を落とし直すことを先に勧める（zip は配布の単位で、移動にも強く、展開先は自動で対象外）。
- 確定した分をまとめて編集へ送る（調べる作業と主観で決める作業を分ける）。
- **右側の並び**（ユーザ指示 2026-09-17）：このファイルについて分かっていること → 商品IDを決める（一覧でチェックしたときのまとめて確定・外すもここ） → 候補 → その他（BOOTHに無い商品として登録・管理対象から外す）。
  候補の「これで確認」と商品ページのドロップは、結果の出る「商品IDを決める」まで画面を送る（候補は欄より下にあり、押した結果が見えなかった）。
- **商品ページのドロップは画面のどこでも受ける**：ファイルを選んでいれば、持っている商品でも開かずにその商品IDとして入れて確かめる（`DropRouting.DecideOnResolve`）。入力欄はドロップを受けず、画面に任せる。説明に「商品IDかURL・商品ページを落としても入る」と書く。
- **展開元のzipファイルが無いフォルダ**：左の一覧のフォルダの束に「zipが無い」の札。そのフォルダのファイルを選ぶ（見出しの「このフォルダを選択」でも選ばれる）と、右の「分かっていること」の下に片付け方の枠：見出し（判断の根拠はツールチップ）・1文（zipを落とし直すのがおすすめ、下の「候補」で探せる、できなければフォルダのまま登録するか外す）・［このフォルダを商品として登録］［このフォルダを管理対象から外す］（補足はツールチップ）。前は右側の上に1枚で出ていてどのフォルダの話か分からず、左の束の中に移すと束ごとに大きな枠が並んでごちゃごちゃした。色は札と見出しだけ（ユーザ指示 2026-09-17）。
- **元zipで登録**：展開した中身で、元のzip（Zone.Identifier の記録）が今もディスクにあれば、「分かっていること」の元のzipの下に「元zipで登録」。押すと未確定の一覧のzipの行を選び、そのまま商品IDを決めて登録できる。zipが一覧に無い（既に商品に結び付いている・取り込んでいない）ときは理由と次の一手（取り込み画面にzipを落とす）を言う。zipがあるかは一覧を読むときにzipごとに1回だけ見る。**元のzipが残っている行は「zipが無い展開物」とみなさない**（フォルダの目印だけで決めると、zipが残っていても「zipが無い」と出た）（ユーザ指示 2026-09-17）。
- 言い方：出口は「商品のIDを登録」と「管理対象から外す」。仮IDは「仮のID（local-…）として登録します」。
- 除外はパスで先に弾き、ハッシュで移動・改名後も効かせる（毎回ハッシュを計算しないため）。`excluded.json` は `unresolved.json` と混ぜない（寿命が違う）。
- 未確定の一覧の書き方は `docs/spec/import.md`（取り込みとの合わせ方・外付け）。
- 画面を開くたびに、手元にあるファイルの Zone.Identifier を読み直す（保存値は旧版の文字化けを含みうる）。

## 間違って紐付いたファイル

- 商品ページのファイルの行ごとに「この商品から外す」→ 未確定へ戻す。**行は消さずに `"detached": true` で灰色に残す**（紐付いていたこと自体は確か）。「この商品に戻す」で戻せる（外した後で別の商品へ紐付けてあれば押せない）。
- 印の付いたファイルは所持・容量・検索・重複・Unity へ送る対象に数えない（`LocalBlock.OwnedFiles`。計算なので書き出さない）。日時は持たない。
- 最後のファイル（とフォルダ）を外して商品が空になるときだけ、残すか消すかを聞く。消すと印も消える。
- 印は設定画面の「隠したもの」に一覧で出し、「記録を消す」を置く（除外とは別の行）。
- 商品ごと別のIDへ移すのは「IDを変更」（`docs/spec/private-items.md`）。
