# 商品IDの決め方と未確定（今の決め事）

> **要点**：手元のファイルから BOOTH の商品IDを決める。確かな手掛かり（zip の中の商品URL・Zone.Identifier の配布URL）があれば即確定、無ければファイル名から BOOTH 内を検索して候補を点数付けする。
> ファイル名だけでは「確度が高い」に届かない設計（誤って確定しない）。決まらない物は未確定へ置き、人が ID 確定をまとめて片付けてから編集へ送る。
> **ログイン（cookie）は使わない**。
>
> **コード**：`BoothIdResolver`（手掛かり）・`BoothZipInspector`・`Core/Scanning/UnresolvedOrigin.cs`、`Core/Resolution/FallbackResolver.cs`・`FileNameQuery`・`AlternateQueries`・`AvatarTokens`・`SiblingTokens`・`RegistryCandidates`・`ExclusionFilter`、
> `App/ViewModels/ResolveViewModel*.cs`、`experiments/ResolveAccuracyProbe`・`QueryVariantProbe`・`ZipOriginProbe`
>
> **経緯**：`docs/research/id-resolution.md`（18本の実ZIP・319本での実測）、`docs/research/zip-linking.md`・`zip-linking-followup.md`（並行調査）、`docs/history/grill-2-ui-and-data-model.md`（Resolve → Edit）

## 手掛かり（強い順）

1. zip の中のテキストの BOOTH 商品URL（依存ツール lilToon などを指す物は除く）
2. Zone.Identifier の `HostUrl` の配布URL `s{n}.booth.pm/<shop>/f/<商品ID>/…`（Chrome/Edge は書く。**Brave はオリジンしか書かない**）
3. unitypackage の名前空間 `Assets/<作者>/…`・中の Readme の URL、PDF の本文
4. ファイル名の接頭辞・末尾がショップのサブドメイン
5. ファイル名からの BOOTH 内検索＋点数付け（下）

- 展開したファイルの Zone.Identifier は `ReferrerUrl=<親zipのフルパス>` を持つ（CP932・末尾 NUL）。**元zipで未確定を束ねる**（zip を消しても、別のドライブへ移しても残る）。ドライブ文字か `\\` で始まり書庫の拡張子で終わる物だけ使う。
- 手掛かりから商品IDが1つに決まるファイルは、未確定を通さずにその商品へ紐付く。**「この商品から外す」の印（`detached`）が付いた組は候補から落とす**。
- ブラウザの履歴DB・ログインしたライブラリは使わない（利用者主導の取り込みを優先。cookie の自動利用は規約・誤検知の点で配布ツールの機能にしない）。

## 自動検索（ファイル名から）

- **検索語を整える**（`FileNameQuery.Tokens`）：版番号・括弧の付け足し・#タグ・作者の略号・配布形態の語・ダウンロードの重複番号・英語の機能語（for・the・of）を落とす。「」の中身は残す。日本語と英字の続きは割る。
  BOOTH の検索はスペースを AND で読み、余計な1語で全滅する。
  英単語の尻の番号（「Hat3」）は割り、同じ商品の中の分け方の語（全部入り・共通・マテリアル・おまけ）も落とす。型番（全部大文字）と番号の後にも字の続く名前は割らない。
- **アバターの名前の語は検索語から外す**（`AvatarTokens`。2026-09-29）：「商品名_アバター名」のファイルで AND が0件になるため。名前は対応アバターの検出と同じ呼び名から取り、
  かな・漢字だけの名前にはローマ字の読みが名前全体と一致するとき当てる（3字以上）。**全部が名前なら外さない**（アバター本体の zip）。
  外した名前は並べ直しに1点だけ使う（同じアバターを名前に出す商品へ。本体には足さない。名前だけのファイルなら本体へ）。
  `FallbackResolver` に登録簿を読む関数を渡したときだけ効く（アプリはつないである。`AppServiceContainer`）。
- **兄弟の zip の間で変わる語も外す**（`SiblingTokens`。ユーザ判断 2026-09-29「案1」）：持っていないアバターの名前は登録簿で見分けられないため。
  未確定の画面は一覧にあるファイルの場所（検索で隠れた行・展開した中身の元zipも）を自動検索に渡す。**兄弟**は同じフォルダ・同じ拡張子で頭の語が同じファイル（商品IDは見ない）。
  語の並びを頭と尻から突き合わせ、両方に入れ替わる語があるときだけ外す（版の数字だけ違う・片方に語が足されただけなら外さない）。
  **外すのは、頭の語が違うほかのファイル（同じ拡張子）2本以上にも出る語だけ**（アバター名は別の商品にも出る。同じショップの別の商品を並べた「ショップ名_帽子」「ショップ名_靴」の語は出ない）。
  外すと英字3字以上・日本語2字以上の語が残らないなら外さない。通信は増えない。効き目は小さい（research §18：画面の1位 +1本・減り0）。
- 1ページ（最大60件）をファイル名との近さ（語・番号・ショップ名）で**並べ直す**（通信は増えない）。語に直接付いた番号（「ポーズ集13」）も使う。商品名の版番号（ver2.1.0）の中の数字には当てない。
  名前は検索カードの見出しから取る（属性の名前は25字前後で切れている）。
- 裏付けが出なければ、**1語だけ**（語が2つ以上なら**ファイル名の最初の語**。短ければ最長の語。1語だけのファイルはしない。アバターの名前は選ばない。2026-09-29）で、次に**別の表記**（読み→漢字・隣り合う2語をつないだ英語→日本語。日本語の表記を先に）で引き直す。別表記が作れなければ何もしない。
- **2ページ目は見ない（試せる形で切ってある）**：`FallbackResolver.SearchSecondPage` を入れると、引き直しでも裏付けが無く、最初の1語の検索が60件埋まり、
  どの候補も検索語の語を全部は名前に持たないとき、その語の検索の2ページ目も見る（1ファイルで検索1本・商品JSON 3本まで増える）。472本で上位3件が1本増えるだけだった（2ページ目に正解があったのは41本中1本。research §19）。
- 候補ごとに商品 JSON を取って点数を付ける（無料の種類のファイル名一致・名前空間とショップ・商品名の語・番号の照合・種類名）。7点以上が「確度が高い」。
  **引き直しで出た候補も元の検索語で点を付ける**（引き直した語はその商品の名前に入っているのが当たり前で、点が水増しされた）。
  **読みの一致は、字面で商品名と一致しなかったときだけ**2点（字面の一致に重ねない。どちらも 2026-09-29）。
- **手元の登録簿からも候補を出す**（通信なし。非公開になった商品でも名前が残っている）。一般的な語・短い語・2項目以上が持つ表記では当てない。
- 実測（友人の正解の分かる319本）：上位3件に正解 54% → 76%。画面の1位が正解 13/30 → 19/30。
  再調整（2026-09-29、318本・全件を端から端まで）：上位3件 76% → 83%、画面の1位 161 → 187、候補のどこかに 244 → 264。
  友人の新しい写しで測り直し（2026-09-29、472本＝前の318本＋増えた154本。research §17）：前の318本で上位3件 264 → 270・画面の1位 187 → 230、
  増えた154本で上位3件 91 → 94・画面の1位 41 → 86。
  測るときは BOOTH の答えの控え（`ResolveAccuracyProbe --cache`）を使い、並べ直し・点数の直しは通信なしで試す。
  兄弟の zip は `--siblings`（保存先の商品が持つ zip の元の場所から、全部が未確定だったときの一覧を再現する）。

## 未確定の画面

- 束ね方：元zipで束ねて畳む（「このzipを選ぶ」で全件を1つの対象。検索語も zip 名）→ 分からなければフォルダで束ねる。展開物の中身は束で外せる（自動では外さない。自作の画像があり得る）。
- **束は2件以上のときだけ畳む**（ユーザ指摘 2026-09-17）：1件だけの束は畳まずに1行で出す。**zip自身は束に入れず**1行で出し、直後に「そのzipを展開した中身」を束にする（札「zipの中身」・「まとめて扱う」）。束を開いた中身は深く字下げして左に線を引く（束と中身が同じ密度で並び、どこを見ればよいか分からなかった）。
- **一覧を探す**（ユーザ指示 2026-09-17）：左の上に検索欄（ファイル名・フォルダ・zipの名前。大文字小文字・かなの種類・全角半角を区別しない。× で消す）。「全て選択」は見えている行だけ。選んでいた行が隠れたら見えている先頭の行を選ぶ（選択が外れると右側ごと消え、まとめて操作できなかった）。1行で出るzipの中身には「展開元：○○.zip」を添える（束の中では見出しにあるので出さない）。
- **元zipとして扱う**（ユーザ判断 2026-09-17）：元のzipが残っている中身の束の見出しと、1行で出ている中身に「元zipとして扱う」。押すと確認のうえ中身（束なら全件）を管理対象から外し、元のzipの行を選ぶ（そのままzipで登録できる）。zipが一覧に無ければ外すだけにして理由と次の一手を言う。
- **動線の直し**（ユーザ判断 2026-09-17）：zipを確定・登録した直後にそのzipの中身も一覧から外す（開いたときだけ見ていたので、残った中身を別の商品に登録できた）／「元zipとして扱う」は中身を外さずzipを選ぶだけ／選んだ行が検索で隠れていれば検索を消し、一覧をその行まで送る。確定後の次の行は見えている行から選ぶ／確定して編集へ送っていない商品は主画面が持つ（画面を離れても残る）／「エクスプローラで開く」／束の帯に検索で隠れている件数／フォルダ登録のボタンに対象のフォルダ名（zipの中身は同じzipの中身の共通フォルダ）／外した直後に上の帯で「外した n 件を戻す」（除外の記録を消し、外す前の未確定の記録を戻す）／空になったら「確定した分を編集へ送る」「取り込みを開く」／自動検索をするまで「候補がありません」を出さない／元zipが未確定にあるときの理由は対象の帯の3行目に（2026-10-03 までは入力欄の上）
- **zipを展開した中身は、元のzipを単位に登録する**（ユーザ判断 2026-09-17。基本は1zip＝1商品。`ResolveViewModel.ZipUnit.cs`）：
  - 元のzipが商品に登録済みで今もディスクにある：中身は未確定に出さず、上の帯に「登録済みのzipを展開したファイル n 件は出していません」。記録には書かず開くたびに決める（zipを消せば中身として戻り、後から紐付け直せる）。統計の容量は今まで通り登録した商品のファイルだけ
  - 元のzipが未確定にある：中身の「このIDで登録」「BOOTHに無い商品として登録」は押せず、対象の帯の3行目に理由（元zipとして扱うか、このファイルだけにする）を出す。「フォルダのまま登録」はできる（同じzipの中身が共通して入っているフォルダ）
  - 元のzipが一覧に無い（消した・取り込んでいない）：同じzipの中身全件を1つの単位に（束を自動で立てる）。選んだ物の登録（このIDで登録・BOOTHに無い商品）も同じzipの中身全件まで広げ、zipが未確定にある中身が混ざれば止める（除外は広げない。下の「今の対象」）
  - **zipが無い展開物は「展開物の根」1つに揃える**（2026-09-17 ユーザ判断 案A）：目印（.unitypackage・.url）の一番外側から中身が1つだけの親を遡ったフォルダ。ドライブの直下や取り込み元（またはその上）になるとき、**中に別の物（zipの中身・zip自身・商品が持っているファイル）が入っているとき**は目印のフォルダ、それも駄目ならファイルのフォルダに戻す（内側の目印までは探し直さない）。組み込んだとき（フォルダビュー）は上の帯が無いので、「外した n 件を戻す」と出していない件数を右側の上と空の表示に出す。左の束・まとめて扱う単位・フォルダのまま登録する先を全部これにし、サブフォルダで束が割れない。「その他」の「フォルダのまま登録する」には「対象：パス（未確定 n 件）」と登録ボタンだけ（外すは同じ欄の「管理対象から除外する」）
  - 単位は確定・BOOTHに無い商品としての登録・管理対象から外すのどれにも効く（元のzipが未確定にある中身も、外すは中身全件）
  - 対象の帯の「このファイルだけ」（1つのzipに複数の商品が入っているときなど）で単位を外す。選び直すと切れる（2026-10-03 までは「商品IDを決める」の下のチェックボックス）
- **一覧の行**（ユーザ指示 2026-09-17）：上に確かな情報（1行目にファイル名と大きさ〔右寄せ〕、1行で出る中身は2行目に展開元）、その下に候補と操作（札：「自動候補:n件」＝取り込んだときに手掛かりから見つかった商品IDの数。自動検索の候補は数えない／「展開」＝zipの無い展開物、最後にボタン）。札まで名前の横に並べると、真ん中くらいの長さ（22文字）の名前でも切れる。
- **壊れたzip**（ユーザ判断 2026-09-30）：取り込みで zip として開けなかった物（記録の `archiveBroken`。`docs/spec/import.md`）は、行の札の先頭に「壊れたzip」（赤：`BadSoft`・`BadBorder`・`Bad`。ほかの札は黄か灰色）、
  吹き出しに「zipを開けませんでした。ダウンロードし直してください。」。選ぶと「分かっていること」の先頭に「このzipは壊れていて開けません。ダウンロードし直して、もう一度取り込んでください。」。
  商品IDを決めて登録することは止めない。古い記録には印が無いので、取り込み直すと付く。登録すると印は商品のファイルの記録へ引き継がれ、商品ページに同じ札が出る。商品から外して未確定へ戻した物も、商品の記録から印を引き継ぐ（ユーザ判断 2026-09-30）。
- **同じ場所にあった商品を候補に出す**（ユーザ判断 2026-09-30「2A」）：手で商品に結んだファイルを同じ名前で上書きすると（壊れた zip を落とし直した・更新版を上書きした）、
  新しい中身は手掛かりが無いので未確定に出る。取り込みが記録に残した商品（`samePathItemIds`。`docs/spec/import.md`）を、右の「候補」の**先頭**に出す（`AddSamePathCandidates`）。
  - 行の作りはほかの候補と同じ3行：商品名／理由「前に同じ場所にあったzipを、この商品に登録していました」（zip でなければ「ファイル」）／出どころ「手元の商品の記録」。
    ボタンも同じ「これで確認」で、押すと「商品IDを決める」に入り、確かめてから「このIDで登録」で登録する。**自動では結ばない**（人が選んだときだけ）。通信は増えない（手元の商品は手元から読む）。
  - 一覧の札「自動候補:n 件」に数える（取り込みが見つけた候補。数えないと、上書きした物に候補があることに一覧で気付けない）。取り込み時の手掛かりと同じ商品なら1行・1件にまとめる。
  - 「BOOTHに無い商品」（仮のID）も候補になる。「BOOTHで開く」は出さず、「商品IDを決める」は手元の商品のIDをそのまま受ける（前は数字とURLだけを受けていた）。
    手元から消した商品は、BOOTHの商品ならIDで出し（選べば取り直して登録できる）、仮のIDなら出さない（登録する先が無い）。
- 出口は3つ：**このIDで登録**（URL も受ける）／**管理から外す**（除外）／**BOOTHに無い商品として登録**（`docs/spec/private-items.md`）。ほかにフォルダを商品として登録と、**BOOTHで見つからなかった商品IDのまま登録**（確かめてBOOTHが「無い」と答えたときだけ確定の欄に出る。⑦で確かめ直し、公開されたら情報を取る。`docs/spec/private-items.md`）。
- **キーボードだけで1件ずつ片付ける**（ユーザ判断 2026-10-01）：商品IDの欄で Enter＝「情報を確認」、確定＝**編集画面の「保存して次へ」と同じ割り当て**（既定 Ctrl+Enter。設定の行は「編集画面で保存して次へ・未確定で登録」）。
  確定・BOOTHに無い商品として登録・除外のどれでも、片付けると次の行が選ばれ、空の欄へフォーカスが戻る（ボタンで押したときも。押したボタンは終わるまで押せなくなり、フォーカスが右側の入れ物へ落ちていた。実機で確かめた）。
  左の一覧・検索欄・画面の外（フォルダビューの木）にいたときは動かさない。「このIDで登録」の吹き出しに今の割り当てのキー（割り当てが無ければ出さない）。
  - 同じ割り当てにしたのは、どちらも「この1件を決めて次へ」で、設定は1つのキーを1つの操作にしか付けない（別の操作にすると既定の時点でぶつかる）ため。
    Enter をもう一度で確定にしないのは、Enter は確かめるキー（I12：確定は取り返しがつかないので Enter では走らせない）で、答えを待つ間に重ねた2回目で見ていない商品に結ぶため。
  - 守りはボタンと同じ（確かめた商品がある・取得や登録の最中でない・元zipで止めていない）に、**欄の文字が確かめた商品と同じこと**を足す。違えば確定せず「先に商品IDを確認してください。」と欄へ戻す
    （BOOTHに無かったなど確かめた結果の文が出ていればそちらを残す）。確定のキーは確かめを走らせない（BOOTH へ行くのは Enter とボタンだけ）。
  - 下に出ている商品と同じIDで Enter を重ねても問い合わせ直さない。フォルダビューの右に組み込んだ未確定でも同じキーが効く。
  - ほかの出口（BOOTHに無い商品として登録・管理対象から除外）と対象の帯の切り替えは Tab でボタンに届く。選んだ物があるときは、このキーも選んだ物を登録する（ボタンと同じ。窓で聞く）。候補は並び（`ArrowGroup`）、左の一覧の束の見出しのボタンと開閉は一覧の中の ↑↓ で届く。
- zip を落とし直すことを先に勧める（zip は配布の単位で、移動にも強く、展開先は自動で対象外）。
- 確定した分をまとめて編集へ送る（調べる作業と主観で決める作業を分ける）。
- **右側の並び**（ユーザ指示 2026-09-17・2026-10-03）：上の「対象」の帯（送っても動かない） → このファイルについて分かっていること → 商品IDを決める → 候補 → その他（BOOTHに無い商品として登録・フォルダのまま登録・管理対象から除外）。
