# 商品IDの決め方と未確定（今の決め事）

> **要点**：手元のファイルから BOOTH の商品IDを決める。確かな手掛かり（zip の中の商品URL・Zone.Identifier の配布URL）があれば即確定、無ければファイル名から BOOTH 内を検索して候補を点数付けする。
> ファイル名だけでは「確度が高い」に届かない設計（誤って確定しない）。決まらない物は未確定へ置き、人が ID 確定をまとめて片付けてから編集へ送る。
> **ログイン（cookie）は使わない**。
>
> **コード**：`BoothIdResolver`（手掛かり）・`BoothZipInspector`・`Core/Scanning/UnresolvedOrigin.cs`、`Core/Services/FallbackResolver.cs`・`FileNameQuery`・`AlternateQueries`・`RegistryCandidates`・`ExclusionFilter`、
> `App/ViewModels/ResolveViewModel*.cs`、`experiments/ResolveAccuracyProbe`・`QueryVariantProbe`・`ZipOriginProbe`
>
> **経緯**：`docs/research/id-resolution.md`（18本の実ZIP・319本での実測）、`docs/research/zip-linking.md`・`zip-linking-followup.md`（並行調査）、`docs/history/grill-2-ui-and-data-model.md`（Resolve → Edit）

## 手掛かり（強い順）

1. zip の中のテキストの BOOTH 商品URL（依存ツール lilToon などを指す物は除く）
2. Zone.Identifier の `HostUrl` の配布URL `s{n}.booth.pm/<shop>/f/<商品ID>/…`（Chrome/Edge は書く。**Brave はオリジンしか書かない**）
3. unitypackage の名前空間 `Assets/<作者>/…`・中の Readme の URL、PDF の本文
4. ファイル名の接頭辞・末尾がショップのサブドメイン
5. ファイル名からの BOOTH 内検索＋点数付け（下）

- 展開したファイルの Zone.Identifier は `ReferrerUrl=<親zipのフルパス>` を持つ（CP932・末尾 NUL）。**元zipで未確定を束ねる**（zip を消しても、別のドライブへ移しても残る）。ドライブ文字か `\\` で始まり書庫の拡張子で終わる物だけ使う。
- 手掛かりから商品IDが1つに決まるファイルは、未確定を通さずにその商品へ紐付く。**「この商品から外す」の印（`detached`）が付いた組は候補から落とす**。
- ブラウザの履歴DB・ログインしたライブラリは使わない（利用者主導の取り込みを優先。cookie の自動利用は規約・誤検知の点で配布ツールの機能にしない）。

## 自動検索（ファイル名から）

- **検索語を整える**（`FileNameQuery.Tokens`）：版番号・括弧の付け足し・#タグ・作者の略号・配布形態の語・ダウンロードの重複番号・英語の機能語（for・the・of）を落とす。「」の中身は残す。日本語と英字の続きは割る。
  BOOTH の検索はスペースを AND で読み、余計な1語で全滅する。
- 1ページ（最大60件）をファイル名との近さ（語・番号・ショップ名）で**並べ直す**（通信は増えない）。語に直接付いた番号（「ポーズ集13」）も使う。
- 裏付けが出なければ、特徴のある**1語だけ**で、次に**別の表記**（読み→漢字・隣り合う2語をつないだ英語→日本語。日本語の表記を先に）で引き直す。別表記が作れなければ何もしない。
- 候補ごとに商品 JSON を取って点数を付ける（無料の種類のファイル名一致・名前空間とショップ・商品名の語・番号の照合・種類名）。7点以上が「確度が高い」。
- **手元の登録簿からも候補を出す**（通信なし。非公開になった商品でも名前が残っている）。一般的な語・短い語・2項目以上が持つ表記では当てない。
- 実測（友人の正解の分かる319本）：上位3件に正解 54% → 76%。画面の1位が正解 13/30 → 19/30。

## 未確定の画面

- 束ね方：元zipで束ねて畳む（「このzipを選ぶ」で全件を1つの対象。検索語も zip 名）→ 分からなければフォルダで束ねる。展開物の中身は束で外せる（自動では外さない。自作の画像があり得る）。
- 出口は3つ：**商品IDで確定**（URL も受ける）／**管理から外す**（除外）／**BOOTHに無い商品として登録**（`docs/spec/private-items.md`）。ほかにフォルダを商品として登録。
- zip を落とし直すことを先に勧める（zip は配布の単位で、移動にも強く、展開先は自動で対象外）。
- 確定した分をまとめて編集へ送る（調べる作業と主観で決める作業を分ける）。
- 除外はパスで先に弾き、ハッシュで移動・改名後も効かせる（毎回ハッシュを計算しないため）。`excluded.json` は `unresolved.json` と混ぜない（寿命が違う）。
- 未確定の一覧の書き方は `docs/spec/import.md`（取り込みとの合わせ方・外付け）。
- 画面を開くたびに、手元にあるファイルの Zone.Identifier を読み直す（保存値は旧版の文字化けを含みうる）。

## 間違って紐付いたファイル

- 商品ページのファイルの行ごとに「この商品から外す」→ 未確定へ戻す。**行は消さずに `"detached": true` で灰色に残す**（紐付いていたこと自体は確か）。「この商品に戻す」で戻せる（外した後で別の商品へ紐付けてあれば押せない）。
- 印の付いたファイルは所持・容量・検索・重複・Unity へ送る対象に数えない（`LocalBlock.OwnedFiles`。計算なので書き出さない）。日時は持たない。
- 最後のファイル（とフォルダ）を外して商品が空になるときだけ、残すか消すかを聞く。消すと印も消える。
- 印は設定画面の「隠したもの」に一覧で出し、「記録を消す」を置く（除外とは別の行）。
- 商品ごと別のIDへ移すのは「IDを変更」（`docs/spec/private-items.md`）。
