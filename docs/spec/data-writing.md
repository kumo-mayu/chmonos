# 保存データの書き方（今の決め事）

> **要点**：商品の `local` は持ち主の項目だけを、錠の中で読み直した最新に重ねる。書き手が複数いるファイルは錠の中で読んで直して書く。
> 計算で出せる値は書かない。手で直した JSON の食い違いは落ちずに知らせ、こちらからは直さない。何か所も順に書く操作は、やりかけの記録で囲む。
>
> **コード**：`Core/Storage/`（`ItemRepository`・`JsonStore`・`JsonFileStore`・`EmptyForNull`・`StoreIds`）・`Core/Models/LocalFields.cs`（持ち主）・`Core/Services/`（`HandEditCheck`・`PendingOperationRunner`・`OperationFingerprint`）
>
> **経緯**：2026-11-20 に [data-model.md](data-model.md) が200行を超えたので、その「書き方」の節をそのまま移した（文は変えていない）。それより前の経緯は data-model.md の「経緯」と同じ。

## 書き方

1. **商品の `local` は `ItemRepository.SaveLocalAsync(itemId, local, owns)` で書く。**`owns` に名指しした項目だけを、保存の直前に読み直した最新へ重ねる。
   持ち主は `LocalOwners` に宣言（編集画面＝タグ・属性・メモ・購入・入手日など／取り込み＝`LocalFiles` `LocalFolders`／検出＝`Avatars` `AvatarBases` …）。
   `Items.SaveAsync`（丸ごと）は**新しく作るときだけ**。商品番号の付け替えも、既にある先へは `SaveLocalAsync`。 商品を消すときは、画像のフォルダを別の名前（`<商品ID>.removing-…`）へ移してから記録を消し、記録を消せなければ画像を戻す（自分で足した画像は取り直せない）。途中で止まって残った退避は、起動の後の片付けで、記録が残っていれば戻し、無ければ消す。商品IDの付け替え（`MoveAwayAsync`）どうしは1本ずつ通す（甲→乙と乙→甲が互いの錠を待たないように。外部の点検 2026-10-07）。
   - **変えていない項目を名乗らない。**名乗った項目は必ず上書きされるので、持ち主が2人いる項目（`Memo` など）で
     相手の書いた値を古い写しで戻す。編集画面は `LocalFields.Changed` で**人が変えた項目だけ**を名乗る。
   - **時間のかかる処理を挟んでから書くなら `ChangeLocalAsync(itemId, change, owns)`。**名指しは他の項目を守るだけで、
     名指しした項目そのものは守らない。変え方を関数で渡し、**錠の中で読み直した今の値に当てる**
     （検出・タグや属性の一括書き換え・取り込みのフォルダの測り直しが、古い写しに当てて人の操作を潰していた）。
     関数が `null` を返せば書かない。
     フォルダの登録・ファイルを外す／戻す・unitypackage の入り先・IDの付け替えもこれで書く（2026-09-23。どれも測る・全件を読む・BOOTH から取る間に取り込みが足した物を消していた）。
   - `booth` を時間のかかる処理の後で書き換えるなら `ChangeBoothAsync(itemId, change)`（取り込みの②。`local` には触らない）。
2. **書き手が複数いるファイルは `JsonFileStore.UpdateAsync`（錠の中で読んで直して書く）。**画面の写しを丸ごと書き戻さない（取り込み元・未確定が消えていた）。
   変える物が無ければ `TryUpdateAsync` で書かずに済ませる（未確定から外す所は、一覧に無ければ書かない）。
   今の値を見て別の物を先に保存してから書くなら `TryUpdateAwaitingAsync`（錠を持ったまま待つ。未確定の1件を商品にする所）。
3. **設定・画面の状態・検索の履歴は、変え方を関数で渡す**（`UiCommand.ChangeSettings` など）。持つのは `SettingsService` だけで、画面は写しを持たない。
4. 書き込みは一時ファイル（`〜.tmp`）に書いてから置き換える。**名前は毎回変え、同じファイルへの書き込みは1本ずつ**
   （固定名だと2本重なったときに保存そのものが例外で落ち、投げっぱなしなので画面には何も出ない）。
   失敗したら `.tmp` を消す。起動時に、保存先の下にある10分より古い `.tmp` を消す。
5. 保存の直前に商品がまだあるかを見て、無ければ書かずに飛ばす（塞がない）。
   **組み直した結果が今の中身（保存する JSON の形）と同じなら書かない**（2026-09-24。取り込み直すたびに変わっていない商品を1件ずつ書き直していた）。呼んだ側への答え（書いたか・在ったか）は変えない。
6. **計算で出せる値は書かない**（`[JsonIgnore]`）。説明の節の `normalizedHeading` も見出しから計算する（2026-09-24。前に書かれたファイルに残っていても読むときに無視される）。
7. **手で書いた `null` の配列は空として受ける**（`Storage/EmptyForNull`。保存の設定1か所で全部の欄に効かせる）。
   落ちるのは読んだ瞬間ではなく、後から一覧・検索・統計が触ったときなので、原因の商品も分からない。
   `?` を付けて宣言した欄は別（「まだ調べていない」と「調べて0件だった」を区別している）。
8. **配った版（v1.0.0〜）の形は、形式の版と移し替え（`data-format.md`）で読む。それより前の形には合わせない**（ユーザ判断 2026-11-10。前は「公開前は古い形に合わせない」）。合わない物は「どの保存先の何件がどう合わないか」を報告して直し方を聞く。
9. **手で直した JSON の食い違いは、落ちずに知らせる**（`Services/HandEditCheck`・ユーザ判断 2026-09-21）。
   - 同じ鍵が2つあっても索引を作る所で落ちない（`FirstWins.Map`。**先に書いてある方**を残す）。
   - 起動時の裏の作業で、同じ名前の大分類・小分類・属性・登録簿の商品ID・素体の名前・別名と、
     **ファイル名と中の商品IDのずれ**（L6）を見て、通知に1件出す。直ったら解消済みにする。
   - **こちらから直さない。**直し方（片方を消す・名前を分ける・IDを揃える）は人が決める。
10. **読めない商品の記録は知らせ、押せば直す**（ユーザ判断 2026-10-05。[notifications.md](notifications.md)「読めない商品の記録」）。
   - 全件の読み込みは `items` の直下の `*.json` だけを読む（`.prev`・`_broken` の中は商品に数えない）。読めない物は飛ばして、JSON の何行目かと一緒に返す（`ItemReadFailure`。中身が `null` だけの物も読めない物に数える）。
   - **控えは「アプリが最後に書いた版」**：本体を据えた後に同じ門の中で写す（`JsonStore.WriteAsync` の `copyTo`）。本体の置き換えは名前の途切れない改名なので、
     `File.Replace` の控えの引数は使えない（使えば改名をやめることになり、読み手が本体を「無い」と見る隙が戻る）。固いリンクも使わない（メモ帳などは本体をその場で書き換え、リンクの先も壊れる）。
     写せなくても書き込みは成功のまま（ログに残す）。手で直した後に壊した物を戻すと、手で直した分は戻らない。
   - 直すときは商品の錠と書き込みの門の中で、本体がまだ読めないことを見てから動かす。**壊れた本体は消さずに `_broken` へよける。**
11. **何か所も順に書く操作は、やりかけの記録で囲む**（`Services/PendingOperationRunner`・ユーザ判断 2026-10-06「A」）。対象は「IDを変える」と、タグ（大分類・小分類）・属性の名前の変更（統合を含む）。
   - 始める前に `pending-operations.json` へ1行足し（**書けなければ始めず失敗として返す**）、保存した検索・設定のカードの属性まで書き終えたら自分の行を消す。途中で例外が出たら行は残す。画面から同時に2つ走り得るので一覧にする。
   - 起動したときに主画面が `UiCommand.ResumePendingOperations` を1回送り、残った行を古い順に続ける（BOOTHへは問い合わせない。設定「起動したとき、裏で取得を始める」でも止めない）。この起動で走っている行は飛ばす。
   - **どの段も2回当てても同じ結果になる作りに頼る**。タグ・属性は操作をそのままもう一度当てる（一覧・商品・保存した検索のどれも「古い名前を新しい名前へ」）。
   - **行に指紋を書き、続きは「記録した時と同じ物か」を指紋で見分ける**（`Services/OperationFingerprint` 1か所で作る。2026-10-06 外部の点検・L108）。
     ID と名前だけだと、操作の前から同じ値の購入を持つ移す先を「合わせ済み」と取り違え（元の購入が1件落ちた）、消せずに残った行が同じ ID・名前で作り直した物に当たった。
     指紋は行にだけ書き、商品の JSON に欄は足さない。商品の指紋は `local` を保存と同じ形で書き出したハッシュ（取得が書く欄と購入の「BOOTHにあるか」は数えない。起動の裏の取得が先に書くため）。
   - IDの変更（`ItemService.ResumeItemIdChangeAsync`）：元を読んだ直後に元の指紋、移す先へ書く直前に移す先の錠の中で「元・合わせる前・合わせた後」を書く（書けなければ書かずに断る）。
     続きでは、合わせた後の指紋が無ければ移す先へは何も書いていない（元が記録のままで移す先があれば、ふつうに合わせる。元が無いのは人が消した物なので何も当てない）。
     元が無ければ改変とほかの参照だけ移す。移す先が合わせた後のままなら元を消すだけ、合わせる前のままならふつうに合わせる。元か移す先が記録と違えば当てない。
     元を読んだ直後には、元のIDを指す改変の ID・ほかの商品の ID・素体の名前と、登録簿に行があったかも `references` に書く。続きが書き換えるのは**これに載った物だけ**
     （登録簿の行は、移す先の行がまだ無いときだけ。L110）。止まった後に元のIDで登録し直したアバター・その後に作った改変に当てないため。足跡と知らせは今の様子のまま移す。
   - タグ・属性：始める前に、一覧の丸ごとの指紋と、古い名前を持つ商品ごとの付け方の指紋を書く。一覧に古い名前が今もあるのに一覧が記録と違う・
     記録に無い商品が古い名前を持つ・付け方が記録と違う、のどれかなら当てない（済んだ後に作り直した名前・後で付けた名前）。
   - 続けられなかった行は残し（次の起動でまた試す）、通知「途中で止まった操作」に1件出す（ID `pending-operation:{行のID}`）。済んだら解消済みにする。
     記録と違って当てなかった行は消して同じ通知に出す（残すと起動のたびに止まるだけ）。その知らせには、もう一度操作する窓に入れる値を `retry`（`kind` と、その操作の `fromId`・`toId`・`top`・`sub`・`oldName`・`newName`。指紋は持たない）で持たせる。済んだ行を消せなかったときは済んだ扱いにせず、同じ通知に出す。
   - **終えた行は、消す前に `finishedAt` を書く**（当てずにやめた行は `skipped` も。2026-10-07 外部の点検・L110）。指紋だけでは、済んだ後に同じ内容で作り直した物と見分けられない。
     次の起動で `finishedAt` のある行は当て直さずに消すだけにし、知らせを解消済みにする（`skipped` の行の「続きは行いませんでした」は残す）。
     印も書けなかった（保存先に書けない）行は印の無いまま残り、次の起動で指紋と `references` で見分けて続きを当てる。
     **知られた限界（ユーザ判断 2026-10-07・8回目の点検）**：記録のファイルだけが書けず、印も消すのも失敗し、次の起動の前に、記録した商品へ元の ID を指す参照を足すか、タグ・属性を同じ内容で作り直すと、古い操作がそれに当たる。条件が重ならないと起きず、印を書けなかったときは「記録を書き込めなかった」の知らせが出るので受け入れる（参照1つずつや世代の印で見分ける作りは取らない）
12. **JSON から来た値を、場所や外のアプリへ渡す前に形で見る**（2026-10-06 外部の点検・L106）。手で直せるので、何が書かれていてもおかしくない。
   - **ID は場所の名前になる**（`Storage/StoreIds`）。商品ID は数字だけか `local-` と小文字の16進、改変ID は `mod-` と小文字の16進、unitypackage の控えの鍵は16進。
     `AppPaths` の ID から場所を組む関数（`ItemFile`・`ItemCopyFile`・`ItemHtmlFile`・`ItemImagesDir`・`AvatarImagesDir`・`ModificationFile`・`ModificationImagesDir`・`UnityPackageFile`）は形が違えば投げる。
     読むだけの入口（在るか・読む・控え）は「無い」と答える。消す・移す直前にも、組んだ場所が所定のフォルダの中かを区切り付きで確かめる（`StoreIds.IsInside`）。
   - 形の外れた記録（ファイル名・中の id・登録簿の行）は読み込み・片付け・IDの変更から外し、ログに1回書き、手で直したファイルの点検（9.）に出す。**こちらから直さない。**
   - **外のアプリへ渡す URL**：商品ページは記録の `booth.url` を使わず番号の商品ID から作る（`Booth/BoothLinks`）。ショップのページは https で `booth.pm`・`*.booth.pm` の物だけ。
     開くのは `Shell.OpenUrl` 1か所で、http/https の絶対 URL だけを解釈し直した形で渡す（説明文のリンク・動画も同じ）。実行ファイルの場所・`file:`・独自の形は開かない。
