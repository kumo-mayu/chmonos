# 外から使う API（案）

> **要点**：Chmonos の手元の資産（自動の紐付けで決まった対応アバター・素体・手元のファイル・タグ・属性）を、何の言語からでも読めるように、**別の実行ファイルがローカルの HTTP で答える**（2026-10-12・ユーザ判断）。読むだけ。BOOTH へは問い合わせない。
> まだ作っていない。この文書は決めたこと（同期・守り・共通の決まり）。URL と答えの形の案は [local-api-shapes.md](local-api-shapes.md)。

## 決めたこと（2026-10-12）

- **何の言語からでも**を重く見て、ローカルの HTTP にする（CLI・MCP・名前付きパイプ・データ形式の公開だけ、と比べた）。
- **別の実行ファイル**（仮の名前 `Chmonos.Api.exe`）。C# の ASP.NET Core（Kestrel）の minimal API で、Native AOT の単体の exe にする。
  `HttpListener` は待つアドレスによって管理者の権限・URL の予約が要るので使わない。C++・Rust で作り直さない（検索の記法・辞書の展開・所持の定義を2か所に持つとずれる）。
- **アプリと同じ zip で配る**（アプリとバージョンを揃える。合わない組み合わせでは答えない）。
- **起動は本体と連動させない**。使う人が手で起動する（ログオン時の起動は後で設定に足すかもしれない）。
- **読むだけ**。書き込みは画面の `UiCommand` だけを通る決まりを崩さない。BOOTH の 1本ずつ・1.5秒の決まりを外から破れないよう、足りない情報も取りに行かない。
- **検索の条件は JSON の式で受ける**。画面の絞り込みの条件を葉にして、AND・OR・NOT を自由に組める（画面は条件ごとの AND だが、API はプログラムが組むので木にする）。判定は Core へ移した（`SearchModuleConditions.From` が保存した条件の形 `SearchModuleState` から判定を作る。画面の条件も同じ判定を使い、`SearchModuleConditionParityTests` で同じ商品に当たることを確かめる。2026-10-12）。API の条件の JSON はこの形へ変換する。
- 検索欄の記法に、条件でしか書けない物（日付・属性・改変など）を足すのは**保留**（API とは別に考える）。
- **画面と分かれる所**：範囲の境を空欄で送ると「制限しないが、数の分かる商品だけ」になる。画面は、手元に数が1件も無い種類を足した直後だけ両側を切って全件を見せる（足した瞬間に0件にならないように）が、API は送られた値どおりに照らす（`SearchModuleConditionTests`）。
- 判定は `SearchModuleConditions.Build(state, context)` で作る（準備まで済ませる。準備を忘れると空欄の日付が手元の端を指さない）。
- **非表示と R-18 は全部返し、印を付ける**（`isHidden`・`isAdult`）。外の道具が画面と同じに隠せるよう、使う人の表示の設定も読めるようにし、絞る引数も用意する。
- **SSE を v1 から付ける**（`GET /v1/events`）。
- **選択肢の件数を v1 から付ける**（`POST /v1/search/facets`。自作の画面で選択肢に件数を添える・0件を隠すため）。
- **アバター・素体・ショップから商品を引く専用の URL は作らない**。検索の式で書く（「対応の指定が無い商品も含める」「素体経由」も条件の値で書ける。同じ問いの答え方を2つ持つとずれる）。使い方に式の例を載せる。
- **自作の Web ページから使える形（許可する住所の一覧）を v1 から入れる**（下の「ブラウザから」）。
- **BOOTH の情報を配り直さないよう、注意を書く**（API の説明と `/v1/version` の答えに。下の「注意」）。

## 同期

- 正しい値はいつも保存先のファイル。API はそれを読んでメモリに持つ。
- アプリは書き込みを終えて錠を外した後に、`POST /internal/changed` で**変わった物の ID と通番だけ**を知らせる（中身は送らない。偽の知らせが来ても読み直しが増えるだけ）。
  待たない・すぐ諦める・API が動いていなければ何もしない。アプリの書き込みを API の都合で遅らせない。
- 知らせは落ち得る。API は起動したとき全部を読み、通番の飛びに気付いたら全部を読み直す。時々の確かめも入れる。
- 書き込み中の JSON は `AtomicReplace` で置き換わるので、書きかけを読むことは無い。
- **まとめて書く操作（取り込み・引越し・戻す）の途中も、古い答えを返し続ける**（長く続くことがあるため。ユーザ判断 2026-10-12）。アプリは始まりと終わりも知らせ、API は `/v1/version` と SSE で「まとめて書いている途中」を伝える。
- API は書き込みの錠を取らない。保存先は `StoreLocation.Resolve`（`CHMONOS_HOME` か `location.json`）で決め、1つの API は1つの保存先にだけ答える。
- 保存の形（`format.json`）が API の知る版より新しいときは答えない（503・「API を新しくしてください」）。

## 守り

- 待つのは `127.0.0.1` だけ。ポートは決まった番号を既定にし、設定で変えられる。使っている番号・トークン・PID・API のバージョンを保存先の `api.json` に書く（API が書く。人は書かない）。
- **API の設定（ポート・許可する住所）は保存先の `api-settings.json`**。Chmonos の設定画面からも足し引きでき（`UiCommand` を通す）、ファイルを手で書いてもよい（ユーザ判断 2026-10-12）。API は変わったら読み直す（ポートを変えたときは起動し直しを求める）。
- **トークン（合言葉）を必須にする**。本当の目的は、同じ PC の別の Windows ユーザーと、待つ先を誤って広げたときに中身を守ること（`127.0.0.1` には PC の中のどのユーザーからも届き、`Host` は自由に書ける。`api.json` は自分のユーザーのフォルダにあって別のユーザーは読めない）。
  ブラウザへの守り（`Host` の確かめ・CORS）の2枚目にもなる。`GET /v1/health`・`GET /v1/version` は合言葉なしで答える。
- 合言葉は起動のたびには変えない（`api.json` に残す）。作り直す操作で変える。ログに書かない。
- `Host` が `127.0.0.1:<ポート>`・`localhost:<ポート>` 以外なら断る（DNS rebinding）。
- 問い合わせの中身はログに残さない（購入履歴と検索の言葉）。
- 式の大きさに上限（深さ・葉の数）を置く。

## ブラウザから（ユーザ判断 2026-10-12：B）

- 使う人が**許可する住所**（例 `http://localhost:5173`）を API の設定に書く。その住所のページにだけ CORS の許可を出す。一覧が空なら今と同じ守り。
- 合言葉はページが取ってこられない（`api.json` を読めない）ので、使う人がページに貼る。
- ブラウザの決まりで、**ヘッダを付けられない読み方**がある。
  - `<img src>`：画像は `fetch` で合言葉を付けて取り、`blob:` の URL にして見せる（使い方に書く）。
  - `EventSource`（SSE の標準の読み方）：ヘッダを付けられないので、`fetch` で流れを読む（使い方に書く）。合言葉を URL に入れる形は受けない（履歴とログに残る）。
- インターネット上の公開ページから `127.0.0.1` への問い合わせは、Chrome が使う人に許可を求める方向へ締めている。作るときにその時点の決まりを確かめる。

## 注意（案）

`/v1/version` の `notice` と使い方の頭に置く。根拠は `docs/research/booth-terms.md` §5（BOOTH 個別規約 第13条：商品の情報の権利は登録した人にある。第5条：購入者の使える範囲は各ショップの利用規約による）。

> この API が返す BOOTH の商品の情報（商品名・説明文・画像など）の権利は、それぞれの作者にあります。自分で使うための物なので、他の人に渡したり、公開したりしないでください。購入したファイルの扱いは、各ショップの利用規約に従ってください。

- 「外へ送らない」とは書かない。自分で使う AI の道具に渡すのは配り直しではなく、それまで禁じると使い道を潰す。

## 共通の決まり

- URL に `/v1/`。項目を足すのは互換、消す・名前を変える・意味を変えるのは非互換で `/v2/`。外の道具には「知らない項目は無視する」と書いてもらう。
- 名前は camelCase。日時は ISO 8601（時差付き）、日付だけの値は `YYYY-MM-DD`。ID は文字列。列挙の値は英字の文字列（保存の JSON が日本語の値でも、API は変えない英字の値にする。例：購入の種類 `self`・`received`・`given`）。値が無いときは項目を省かず `null`。
- 一覧は続きの印（`cursor`）で分ける。1回 200 件まで。並びは必ず一意（同じ値なら ID で決める）。
- 答えに `ETag`。変わっていなければ `304`。
- エラーは `application/problem+json`（RFC 9457）。機械が読む `code` は変えない。
- 仕様書は OpenAPI をコードから作り、`/v1/openapi.json` で出す。
- 内部の状態の区別を潰さない：確認済み／候補／消した、外したファイル・古い版・見つからない、非表示、未評価と 0。
- 計算で出す値（持っているか・所有アバター・更新がある）も返す。外で計算させるとずれる。答えは Core の同じ所（`LocalBlock.IsOwned` など）から取る。

## 未決

- **外付けのドライブの文字が変わったときの読み替え**：画面はドライブの通し番号を調べて読み替える（`VolumeTable`）。API は v1 では記録の場所のまま返し、照らす。
  画面も読み直しのときは調べるだけで書かない（書くのは取り込み・フォルダビュー）ので、調べる道具（`VolumeReader`・App にある）を Core へ移せば API でも使える。
- **保存した検索・履歴を返す**には、保存の形（`SearchModuleState`）から API の条件へ戻す変換が要る。
- **辞書で別表記に広げる**：画面でも既定は切。索引の控えが無いと保存先へ書くので、控えがあるときだけ使う形なら足せる。
