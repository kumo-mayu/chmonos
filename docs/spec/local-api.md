# 外から使う API

> **要点**：Chmonos の手元の資産（自動の紐付けで決まった対応アバター・素体・手元のファイル・タグ・属性）を、何の言語からでも読めるように、**アプリと同じプロセスがローカルの HTTP で答える**（2026-10-12・ユーザ判断。2026-10-13 に別の実行ファイルから移した）。書き込みは設定で許したときだけ（段3で足している途中）。BOOTH へは問い合わせない。
> この文書は決めたこと（起動・同期・守り・共通の決まり）。URL と答えの形は [local-api-shapes.md](local-api-shapes.md)。画面を出さずに動かす起動は [headless.md](headless.md)。

## 決めたこと（2026-10-12）

- **何の言語からでも**を重く見て、ローカルの HTTP にする（CLI・MCP・名前付きパイプ・データ形式の公開だけ、と比べた）。
- C# の ASP.NET Core（Kestrel）の minimal API（`Chmonos.Api`。ライブラリで、アプリの exe に入る）。
  `HttpListener` は待つアドレスによって管理者の権限・URL の予約が要るので使わない。C++・Rust で作り直さない（検索の記法・辞書の展開・所持の定義を2か所に持つとずれる）。
- **アプリの1ファイルの exe に同梱**（2026-10-13。前は .NET を同梱した別の1ファイル、圧縮なし。下の数字はそのときの物）。
  Native AOT は、Core の保存の JSON が実行時に型を組み立てるため、商品を読む所で止まった（型を残す設定でも組み合わせの型が入らない）。AOT にするには保存の読み書き全体を作り替える要がある。
  メモリ（ユーザ「ランタイムの分メモリがもったいない」）を測ると、.NET の土台は小さく、件数が増えるとデータの分が大半を占めた：

  | 保存先 | 作業セット | 専用 |
  |---|---|---|
  | 空（.NET の土台）・圧縮あり → **圧縮なし** | 124 → **67MB** | 57 → **19MB** |
  | 2,000 件・説明文を持つ → 写しから落とす → 読み込み後に片付ける → **Core の控えを使わない** | 191 → 172 → 161 → **148MB** | 143 → 120 → 111 → **96MB** |
  | 2万件（`perf20k`）：起動から答えるまで 8.1 秒 | 272 → **253MB** | 221 → **202MB** |

  だから効く順に、圧縮をやめる・写しに持つ物を絞る（説明文は本文を探すときだけファイルから読む）・読み込み後に片付ける、を入れた。AOT は、それでもまだ気になれば別の作業として考える。
- **アプリと同じプロセスで動く**（2026-10-13・ユーザ判断。`docs/history/headless-core-2026-10-13.md` 段2）。前の「起動は本体と連動させない・別の実行ファイル」は覆った：
  別のプロセスが保存先へ書くと、書き込みの門（`StoreWriteGate`）・商品の錠・`UiCommand` を全部すり抜けるので、書き込みを足せなかった。
  - **設定の「APIを使う」でオンのときだけ待ち受ける（既定はオフ）**。オンにしたらすぐ待ち受け、オフですぐ止める。ポートを変えたらその場で待ち受け直す（`ApiRunner`）。
    画面を出さない起動（`--headless`）でも同じ設定に従う（オフならポートを開けない）。オンにするかは、ポートを開けて合言葉を持つ道具に読ませるかの判断なので使う人が選ぶ
  - 保存先ごとに1プロセスなので、錠はアプリの `app.lock` だけ（前の API 専用の `api.lock` はやめた）。設定の画面の状態は、同じプロセスの係から直に知らせを受ける
  - ポートが使われていれば始めずにログに残し、設定の画面が「待ち受けられませんでした。…ポートを変えてください。」と言う。アプリは止めない
  - `api.json` にはポート・合言葉・このプロセスの番号を書く（外の道具が読む）。止めるときに「止まった」に書き戻すのは、自分の記録のときだけ。合言葉は始めるたびには変えない。
    作り直すのは設定の「合言葉」の「作り直す」（前の `--new-token` の代わり。動いていれば止めて作り直し、新しい合言葉で待ち受け直す）
  - 商品の記録はアプリの控え（`ItemRepository`）と共有する（`QuerySnapshot.SharesItemCache`）。画面が説明文ごと控えに持っているので、説明文を落とした写しを別に作らない。
    アプリと同じプロセスでは、読み込み後の強い片付け（`GC.Collect` の圧縮）もしない（画面のスレッドも止まる）
  - **メモリ**（2026-10-13・`perf20k`＝2万件の作り物。起動し直して専用メモリが5秒動かなくなってから測った。オフ・オンを交互に2巡）：
    API オフ 352〜356MB・オン 437〜457MB（専用）。オンの上乗せは約 85〜100MB で、別のプロセスだった頃の API 単独 202MB より約 100〜115MB 少ない。
    API で初めて検索すると検索用の文字列を作って +13MB、本文まで探すと更に +12MB（画面と二重に持つ分。作り物は説明文が短いので実際は多め）。
    この程度なので、検索用の文字列は共有していない（共有するなら、画面と API で同じ作り方・同じ写しの世代を揃える作りが要る）
  - **件数とメモリ**（2026-10-13・画面あり・専用 MB。同じ台本で作った作り物 5千・1万・2万件と、実物に近い `stress-realcat` 2千件）：

    | 写し | API オフ | オン | オンで検索した後 |
    |---|---|---|---|
    | stress-realcat 2,000 | 162〜200 | 172〜176 | 221 |
    | perf5k 5,000 | 204 | 222 | 233 |
    | perf10k 10,000 | 260 | 297 | 316 |
    | perf20k 20,000 | 352〜357 | 433〜457 | 473 |

    作り物ではどれも件数にほぼ比例する：アプリは1件あたり約10KB（土台は約150MB）、API の上乗せは約3.8KB、API で検索すると更に約2KB。
    実物に近い2千件では API の上乗せはぶれ（同じ条件で約40MB）に埋もれるが、検索すると +45MB（1件あたり約22KB。説明文が長い）。
    実物で件数が多い人が API で検索すると、検索用の文字列の二重持ちが効いてくる見込み（共有するかは、実物に近い大きな写しで測ってから決める）
  - 取り込みの始まりと終わりはアプリが直に伝える（`ApiServer.SetBusy`。前は HTTP の `/internal/busy`）
- **書き込みは `UiCommand` を通す**（2026-10-13。前は「読むだけ」）。決め事と段取りは `docs/history/headless-core-2026-10-13.md` の「段3」：
  - アプリが命令の口を渡す（`ApiWriteHooks`。API のライブラリはアプリを参照しない）。API から来た命令には「人が押した」優先度を掛けない（`CommandOrigin.Api`）
  - 設定の「ほかのアプリからの変更を許す」（`allowWrites`。既定オフ）で許す。合言葉は読むのと同じ1本。変えたらその場で効く。許していなければ 403 `writesDisabled`
  - 保存先を運んでいる間（引越し・書き出し・戻す）は待たせず 503 `storeBusy`（`Retry-After: 5`）。編集画面で開いている商品には 409 `itemBeingEdited`。
    入口で1回見るだけでは、見た後に開いた編集画面が古い値を読み、後の保存で API の分を消す。API は書き終えるまで商品の札（`ItemEditGate`）を持ち、編集画面は札が返るまで商品を読まない（点検37）
  - 書いた後は写しを読み直してから答える（直後の GET と同じ答え）。取り込み中は写しを差し替えないので 202 と `busy` を返し、終わったら変化の知らせで伝える。読み直しは1つずつ（`StoreSync` の錠）
  - 書いたらアプリ（画面）へ知らせる（`ApiWrite`）。主画面は見回りの後と同じ道で検索の写しへ映し、開いている商品ページは開き直す（メモを打っている途中なら書き終えてから）。
    足跡なら「最近」の絞り込みと並び、一覧に足したらタグ・属性の候補を作り直す（点検37）
  - 取り込みの途中も、書き込みの許しと許す住所はその場で読み直す（商品の写しとは別。切ったらすぐ効く）。名前は保存先の今の一覧に照らす（写しは取り込みの間は古い）
  - API から来た命令は、いつもログ（`logs/app.log`）に1行残す（`外から使う API：命令の種類 → 結果`。商品 ID などの中身は書かない）
  - `createMissing` で一覧に足した後に商品への書き込みが失敗すると、一覧だけ増えて商品は変わらない（画面の「一覧に足してから付ける」と同じ順。受け入れる）
  - 許した住所のページからは書ける（書き込みを許しているときだけ CORS で PUT・PATCH・DELETE も許す）
  - 今ある URL（3a）：`PUT /v1/items/{id}/favorite`・`PUT /v1/items/{id}/hidden`（`{"value": true}`。答えは商品）、
    `POST /v1/items/{id}/recent`（`{"kind": "used"}` だけ。「見た」は画面が打つ）・`PUT /v1/notifications/{id}/read`（`{"value"}`）・
    `POST /v1/notifications/read`・`POST /v1/notifications/resolve`（`{"ids": […]}`。解消は消さずに印を付ける）。答えは本文なし（204）
  - **Unity へ送る**（3a。ユーザ判断 2026-10-13）：`POST /v1/items/{id}/send-to-unity`（`{"entry"?, "zipHash"?, "project"?}`）。画面と同じ部品（`UnityImportQueue`）で送る（`ApiUnitySender`）。
    送る物は unitypackage が1つなら省ける・送り先は開いているエディタが1つなら省ける（API は選ぶ窓を出せない。複数なら 400 `unityPackageAmbiguous`・409 `unityTargetAmbiguous`）。
    「送りますか」の確認は出さない（Unity の取り込み画面が確認になる）。送り終えるまで待たずに 202（`state: sending`）で返し、終わりは変化の知らせ `unity` と `GET /v1/unity/last-send`。
    送れたら「使った」の足跡、送れなかったら「見つからない」の印を確かめ直す（画面と同じ。どちらも API の起点で命令の口を通す）。送っている間（後始末まで）は次の頼みを 409 `unityBusy` で断る。送り先は `GET /v1/unity/editors` で選ぶ。結果の種類はログに1行（`Unity へ送る → imported` など）。
    実際の Unity 2022.3 で確かめた（2026-10-13・確かめ用のプロジェクトに作り物の unitypackage を送り、取り込み画面→取り込んだ→「使った」の足跡まで）
  - **分類**（3b）：`PUT /v1/items/{id}/user-tags`（丸ごと置き換え）・`POST /v1/items/{id}/user-tags`・`…/user-tags/remove`（1つ足す・外す。小分類を省くと大分類ごと）・
    `PATCH /v1/items/{id}/attributes`（`{"values": {"名前": 0〜100 | null}}`。名指しした物だけ。null は外して未評価に戻す＝キーが無いのと 0 を分ける）・
    `PUT /v1/items/{id}/memo`（null か空で消す）・`POST /v1/user-tags`・`POST /v1/attributes`（一覧に足す。既にあれば足さない）。
    名前は一覧の綴りに寄せる（大文字小文字・前後の空白）。一覧に無い名前は既定で 400（`unknownUserTag`・`unknownAttribute`）、`?createMissing=true` なら一覧に足してから付ける。
    足す・外す・属性は錠の中で今の値に当てる（`UiCommand.ChangeItemLocal`。読んでから丸ごと書くと、間に書かれた分を消す）
  - 足跡は `UiCommand.TouchRecent` で書く（画面は裏の列で書く `RecentTracker`。書き方は同じ `RecentActivity.Touch`）
- 書き込み以外は今までどおり読むだけ。BOOTH の 1本ずつ・1.5秒の決まりを外から破れないよう、足りない情報も取りに行かない。
- **検索の条件は JSON の式で受ける**。画面の絞り込みの条件を葉にして、AND・OR・NOT を自由に組める（画面は条件ごとの AND だが、API はプログラムが組むので木にする）。判定は Core へ移した（`SearchModuleConditions.From` が保存した条件の形 `SearchModuleState` から判定を作る。画面の条件も同じ判定を使い、`SearchModuleConditionParityTests` で同じ商品に当たることを確かめる。2026-10-12）。API の条件の JSON はこの形へ変換する。
- 検索欄の記法に、条件でしか書けない物（日付・属性・改変など）を足すのは**保留**（API とは別に考える）。
- **画面と分かれる所**：範囲の境を空欄で送ると「制限しないが、数の分かる商品だけ」になる。画面は、手元に数が1件も無い種類を足した直後だけ両側を切って全件を見せる（足した瞬間に0件にならないように）が、API は送られた値どおりに照らす（`SearchModuleConditionTests`）。
- 判定は `SearchModuleConditions.Build(state, context)` で作る（準備まで済ませる。準備を忘れると空欄の日付が手元の端を指さない）。
- **非表示と R-18 は全部返し、印を付ける**（`isHidden`・`isAdult`）。外の道具が画面と同じに隠せるよう、使う人の表示の設定も読めるようにし、絞る引数も用意する。
- **SSE を v1 から付ける**（`GET /v1/events`）。
- **選択肢の件数を v1 から付ける**（`POST /v1/search/facets`。自作の画面で選択肢に件数を添える・0件を隠すため）。
- **アバター・素体・ショップから商品を引く専用の URL は作らない**。検索の式で書く（「対応の指定が無い商品も含める」「素体経由」も条件の値で書ける。同じ問いの答え方を2つ持つとずれる）。使い方に式の例を載せる。
- **自作の Web ページから使える形（許可する住所の一覧）を v1 から入れる**（下の「ブラウザから」）。
- **BOOTH の情報を配り直さないよう、注意を書く**（API の説明と `/v1/version` の答えに。下の「注意」）。

## 同期

- 正しい値はいつも保存先のファイル。API はそれを読んで写しを持つ（`QuerySnapshot`。作った後は変えず、読み直すたびに新しい写しへ差し替える）。
- **変わったことは API がファイルの変化を見張って拾う**（`StoreSync`・`FileSystemWatcher`）。2026-10-12 に「アプリが変わった ID を知らせる」案から変えた：
  アプリの書き込みの出口は JSON の書き込み・商品の削除・画像の保存などに分かれ、全部に知らせを入れても漏れたときに気付けない。ファイルを見張れば、どの道の書き込みも同じに拾える。
  - 見張りの知らせは 300ms 待ってまとめ、場所から変わった部分（商品・画像・登録簿・タグ…。`StoreChanges.Classify`）を見分けて、その部分だけ読み直す。
    部分のファイルの印（大きさ・日時）が変わっていなければ読み直さず、知らせもしない。商品は一覧を見直し、変わったファイルだけ読む（2,000 件でも一覧だけ）。
  - 知らせがあふれたら全部を読み直す（`reloaded`）。見張りは取りこぼし得る（ネットワークのドライブなど）ので、**2分ごとに**画像以外の全部の部分の印を見比べる。
  - 商品の読み込みに Core の `ItemRepository` の控えを使わない（読んだ記録を説明文ごと控えるので、写しで落とした分が戻る）。
- **アプリが知らせるのは、まとめて書く操作の始まりと終わりだけ**（`ApiRunner.NoteBusy` → `ApiServer.SetBusy`。今は取り込み）。ファイルを見ても分からないのはここだけ。
  同じプロセスなので直に呼ぶ。API が動いていなければ何もしない。アプリの書き込みを API の都合で遅らせない。
- 書き込み中の JSON は `AtomicReplace` で置き換わるので、書きかけを読むことは無い。開けなかった商品は前の記録のまま残す。
- **まとめて書く操作の途中も、古い答えを返し続ける**（長く続くことがあるため。ユーザ判断 2026-10-12）。終わりの知らせで読み直す。知らせが来ないまま（アプリが落ちた）30分経ったら待つのをやめる。
  API は `/v1/version` の `busy` と SSE の `busy` で「まとめて書いている途中」を伝える。引越し・戻すは保存先ごと変わるが、アプリが起動し直すので API も一緒に新しい保存先で始まる。
- 外の道具への知らせ：通番は API の起動ごとに数え直し、起動ごとに変わる名前（`epoch`）を添える。`/v1/changes?since=&epoch=` は直近 1000 件まで持ち、
  持っていない分は `reload: true`（全部を取り直してもらう）。一覧と通番は同じ錠の中で取る。SSE（`/v1/events`）は `id: 起動の名前-通番` で、つなぎ直しの `Last-Event-ID` から続きを流す（持っていなければ、送り済みの境の通番で `reloaded`）。15秒ごとに印（`: ping`）を流す。
  聞き始めと通番は同じ錠の中で取り、受け手が遅れて待ち行列があふれ通番が飛んだら `reloaded` を流す（点検30）。
  読み直しに失敗したら、部分のファイルの印を確認済みにせず、取り出した変化を貯め直す（点検30）。
- API は書き込みの錠を取らない。保存先は `StoreLocation.Resolve`（`CHMONOS_HOME` か `location.json`）で決め、1つの API は1つの保存先にだけ答える。
- 保存の形（`format.json`）が API の知る版より新しいときは答えない（503・「API を新しくしてください」）。

## 守り

- 待つのは `127.0.0.1` だけ。ポートは決まった番号を既定にし、設定で変えられる。使っている番号・トークン・PID・API のバージョンを保存先の `api.json` に書く（API が書く。人は書かない）。
- **API の設定（ポート・許可する住所）は保存先の `api-settings.json`**。Chmonos の設定画面からも足し引きでき（`UiCommand` を通す）、ファイルを手で書いてもよい（ユーザ判断 2026-10-12）。API は変わったら読み直す。オン・オフとポートは、設定の画面で変えたらその場で当たる（ファイルを手で書いたときは、次に起動したとき）。
- **トークン（合言葉）を必須にする**。本当の目的は、同じ PC の別の Windows ユーザーと、待つ先を誤って広げたときに中身を守ること（`127.0.0.1` には PC の中のどのユーザーからも届き、`Host` は自由に書ける。`api.json` は自分のユーザーのフォルダにあって別のユーザーは読めない）。
  ブラウザへの守り（`Host` の確かめ・CORS）の2枚目にもなる。`GET /v1/health`・`GET /v1/version` は合言葉なしで答える。
- 合言葉は起動のたびには変えない（`api.json` に残す）。作り直す操作で変える。ログに書かない。
- `Host` が `127.0.0.1:<ポート>`・`localhost:<ポート>` 以外なら断る（DNS rebinding）。
- 問い合わせの中身はログに残さない（購入履歴と検索の言葉）。
- 式の大きさに上限（深さ・葉の数・枝も含めた段の数）を置く。
- 1回の問い合わせでは写しを1回だけ取り、答えができるまでそれを使う（途中で差し替わると、古い商品と新しい登録簿を組み合わせる・点検30）。

## ブラウザから（ユーザ判断 2026-10-12：B）

- 使う人が**許可する住所**（例 `http://localhost:5173`）を API の設定に書く。その住所のページにだけ CORS の許可を出す。一覧が空なら今と同じ守り。
- 合言葉はページが取ってこられない（`api.json` を読めない）ので、使う人がページに貼る。
- ブラウザの決まりで、**ヘッダを付けられない読み方**がある。
  - `<img src>`：画像は `fetch` で合言葉を付けて取り、`blob:` の URL にして見せる（使い方に書く）。
  - `EventSource`（SSE の標準の読み方）：ヘッダを付けられないので、`fetch` で流れを読む（使い方に書く）。合言葉を URL に入れる形は受けない（履歴とログに残る）。
- インターネット上の公開ページから `127.0.0.1` への問い合わせは、Chrome が使う人に許可を求める方向へ締めている。作るときにその時点の決まりを確かめる。

## 共通の決まり

- URL に `/v1/`。項目を足すのは互換、消す・名前を変える・意味を変えるのは非互換で `/v2/`。外の道具には「知らない項目は無視する」と書いてもらう。
- 名前は camelCase。日時は ISO 8601（時差付き）、日付だけの値は `YYYY-MM-DD`。ID は文字列。列挙の値は英字の文字列（保存の JSON が日本語の値でも、API は変えない英字の値にする。例：購入の種類 `self`・`received`・`given`）。値が無いときは項目を省かず `null`。
- 一覧は続きの印（`cursor`）で分ける。1回 200 件まで。並びは必ず一意（同じ値なら ID で決める）。
- 答えに `ETag`（中身の SHA-256 の頭）。`If-None-Match` が同じなら `304`（弱い印 `W/` も同じと見る。`304` は GET だけで、検索・batch の POST は毎回中身を返す）。`Cache-Control: no-cache`（使う前に毎回確かめてもらう）。許したページには `ETag` を見せ、事前の確かめで `If-None-Match` を許す（点検31）。
- 改変のファイルが読めなかったとき（ほかのアプリが開いている）は、その改変だけ前の写しの記録を残し、部分の印を確定せずに次の見比べで読み直す（点検31）。読み直しても中身が変わらなければ知らせない（点検32）。
- 要求の配列の中の `null`（`ids`・`and`・`or`・`sort`）は入力の誤りとして 400 で断る（点検32）。
- エラーは `application/problem+json`（RFC 9457）。機械が読む `code` は変えない。
- 仕様書は OpenAPI をコードから作り、`/v1/openapi.json` で出す（合言葉なし）。合言葉の要る URL には Bearer の印を付ける。
- 内部の状態の区別を潰さない：確認済み／候補／消した、外したファイル・古い版・見つからない、非表示、未評価と 0。
- 計算で出す値（持っているか・所有アバター・更新がある）も返す。外で計算させるとずれる。答えは Core の同じ所（`LocalBlock.IsOwned` など）から取る。
