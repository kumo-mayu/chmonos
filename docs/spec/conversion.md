**この文書は全部が［案］**（2026-11-06。ユーザが読んで意見を返す。決まった所から［決定］に変える）。
ユーザ指示「ユーザ環境で変換可能な対応関係を保持してそれを用いて対応アバターによる絞り込みに対応させたい」（`docs/plan.md` 8）。
もちふぃった～の事実と、写しで確かめた数は `docs/research/mochifitter.md`。**VRChat の使い方として分からない所は［要確認］にしてユーザに聞く**（推して決めない）。

## 言葉（画面）

- **変換**：衣装の変換ツールで、別のアバター向けの衣装を合わせること。画面の語は「変換」（ユーザ判断 2026-11-06）。「変換経由」「変換で使える物も含める」。`ui-terms.md` に足す
- **プロファイル**：変換に要る、アバター（または共通素体）ごとのデータ。画面でも「プロファイル」と書く（BOOTH の商品名と同じ語）［要確認：「変換データ」の方が通じるか］
- **順方向・逆方向**：ツールの語のまま。順方向＝ほかのアバターの衣装を、そのアバターに合わせる。逆方向＝そのアバターの衣装を、ほかのアバターに合わせる
- **変換扱い**：その商品をプロファイルとして扱うか。「アバター扱い」（アバターかどうか）と**独立に**決める（ユーザ 2026-11-06）

## 使える、と見なす決まり

衣装の対応 S＝直接対応＋素体経由（今の相性の 1＋2。`avatar-bases.md`）。アバター B が**変換経由**で使えるのは、

- S のどれか A について「A か A の素体に**逆方向**のプロファイル」があり、かつ
- 「B か B の素体に**順方向**のプロファイル」があるとき（作者の使い方ガイド「衣装元のプロファイルは逆方向、変換先のプロファイルは順方向」）

素体経由は元の側に1回まで（ユーザ判断「基本は b」）。変換は1回まで（変換した先の素体の仲間へは広げない）。
素体に付けたプロファイルは、その素体の仲間全員に効くと見なす［要確認：別のショップの同じ素体のアバターにも効くか］。
相性は保存しない（今と同じく、その場で計算する）。

## データの形

- **商品ごとの変換扱い**（`items/{id}.json` の `local.conversion`。人が決めた値）：
  - `mode`：`auto`（既定・書き出さない）／`profile`（プロファイルとして扱う）／`notProfile`（扱わない）
  - `targets[]`：つなぎ先1つ＝ `avatarItemId` か `baseName` のどちらか・`forward`・`reverse`・`slug`（中のプロファイルの名前。分かれば）・`confirmed`（人が決めたか）
  - 自動で推した値は `confirmed: false` で持ち、変換経由の計算には**確認したものだけ**を使う（推定を勝手に入れない）［要確認：確認待ちも点線の札では出すか］
- **unitypackage の控えに足す**（`unitypackages/{zipのハッシュ}.json`。中身から決まるので古くならない）：
  プロファイルの `avatar_data_{slug}.json` から読んだ `slug`・`name`・`defaultFBXPath`。読むのは取り込みのときで、zip が手元にある物だけ
  （今の `UnityPackageInspector` は 2MB までの `.json` を手掛かりに読んでいるが、残していない）

## 判定（自動で推す所）

**1. プロファイルらしいか**（候補に積む条件）
- 強：unitypackage の控えに `Assets/OutfitRetargetingSystem/Editor/` の下の `config_template2{slug}.json` か `config_{slug}2template.json` がある（18 商品とも当たった）
- 弱（zip が手元に無いとき）：BOOTH のタグが「もちふぃった」で始まるか「MochiFitter」を含み、カテゴリが「3Dキャラクター」でない
- ツールの本体（しなの・桔梗・マヌカ・ベリルのプロファイルを同梱）は、プロファイルの商品として扱うか［要確認］

**2. 向き**（slug ごと）
- `config_template2{slug}.json` → 順、`config_{slug}2template.json` → 逆、両方 → 両方向（`posediff_*` は使わない。逆方向のみの物にも入っていた）
- zip が無いとき：バリエーション名 → 商品名の順に「両変換・双方向・順逆」→ 両方向、「逆変換のみ」→ 逆、それ以外は順（ガイド「表記が無い場合は順方向のみ」）

**3. つなぎ先**（強い順。当たった所で止める）
1. 商品のカテゴリが「3Dキャラクター」→ **その商品自身**（アバター本体に同梱。その商品の対応アバターは使わない）
2. `defaultFBXPath` が、持っているアバターの unitypackage のパスと一致 → そのアバター
3. 商品から検出された**対応の共通素体** → その素体
4. 商品から検出された**対応アバター**：1体ならそのアバター。2体以上なら slug と名前を照らして絞る（かなをローマ字にした形・英字の名前・呼び方。大文字小文字と空白は無視）。絞れなければ全員を確認待ちで
5. slug・`name` が共通素体の名前か別名と一致 → その素体。一覧に無ければ「共通素体「〇〇」を足してつなぎますか」と聞く
6. どれも当たらない → 人が選ぶ

18 商品での見込み：自動で正しく当たる 11・聞く 1・広げすぎる 2（4. でバリエーションごとに対象を分ける商品）・人が選ぶ 4。

## 画面

**商品ページ**（「アバター扱い」の欄の隣か下）
- 「変換扱い」：今の扱いを文で（「プロファイル（自動の判定）：まめふれんず（共通素体）・順方向」）。繋がったボタン「自動の判定に任せる」「プロファイルとして扱う」「プロファイルとして扱わない」（「アバターかどうか」と同じ形）
- つなぎ先の行：アバターか素体・向き（順・逆・両方を選べる）・中のプロファイルの名前・確認待ちの印と ✓。足す欄（アバターか共通素体の候補）と × で外す
- 対応アバターの欄には、変換経由の札を素体経由の点線と別の線で並べる。吹き出しは「「A」から変換します」［要確認：見た目］

**変換扱いの画面**（ユーザ案「未確定のような形で「変換扱い」をリストで積んで順々に設定する」）
- 置き場：アバターの管理の左の切り替え（アバター／共通素体）に「変換」を足すか、ナビに足すか［要確認］
- 左：プロファイルらしい商品の一覧（決めていない物が上・件数）。右：分かっていること（カテゴリ・中のプロファイルと向き・FBX の場所）・推したつなぎ先と理由（「商品の対応素体から」など）・ボタン「これで決める」「プロファイルではない」「後で」
- 決めたら次の行へ進む（未確定と同じ。Ctrl+Enter）

**検索**：対応アバターの条件に「変換で使える物も含める」（「素体経由の対応も含める」の隣）
**設定**：「変換経由の対応アバターも表示する」（既定は入）。どちらも素体経由と同じ作り

## 決まっていないこと（［要確認］のまとめ・ユーザに聞く）

1. 素体に付けたプロファイルは、別のショップの同じ素体のアバターにも効くか
2. 素体向けの衣装を、素体の仲間のアバターの逆方向で変換できるか（「使える」の元の側の素体経由の前提）
3. 確認待ちの推定を、検索・札に出すか（出すなら点線のように見分ける）
4. 「プロファイル」と「変換データ」のどちらが通じるか
5. 変換扱いの画面の置き場
6. ツールの本体（4体分のプロファイルを同梱）の扱い
7. バリエーションで対象を分けるプロファイルの商品で、どのバリエーションを持っているかの手掛かり：zip の名前・slug のほか、購入の記録（`purchases[].variationId`。人が入れた物）も使えるか
