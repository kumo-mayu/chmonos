# 見つからないファイルを探す

取り込み画面の「見つからないファイルを探す…」（`ImportViewModel.FindMissingFilesAsync` → `UiCommand.FindMissingFiles` → `MissingFileFinder`）。
`import.md` が200行に達したので、2026-10-05 にここへ分けた。見つからない物の全体の地図は `docs/dev/file-lifecycle.md`「見つからない」。

## 探す範囲（ユーザ判断 2026-10-05・見つからない・移動の点検 11-A）

- 押すと、どこを探すかを選ぶ窓（`MissingSearchScopeDialog`・`MissingSearchScopeViewModel`）が開く。**監視フォルダは既定で選んである**。
  「フォルダを追加…」で、ほかの場所を**この回だけ**足せる。チェックを外せば、その回は探さない。1つも選んでいなければ「探す」は押せない。
- **足した場所は監視フォルダに足さず、覚えもしない。**探したいだけの場所を監視に足すと、起動のたびにそこを新着として見に行く。
  次に探すときは移した先が違うのが普通なので、覚えると外す操作の方が要る。
- 前は監視フォルダの中だけを探し、ほかへ移した物は「移した先を監視フォルダに追加してから、もう一度押してください」と言うしかなかった。
  今は「移した先のフォルダを追加して、もう一度探してください」。
- 起動時に勝手に走査してよい範囲は監視フォルダだけ、という決まりは変わらない（ここは人が押して選んだ場所を読む）。

## 何を探し、どう書くか

- **見つからないファイルは、選んだフォルダの中から中身で探して結び直せる。**監視フォルダが無いときは、ドライブがつながっていない（外付けを外している・黙る）と、ドライブは在ってフォルダが無い（名前を変えた・移した）を分け、後者は監視・探す所・設定の一覧が「見つかりません」と言う（2026-10-05。監視からは外さない）。結び直したとき・見つからなかった物に日時を付けたときは検索の写しを読み直す（前は検索の `path:` が起動し直すまで古い場所で絞っていた・点検 2026-09-30 の C。日時だけの回は 2026-10-05 から）。
- 探すのは外していないファイルのうち、記録の場所がディスクに無い物（見つけた場所へ差し替える）と、**場所が空の物**（取り込みが無い場所を全部外した物。見つけた場所を足す。
  ユーザ判断 2026-10-04。検索の条件「見つからないファイル」・カードの印が数えるのはこちらと、見つからなくなった日時の付いた物）。結び直したら日時を消し、**探しても見つからなかった物には日時を付ける**（2026-10-05。つながっていないドライブの上の物には付けない。決まりは見回りと同じ）。書くのは商品ごとの錠の中で今の値に当てる（`ChangeLocalAsync`）。
- 場所の1つでもつながっていないドライブの上にある物は探さず、その場所も外さない（2026-10-05。取り込みの `LocalFileMerger` と同じ判定。`FilePresenceProbe`）。
- 結果の数（探す前に無かった数・結び直した数・見つからなかった数）はどちらも中身ごとに1件で数える。読めずに確かめられなかったファイル・フォルダも数えて結果に出す（2026-10-05・点検の13）。
- 探す処理は丸ごと画面のスレッドの外で走る（2026-09-30。`architecture.md`「スレッドとディスク」）。取り込み中に押してもよい：控えは錠の中で今の控えに足し、商品は錠の中で今の値の場所だけを差し替える。
- 同一性はハッシュなので、移した・名前を変えただけなら戻る。大きさが合う物だけ中身を確かめる（全部をハッシュすると数百GBを読む）。
