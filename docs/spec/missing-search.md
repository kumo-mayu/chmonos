# 見つからないファイルを探す

取り込み画面の「見つからないファイルを探す…」（`ImportViewModel.FindMissingFilesAsync` → `UiCommand.FindMissingFiles` → `MissingFileFinder`）。
`import.md` が200行に達したので、2026-10-05 にここへ分けた。見つからない物の全体の地図は `docs/dev/file-lifecycle.md`「見つからない」。

## 探す範囲（ユーザ判断 2026-10-05・見つからない・移動の点検 11-A）

- 押すと、どこを探すかを選ぶ窓（`MissingSearchScopeDialog`・`MissingSearchScopeViewModel`）が開く。**監視フォルダは既定で選んである**。
  「フォルダを追加…」で、ほかの場所を**この回だけ**足せる。チェックを外せば、その回は探さない。1つも選んでいなければ「探す」は押せない。
- **足した場所は監視フォルダに足さず、覚えもしない。**探したいだけの場所を監視に足すと、起動のたびにそこを新着として見に行く。
  次に探すときは移した先が違うのが普通なので、覚えると外す操作の方が要る。
- 前は監視フォルダの中だけを探し、ほかへ移した物は「移した先を監視フォルダに追加してから、もう一度押してください」と言うしかなかった。
  今は「移した先のフォルダを追加して、もう一度探してください」。
- 起動時に勝手に走査してよい範囲は監視フォルダだけ、という決まりは変わらない（ここは人が押して選んだ場所を読む）。

## 何を探し、どう書くか

- **見つからないファイルは、選んだフォルダの中から中身で探して結び直せる。**監視フォルダが無いときは、ドライブがつながっていない（外付けを外している・黙る）と、ドライブは在ってフォルダが無い（名前を変えた・移した）を分け、後者は監視・探す所・設定の一覧が「見つかりません」と言う（2026-10-05。監視からは外さない）。結び直したとき・見つからなかった物に日時を付けたときは検索の写しを読み直す（前は検索の `path:` が起動し直すまで古い場所で絞っていた・点検 2026-09-30 の C。日時だけの回は 2026-10-05 から）。
- 探すのは外していないファイルのうち、記録の場所がディスクに無い物（見つけた場所へ差し替える）と、**場所が空の物**（取り込みが無い場所を全部外した物。見つけた場所を足す。
  ユーザ判断 2026-10-04。検索の条件「見つからないファイル」・カードの印が数えるのはこちらと、見つからなくなった日時の付いた物）。結び直したら日時を消し、**探しても見つからなかった物には日時を付ける**（2026-10-05。つながっていないドライブの上の物には付けない。決まりは見回りと同じ）。書くのは商品ごとの錠の中で今の値に当てる（`ChangeLocalAsync`）。
- 場所の1つでもつながっていないドライブの上にある物は探さず、その場所も外さない（2026-10-05。取り込みの `LocalFileMerger` と同じ判定。`FilePresenceProbe`）。
- 結果の数（探す前に無かった数・結び直した数・見つからなかった数）はどちらも中身ごとに1件で数える。読めずに確かめられなかったファイル・フォルダも数えて結果に出す（2026-10-05・点検の13）。
  結果は数のほかに、紐付け直した物と見つからなかった物を**商品ごとに1行**で持つ（`MissingFileSearchResult.RelinkedFiles`・`NotFoundFiles`。商品・探す前の場所・紐付け直した場所。紐付け直した方は書いた物だけ）。
  同じ中身を2つの商品が持てば2行になるので、一覧の件数は要約の数より多いことがある。

## 結果の見せ方（手触りの確認 2026-10-06・メモ73）

- 前は結果がボタンの横の1行の文だけで、長いと切れて読めず、どの商品のどのファイルがどこへ移ったかも分からなかった
  （監視していない場所を足して探した回に結び直っていたのに、見つからなかったように見えた）。仕組みの説明は書かず、何が起きたかを並べる。
- 1行目は短い要約（`ImportViewModel.MissingSearchSummary`）：「n 件を新しい場所に紐付け直しました。」／「n 件を新しい場所に紐付け直し、m 件は見つかりませんでした。」／「m 件を探しましたが、見つかりませんでした。」。
  何も無ければ「見つからないファイルはありませんでした。」。
- 要約はボタンの横（押した所で何が起きたかが分かる）。中身は**監視対象のすぐ下の独立した欄「見つからないファイルを探した結果」**に出す（メモ74・2026-10-06。前は監視対象の欄の中）。
  並べる物も探せなかった場所の文も無ければ欄ごと出さない（`HasMissingResult`）。監視フォルダが数本なら、押した位置のまま欄の頭が見える。
- 欄の頭に、探せなかった場所（つながっていない・見つからない監視フォルダ）と読めなかった物の文を1行ずつ（`MissingSearchNotes`）。
- 探せなかった場所の文は**何が起きたかだけ**を名前で言う（「監視フォルダ「名前」は見つからなかったため確認できませんでした。」・その回だけ足したフォルダは「フォルダ「名前」は…」・4つ以上は数でまとめる）。**直し方は言わない**（監視フォルダが見つからないときの直し方は監視対象の欄の注意が言う。ユーザ 2026-10-06）
- **成否を色で分ける**：見出しの字と行の左の線を、紐付け直した物は緑（`Good`）、見つからなかった物・見つからない登録フォルダは赤（`Bad`）（ユーザ 2026-10-06「成功と失敗が読まないとわからない」）
- 「紐付け直したファイル n 件」：商品名・ファイル名（新しい場所の名前）・「新しい場所：フォルダ」。「見つからなかったファイル n 件」：商品名・ファイル名（場所が空の物は「名前の分からないファイル」）と、
  見出しの下に次の手「移した先のフォルダを追加して、もう一度探してください。」（畳んでいても出す）。どちらも名前の順。下に「見つからない登録フォルダ n 件」が同じ形の見出しで続く。
- **一覧は見えている行だけを作る**（メモ74）：3つの見出しと中の行を1本の平らな一覧（`MissingResultLines`）に並べ、`VirtualizingStackPanel` に載せる（通知の画面と同じ作り）。
  畳んだ見出しの中の行は一覧から抜く。画面全体の1本のスクロールの中では仮想化が効かないので、一覧の高さは窓の見えている高さまでにして中で流し、
  端まで流したらホイールは画面へ渡す（`ForwardWheel.AtEdges`）。前は3000件ずつの結果を開くと約4.6秒固まり、メモリが約300MB増えた → 約0.05秒・約10MB。
- **行の左に商品のサムネイル**（メモ76・ユーザ 2026-10-06「名前での認識は大量に行うと疲れるので商品サムネをアイコン的に添える。小さすぎると認識できないので3行の幅を使う」）。
  一辺 56 の四角（ファイルの行の3行の高さ。`ResultThumbnail.EdgeDip`）。絵の決め方は検索のカードと同じ（BOOTH の並び・自分で足した絵・★の指名・設定の役割。`ResultThumbnail.PathOf`）。絵が無い・商品が消えていれば頭文字。
  - **ファイルの行は折り返さず、いつも3行**（商品名・ファイル名・場所）で高さをそろえる（判断B）。商品名とファイル名は末尾を「…」で切り、
    場所は奥のフォルダが残るよう**頭**を「…」で切る（`…\AnotherVeryLongFolderName`。`PathLine.TrimHead`・`PathEllipsis.FitHead`。区切りの単位で切り、いちばん奥の名前も入らなければその後ろの字を残す。幅が変われば切り直す）。
    全部の場所は行に乗せると吹き出し（`PathTip`）。見つからなかった行の場所の行は「元の場所：」（前は無かった。3行にそろえるため）
  - **登録フォルダの行は、絵を上にそろえて固定し、文と候補は下へ伸びる**（判断A。候補の数で高さが変わる）
  - **絵は見えた行だけ読む**：絵の場所は、行が作られて絵が読まれたときに初めて、裏で商品の記録から決める（数千行ぶんの記録を先に読まない）。決めた場所は行が持つので、再利用で作り直されても読み直さない。
    絵は縮めて読む（`PeekForFill`。56 の枠なので1枚約12KB）。3000件の場面で、開く 0.06 秒・流す1歩の最長 8ms・止まったコマ 0。メモリは、先頭600件に絵がある場面を300歩流して約+37MB（絵なしの行は約+10MB）
- **20件を超える見出しは畳んで出す**（`ResultFoldOver`。メモ74 で 5 から上げた）。数は重さに効かないので、境目は次の見出し（押して選ぶ登録フォルダの候補）へ届くまでの送りの長さだけで決める。
- 商品名（登録フォルダの行も）は押すと商品ページを開く。その間に商品が消えていれば行に「この商品は見つかりませんでした。…」。探し直すと前の回の結果は消える。
- 見た目は撮影台の `import-missing-results`（畳んだ一覧・探せなかった場所）・`import-missing-notfound`（見つからなかった物だけ）・`import-missing-folders`・`import-missing-results-many`（3000件を流した所）。速さは `perf-import-missing-3000`。
- 探す処理は丸ごと画面のスレッドの外で走る（2026-09-30。`architecture.md`「スレッドとディスク」）。取り込み中に押してもよい：控えは錠の中で今の控えに足し、商品は錠の中で今の値の場所だけを差し替える。
- 同一性はハッシュなので、移した・名前を変えただけなら戻る。大きさが合う物だけ中身を確かめる（全部をハッシュすると数百GBを読む）。

## 見つからない記録をまとめて消す（ユーザ判断 2026-10-07）

- 設定の「データ」の節に、「見つからないファイル」の行と赤の「記録をすべて削除…」を置く（監視フォルダと関係の無い、ライブラリ全体の片付けなので取り込み画面には置かない。ユーザ判断 2026-10-07）。大量に見つからなくなると、1件ずつ判断して外すのは我慢を強いるので、**件数を見せる確かめ1回だけで、全部の商品から**消す（`MissingRecordCleaner`・`UiCommand.ForgetMissingFiles`）
- **外した印は付けずに記録ごと消す**（外した印は「この商品の物ではない」で、次の取り込みで戻るのを止める。見つからないだけの物は、ファイルが戻れば取り込みでまた紐付いてよい）。商品そのもの（購入の記録・メモなど）は残り、手元のファイルが無くなった商品は未所持になる
- 消すのは、見つからなくなった日時の付いた物と場所が空の物のうち、今どの場所にも無く、つながっていないドライブの上でも無い物。外した物・古い版は消さない。フォルダは日時が付き、今も無い物。商品ごとの錠の中で今の値に当てる
- 確かめの窓：「○ 商品の、見つからないファイル ○ 件・フォルダ ○ 件の記録を削除します。」「手元のファイルが無くなる ○ 商品は、未所持になります。」「ファイルが戻れば、取り込みでまた紐付きます。」「削除した記録は元に戻せません。」。消し終えたらボタンの下に件数を出す

## 登録したフォルダの候補（ユーザ判断 2026-10-05・見つからない・移動の点検 10-A）

- 登録したフォルダ（`LocalFolderRecord`）はハッシュを持たず場所が同一性なので、移すと「見つかりません」のままだった（登録を外して登録し直すしかなく、登録した日時も失う）。
- 探すとき、どこにも無い登録フォルダ（つながっていない・確かめられない場所の上の物は入れない。ファイルと同じ決まり）があれば、**選んだフォルダの木を1回たどり**、
  フォルダごとに下の全部のファイル数と合計の大きさを数えて（`MovedFolderCandidates.MeasureTree`。数え方は登録の `RegisteredFolderSet.Measure` と同じ）、記録と比べる。
- 合い方（`MovedFolderCandidates.Match`）は強い順に、名前・ファイル数・大きさが同じ／ファイル数と大きさが同じ（名前を変えた）／名前だけ同じ（中が増えた・減った）。
  どれも合わない物は出さない。数えた物が空の記録は数で合わせない（空のフォルダがみな候補になる）。中を読めなかったフォルダは名前でだけ合わせる。
- 出さない物：ほかの登録そのものとその中（2つの登録が同じ場所を指す）。数で合うが、下に同じ数のフォルダがある親（移したフォルダを包んでいるだけ）。
  1つの登録フォルダに5つまで（ありふれた名前で並びすぎないように。強い順なので本命は上）。
- **候補は見せるだけで、記録は変えない**（CLAUDE.md「推定した値を勝手に入れない」）。結果の欄の「見つからない登録フォルダ」の見出しの下に、
  商品名・元の場所・記録の数と、候補ごとに場所・合い方・数・「この場所にする」を並べる。候補が無ければ、そう言って移した先のフォルダを足すよう言う。
- 「この場所にする」は `UiCommand.RelocateFolder` → `ItemService.RelocateFolderAsync`：測るのは錠の外、書くのは商品ごとの錠の中の今の値に当てる
  （場所・数・`lastSeenAt` を入れ、`missingSince` を消す。登録した日時は残す。同じ商品が同じ場所を登録していれば1つにまとめる）。
  登録したときと同じく、新しい場所の下の未確定を片付ける。結果は押した行に出し、検索の写しを読み直す（カードの「見つかりません」が消える）。
  差し替えないとき：選んだ場所がもう無い・ほかの商品が登録している・その間に元の登録が外された（行に理由を出す）。
