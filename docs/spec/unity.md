# Unity への受け渡し（今の決め事）

> **要点**：プロジェクトにエディタ拡張を入れずに、開いている Unity エディタへ unitypackage を渡す。zip は展開せず、中の1件だけを一時的に取り出し、
> **エディタの窓を名指しして**メニュー「Assets > Import Package > Custom Package...」から渡す（複数のエディタが開いていても入る先を間違えない）。
> 連続送りは、前の物の後処理が終わったのを Editor.log の完了の行で掴んでから次を出す。送信は1列に限る。
>
> **コード**：`Core/Services/UnityHandoff.cs`（zip の中を数える・入り先を読む）・`UnityImportWatch`（終わりの判断）・`UnityPackageCatalog`・`UnityPackagePathStore`・`UnityEditorLocator`・`UnityProjects`、
> `App/Services/UnityEditors.cs`・`UnityImportQueue.cs`・`UnityLaunch.cs`・`UnityProjectTab.cs`・`UnityFocusWatch.cs`・`VccLaunch.cs`・`InstalledApps.cs`・`TemporaryUnpacker`、`App/Views/PickPackagesDialog`
>
> **経緯**：`docs/history/unity-handoff.md`（§2 シェルで渡す実測・§8 拡張なしでできること・§9 連続送りの比較・§11 終わりの掴み方・§13 プロジェクトタブ）

## 送り先

- 開いているエディタを数える（**窓を持たない Unity.exe は数えない**：取り込み後の `AssetImportWorker` が残る）。起動中の題（「Compiling Scripts」など）はプロジェクト名として読まない。
  **どのプロジェクトかは、題の頭を Hub・VCC の一覧の名前と照らして言い当て、場所も持つ**（`UnityHandoff.ProjectFromWindowTitle`・`UnityProjects.KnownPaths`）。題の頭が当たる物が複数なら開いている方、次に長い名前。
  一覧に無いときだけ、題の最初の「 - 」で切る（2026-09-19：「cleanTest - コピー」を開いているのに「cleanTest」と読み、同じ名前の別のプロジェクトを調べて「まだ入っていません」と言っていた）。
  場所が分かっているエディタは、選択・改変に追加して送る・開く（既に開いているか）で**名前ではなく場所で照らす**。
  **同じ名前のフォルダのプロジェクトが両方開いていると、題からは見分けられない**（2026-09-23）。場所は決め打ちせず（`UnityHandoff.IdentifyProject` の `IsAmbiguous`）、
  送り先は選ばせ（プロセス番号を添える）、「Unityで選択」は見分けられないと言って止める。
- エディタの窓は**メニューを持つ `UnityContainerWndClass`** を主の窓とする（`UnityEditors.MainWindowOf`）。`Process.MainWindowHandle` は Z 順の先頭の窓で、浮かせたタブに当たるとメニューが無く題も読めなかった。
- 開いていなければ送らない（シェルで渡すと Hub が開くだけ）。複数なら送り先を選ばせる。改変に紐付けたプロジェクトが開いていればそれに決める。
- 送り先の表示は窓が手前に戻るたびに読み直す（Unity の開き閉じはアプリの外で起きる）。
- シェル（関連付けの `-openfile`）で渡す道はやめた：エディタが2つ開いていると渡す先を保証できない（実際に別のプロジェクトへ4回行った）。

## 1件を送る

1. メインの窓のメニューを**文字でたどって**「Custom Package...」の ID を得て `WM_COMMAND` で送る。**ID は毎回探し直す**（スクリプト入りのパッケージを取り込むとメニューが作り直され、ずれる）。
2. ファイル選択の窓（`#32770`・**ファイル名の欄＝部品番号1148 を持つ物だけ**。進捗の窓も `#32770`）の欄へ `WM_SETTEXT` でパスを入れ、`IDOK`。
3. 取り込み画面は利用者に見せ、Import か Cancel は人が押す。
- 取り込み画面は重ねられない（開いたまま次を開くと同じ窓の中身が差し替わり、前の物は入らずに捨てられる）。
- 取り出す先（`TemporaryUnpacker.ExtractEntry`）が 260 字以上になるときだけ、zip の中のフォルダの段を中のパスの印1段に畳む（ファイル選択の窓に渡せないため。2026-09-23 の手元の実測は最長 171 字）。
- プロジェクトを開く引数は `ArgumentList` で渡す（手で引用符を組むと、`\` で終わるパスで引数が閉じなかった）。

## 連続で送る

- 入口：検索の複数選択「Unityへ順に送る…」、改変の「使ったものを順にUnityへ送る」、商品ページの1件送りも同じ列。
- **次を出すのは前の物の後処理が終わってから**（取り込み画面が消えた直後に出すと、読み込み直しをまたいだ画面は中身が抜けて黙って0件になる）。
- 終わりの判断（`UnityImportWatch`）：
  - 送った物のパスの `Start importing` か、送り先のエディタの新しい窓が出たら「動いた」＝Import。**完了の行**（`Asset Pipeline Refresh … Total: …`）が出るまで待ち、完了の行と窓が消えた時の遅い方から1秒静かなら次へ。
  - 取り込みの行も窓も**5秒動かなければ Cancel**。取り込みと関係のない行は数えない。
  - **既に全部入っている物は Cancel と数えない**（2026-09-19）。そのとき Unity は取り込み画面に「Nothing to import!」しか出さず、閉じても1行も書かないので、ログでは Cancel と見分けられない。**送る前に「中身が全部プロジェクトにあるか」を調べておく**（`UnityProjectMatcher`＝「Unityで選択」と同じ調べ方。パスの一覧は控えがある）。全部あるなら、何も動かないまま閉じられたときは Cancel ではなく「既に入っていた」とし、閉じてから2秒で次へ（Cancel の5秒は待たない。調べた後に中身が変わっていて取り込みが起きたら、取り込みの行の方を信じる）。**送れたと数える**（ユーザ判断：入っていることが目的）ので「使った」の足跡も付ける。窓の絵で見分ける案は 2026-09-20 に取り下げた（やりすぎ・ユーザ指摘）。
  - 送る前に、最小化されている Unity の窓を開く（取り込み画面は人に押してもらう物なので、最小化のまま Cancel と数えるのは筋が通らない。ユーザ指摘 2026-09-20）。
  - ログが来ないまま窓だけ動いたら、窓が5秒静かで終わり（Unity 6.5 以降はログがプロジェクトごと）。待ちの上限は30分。
- `Editor.log` は PC に1つで、複数のエディタが取り合う。`LogTail` で前回の続きから読み、縮んだら先頭から、NUL は捨てる。**前の列が終わるまで別の Unity への送信を混ぜない**。
  - **行からは送り先を見分けられない**（2026-09-21 に実機のログで確認。Unity 2022.3.22f1）。
    完了の行は `Asset Pipeline Refresh (id=…): … ForceSynchronousImport` で、`id` は更新の番号であってプロジェクトではない。
    プロジェクトを名乗るのは**エディタが起動したときの1行**（`Successfully changed project path to: …`）だけで、以降の行に印は付かない。
    プロジェクト側の `Logs/AssetImportWorker*.log` にも完了の行は出ない。だから**1列に限る決まりは外せない**（ユーザ確認 2026-09-21・C17）。
- 進捗の窓（Importing・Compiling Scripts・Reloading Domain・Completing Domain・Hold on・Unity Package Manager）以外の `#32770` はパッケージの確認とみなし、「Unity 側で確認（「…」）が出ています」と1行で伝えて待つ。
- Cancel された物は最後の知らせで「うち ○ 件は Cancel されたので入っていません」と言い、「使った」の足跡も付けない。**中身がディスクに入ったかは数えない**（欲しい物だけ選ぶのは普通の使い方）。既に入っていた物は「○ 件は既に全部入っていました」と言い分ける。
- Unity を操作した後の知らせ（順に送った終わり・カードの「選択…」の結果・送れなかった知らせ）は、**主の窓を手前に戻し、主の窓を持ち主にして出す**（`FrontNotice`）。持ち主の無い知らせは手前の Unity の後ろに隠れた（2026-09-19）。

## 進み具合と中止（ユーザ判断 2026-09-20・E7・E10）

- **1件でも進み具合を出す。**1件につき3〜4段（送っています → 取り込み画面で押してください → 既に入っています → Unity 側で確認の窓が出ています）を報告している。
  出す先は押した画面：商品ページは手元のファイルの欄の1行、カードの右クリックは選んでいるときの帯（送っている間も出す）。前は捨てていて、押してから Unity の窓が出るまで無言だった。
- **送っている間だけ「中止」を出す。**止まるのは待っている間（0.2 秒ごと）で、いちばん長いのは人が取り込み画面を見ている時間（上限30分）。
- **「中止」は画面の下の帯に置く**（ユーザ判断 2026-09-20）。送信は1本ずつで、どの画面からでも始められるのに、
  始めた画面にしか「中止」が無いと、移った先では止める手立てが無くなる（実機で踏んだ）。
  帯は送っている間だけ出て、始めた画面の1行と同じ文を出す。
  zip の取り出し・中身のパス読み・プロジェクトの走査は、始まったら最後まで走る（割り込む手段が無い）。
- 止める合図は `UnityImportQueue.Stop` の1つだけ（送信は1本ずつなので、どの画面から押しても同じ物が止まる）。
- **止めた後の言い方**：Unity の取り込み画面は残る（閉じる手段をこちらは持たない）。
  そこで Import を押せば実際に入るが、こちらは見ていないので記録には残らない。「入っていない」と言い切らない。
- 止めると待ちから例外で出てくるので、**中で受け止めて**「残りは理由を付けて返す」約束を守る（そのまま投げると呼んだ側が結果を受け取れない）。

## 送る物を選ばせる

- 送り先を決めた後、候補が2つ以上ある商品だけ unitypackage を一覧で選ばせる。種類（無ければ zip の名前）ごとの塊にまとめ、畳める。**最初はチェック無し**（「最新」も選んでおかない）。種類を名前から推して添えない。（改変から送るとき）
- **検索・フォルダビューの複数選択「Unityへ順に送る」**（ユーザ指示 2026-09-19）：候補が2つ以上ある商品だけ、右クリックと同じ一覧から選ぶ窓（`ListChoice`）を**1件ずつ順に**出す。題に「（2/5）」、本文に「選ぶ必要がある商品 5 件のうち 2 件目」。
  一覧の最後に「全部（n 件を zip に入っている順に）」（1つの zip に依存物と本体があると両方要る）。ボタンは「これを送る」「この商品は送らない」（その1件だけ見送る）「やめる」（全体をやめる）。
  選び終えたら、送る unitypackage の数を1回だけ確かめてから送る。送り先の Unity が2つ以上開いていれば、先に同じ形の窓で選ばせる。
- 改変から送ったときは**選んだ物をその行に記録する**（送る前に。`UiCommand.RecordModificationMemberFiles`。行がまだ記録の無い同じ商品のときだけ書く）。次からは聞かずにその物を送る。検索の複数選択は残さない。

## どこに入るか

- unitypackage は tar.gz で、`<guid>/pathname` に Unity 上のパスがある。**最初の2段にまとめて**「Assets/Piyo_crafts に入ります」と行に出す（3か所まで、残りは数）。**Packages/ も出す**（Assets だけ見ると取り違える）。
- **取り込みの裏で1度だけ読んで残す**（中身は zip のハッシュが同じなら変わらない）：
  - item の手元のファイルには `unityPackages: [{ entry, roots }]` だけ。全部のパスは `unitypackages/<ハッシュ>.json`（1つで千本を超える物があり、検索のメモリと読める形を損なうため）。
  - 控えには**パスごとの GUID も書く**（2026-09-29）：`{ "packages": { "<zip の中の場所>": { "<GUID>": "Assets/…" } } }`。読めない控え（無い・壊れている）は、取り込みの裏か使うときに zip を解いて書き直す（控えは作り直せる写し）。
  - ①と同時に、小さい zip から1件ずつ、優先度を下げたスレッドで読む。item への書き込み（入り先を写す）は①の後（①も手元のファイルを書くので重ねない）。
  - 手でファイルを付けた後も、その商品だけ裏で同じことをする。読めなかった物は使うときに zip を解いて控えに足す。
  - **一部しか載っていない物も読み直す**（2026-09-29。`UnityPackageCatalog.NeedsSummary`）：控えは商品ページなどで包みを1つずつ足しても作られるので、
    控えか要約が中身の一覧 `contents` の unitypackage を全部持っていなければ、取り込みの裏で欠けた包みだけ解いて控えを埋め、要約を書き直す。
    zip を開けなかったときは控えを書かない（次の取り込みでまた開く）。
- **使うときは item の要約を先に見る**（2026-09-29。`UnityHandoff.PlacesOf`）：商品ページ・改変の画面・連続送りの前の包みの一覧と入る先は、`unityPackages` があればそれを使い、zip を開かない（zip が在るかは見る。無ければ行を出さない）。
  要約が zip の中の unitypackage を全部覆っていない（中身の一覧 `contents` と名前がそろわない）ときは zip を読む（取り込みの裏が埋めるまでの間の守り）。中身は zip のハッシュで決まるので、要約と zip は食い違わない（差し替えた zip は別のハッシュ）。
  改変の画面の入る先は、包みが2つ以上で入る先が分かれると数を持たない要約からは並びを決められないので、そのときだけ読む。
  全部のパスが要る所（「Unityで選択」・プロジェクトの中を調べる・既に全部入っているか・連続送り）は控えを読むが、**1回の操作・表示の中で控えは zip ごとに1回だけ読んで包みに配る**（`UnityPackageReads`。前は包みごとに控えを丸ごと読み、包み数の2乗だった）。
- アプリが開いている間は、zip の場所・名前・大きさ・更新時刻が同じならパスの一覧を覚えておく（1GB の物で1件約2.8秒かかるため）。
  覚えるのは合計 16MB（文字列の見積もり）までで、古く使った物から捨てる。取り込みの裏の読み取りは覚えない（控えのファイルに書くので足りる）（2026-09-24。前は5000件まで覚えて丸ごと忘れていた）。

## プロジェクトタブでフォルダを開く（改変の「Unityで選択」）

- **座標を使わない**。メニュー「Window > General > Project」→「Edit > Find」を番号で送り、フォーカスのある窓（`GetGUIThreadInfo`）へ文字とキーを送る。
- **最後に選んでいたプロジェクトタブで開く**：アプリの起動時からプロセスを決めずに WinEvent を見張り、Unity ごとに「マウスをつかんだ」プロジェクトタブを覚える（前面に戻っただけは数えない）。
  覚えたタブが表に出ていればそれ → 見えているタブが1つならそれ → **複数なら最初に見つけた1つ**（窓の並びで手前の物。2026-09-19 まで全部で開いていたが、見ていないタブの今のフォルダまで変わった・ユーザ判断）→ 無ければメニューに任せる。
  覚えるのはアプリの起動後に触ったタブだけなので、アプリを開き直した直後は「分からない」に落ちやすい。開いたタブは覚え、次もそこで開く。フォーカスは中ボタンの押下で渡す（選択を変えない）。最小化なら先に戻す。
- 検索の語は `a:assets glob:"入り先のパス" t:Folder`（`a:assets` で範囲を戻す。パスに glob の記号があるときだけ名前で探す）。文字は `PostMessageW` で送る（ANSI 版で日本語が化けた）。
- **送る前にディスクのフォルダで決める**（`UnityProjectTab.Plan`）：1件と言い切れるときだけ ↓・Enter で開く。そうでなければ結果を出したところで止め、理由と入り先を1行で出す。
- `Packages/` の下は Unity の検索に出ないので探さず、左の木で見つける名前を伝える。
- **入り先の頭の記号を利用者が消していても探せる**（ユーザ指摘 2026-09-16）：ショップは Assets の先頭に並べるため `_FUKA`・`!FUKA` のように記号を付けることがある。
  初めは記号を外した名前で読み替えていた（`UnityFolderNames`）が、**GUID に置き換えた（2026-09-29）**：記号を消したのは名前を変えた物の1つなので、下の GUID の道で見つかる。
  Unity 2022.3 で、作者フォルダを `.meta` ごと別の名前に変えても、Unity は GUID で見て「Nothing to import!」を出し、「Unityで選択」は名前を変えたフォルダを開いた（2026-09-29）。
  `.meta` を持たずに写した物（Unity が新しい GUID を振る）は見つからないが、Unity もそれを別の物として取り込み直す。
- **フォルダを移した・名前を変えた物は GUID で探す**（ユーザ指示 2026-09-29。`UnityProjectGuids`・`UnityProjectMatcher`）：Unity は取り込んだアセットの `.meta` にパッケージと同じ GUID を書き、移しても変えない。
  照らし方は「パス → GUID」だけ。まずパスで照らし、**見つからない物があったときだけ**プロジェクトの `Assets/` と `Packages/` の下の実フォルダの `.meta` の頭の行から「GUID → 今のパス」の表を作る。
  表はアプリを開いている間プロジェクトごとに覚え、2回目からは更新時刻の変わった `.meta` だけ読み直す（手元の19のプロジェクトで `.meta` は 1,034〜5,449 個。冷えた 5,000 個を8本並べて読んで約2秒、2回目は 11〜46ms）。同じ GUID が2か所にある物は表に入れない。
  - 入っているかを数える（「Unityで選択」・プロジェクトの中を調べる・既に全部入っているか）：GUID で見つかった物も「ある」と数える。2つ以上の商品に同じパスか同じ GUID で入っているファイルは数えない。
  - 「Unityで選択」で開くフォルダ（`LocateRoot`）：入り先に商品のファイルがパスで1つでもあればそこ。無ければ入り先のフォルダ自身の GUID の今の場所、それも無ければ GUID で見つかったファイルの今の場所から入り先に当たるフォルダを推す（下の段が同じならその上、違えばファイルのあるフォルダ。いちばん多くのファイルが指す所）。
    移った先を開いたときは、結果の1行を「入り先の Assets/FUKA は Assets/Mine に移動されています。」にする。1件と言い切れるときだけ開く決まり（`Plan`）はそのまま。
- 確かめていない：Unity 6 以降・日本語表示のメニュー（当面は確かめない）。閉じているプロジェクトのレイアウトを書き換えて開く道（§8-1）は未実装。

## プロジェクトを開く・VCC

- エディタの探し方（`UnityLaunch.EditorCandidates`）：Hub の置き場所 → Hub の一覧（`editors-v2.json`・`editors.json`）→ Unity の登録 → アンインストール情報 → 起動中のエディタ → `.unitypackage` の関連付け。後の2つは実行ファイルの版の欄で見分ける。
- 開いていれば手前に出す／版が無ければ `unityhub://`／Hub も無ければ渡さず、Hub を入れれば開けると言う。
- **VCC は起動するだけ**（中身を管理しない）。場所はアンインストール情報の場所 → アイコンの欄 → `vcc://` の関連付け。起動中なら窓を戻して手前に出す（2回目の起動は VCC が前に出さない）。見つからなければボタンを押せない状態で理由と入れ方を添える。

## そのほか

- 「一時的に展開して開く」（2026-09-19 に「展開して開く」から改めた：元の zip の横に広げると読まれないように）：zip を一時フォルダに展開してエクスプローラで開く（unitypackage でない配布物用）。アプリを閉じると消し、消し残りは次の起動で消す。一時フォルダの中は取り込まない。
- VPM で配られる物・拡張を作る道は、今は扱わない（配布物が増える）。
