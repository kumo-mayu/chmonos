# Unity で選ぶ（今の決め事）

> **要点**：開いている Unity のプロジェクトタブで、商品の物を**座標を使わずに**示す。手で置いた画像を選ぶ・改変の使ったものの入り先のフォルダを開く・1件だけ送った後に入ったフォルダを選ぶ。
> 探す語は `a:assets glob:"パス"` で、1件と言い切れないときは結果を出したところで止める。
>
> **コード**：`App/Services/UnityProjectTab.cs`・`UnityFocusWatch.cs`、`Core/Services/UnityProjectMatcher.cs`（`LocateRoot`）・`UnityProjectGuids`・`UnityProjectImages`・`UnityImportedFolder`、
> `App/ViewModels/UnityMemberSelect.cs`・`ItemUnityActions.cs`
>
> 送る作り（送り先・1件を送る・連続で送る・設定）は [unity.md](unity.md)。2026-11-25 に unity.md が200行に達したので分けた。経緯は `docs/history/unity-handoff.md` §13。

## 手で置いた画像を見つける（`UnityProjectImages`・`ZipImageStore`）

- 手で置いた画像には GUID も決まったパスも無い。**名前から探さず、大きさ → 中身の順に探す**（ユーザ判断 2026-11-01）。名前を変えた画像も見つかり、大きさの合う物しか読まないので軽い（手元で最多の 514枚・0.50GB で、大きさが他と重なるのは46枚、一覧は約0.4秒）。Unity は取り込みで元の画像を書き換えない（作り物の画像で確かめた）。
- 形式は png・jpg・jpeg・tga・psd。見る所は `Assets` の下だけ。商品の側は単体のファイル（記録の SHA-256）・zip の中（目次の CRC）・登録したフォルダの中（その場で CRC を計算。在るときだけ）。
- **見せ方は割合にせず、見つかり方を書く**（数字は根拠を説明できない）。「同じ画像」＝大きさと中身が一致。「名前が同じ」＝名前だけ一致（外で編集した物か、別の画像）。条件は既定で同じ画像だけで、「名前が同じファイルも含める」で足す（吹き出し「手で置いた画像などを、中身が違っても名前が同じなら含めます。」を 2026-11-25 に付けた。名前で当てるのは今は手で置いた画像だけだが、ほかの種類を足す余地を残して見出しは「ファイル」のまま）。
- unitypackage で入ったと分かっているファイルには、名前だけでは当てない（よくある名前で別の商品と取り違える。写しの3つで、同じ名前が別の商品にも出る割合は 5.6〜13.7%）。同じ画像が複数の商品にあれば両方に出す（どちらから入れたか決められない）。
- **zip の目次の控え**：`zipimages/{zipのハッシュ}.json`。zip を解かず目次だけ読み、取り込みの裏（今ある商品の分も）と、調べたときに控えが無ければ作る。zip が無く控えも無い物は名前でだけ照らす。zip 以外の圧縮ファイルの中は見ない。
- **Unityで選択**（カード・商品ページの「Unityで画像を選択…」）：`a:assets glob:"パス"` で検索し ↓ で止める。**Enter は押さない**（ファイルが外の編集ソフトで開く）。同じ名前が別のフォルダにあってもパスで1件に絞れ、日本語・空白も通る。glob の記号は `?` に置き換える（`[作者]` のままは0件）。登録したフォルダは中を押してから調べるので、在るフォルダを持つ商品は押せる。同じ画像が1枚だけで unitypackage も無ければ聞かずに選び、ほかは選ばせる（8件以下は平らな一覧で行の頭に見つかり方、9件以上は Unity の中のフォルダの木。[ui-dialogs.md](ui-dialogs.md)「Unityで選択の木」）。見つからなければ言うだけで、入れない。

## プロジェクトタブでフォルダを開く（改変の「Unityで選択」）

- **座標を使わない**。メニュー「Window > General > Project」→「Edit > Find」を番号で送り、フォーカスのある窓（`GetGUIThreadInfo`）へ文字とキーを送る。
- **最後に選んでいたプロジェクトタブで開く**：アプリの起動時からプロセスを決めずに WinEvent を見張り、Unity ごとに「マウスをつかんだ」プロジェクトタブを覚える（前面に戻っただけは数えない）。
  覚えたタブが表に出ていればそれ → 見えているタブが1つならそれ → **複数なら最初に見つけた1つ**（窓の並びで手前の物。2026-09-19 まで全部で開いていたが、見ていないタブの今のフォルダまで変わった・ユーザ判断）→ 無ければメニューに任せる。
  覚えるのはアプリの起動後に触ったタブだけなので、アプリを開き直した直後は「分からない」に落ちやすい。開いたタブは覚え、次もそこで開く。フォーカスは中ボタンの押下で渡す（選択を変えない）。最小化なら先に戻す。
- 検索の語は `a:assets glob:"入り先のパス" t:Folder`（`a:assets` で範囲を戻す。パスに glob の記号があるときだけ名前で探す）。文字は `PostMessageW` で送る（ANSI 版で日本語が化けた）。
- **送る前にディスクのフォルダで決める**（`UnityProjectTab.Plan`）：1件と言い切れるときだけ ↓・Enter で開く。そうでなければ結果を出したところで止め、理由と入り先を1行で出す。
- `Packages/` の下は Unity の検索に出ないので探さず、左の木で見つける名前を伝える。
- **入り先の頭の記号を利用者が消していても探せる**（ユーザ指摘 2026-09-16）：ショップは Assets の先頭に並べるため `_FUKA`・`!FUKA` のように記号を付けることがある。
  初めは記号を外した名前で読み替えていた（`UnityFolderNames`）が、**GUID に置き換えた（2026-09-29）**：記号を消したのは名前を変えた物の1つなので、下の GUID の道で見つかる。
  Unity 2022.3 で、作者フォルダを `.meta` ごと別の名前に変えても、Unity は GUID で見て「Nothing to import!」を出し、「Unityで選択」は名前を変えたフォルダを開いた（2026-09-29）。
  `.meta` を持たずに写した物（Unity が新しい GUID を振る）は見つからないが、Unity もそれを別の物として取り込み直す。
- **フォルダを移した・名前を変えた物は GUID で探す**（ユーザ指示 2026-09-29。`UnityProjectGuids`・`UnityProjectMatcher`）：Unity は取り込んだアセットの `.meta` にパッケージと同じ GUID を書き、移しても変えない。
  照らし方は「パス → GUID」だけ。まずパスで照らし、**見つからない物があったときだけ**プロジェクトの `Assets/` と `Packages/` の下の実フォルダの `.meta` の頭の行から「GUID → 今のパス」の表を作る。
  表はアプリを開いている間プロジェクトごとに覚え、2回目からは更新時刻の変わった `.meta` だけ読み直す（手元の19のプロジェクトで `.meta` は 1,034〜5,449 個。冷えた 5,000 個を8本並べて読んで約2秒、2回目は 11〜46ms）。同じ GUID が2か所にある物は表に入れない。
  - 入っているかを数える（「Unityで選択」・プロジェクトの中を調べる・既に全部入っているか）：GUID で見つかった物も「ある」と数える。2つ以上の商品に同じパスか同じ GUID で入っているファイルは数えない。ただし、持つ商品の全部が**同じ unitypackage**（同じハッシュの zip の同じ場所。単体の unitypackage はそのハッシュ）から持つなら数える（セットと単品に同じ zip を付けた。ユーザ判断 2026-11-11・`UnityPackageContents`。[shared-files.md](shared-files.md)）。どれか1つでも別の unitypackage（ハッシュの無いフォルダの中の物を含む）から持てば、同梱の部品として今までどおり数えない。
  - 「Unityで選択」で開くフォルダ（`LocateRoot`）：入り先に商品のファイルがパスで1つでもあればそこ。無ければ入り先のフォルダ自身の GUID の今の場所、それも無ければ GUID で見つかったファイルの今の場所から入り先に当たるフォルダを推す（下の段が同じならその上、違えばファイルのあるフォルダ。いちばん多くのファイルが指す所）。
    移った先を開いたときは、結果の1行に「場所：Assets/FUKA → Assets/Mine。」と元の場所と今の場所を矢印でつないで出す（ユーザ指示 2026-09-29：「移動されています」の文は長い。画面では「入り先」を「場所」と呼ぶ）。1件と言い切れるときだけ開く決まり（`Plan`）はそのまま。
- 確かめていない：Unity 6 以降・日本語表示のメニュー（当面は確かめない）。閉じているプロジェクトのレイアウトを書き換えて開く道（§8-1）は未実装。

## 1件だけ送った後、入ったフォルダを選ぶ（設定・ユーザ判断 2026-11-25）

- 設定「1件だけ送ったら、入ったフォルダをUnityで選択する」（Unity の欄。既定は**切**：Unity の検索欄と選択をこちらが書き換えるので、望む人だけが入れる。設定のファイルは `selectAfterUnitySend`）。
- **選ぶフォルダは、中身が枝分かれする最初のフォルダ**（`UnityImportedFolder.Pick`。Core の純粋な関数で、例は `UnityImportedFolderTests`）：
  unitypackage の中のパスの木を `Assets` から下り、子が1つしか無い段はたどり、子が2つ以上に分かれる所で止める。`Assets/作者/商品/…` なら `Assets/作者/商品`（ユーザ判断：「このProductNameが選択されたら良さそう」）。
  1つだけの子が葉（下に何も無い）ならそこで止めるので、ファイルが1つだけの物はそのファイルのあるフォルダを選ぶ（選ぶ物はいつもフォルダにし、検索を `t:Folder` に絞る）。
  拡張子ではなく木の形で決める（unitypackage のパスにはフォルダの行も混ざる）。大文字小文字は区別しない。
  **選ばない**：`Assets` の直下で分かれる（頭のフォルダが2つ以上・直下にファイルがある）・`Assets` の外（`Packages/` など）に入る物がある（ユーザ判断：「複数の時は選択しない」）。このときは黙る。
- **選ぶ時**：1件だけ送った時（商品ページ・カードの右クリックの「Unityへ送る」で1件選んだ時と、「改変に追加して送る」で1件の時。`ItemUnityActions.SendOneAsync`）で、
  取り込んだ時と、既に全部入っていて「Nothing to import!」だった時（`UnityImportedFolder.ShouldSelect`：窓を出せた・Cancel でない・理由が無い）。
  取り消した・止めた・待ちきれなかった・Unity ごと閉じられた・送れなかった時は選ばない。
  **選ばない道**：複数を順に送る（同じ商品から2つ以上・検索の複数選択）・改変の「使ったものを順にUnityへ送る」・改変の「Unityで選択」から送った時・新しい版を送る・外から使う API。
- **選び方**：改変の「Unityで選択」と同じ探し方（`UnityProjectTab.Plan`：`a:assets glob:"パス" t:Folder`・glob の記号があれば名前で探して数える・1件と言い切れなければ止める）で探し、
  画像と同じく **↓ で止めて Enter は押さない**（`HighlightFolderAsync`。開かずに選んだまま残す）。
  既に入っていた物は利用者がフォルダを移していることがあるので、GUID で今の場所を探す（`LocateRoot`）。
  **Unity に触る前にディスクでフォルダが在るかを見る**（0件のまま ↓ を送ると前の選択が残って見間違える）。取り込み画面で中身を全部外した時もここで止まる。
- **選べなかった時は理由を1文で言う**（場所が分からない・同じ名前のプロジェクトが2つで見分けられない・フォルダが見つからない・タブにフォーカスを移せない・1件と言い切れない）。
  商品ページは欄の下の1行、カードは「送った結果を知らせる」の設定に従う（`UnitySendNotice.Result`）。「改変に追加して送る」は「追加して、Unityへ送りました。」の後に続ける。失敗の顔（⚠）にはしない（送れてはいる）。
- glob がフォルダに当たるのは [実測]（`docs/history/unity-handoff.md` §13-7。`glob:"入り先のパス" t:Folder` でそのフォルダだけが出た）。
  ↓ だけでフォルダが選ばれる（Inspector に出る）か、スクリプト入りの物を取り込んだ直後（読み込み直しの後）に「Edit > Find」が通るかは [要確認]（Unity を動かして確かめていない）。
