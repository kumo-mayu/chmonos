# 動いている Chmonos の一覧

> **要点**：動いている Chmonos は、保存先によらない決まった場所（`%LOCALAPPDATA%\Chmonos-running\`）に、1本ごとに `<プロセスの番号>.json` の札を書く（2026-11-11。plan 33）。
> 外の道具は、ここを読めば、どの保存先のアプリが動いていて、どの `api.json` を読めばよいかが分かる。**トークンは書かない**（場所だけを指す）。
> API の決め事は [local-api.md](local-api.md)、画面を出さない起動は [headless.md](headless.md)。

## なぜ

拡張を作っている別のセッションの意見（2026-11-11）：「api.jsonが見つけにくい。動いているchmonosの一覧(保存先、ポート、api.jsonのパス、exeの場所など)が欲しい」。
`api.json` は保存先の中にあり、保存先は `location.json`・`CHMONOS_HOME`・写しの保存先で変わる。確かめ用に写しで開いたアプリも同時に動く。

## 置き場（2026-11-11 に決めた）

- `%LOCALAPPDATA%\Chmonos-running\`。`%LOCALAPPDATA%\Chmonos\running\` の案は退けた：
  - `location.json` の無い人では、`%LOCALAPPDATA%\Chmonos` が保存先そのもの（`StoreRootSource.Default`）。その下に置くと、
    引越し（`StoreMover`。元の中身を全部運んでから消す）・置き換え（中身を `_置き換え前-…` へ退ける）・戻す先の「空か」の確かめ（`StoreLocation.IsEmpty`）が、
    ほかのアプリ（写しで開いた物）の札まで運ぶ・消す・「空でない」で断る。除く名前を各所に足すより、どの保存先にもならない隣のフォルダの方が漏れが無い。
  - 本番の決まり（CLAUDE.md の3・`.claude/guard.json`）が守るのは `location.json` と普段の保存先で、隣のフォルダはどちらにも当たらない。`location.json` は読みも書きもしない。
  - `%TEMP%` は、Windows の掃除（ストレージ センサー）が動いているアプリの札まで消し得るので使わない。
- **写しの保存先で起動したアプリ（`CHMONOS_HOME`・`CHMONOS_DEFAULT_HOME`）も同じ場所に書く**。読む側は保存先で見分ける。
- 置き場を差し替える環境変数は `CHMONOS_RUNNING_DIR`（試験・確かめの道具）。
- **既定の場所に書くのはアプリ本体として起動したときだけ**（`StoreLocation.AllowsUserStore` と同じ考え）。試験・ViewShot などがアプリの一式を組んでも、環境変数が無ければ書かない（入れ忘れても本物の一覧を汚さない）。
- 2本目の起動（多重起動で終える方）は書かない・消さない。

## 中身

```json
{
  "processId": 12345,
  "startedAt": "2026-11-11T09:00:00.12+09:00",
  "storeRoot": "D:\\作り物\\Chmonos",
  "port": 39847,
  "apiFile": "D:\\作り物\\Chmonos\\api.json",
  "exePath": "C:\\作り物\\Chmonos\\Chmonos.exe",
  "version": "1.3.0",
  "headless": false
}
```

- `startedAt` は**プロセスが始まった時刻**（書いた時刻ではない）。プロセスの番号は使い回されるので、読む側はこれで本人かを確かめる。
- `port` は API が待ち受けているときだけ数。オフ・始める途中・始められなかった（ポートが使われている）ときは `null`（欄は省かない）。待とうとしただけの番号は書かない。
- `apiFile` は API が止まっていても書く（保存先の `api.json` の場所。無いこともある）。
- 名前は camelCase。知らない欄は無視してもらう（足すのは互換）。

## 書く時・消す時

- **書く**：起動して、多重起動の錠を取り、保存先の形式を決めた後（`App.OnStartup`。画面の有無で分かれる前の1か所なので、`--headless` も同じ道）。API を始める前に書くので、最初は `port: null`。
- **書き直す**：API の状態が変わったとき（`ApiRunner.StateChanged`：始めた・止めた・ポートを変えて待ち受け直した・始められなかった）。値は錠の中で今の状態から読む（知らせは裏のスレッドから続けて来る）。
- **消す**：正しく閉じたとき（`OnExit`。API を止めた後）。引越し・戻すの開き直しも `OnExit` を通る。消した後は書き直さない。
- **落ちて残った札**：次に起動した Chmonos が片付ける（`RunningInstances.Sweep`）。消すのは、番号のプロセスが無い・プロセスの始まりが `startedAt` と1秒より離れている（番号が別のプログラムに使い回された）札。
  権限などで確かめられない札は残す。壊れた札は、プロセスが無いときだけ消す。自分の番号の札は書き直すので触らない。
- 書けなくてもアプリは止めない（ログに残す）。一時ファイルに書いてから名前を付け替えるので、読む側が書きかけを読むことは無い。

## 読む側の手引き

1. `%LOCALAPPDATA%\Chmonos-running\*.json` を全部読む（名前が数字でない・読めないファイルは飛ばす）。
2. 生きているかを確かめる：`processId` のプロセスがあり、その始まりの時刻が `startedAt` と1秒以内なら動いている。そうでなければ落ちた残り（無視する。消すのは Chmonos に任せてよい）。
3. 保存先（`storeRoot`）で選ぶ。確かめ用の写しも並ぶので、決め打ちせず使う人に選ばせるか、保存先を設定で持つ。
4. `port` が `null` なら API はオフ（設定の「API」で「APIを使う」をオンにしてもらう）。
5. `apiFile` を読み、`token` を `Authorization: Bearer …` で送る。ポートは札と `api.json` の両方にあり、同じ値。

PowerShell の例は使い方の文書（`manual/40-api.md`「動いている Chmonos を探す」）。

## 守れる範囲

- 札は自分の Windows ユーザーのフォルダにあり、別のユーザーは読めない。トークンは書かないので、札を読めてもトークンは `api.json` を読める道具にしか取れない（今までと同じ）。
- 同じ Windows ユーザーで動く道具は、今までも保存先を直に読めた。札が増やすのは「どこにあるか」だけ。
