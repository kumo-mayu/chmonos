# 検索の手直し（2026-10-02・担当SRC）

元は `docs/feedback/open.md` のメモ1-①・1-③・2-①〜⑤（2026-10-02 のメモ1・2）と、まとめ役から追加で受けた「更新あり」の件。
今の決め事は `docs/spec/search.md`・`search-filters.md`・`ui-input.md`。

## 決めたこと

- **絞り込みの欄の境目（メモ1-①）**：境目（`PaneSplitter`）を欄の地の `Border` より前に同じ ZIndex で置いていたため、後ろの地が上に重なって掴めなかった。
  境目を ZIndex 1、開け閉めのつまみを 2 にした。友人に回した版でも同じ並びだったので、境目を足したとき（75ce2e5）から効いていなかったと見られる（その版で確かめてはいない）。
- **条件の並びのキー（メモ1-③）**：ユーザ判断「条件の並びを1つの止まりにする」。カードの一覧の並び（`ArrowGroup`）は中の止まり先を全部1段に並べて矢印で渡る作りで、
  条件の中の入力欄・選ぶ欄・スライダーの矢印と食い合うので使わず、枠（`FocusFrame`）の上だけ矢印を使う2段の作り（`FrameList`）にした。
  - 仮に決めた所：枠の上の Tab は**中へ入る**（ユーザの言葉「Enter（か Tab）でその条件の中へ入る」のとおり）。並びを素通りしたいときも、中へ入って最後の部品まで Tab を押す
    （条件1つ分。前は全部の条件の分）。別案：枠の上の Tab で並びの後ろへ出る（中へは Enter だけ）。
  - 枠の中の Tab の順（チェック → 札「除く」→「…」→ ⌃ → × → 中身）は変えていない。
- **条件を消すもたつき（メモ2-①）**：測ると ViewModel は 0.3〜1.6ms で、画面まで約190ms のうち約90ms は隠れたリストの組み直しだった（`docs/research/search-modules-2026-10-01.md` §13）。
  予想の「全部を組み立て直している」は当たっていなかった。結果が同じなら画面に渡す並びを替えず、カードの間はリストに空を渡す。
- **範囲・日付の和集合（メモ2-②）**：ユーザ判断で公開日・入手日も同じ扱い。「除く」が混ざるときは、おすすめのとおり**除かない物の和集合から、除く物をそれぞれ引く**
  （除かない物が無ければ、除く物のどれにも当てはまらない物）。別案：除く物も和集合に入れて「どれかの範囲に入る、または除く範囲の外」——除くを足すと結果が増え得るので採らなかった。
  要約は除かない物を「・」でまとめる（「 / 」だと全部に当てはまる物に読める）。検索の履歴の要約（Core の `SearchHistoryEntry.Summary`）は条件ごとに「 / 」のままで、まとめていない。
- **パネルの「…」（メモ2-③）**：いつも見せ、本文の濃さの字と枠を付ける。「条件をクリア」のボタンは見出しの行にも残す（おすすめで決めた）。
- **編集状況の「両方」（メモ2-④）**：項目とつなぎ方を押せず薄くする。つなぎ方は前は「両方」で隠していたが、隠すと欄の高さが変わるので出したまま押せなくした。
- **ショップの札（メモ2-⑤）**：文言は商品の右クリックに揃えて「ショップを開く」「BOOTHで開く」。札はキーボードの止まりにしないまま（2026-10-01）。
  読み上げ・自動操作からは「押す」で届く（`SortDividerBorder` をショップの札だけボタンとして出す）。
- **更新あり（まとめ役から追加・ユーザ判断／指示 2026-10-02）**：検索とフォルダの右の欄のカードにも札、条件「更新あり」（BOOTHの情報・販売終了のすぐ後）、
  カードとリストの行の右クリックに「既読にする」（ショップのカードにも同じ道を渡した）。まとめて既読にする操作（選んだ物すべて）は入れていない。
