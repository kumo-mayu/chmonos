### 全体

複数のitemなどを表示する可能性があるのでブラウザのタブ機能相当のものがあると便利かもしれない。実装難易度を見て考える。また、モックには実装する必要は無い

### item

ユーザが認識できる名前 : 商品ページ

基本はboothの商品ページのデザインを参考にしてローカル情報から再構築する

#### boothとの違い

- tasは検索対象なのでboothでは下部に配置されるが、上側に配置できる設定などが必要
- variationsとordered_variationsを利用して購入済を判定
- 購入済のvariationはexplorerで開くボタンが出現(カートに入れるの箇所が変更になっても良い)
- boothの商品ページに飛ぶ機能がある
- 後述の属性要素によるグラフを表示する箇所が存在する

### shop

ユーザが認識できる名前 : ショップページ

基本はboothのショップページに準拠してローカル情報から再構築する
表示されているitemsへの操作はsearch画面と同等

#### boothとの違い

- ここに表示される商品は購入済も物だけであるのがデフォルトl(取得ボタンを押すなどしてboothから取得してきて初めて完全なデータが見れるが、それをするならboothサイトに飛ぶべきだろう)
- 所持件数などを表示しても良い

### search

ユーザが認識できる名前 : 検索

#### 目標
この検索画面は、ユーザによる指定でitemを一意に検索することを目的としない。ユーザが目を通すのが現実的な数のitemまで絞り込めればユーザが自分でサムネイルなどを利用して十分の判断できる

#### UIでは以下の二つの検索種類を仮定する
- 絞り込み検索 : category, tag, 属性, published_at, 入手日, 対応avatar(item側が対応しているもの、ユーザが持っているアバターから選ぶなどがあるので要検討)
- 文字列検索 : name, description, h2, memo, filename or filepath, shop

「絞り込み」はデータで一発で決まる条件による検索で、「文字列検索」はユーザが覚えている曖昧な文字列による重複検索である。絞り込みはそれぞれ独立した指定UIにすることができ、文字列検索は1つの検索欄を利用してそれぞれの要素を横断して検索するのをデフォルトにして、 name:, des:, h2:, memo:, file:などのprefixを利用して指定するようにすれば良いだろう。

#### 属性という項目について

属性はユーザの操作文脈によって、絞り込みの条件なのか、表示順序の指標なのかが大きく変わる。そのため、絞り込み条件でも利用できるし、表示リスト側でも別途指定することができる。この機能を便利にするために、属性は「ある/ない」の二値から「"属性名" : 0.0-1.0」という連続のものとして扱い、「可愛さ60%,かっこよさ40%」のようさ検索・表示優先を実現できるようにする。

#### tagの統合について

ユーザによるタグの指定の他に、boothによるタグがあるが、入力欄は同じにし、どちら由来のタグかはUIで分かるようにする。
こうすることによってタグを指定する部分が一箇所になり、補完などによって便利で分かりやすいものとなる

#### 検索以外の機能
- 各itemにboothとexplorerで開くという操作ができる
- item画面に入ることができる
- 複数選択をすることができる
    - 選択をedit画面へ送ることができる

### Edit(旧decide)

ユーザが認識できる名前 : 商品編集・取り込んだデータを完成させる(要検討)

#### 機能

ユーザが自分で指定しないといけないメタデータを入れていく場所
途中で止めても次回同じ場所から再開できるように保存しておく機能が必要かも

##### 入力するのは以下の項目

###### 最初に求める
- appTag
- 属性(任意・連続値)
- メモ(任意)
- 対応アバター(確認と修正)
- ordered_variations
    - 購入価格(デフォルトは商品のvariationsからpriceを取得して利用)

###### その他
- filepath
- 入手日

#### UI
- 左半分がItemViewで、右半分に上の項目を入れていく。
- appTagはtopLevelを選択したらsubLevelの候補が出てきてそれぞれトグルで複数選択できる。検索するほどかは未定
- search画面などから複数選択して入った場合はマッチングアプリのように順々に処理していける。また、上に1/n件というようなstep表示がされる。

### Tag customize
ユーザが認識できる名前 : タグの管理

### 機能
- appTagの検索
- それぞれのtopLevel,subLevelがメモを保持できるのでそれを編集
- appTagの削除・新規追加(top, sub両方)

### 属性 Customize

ユーザが認識できる名前 : 属性の管理(未定気味)

#### 機能
- 属性名と該当アセットの件数の表示
- 属性の新規追加・削除
- 属性の統合(ユーザによる表記揺れなどの吸収用)
