# 人が足す変換の組（2026-11-20）

今の決め事は [conversion.md](../spec/conversion.md)「人が足す組」。ここは決めた順の控え。

- きっかけ：プロファイルを使わない変換ツール（avatar2avatar など）や、プロファイルの商品を持っていない組は、変換経由に出す方法が無かった（open.md の意見・ユーザ判断 2026-11-20）
- ユーザ判断：組は保存先の新しいファイル `conversion-pairs.json` に `{from, to}` で持つ。端はアバターか共通素体。ツールの名前とメモは任意。計算はプロファイルの組 ∪ 人の組で、人の組は確認を要らない。素体経由は元の側に1回、変換は1回まで。画面はアバターの管理の「変換」に候補付きの欄を置き、商品ページの「変換経由」の吹き出しで組からかプロファイルからかを言う。今のプロファイルの画面は残す。既定の向きは1方向（「逆も」は要確認）
- 段に分けた：段1（データ・計算・試験）を先に入れ、画面は段2
- 作るときに決めた事：
  - 組はプロファイルの「逆方向の集合×順方向の集合」に混ぜず、別に持って道筋を足す（混ぜると A→B の組が A→順方向の全員に化ける）
  - プロファイルが1つも無い時に何も出さない早帰り（`IsEmpty`）を、組も見るように直した
  - プロファイルと組の両方で届くアバターは、プロファイルの道筋を言う（組を足す前からの吹き出しを変えない）
  - 新しいファイルなので形式の版は上げない（`data-format.md`）。バックアップの類は保存先の直下の `*.json` を除外の名前で選ぶ作りなので、名指しせずに入る
- 段2（画面）：アバターの管理の「変換」の一覧はプロファイルの商品の一覧なので、「このアバター」が決まるアバターの詳細（「共通素体」の欄の下）に欄を置いた。吹き出しの語は画面の決まり（「足す」は使わない）に合わせて「追加した組で」にした
- 段3（編集を「変換」の側へ）：段2 を写しで見たユーザが「アバターの詳細ではなく変換側に足していけた方が良い」と判断した（2026-11-20）。元と先の両方にアバターと共通素体を選べるようにし、組ごとに任意のメモを画面で書く。アバターの詳細の欄は、読むだけの札と「変換で編集」に変えた。「逆も」と、商品ページに常に置く変換扱いの入口は作らないと決まった
  - 節は左の一覧の上に置いた（ユーザの言う「一覧の上」）。左の欄は既定 360px と狭いので、組を追加の欄は元と先を縦に積んだ。節は畳めるようにし、行の高さに上限を付けた
  - 足さない理由（候補に無い・同じ物同士・既にある）は画面で言う。Core の `Add` は理由を返さずに元の値を返すので、錠の中の判定はそのまま残した
  - メモは他の画面のメモと同じ `MemoAutoSave`（0.8 秒の待ち・離れる時に書き切る）。書いた後に行を作り直すと、次の行の欄へ移ったフォーカスが飛ぶ。行の組をその場で差し替える
  - 詳細の札は、そのアバターを直に指す組だけにした（共通素体が端の組まで出すかは決めていない）
- 段4（組の行と右の欄）：段3 を写しで見たユーザが「変換の組は、普通のプロファイルと同じような行にして、右側ビューで見れるようにしたい。先を候補から選んだ瞬間に自動で追加されているが、"追加"ボタンを押して追加する形にする」と判断した（2026-11-20）
  - 組の行は、プロファイルの商品と同じ選ぶ一覧（同じ字・間）にした。同じ一覧に混ぜると、プロファイルの商品の選び（`SelectedConversion`）と群（決めていない・決めた・扱わない）の作りが崩れるので、節の中の別の一覧にし、どちらか1つだけを選ぶ形を ViewModel で持つ
  - 行の上のメモの欄と × はやめ、右に元・先・メモ・「この組を外す」を出した。元・先は、素体の中のアバターを開くのと同じく、移る前を履歴に積む（戻ると同じ組を選ぶ）
  - メモの自動保存の待ちは1つしか持てないので、組を選び直す前にも書き切る（右の欄は選んだ組のメモに結ぶので、書き切らずに別の組で打つと、前の組に打った文が消える）
  - 足すのは「追加」と Enter だけ。足した組を選んで右に出すのは、同じ画面の共通素体の「追加」（足した素体を選ぶ・既にあればそれを選ぶ）に合わせた
- 段5（行の形・ユーザ判断①〜④ 2026-11-20）：行に元と先の絵、「組を追加」を一覧の上へ、並び4つ、いつも元でまとめて畳める見出し
  - 追加した順は配列の位置で持つ（足すと末尾・外す・メモ・読み替えで順を保つ）。まだ配っていない形だが、時刻を足すと古いファイルの並びの決め方が要るので、足さずに済む方を選んだ
  - 並びと畳んだまとまりは ui-state（前回の続きの状態。タグの並び・改変の仲間の向きと同じ置き場）。畳んだまとまりは表示の名前でなく元の端（ID・素体の名前）で覚える
  - 見出しは選ぶ行にしない（右に出す物が無い）。見出しの入れ物は止まらず、中の開閉の部品に止まる（通知の束の見出しと同じ作り）。↑↓ は見出しと行を1つの並びとして渡る
  - 見出しと行を1本の一覧に差分で出し入れする。ListBox は選んだ物が一覧から消えると選びを null で書き戻すので、出し入れの間は受けない（選んだ組のまとまりを畳むと右が商品へ移った）
- 段6（探す欄・右の絵・畳んだ帯の名前 2026-11-20・ユーザの意見）：「変換」の上に組を探す欄と探す所（両方・元・先）、共通素体の見方にも探す欄、右の組の欄の元・先に絵、畳んだ左の帯は今の見方の名前
  - 絞りの開閉は「覚えた値」と「絞りの間だけの値」に分けた。覚えた値で開くと ui-state に書かれ、黙って開くと（まとまりは作り直しでも使い回すので）語を消しても畳みへ戻らない
  - 当たらない組を足した時は絞りを外す（「アバター」の見方で絞りで外れたアバターへ移る時と同じ前例）。ただの読み直しでは打った語を消さない
  - 共通素体の一覧は、全部の一覧（Bases）を残して出す物だけ別に持つ。Bases を絞ると、改名の統合先・「既にあります」・組の端へ移れるかが見落とす
- 段7（探す欄の続き・ユーザ判断①〜⑤ 2026-11-20）：b436d12c を写しで見たユーザの意見から
  - ① 探す欄の案内（薄い字）は、絞りに使う値（`Query`・`BaseQuery`。Delay=200 で遅れて入る）が空かで出していたので、打ってから 200ms の間は打った字と重なった。欄そのものの字（`ElementName` の `Text.IsEmpty`）で出し分ける（検索・改変の画面と同じ直し方）。ほかの画面の同じ作りは報告に挙げて残した
  - ④ 群に「途中」：何も決めていない→決めていない、1つ以上のつなぎ先を確認済みにしたが未設定か確認待ちが残る→途中。「決めた」の数え方は確認済みのつなぎ先で、外しただけ（Rejected）は数えない（外すと行は選ぶ欄に戻り、つなぎ先はまだ無い）。「未確定」は BOOTH の商品が決まっていない商品の語なので使わない
  - ② 組を探す欄の語と探す所を、プロファイルの商品の一覧にも当てる（`ConversionItemSearch`）。商品には元・先が無いので、つなぎ先の向きで振り分けた：逆方向（その衣装を持っていく側）を元、順方向（着せる側）を先。検索の条件「プロファイル」の変換元・変換先と同じ割り振り。商品名は元でも先でもないので「両方」の時だけ当てる（「元」を選んで名前に先のアバター名を含む商品が残ると、探す所を選んだ意味が無い）。群は見出しの字（`GroupHeading`）で分け、絞っている間は「当たった数/全部」。選んだ商品は絞りで隠れても外さず、ListBox が書き戻す null を受けない（追加した組と同じ）。「後で」は見えている行の中で回る
  - ③ プロファイルの商品の行の頭に商品の絵。部品は取り込みの探した結果・通知・ファイルの割り振りと同じ `ResultThumbnail`（見えた行だけが場所を決め、縮めて読む）で、枠はファイルの割り振りと同じ 36。場所は手元の記録から決める（`ForItem` のように商品を読み直さない）。群で分けた一覧は WPF が既定で全行を作るので、「アバター」の一覧と同じく `IsVirtualizingWhenGrouping`・`Recycling` を付けた。行の書き直し（確認済み・外す）では絵を作り直さない（★の指名を替えても、一覧を読み直すまで前の絵）
  - ⑤ 共通素体の探す欄と足す欄を1本に。部品は `SearchAddBox` でなく `SuggestBox`（素体に入ったアバターの名前を候補に出すため）。候補は探すための物で、素体の名前は候補にしない（「新しく名付ける欄に候補を付けない」の決まりは素体の名前に当てている・ui-input.md と screen-and-wording.md に書き足した）。当てるのは素体の名前と、入ったアバター（`AvatarRowViewModel.Matches` と同じ照らし）。段6で「名前だけ」にしたのは行になぜ残ったかが出ないためだったので、アバターで当たった行に「アバター「A」」（2体以上は「ほか n 体」）を添えた。Enter：アバターの候補なら絞るだけ、ほかの語は足す。SuggestBox は候補が開くと最初の行を選んでおくので、アバターの名前を含む新しい名前の Enter は候補を選ぶ。足すのは「追加」（いつも足す）。打ってすぐの Enter・「追加」は Delay=200 を先に流し込む（遅れて届いた語が「既にあります」を消さないように。SearchAddBox と同じ）。NewBaseName は無くした
