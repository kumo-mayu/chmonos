# 人が足す変換の組（2026-11-20）

今の決め事は [conversion.md](../spec/conversion.md)「人が足す組」。ここは決めた順の控え。

- きっかけ：プロファイルを使わない変換ツール（avatar2avatar など）や、プロファイルの商品を持っていない組は、変換経由に出す方法が無かった（open.md の意見・ユーザ判断 2026-11-20）
- ユーザ判断：組は保存先の新しいファイル `conversion-pairs.json` に `{from, to}` で持つ。端はアバターか共通素体。ツールの名前とメモは任意。計算はプロファイルの組 ∪ 人の組で、人の組は確認を要らない。素体経由は元の側に1回、変換は1回まで。画面はアバターの管理の「変換」に候補付きの欄を置き、商品ページの「変換経由」の吹き出しで組からかプロファイルからかを言う。今のプロファイルの画面は残す。既定の向きは1方向（「逆も」は要確認）
- 段に分けた：段1（データ・計算・試験）を先に入れ、画面は段2
- 作るときに決めた事：
  - 組はプロファイルの「逆方向の集合×順方向の集合」に混ぜず、別に持って道筋を足す（混ぜると A→B の組が A→順方向の全員に化ける）
  - プロファイルが1つも無い時に何も出さない早帰り（`IsEmpty`）を、組も見るように直した
  - プロファイルと組の両方で届くアバターは、プロファイルの道筋を言う（組を足す前からの吹き出しを変えない）
  - 新しいファイルなので形式の版は上げない（`data-format.md`）。バックアップの類は保存先の直下の `*.json` を除外の名前で選ぶ作りなので、名指しせずに入る
- 段2（画面）：アバターの管理の「変換」の一覧はプロファイルの商品の一覧なので、「このアバター」が決まるアバターの詳細（「共通素体」の欄の下）に欄を置いた。吹き出しの語は画面の決まり（「足す」は使わない）に合わせて「追加した組で」にした
- 段3（編集を「変換」の側へ）：段2 を写しで見たユーザが「アバターの詳細ではなく変換側に足していけた方が良い」と判断した（2026-11-20）。元と先の両方にアバターと共通素体を選べるようにし、組ごとに任意のメモを画面で書く。アバターの詳細の欄は、読むだけの札と「変換で編集」に変えた。「逆も」と、商品ページに常に置く変換扱いの入口は作らないと決まった
  - 節は左の一覧の上に置いた（ユーザの言う「一覧の上」）。左の欄は既定 360px と狭いので、組を追加の欄は元と先を縦に積んだ。節は畳めるようにし、行の高さに上限を付けた
  - 足さない理由（候補に無い・同じ物同士・既にある）は画面で言う。Core の `Add` は理由を返さずに元の値を返すので、錠の中の判定はそのまま残した
  - メモは他の画面のメモと同じ `MemoAutoSave`（0.8 秒の待ち・離れる時に書き切る）。書いた後に行を作り直すと、次の行の欄へ移ったフォーカスが飛ぶ。行の組をその場で差し替える
  - 詳細の札は、そのアバターを直に指す組だけにした（共通素体が端の組まで出すかは決めていない）
