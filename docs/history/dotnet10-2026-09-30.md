# .NET 9 から .NET 10 へ上げた（2026-09-30）

> **要点**：全部のプロジェクトを .NET 10（長期サポート。2028-11-14 まで）へ上げた。絵（99 枚）と読み上げの木（1,091 行）は前後で同じ、試験は 2,762 件とも通る。
> 変わったのは、配る exe の大きさ（+5.7 MB）と、起動が少し遅くなったこと（配る形で +0.09 秒・開発用のビルドで +0.23 秒）。起動の遅れは原因を絞りきれていない。

ユーザ指示（2026-09-30「タイミングを見て .NET 10 に上げてください」）。.NET 9 のサポートは 2026-11-10 に切れる。
測ったのは SDK 10.0.401・ランタイム 10.0.12（前は 9.0.14）。

## 上げた物

- `TargetFramework`：33 プロジェクトと配る設定（`win-x64.pubxml`）を `net9.0`／`net9.0-windows` → `net10.0`／`net10.0-windows`。
  実験のうち `net8.0` のままだった 4 つ（BrowserHistoryProbe・JapaneseBridgeProbe・ThumbnailHashProbe・UnityPackageProbe）も同じに上げた（.NET 8 も同じ日に切れる）
- NuGet の参照の版は変えていない。変わったのは 2 つ：
  - `System.Text.Encoding.CodePages` の参照を外した（BoothZipInspector・実験 2 つ）。枠組みに入っている型で、.NET 10 の SDK は要らない参照として警告する（NU1510）。
    前は net9.0 に 10.0.11 のパッケージを重ねていて、その DLL（0.7 MB）が出力に入っていた
  - AngleSharp 1.8.0 は `net10.0` 向けの DLL を持っていて、上げると自動でそちらが選ばれる（前は `net8.0` 向け）。版は同じ
- 出力のフォルダ名が `net10.0`／`net10.0-windows` に変わる。道具に埋まっていた道（`ui-kit.ps1` の `$ChmonosExe`・`sandbox-recipes.ps1` の SandboxGen・`research/Inspect-BoothSample.ps1`）を直した

## 警告

.NET 10 と C# 14 の解析で新しく出た警告は NU1510 の 2 つだけ（上のとおり参照を外した）。
ほかに、前から出ていた物を 2 つ直した（どちらも実験で、ソリューションに入っていないので見逃されていた）：
ThesaurusBridgeProbe の CS8714、ZipOriginProbe のビルドエラー（`ProposeAsync` の戻りが変わった後、直されていなかった）。

## 確かめ

| 何を | 結果 |
|---|---|
| ビルド | ソリューションと、入っていない 23 プロジェクト（実験・SandboxGen・PdfProbe）とも 警告 0・エラー 0 |
| 試験 | 2,762 件とも合格（本体 2,341・画面の側 368・zip 45・ID 8） |
| 絵（`tools/ViewShot`） | 50 場面×明暗の 99 枚、前後で 1 画素も違わない。倍率 150%・表示の大きさ 125% の 8 枚も同じ |
| 読み上げの木（`experiments/PeerProbe`） | 12 場面とも完走。1,091 行、前後で同じ |
| 配る形 | `dotnet publish -p:PublishProfile=win-x64` が通る。exe 1 つ＋LICENSE・NOTICE＋`assets` 4 件（辞書 2 つを含む）。作り物 2,000 件の写しで起動し、商品ページまで開けた |

### 配る物の大きさ

| | 前（.NET 9） | 後（.NET 10） | 差 |
|---|---|---|---|
| exe | 141,528,856 バイト | 147,190,615 バイト | +5.66 MB（+4.0%） |
| 全部（exe＋辞書など） | 146.5 MB | 151.9 MB | +5.4 MB |

一時フォルダへ展開されるネイティブ DLL は前後とも 5 つ・7.8 MB。

### 速さとメモリ

作り物 2,000 件の写し（台本 `many`）で、前 → 後を交互に測った。Release のビルド。
起動は「プロセスが始まってから、画面のスレッドが 1.5 秒続けて 33ms 以内に返事をするようになるまで」。
**測っている間、ユーザのアプリ（別の写し・.NET 9）が 1 本開いていた**（閉じない決まり）。前後を交互に測って揃えたが、1 本だけで測った数字ではない。

| | 前 | 後 | 差 |
|---|---|---|---|
| 起動（開発用のビルド・9 巡） | 1,314 ms（1,276〜1,364） | 1,548 ms（1,526〜1,563） | **+234 ms（+18%）** |
| 起動（配る形・3 巡） | 1,450 ms（1,435〜1,465） | 1,544 ms（1,534〜1,558） | **+94 ms（+6%）** |
| 検索を開く（設定から戻る） | 止まり 1 回・43〜48 ms | 9 巡のうち 8 巡は止まりなし（最長 20〜25 ms） | 差は測れなかった（配る形では前後とも 40〜49 ms の止まりが 1 回） |
| 商品ページを開く | 224 ms（222〜228） | 225 ms（221〜251） | 差は測れなかった（配る形は 244 → 251 ms） |
| 落ち着いた後のメモリ（作業セット／プライベート） | 199 MB ／ 143 MB | 209 MB ／ 145 MB | 作業セット +10 MB。プライベートは同じ |
| 商品ページまで開いた後 | 236 MB ／ 174 MB | 233 MB ／ 167 MB | プライベート −7 MB（9 巡のうち 8 巡）。配る形では差なし（174 → 176 MB） |

起動の遅れについて分かったこと：

- 差は巡ごとのぶれ（前 88 ms・後 37 ms の幅）の 2 倍を超えていて、9 巡とも同じ向き
- 増えたのは画面のスレッドの CPU 時間（開発用のビルドで 1.11〜1.17 秒 → 1.31〜1.39 秒、配る形で 1.25〜1.28 秒 → 1.33〜1.34 秒）
- 窓を出さない道具の起動（`ViewShot list`。ランタイムを立ち上げて場面の名前を書くだけ）は前 74〜85 ms・後 68〜73 ms で、遅くなっていない。遅れはアプリの画面を組む間に出ている
- .NET 10 のアプリをもう 1 本開いたままにして測っても同じだった（ランタイムの DLL が読み込み済みかどうかの差ではない）
- JIT の設定（`DOTNET_TieredPGO=0`）を変えても同じだった
- 開発用のビルドでは、後の版だけ「.NET Tiered Compilation Worker」（裏で作り直すスレッド）が起動の直後に 1.3〜1.5 秒 CPU を使う回が多い（CPU 時間を控えた 8 巡のうち 6 巡。前の版は、スレッドごとに見た 5 巡とも 0.03〜0.06 秒）。
  画面は止めないが、その間 CPU を 1 本使う。配る形では前後とも出ていない（起動から静かになるまでの CPU 時間は前後とも 2.7〜2.8 秒）
- **原因は絞りきれていない**（推測：アプリ自身のコードを最初に翻訳する所か、WPF 10 の画面を組む道。事前に翻訳しておく配り方 `PublishReadyToRun` で縮むかは測っていない）

## 互換性に影響する変更

公式の一覧（[Breaking changes in .NET 10](https://learn.microsoft.com/en-us/dotnet/core/compatibility/10.0)・
[C# compiler breaking changes since C# 13](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/breaking-changes/compiler%20breaking%20changes%20-%20dotnet%2010)）から、このアプリが当たり得る物を拾ってコードで確かめた。

| 変更 | 当たるか | 確かめ方 |
|---|---|---|
| NU1510（枠組みに入っているパッケージの参照に警告） | **当たった**。直した | ビルドで出た。参照を外した |
| WPF：型の合わない `DynamicResource` で落ちるようになった | 当たらない | 色・大きさに `DynamicResource` を使う 19 か所の鍵（`Color` 2 つ・`Double` 4 つ）が、受ける側の型と合っている。全場面が描けている |
| WPF：空の `Grid.ColumnDefinitions`／`RowDefinitions` がビルドエラー | 当たらない | ビルドが通る。XAML・場面のファイルに空の定義は無い |
| 1 ファイルのアプリが、実行ファイルの隣のネイティブ DLL を探さなくなった | 当たらない | P/Invoke の相手は Windows の DLL だけ（user32・kernel32・dwmapi・shcore）。WPF のネイティブ DLL は exe の中から展開される道で、配る形の起動で確かめた |
| System.Text.Json：`$type` などの予約の名前とぶつかる項目を検査 | 当たらない | 多態（`JsonPolymorphic`）・参照の保持（`ReferenceHandler`）を使っていない |
| C# 14：配列にスパンの版のメソッドが選ばれるようになった | 当たる所は見つかっていない | 式の木（`Expression<>`）を使っていない。ビルドが通り、試験が全部通る。**共変の配列（`string[]` を `object[]` として渡す）で実行時に落ちる形は、コードを全部は洗っていない** |
| C# 14：`field`・`extension` がキーワードに | 当たらない | 当たれば警告（CS9258）かエラーになる。どちらも出ていない |
| 反復子：破棄した後の `MoveNext` が続きを走らせなくなった | 当たる所は見つかっていない | 試験が全部通る（コードは洗っていない） |
| `BufferedStream.WriteByte` が一杯でも流さなくなった | 当たらない | `BufferedStream` を使っていない |
| tar の書き出しに atime・ctime が入らなくなった | 当たらない | tar を書くのは試験の作り物だけ（アプリは読むだけ） |
| HttpClient：追跡の見出しの形が W3C に | 当たらない | `Activity`・`ActivitySource` を使っていないので、見出し自体が付かない |
| `System.Linq.AsyncEnumerable` が枠組みに入った | 当たらない | `System.Linq.Async` のパッケージを参照していない |
| 使うのをやめる API（obsoletions） | 当たらない | 当たれば警告になる。出ていない |
| deps.json から、実行時の物を持たないパッケージが外れる | 影響なし | deps.json を読む道具を使っていない |
| zip・文字コード・ファイルの既定の値 | 一覧に、当たる項目が無い | zip の Shift_JIS の名前の試験（45 件）は通る |

一覧は「作業中で、全部ではない」と書かれている。載っていない変更は、試験・絵・木の比べで見える範囲でしか確かめていない。

## 確かめていない事

- 実際の画面での操作の手触り（乗せたときの色・メニュー・ドラッグ・フォーカス・文字の縁の ClearType）。台は窓を出さずに描くので見えない
- BOOTH への問い合わせを伴う動き（取り込み・取り直し・自動検索）。問い合わせない決まりで確かめた
- Unity へ送る動き
- 実データの保存先での動き（作り物の写しだけで確かめた）
- .NET 10 のランタイムを入れていない PC での、配る形の起動（この PC には入っている。自己完結なので要らないはずだが、確かめていない）
- 長く使った後のメモリ（測ったのは起動から商品ページまで）
