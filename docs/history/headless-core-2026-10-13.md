# 画面を必須にしない作り（核と API を最小の起動単位にする）2026-10-13

## きっかけ

外から使う API（2026-10-12）は読むだけで、別のプロセス（`Chmonos.Api.exe`）として動く。
「この API で足りるか」を、作りたくなるサービスから逆引きして調べると（Fable に依頼）、大きな穴は「操作・書き込みが無い」だった
（Unity の拡張・Stream Deck・改変のレシピの取り込みは、読むだけでは完結しない）。

別のプロセスの API が保存先へ書くと、書き込みの門（`StoreWriteGate`。プロセスの中の錠）・商品ごとの錠・`UiCommand` を全部すり抜ける。
そこでユーザが提案した（2026-10-13）：**画面を必須の物と考えず、最小の起動単位を「核（Core のサービス一式）＋API」にし、引数があれば画面も起動する。**
書き込み・更新の処理を今のまま使い回しつつ、書き込みの API を破綻なく足せる。

## 調べたこと

- 書き込み（`UiCommand`・`CommandHandler`）とサービスは全部 Core にある。組み立て（`AppServiceContainer`）は App にあるが、`new` するのはほぼ Core の物。
  App の部品で WPF に依存するのは `PaneWidths` だけ（`RecycleBin`・`VolumeReader` は Windows の機能を呼ぶが画面は要らない）
- 起動したときの裏の作業は主画面の ViewModel（`MainViewModel.Background.cs`）が始め、進み具合を画面の帯に出している
- 取り込みの本体は `UiCommand.ScanFolders` だが、対象の決め方・取り込み元の履歴・走っている取り込みへの追加・進み具合は取り込み画面の ViewModel が持つ
- 画面は外からの変化を知らない（自分が押した操作の後に自分で読み直す）。保存先を見張っているのは API の側（`ApiSync`）だけ
- 画面の検索と API は、同じ商品の記録と検索用の文字列（`SearchHaystack`）を別々に持っている（API は 2万件で約200MB の大半がこの分）。
  同じプロセスにすれば共有できる

## 決めたこと（ユーザ判断 2026-10-13）

| 問い | 決め |
|---|---|
| 起動の既定 | 画面あり。`--headless` を付けたときだけ画面を出さない（ダブルクリックの操作は変えない） |
| API はいつ立ち上げるか | 設定でオンのときだけ（既定はオフ）。メモリを共有すれば費用は小さいが、ポートを開けて合言葉を持つ道具に読ませる（書かせる）かは使う人が選ぶ |
| `Chmonos.Api.exe` | やめて1本にまとめる。保存先ごとに1プロセス（錠も1つ） |
| 画面無しの起動時の裏の作業 | 画面ありと同じ設定（「起動したとき、裏で取得を始める」）に従う |
| 画面無しの起動時の自動の取り込み | **経路は画面ありと1本にし、設定は画面無し（API）用を別に立てる** |
| 保存先が決まっていないのに画面無しで起動された | 断って終わる（保存先を勝手に作らない） |
| 書き込みの API の BOOTH の優先度 | 「人が押した」にしない |
| 画面無しで動いていることの見せ方・止め方 | 通知領域のアイコン。右クリックで「窓を開く」「終了」 |
| 画面無し用の自動の取り込みの設定の置き場 | 設定の「API」の節（既定はオフ） |
| 画面無しの起動での新しい版の確認 | しない（知らせを出す場所が無い）。窓を開いたときに回す |
| 画面無しの起動での「このIDで登録」の続き | 行う（人が押した物なので、画面が無くても進める） |

`docs/spec/local-api.md` の「起動は本体と連動させない（ユーザ判断 2026-10-12）」は、この判断で覆る。

## 作り

新しいプロジェクトは作らない。画面無しの起動は「同じ `Chmonos.exe` で窓を作らない起動」。起動の順（保存先の確かめ → 初回の窓 → 形式の版 → 錠 → 組み立て）と、
`App` の静的な初期化（`StoreLocation.AllowsUserStore`。2026-09-30 の事故の守り）は、画面無しでも同じ道を通す。

| 段 | すること |
|---|---|
| 1a | 起動したときの裏の作業を、画面に依存しない係（`StartupWork`）へ移す。画面へ戻るのは「進み具合」「読み直しの合図」「件数を数え直す合図」だけ。動きは変えない |
| 1b | 取り込みを画面に依存しない係へ移す（対象の決め方・履歴・追加・進み具合）。取り込み画面はその係を映すだけにする。動きは変えない |
| 1c | `--headless` の起動。保存先が決まっていなければ断る。裏の作業と、画面無し用の自動の取り込みの設定 |
| 2 | API を同じプロセスで動かす（設定でオン）。`Chmonos.Api` はライブラリにし、`Chmonos.Api.exe` をやめる。商品の記録と検索用の文字列を画面と共有する。保存先の変化を画面にも知らせる（`ChangeFeed` を画面が聞く）——**段2で済ませたのは商品の記録の共有まで**。検索用の文字列は画面と API でまだ別に持つ（測ってから決める）。画面に知らせる道は、API が書くようになる段3で足す（今は画面しか書かない） |
| 3 | 書き込みの API を `UiCommand` で足す（書く合言葉、既定はオフ） |
| 4 | 画面無しで動いているプロセスに、窓を開かせる頼み方（2本目の起動を断らず、動いている方へ頼む） |

各段は、先に今の動きを押さえる試験を足してから移す。

## 進み

- 1a（2026-10-13）：`StartupWork`。主画面の公開の入口は残し、中身を係へ渡した
- 1b（2026-10-13）：`ImportRunner`。取り込み画面は対象の一覧と展開先を尋ねる窓だけを持ち、係の知らせを映す
- 1c（2026-10-13）：起動したときの作業をプロセスで1回に・登録の列を一式へ・`--headless`・通知領域のアイコン・画面無し用の自動の取り込みの設定。決め事は `docs/spec/headless.md`。
  写しで、窓を出さない起動・2本目が黙って終わる・開く・閉じると隠れる・開き直す・メニューの「終了」を確かめた。
  **マニュアルは段2の後に書く**（今は API が別の実行ファイルのままで、画面無しで起動しても使う人にとっての意味がそろっていない）
- 2（2026-10-13）：API をアプリと同じプロセスで動かす（`ApiServer`・`ApiRunner`）。ユーザ判断：設定の「APIを使う」でオンにしたらすぐ待ち受け、オフですぐ止める。ポートを変えたらその場で待ち受け直す。
  画面無しの起動も同じ設定に従う。`Chmonos.Api.exe`・`api.lock`・`/internal/busy`・`ApiNotifier` をやめた。商品の記録はアプリの控えと共有する（`QuerySnapshot.SharesItemCache`）。
  配る exe は 170.5 → 223.8MB（ASP.NET Core のランタイムの分）、前の `Chmonos.Api.exe`（110MB）が無くなるので合計は 280 → 224MB。
  合言葉の作り直し（前の `--new-token`）は、当面「オフにして api.json を消してからオン」。メモリは 2026-10-13 に測った：2万件で API の上乗せは専用 約85〜100MB（別のプロセスの頃は 202MB）。API で検索すると検索用の文字列が +25MB。共有はしない（`docs/spec/local-api.md`）

- 3（2026-10-13）：最初の一束（3a 軽い印・Unity へ送る・3b 分類）。Codex の点検36（段1〜2）・37（段3）の指摘を全部直した。
  編集画面との順序は、入口の確かめではなく商品ごとの札（`ItemEditGate`）で決める。3c（改変）は、API の目的（画面の機能を全部出すか、資産を使う物に絞るか）を決めてから
- 4（2026-10-13）：2本目の起動が動いている方に窓を開かせる（`OpenRequestChannel`）・API の「画面で開く」。写しで、画面無しの起動に2本目を当てて窓が開き前に出ることを確かめた。
  「エクスプローラで開く」は、商品のどの場所を開くか（登録したフォルダが複数・zip の中）を決めてから

## 段3 書き込みの API の決め事（ユーザ判断 2026-10-13）

案は Fable が `UiCommand` の全部を分類して出し、助言を受けて絞った。

- 下地（3a-0）：命令の口（`CommandHandler.ExecuteAsync`）を API へ渡す（API のライブラリは App を参照しない）。命令の入口に「どこから来たか」を足し、
  API から来た命令には「人が押した」優先度を掛けない（今の入口はいつも `Prioritize(User)` を張る）。書き込みは `api-settings.json` の `allowWrites`（既定オフ）で許す。
  書き込みの門が閉じている間（引越し・書き出し・戻す）は待たせず 503。書いた後は API の写しを読み直してから答える（取り込み中は「受け付けた」と返し、変化の知らせで伝える）。
  API が書いたら画面へ直に知らせる（検索の一覧はその商品だけ差し替え、開いている商品ページには「表示する」を出す）
- 最初の一束：3a 軽い印（お気に入り・非表示・通知の既読と解消・「使った」の足跡）・**Unity へ送る**・3b 分類（タグ・属性・メモ・一覧に足す）。次の束が 3c 改変
- **Unity へ送るを入れる**（ユーザ判断）。zip からの取り出し・置き場・「使った」の足跡を Chmonos が受け持ち、Unity の拡張が同じ判断を別に持たない。
  「エクスプローラで開く」「画面で開く」は段4と一緒に
- 合言葉は1本のまま、書き込みは設定で許す（同じ Windows ユーザーの道具なら api.json を読めれば2本目も読めるので、分ける効き目が小さい）
- ブラウザからの書き込みは、許可した住所のページなら許す
- 編集画面で開いている商品へ外から書こうとしたら 409 で断る（人が後から保存すると API の分が消える）
- 「使った」の足跡は外から付けられる（「見た」は付けない）
- 出さない：対応アバターを確定させる操作（推定が人を介さず確定になる）・削除と名前の変更と統合（取り返しがつかない。v2）・BOOTH へ問い合わせる操作と取り込み（後で）・保存先を丸ごと扱う操作
- Fable のおすすめで決めた：一覧に無いタグ・属性の名前は既定 400、`createMissing` で足す／記録はログに1行で商品 ID は確かめ用の記録のときだけ／外からの「通知」の追加は出さない／`If-Match` は後で
- Codex の点検は、段3がある程度進んでから
