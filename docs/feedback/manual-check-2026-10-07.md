# 実機の確かめ（2026-10-07・強制終了と起動の失敗）

外部の点検（7回目）の「公開前に人が確かめるべき所」のうち、手元の写しで起こせる物を、組んだアプリを起動して確かめた。
どれも写し（`Chmonos-sandboxes` の下）だけを使った。本番の `location.json` の更新日時は、確かめの前後で変わっていない。
引越しと戻すは、`CHMONOS_DEFAULT_HOME` で既定の置き場を写しの下へ差し替え、`CHMONOS_HOME` なしで起動して行った（`CHMONOS_HOME` では「場所を変える」が押せない）。

## 結果

| 確かめ | 結果 |
|---|---|
| 設定の JSON が壊れた写しで起動する | 「起動できませんでした」の窓（理由と次にやること）が出る。窓が出ている間に錠はもう放されている。OK で終わり、アプリは残らない。ログに例外が残る |
| 書き出し（画像も入れる）の途中で強制終了する | 前の zip は中身ごと残る。保存先の錠と一時ファイルは残らない。起動し直すとふつうに開く。**書き出し先に書きかけの `<名前>.zip.tmp` が残り、起動し直しても消えない**（下の 2） |
| 引越し（20,416ファイル・285MB）の途中で強制終了する | `location.json` は元を指したまま。元は全部残る。錠は残らない。起動し直すと元が開く。**移し先に写しかけ（2,173ファイル）が残り、何も言わない**（下の 1） |

## 見つけた物（判断待ち）

1. **引越し・戻すの途中で止まると、写しかけが「既にあるライブラリ」に見える**（中）
   元のデータは残るが、写しかけの場所を後で選ぶと、写しかけを「選んだ場所のライブラリ」として出す。
   「選んだ場所のデータを使う」を選ぶと、商品の大半が欠けたライブラリへ切り替わり、使う人からはデータが消えたように見える。
   途中で止まった物だと分かる手掛かりが無い。直し方の案：写す前に移し先へ「写している途中」の印を置き、終わったら外す。
   印のある場所は、選んだときに「前の引越し・戻すの途中で止まった写しかけです」と言い、片付けてからやり直せるようにする。
2. **書き出しの途中で止まると、書き出し先に `.zip.tmp` が残る**（軽い）
   使う人が選んだフォルダに、知らないファイルが残る。同じ場所へ書き出し直せば上書きされると見ているが、別の場所へ書き出すと残り続ける。
   直し方の案：一時ファイルの名前を、何の物か分かる名前にする（例：`<名前>.zip.書きかけ`）か、次の起動で、前に書き出した場所に残った物を片付ける。

## 直した後の確かめ（2026-10-07 午前）

- 見つけた物 1（写しかけ）は担当L111 が直した（写す前に途中の印 `_Chmonos-コピーの途中.json`）。同じ手順で、引越しの途中（2,449ファイル）で強制終了すると、移し先に印が残った
- 起動し直して同じ移し先を選ぶと、「コピーが途中で止まった場所です」の窓が出る（選んだ場所・始めた日時・ライブラリとしては使えないこと・削除するファイルの数と大きさ・元のデータが残ること）。並びと折り返しは引越しの窓と揃っている
- 「途中のコピーを削除する」で写しかけ（2,533ファイル・32MB）が消え、前から在った移し先のフォルダは残り、そのまま「データを引っ越しますか」に進む。元のデータは全部残る
- 見つけた物 2（書き出しの `.zip.tmp`）は、次の起動で片付ける形にした（9d6b028c。試験で確かめた）

## 保存先のドライブを抜く（2026-10-07 午前・USB メモリ 8GB・FAT32）

`ui` の写しを USB メモリへ写し、`CHMONOS_HOME` をそこへ向けて起動し、使っている最中に引き抜いた（安全な取り外しを使わない）。

| 確かめ | 結果 |
|---|---|
| FAT32 の上で起動する | ふつうに開く（商品49件） |
| 抜いた後に操作する | アプリは落ちない |
| 抜いた後に星（お気に入り）を押す | 「対象の商品データが手元にありません。」の窓。**記録は無事なのに消えたように見える**（下の 1） |
| 抜いた後に設定を変える | 「保存できませんでした。ファイルかフォルダが見つかりません。…外付けやネットワークのドライブがつながっていないことがあります。」が設定の画面の下の帯に出る。**見落としやすい**（下の 2） |
| 挿し直した後 | 設定も星も書ける。USB の上の JSON 196件は全部読め、書きかけ（`.tmp`）も残らない |

直した物（ユーザ判断 2026-10-07）：
1. 商品の記録が見つからないとき、保存先のフォルダそのものが無ければ「保存先のフォルダが見つかりません。外付けやネットワークのドライブがつながっているかを確かめて、もう一度押してください。」と言う（`CommandHandler.ItemMissing`）
2. 設定を保存できなかったら窓で知らせ（「設定を保存できなかったので、変える前のままです。」）、欄は保存してある値へ戻す。前は欄が変えた値のまま残り、保存してある値と食い違っていた

## Hub・VCC の入っていない PC でリンクを開く（2026-10-07 午前・LAN の別の PC）

Windows 11 の別の PC（Hub・VCC・ALCOM のアンインストール情報も `unityhub`・`vcc` のリンクの登録も無いことを、記録を読んで確かめた）へ SSH で確かめの道具 `ToolDetectProbe` を送り、ログオンしている人の画面で走らせた（予定の作業 `/IT`）。

- 見分け：Hub・VCC・ALCOM はどれも「無い」（`UnityTools.Detect` が全部 False）
- `Process.Start("unityhub://")`・`Process.Start("vcc://…")`（`UseShellExecute`）は**例外にならずに返る**（プロセスは無し）。画面には Windows の窓「アプリを取得してこの 'vcc' リンクを開く／お使いの PC には、このリンクを開くことができるアプリがありません。Microsoft Store で互換性のあるアプリをお探しください。」が出る
- つまり、受け手の無いリンクを開いても、アプリからは失敗に見えない。アプリのふつうの道は開く前に止まる：Unity を開くは Hub が無ければリンクを渡さない（`UnityLaunch` の `HasHub` の確かめ。結果 `NoEditorNoHub`）、VCC・ALCOM を開くはリンクでなく実行ファイルを開く（結果 `NotInstalled`）
- 使った物は確かめの道具だけで、終わったら相手の PC の置き場と予定の作業を消した
- 確かめていない物：Hub・VCC を入れた後に消した PC の残りかす（`UnityToolPresence` は記録の指す実行ファイルが在るかで見るので、残りかすでは「入っている」と見ない作り。試験で確かめてある）
