# 実機の確かめ（2026-10-07・強制終了と起動の失敗）

外部の点検（7回目）の「公開前に人が確かめるべき所」のうち、手元の写しで起こせる物を、組んだアプリを起動して確かめた。
どれも写し（`Chmonos-sandboxes` の下）だけを使った。本番の `location.json` の更新日時は、確かめの前後で変わっていない。
引越しと戻すは、`CHMONOS_DEFAULT_HOME` で既定の置き場を写しの下へ差し替え、`CHMONOS_HOME` なしで起動して行った（`CHMONOS_HOME` では「場所を変える」が押せない）。

| 確かめ | 結果 |

## 見つけた物（判断待ち）

1. **引越し・戻すの途中で止まると、写しかけが「既にあるライブラリ」に見える**（中）
   元のデータは残るが、写しかけの場所を後で選ぶと、写しかけを「選んだ場所のライブラリ」として出す。
   「選んだ場所のデータを使う」を選ぶと、商品の大半が欠けたライブラリへ切り替わり、使う人からはデータが消えたように見える。
   途中で止まった物だと分かる手掛かりが無い。直し方の案：写す前に移し先へ「写している途中」の印を置き、終わったら外す。
   印のある場所は、選んだときに「前の引越し・戻すの途中で止まった写しかけです」と言い、片付けてからやり直せるようにする。
2. **書き出しの途中で止まると、書き出し先に `.zip.tmp` が残る**（軽い）
   使う人が選んだフォルダに、知らないファイルが残る。同じ場所へ書き出し直せば上書きされると見ているが、別の場所へ書き出すと残り続ける。
   直し方の案：一時ファイルの名前を、何の物か分かる名前にする（例：`<名前>.zip.書きかけ`）か、次の起動で、前に書き出した場所に残った物を片付ける。

## Hub・VCC の入っていない PC でリンクを開く（2026-10-07 午前・LAN の別の PC）

Windows 11 の別の PC（Hub・VCC・ALCOM のアンインストール情報も `unityhub`・`vcc` のリンクの登録も無いことを、記録を読んで確かめた）へ SSH で確かめの道具 `ToolDetectProbe` を送り、ログオンしている人の画面で走らせた（予定の作業 `/IT`）。

- 見分け：Hub・VCC・ALCOM はどれも「無い」（`UnityTools.Detect` が全部 False）
- `Process.Start("unityhub://")`・`Process.Start("vcc://…")`（`UseShellExecute`）は**例外にならずに返る**（プロセスは無し）。画面には Windows の窓「アプリを取得してこの 'vcc' リンクを開く／お使いの PC には、このリンクを開くことができるアプリがありません。Microsoft Store で互換性のあるアプリをお探しください。」が出る
- つまり、受け手の無いリンクを開いても、アプリからは失敗に見えない。アプリのふつうの道は開く前に止まる：Unity を開くは Hub が無ければリンクを渡さない（`UnityLaunch` の `HasHub` の確かめ。結果 `NoEditorNoHub`）、VCC・ALCOM を開くはリンクでなく実行ファイルを開く（結果 `NotInstalled`）
- 使った物は確かめの道具だけで、終わったら相手の PC の置き場と予定の作業を消した
- 確かめていない物：Hub・VCC を入れた後に消した PC の残りかす（`UnityToolPresence` は記録の指す実行ファイルが在るかで見るので、残りかすでは「入っている」と見ない作り。試験で確かめてある）

## スマート アプリ コントロールの入った PC と、OneDrive の「オンラインのみ」の置き場（2026-10-07 午前・LAN の別の PC）

Windows 11 の別の PC（スマート アプリ コントロールが「オン」。`VerifiedAndReputablePolicyState` = 1）で、作り物の写し（台本 `small`）を使って確かめた。終わったら、送った物・写し・予定の作業・展開の置き場（`%TEMP%\.net\Chmonos`）を消した。

**スマート アプリ コントロール**
- DLL を分けた形（`dotnet publish` の既定）は止められる：`Chmonos.Core.dll` を「アプリケーション制御ポリシーによってこのファイルがブロックされました」で読めず、`App` の型の初期化で落ちる。**窓もログも出ずに消える**（起動の失敗の窓より前で落ちるため）
- 配布の形（`win-x64.pubxml`、実行ファイル1つ）は止められず、ふつうに起動した
- 作業用の小さな確かめの道具（実行ファイル1つ・署名なし）は、1つは通り、1つは止められた。止めるかは実行ファイルごとの評判で決まるようで、配布の形が通ったのも、この PC・この日の判定にすぎない（`docs/research/antivirus.md`「まだ打っていない手」のコード署名）

**OneDrive の「オンラインのみ」**（OneDrive の中に写しを置き、`attrib +U -P` で全49ファイルをオンラインのみにした）
- 起動：窓は 1.2 秒で出て、作り物の12件と絵が並ぶ。ログに失敗は無い
- 取り寄せられたのは、読む必要のあった物（商品の JSON・見えている絵・設定）だけ：49 のうち 22
- 設定の画面の保存先の容量：絵 140.6 KB / 24 ファイル、商品の記録 52.8 KB / 24 ファイル（手元の写しと合う）。OneDrive の印（再解析の印）をリンクと取り違えて「読めませんでした」にすることは無く、数えるときに取り寄せることも無い
- 確かめていない物：バックアップの書き出し（全部を読むので、全部を取り寄せるはず）・場所を変える・ネットの無いときのオンラインのみの読み込み

**確かめの最中の事故**：オンラインのみにする命令を、写しのフォルダでなく、その PC のユーザのフォルダ全体に掛けてしまった（SSH 越しの `cmd /c cd … && attrib … /s` で、`&&` が外側で切れた）。消えた物は無いが、その PC の OneDrive の中が全部オンラインのみになった。持ち主の了解を得て、そのまま続けた

### 続き：書き出し・取り寄せられないとき・場所を変える（同じ PC・配布の形・作り物の写し）

写しを毎回オンラインのみに戻してから確かめた。「取り寄せられない」は OneDrive を止めて作った（`OneDrive.exe /shutdown`。ネットを切ると SSH も切れるため）。ネットだけが切れて OneDrive が動いている形は確かめていない。

### Googleドライブ（この PC・ストリーミングの形・作り物の写し）と、文の直し

- Googleドライブの中のファイルは、OneDrive と違って印（再解析の印）が付かず、ふつうのファイルに見える。動いている間は、見分け・数え方・読み込み（12件）・書き出し（37ファイル）が手元の写しと同じ
- Googleドライブを終了すると、`G:` のドライブそのものが消える（「ダウンロードできない」ではなく「ドライブが無い」）
  - 動いている最中：設定を変えると「設定を保存できませんでした」の窓が出る（「ファイルかフォルダが見つかりません。…」）
  - ふつうの使い方（`location.json`）で起動し直すと「保存先が見つかりません」の窓。`CHMONOS_HOME` で起動したときだけは初回の窓（環境変数の保存先は「指定した側が作る」作りのため）
- 直した文（ユーザ判断 2026-10-07。Googleドライブなどを保存先にする人もいる）：
  - クラウドのファイルをダウンロードできない番号（`ERROR_CLOUD_FILE_*`）を見分け、「OneDriveなどのクラウドにあるファイルをダウンロードできませんでした。同期のアプリが動いているか、ネットにつながっているかを確かめてください。」
  - 「見つかりません」の文3つ（原因の見当・商品の記録が無いとき・起動のときの保存先）に、Googleドライブなどの同期のアプリが止まっている場合を足した
- 直した版を同じ別の PC で確かめようとしたら、**組み直した配布の形の `Chmonos.exe` が、スマート アプリ コントロールに止められた**（前の版は通った）。止めるかは組むたびの評判で決まるので、配布の形でも止められ得る。直した文は試験で確かめた
