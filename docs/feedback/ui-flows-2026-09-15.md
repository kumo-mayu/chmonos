# 操作の動線：画面と状態ごとの全部（2026-09-15）

> **要点**
> - **頼み**（ユーザ・原文）：「このまま操作動線を画面と状態ごとに全部洗い出してファイルに記録しておいてください。UI案練る時に使いたいです」「今回調べた例外や勝手に意図を無視する所も同じファイルで併記してください」。
>   前の頼み：「現在のユーザ動線を洗い出してツールがユーザの意図を無視した動作（アセットがない時に選択しようとすると勝手にインポートが走るなど。これはダイアログを出して確認すべき内容ですね）をする箇所や、そもそもユーザが意図した機能がその画面にない可能性がある箇所を細かく洗い出しておいてくれ。」
> - **何を書いたか**：画面ごとに「入り方」「状態（何によって何が出る・消える）」「操作（押す物 → 起きること → 移る先）」「出口」。問題のある所は **⚠番号** を付けて同じ行に書き、番号の一覧は最後の §17 にまとめた。
> - **方法**：コードを読んだだけ（画面では確かめていない）。XAML の全ボタン・右クリック・リンクの命令（`Command`）、状態で出し分ける所（`Visibility`）、画面の裏で受けるクリック・ドロップ・キー、ViewModel の命令の中身、画面を切り替える所（`Show*`）を突き合わせた。**書かれた時点の記録**なので、画面を直したら食い違う。
> - **記録のみ。**直すのはユーザが番号を指して頼んだものだけ（`open.md` の決め事）。

**記号**：`→ 画面` は移る先、`⟳` はその場（画面は移らない）、`?` は確認のダイアログを出す、`⚠A1` は §17 の問題の番号。
**重さ**（⚠）：高＝意図と違うことが起きる・取り返しがつかない、中＝戻せるが迷う・手間が増える、低＝揃っていない。

## 1. 検索（ナビ「検索」）

## 3. 編集（ナビ「編集」）

- **入り方**：ナビ（前回の続き、無ければユーザタグの無い商品を積む）・商品ページ「この商品を編集」・右クリック「編集に入る」・まとめて編集する・未確定「確定した分を編集へ送る」・統計・閉じるときの「移動する」。

| 場所 | 操作 → 起きること |
|---|---|

| 終えたとき | 検索へ戻る／ここに留まる |
| 右の頭 | 基本情報を直す（名前・ショップ・分類。候補を当てる）／星／ID をコピー／IDを変える |
| ユーザタグ | 候補付きの欄で足す・外す・小分類を足す・外す（保存するまで下書き） |

| 購入記録 | 自分用／貰った／贈った・＋ 追加購入・この記録を消す（下書きかは見ていない） |
