# PowerShell とスクリプトの落とし穴

確かめ・作り物のデータ・数えるためのスクリプトを書く前に読む。どれも**黙って違う結果を返す**種類で、実際に踏んだもの。

## 数える・配列

- `@($null).Count` は **1**。JSON の件数を数えるのに使うと嘘をつく。`items/` には説明の HTML も同じ数だけあるので、商品は `items/*.json` で数える
- 配列の配列を作ると、**要素が1つのときにほどけて文字列になる**（`,(...)` で包んでも、関数の戻りや `@()` でほどける）。
  文字の1つずつに `.ToUpperInvariant()` を呼んで落ちた。`[System.Collections.Generic.List[string[]]]` で持つ
- 配列の中の `$x - 6, 1` は `$x - (6, 1)` と読まれる。計算は括弧で囲む

## 名前

- 自作の関数に `Where`・`Measure`・`Clear` のような名前を付けると、既にある別名（`Where-Object`・`Measure-Object`・`Clear-Host`）とぶつかり、
  **黙って別の物が動く**（3回踏んだ）。`Loc`・`ClearBox` のように被らない名前にする

## JSON

- `ConvertTo-Json` は**空の配列を `null` にする**。アプリの読み込みが落ちる（作り物の `userTags.json` で0件表示になった）。
  作り物の JSON は文字列で組み立てるか、アプリが書いた JSON を写して書き換える
- 値はアプリが書く形に合わせる（購入の種類は `自分用`・`貰った`・`贈った`。`self` では取り直しが黙って失敗した）

## 環境変数・プロセス

- `$env:X = ''` としても、変数が空文字のまま子のプロセスに渡ることがある。消したい変数は、起動する側の環境（`ProcessStartInfo.Environment`）から取り除く
- この環境のシェルは `GIT_TERMINAL_PROMPT=0`・`GCM_INTERACTIVE=never` が最初から入っている。プッシュのときだけ上書きする（`wrap-up` スキル）

## 文字列を書き換える

- here-string を `git commit -m` に渡す書き方は壊れた。メッセージはファイルに書いて `git commit -F`
- `perl -pe` で C# を書き換えると、置き換え側の `\\n` が本物の改行になり、`` が `0001` になった。C# の文字列を含む置き換えは `Edit` で行う
- Python は入っていない（ストアへの案内が出るだけ）。一括の書き換えは `Edit`・`sed`・`perl`・PowerShell で行う
