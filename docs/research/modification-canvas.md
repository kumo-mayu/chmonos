# 改変とアセットを1枚にまとめるキャンバス — 実現方法の調査（2026-09-11）

ユーザのメモ：「ドラッグとテキスト入力でアバター改変とそのアセットを一枚にまとめれるキャンバス機能が気になっている。
どのようにしたら実現できそうかの調査をお願い」。**まだ作るかは決めていない。**判断材料を並べる。

---

## 1. 何が1枚に載るか

今の改変の記録（`docs/history/modifications.md`）が既に持っているものを、**並べ方を自由にして1枚に置く**ものと読んだ。

| 載るもの | 今どこにあるか | キャンバスで増えるもの |
|---|---|---|
| アバター | `ModificationRecord.AvatarItemId` | 置く場所 |
| 使ったアセット（衣装・ギミック…） | `Members`（並びが導入の順） | 置く場所・大きさ |
| 改変後の写真 | `Images`（`images/_mods/{ID}/`） | 置く場所・大きさ |
| 文字 | `Memo` が1つだけ | **付箋のような文字の塊をいくつでも** |

**新しく持つのは「どこに置いたか」と「文字の塊」だけ。**名前・サムネイル・ショップは商品IDから毎回引く
（CLAUDE.md「計算で出せる値をJSONに書かない」）。何を使ったかの正は今までどおり `Members` に置く。

## 2. 作り方の候補

| 方式 | 中身 | 依存 | 向いているもの |
|---|---|---|---|
| **A. WPF標準だけで組む** | `ItemsControl`＋`Canvas` を並べ場にし、ドラッグは `Thumb`、ズームとパンは `ScaleTransform`／`TranslateTransform`、書き出しは `RenderTargetBitmap` | **無し** | 1枚に数件〜数十件（改変1つの構成物はこの規模） |
| B. Nodify | WPF 用のノード編集部品。MVVM 前提、選択・ズーム・パン・端での自動スクロール、数百件でも軽い作り。**線でつなぐ**のが得意 | 1つ（MIT、NuGet `Nodify`） | 「この衣装にこのギミックを入れた」を**矢印でつなぎたい**とき |
| C. RichCanvas | ズーム・パン・無限スクロール・選択・ドラッグ付きの Canvas。MVVM 前提 | 1つ（MIT、3.0.0） | A の手間を省きたいとき |
| D. `InkCanvas`（WPF標準） | 手書きの線 | 無し | 丸で囲む・書き込むを足したいとき（A・B・C のどれにも重ねられる） |

**推し：A。**置くものは多くても数十件で、B・C が得意な「数百件を軽く」は要らない。
依存を足さずに済み、見た目も今の画面と同じ部品で揃う。**矢印でつなぎたいと分かったら B に移る**
（B は線が主役の部品なので、線が要らないなら持て余す）。

## 3. 操作の形

- **最初は自動で並べる。**開いた時点で空だと何から始めればよいか分からない。アバターを左上、
  構成物を導入の順に格子で並べ、写真を右に置く。触ったものだけ座標を覚える
- **ドラッグで動かす・角で大きさを変える。**格子に吸い付かせる（揃えるのが楽になる）
- **文字は空いた所をダブルクリックで足す**、そのまま打てる。IME の確定と Enter を取り違えないよう、
  改行は Enter、確定は外をクリック（候補入力の #36 と同じ落とし穴を避ける）
- **外から入れる：**写真はエクスプローラから落とす（今の改変の写真と同じ3経路）。
  商品は画面が差し替え式なので検索画面から直接は落とせない。**キャンバスの横に候補の欄**（構成物の一覧と検索）を置き、そこから落とす
- **書き出し：**PNG。`RenderTargetBitmap` で倍率を上げて書く。保存してある商品画像は長辺384px
  なので、大きく書き出すと粗くなる（設定で上げれば新しく取る分から効く）

## 4. 持ち方

改変のJSONに `board` を足す案。**1改変1ファイルの作法を崩さない。**

```jsonc
// modifications/mod-3f9c1b7e.json（足す分だけ）
"board": {
  "cards": [
    { "kind": "avatar", "x": 40,  "y": 40,  "width": 240 },
    { "kind": "member", "index": 0, "x": 320, "y": 40, "width": 180 },
    { "kind": "image",  "fileName": "user-3f9c1b7e.webp", "x": 760, "y": 40, "width": 360 },
    { "kind": "text",   "text": "袖の貫通はシェイプキーで直した", "x": 320, "y": 300, "width": 220 }
  ]
}
```

- 座標は整数の px。人が開いて読める・直せる
- 構成物は `Members` の何番目かで指す。**構成物を消したらカードも消える**（参照が切れたカードを残さない）
- `board` が無い改変は自動の並べ方で出す。**今ある改変の記録はそのまま読める**

## 5. 懸念

- **書き出した画像を人に見せるなら、出品者の画像を並べることになる。**「使用アセット」を画像で紹介するのは
  よく見かけるが、画像の扱いは出品者の規約しだい。書き出しでは「商品画像を入れない（名前とショップだけ）」を選べるようにし、
  入れるときは一言添える
- 改変は今のところ手元に1件しか無い。何十件になったときの一覧との行き来は測っていない
- ズームしたときの文字の滲み：WPF は拡大しても文字をベクターで描き直すので、書き出しの画像以外は問題にならない見込み（未確認）

## 6. 手間の見積もり（A の場合）

| 段 | 中身 | 見込み |
|---|---|---|
| 1 | 並べ場・ドラッグ・ズーム・パン・自動の並べ方 | 1.5日 |
| 2 | `board` の保存と読み込み（`SaveLocalAsync` と同じく自分の項目だけ書く） | 0.5日 |
| 3 | 文字の塊（足す・直す・消す） | 0.5日 |
| 4 | 候補の欄からのドラッグ、写真のドロップ | 1日 |
| 5 | PNG への書き出し（商品画像を入れる／入れない） | 0.5日 |

合わせて4日ほど。**先に experiments/ で段1だけの試作を作り、触ってから決める**のが安い。

## 7. 決めてほしいこと

1. **誰に見せる1枚か。**自分で見返すためか、人に見せる画像を作るためか（後者なら書き出しと §5 の配慮が主役になる）
2. **キャンバスに置いた商品は、改変の構成物にも足すか。**足すなら「置く＝使った」になり記録と揃う。足さないなら「参考に置いただけ」を表せる
3. **矢印や手書きは要るか。**要るなら B（Nodify）や D（`InkCanvas`）を足す
4. **1改変に1枚か。**改変をまたいで自由に並べるボードは、今の「改変」という単位の外になる（ワールドの改変を別にしたのと同じ判断）
