# 保存先の引越しとバックアップを数GBで通した（2026-10-01）

`open.md` の「引越し・バックアップ（E8）」に残っていた「実際に運ぶ確かめは未」を、作り物の約2GBで通した。
道具は `experiments/StoreTransferProbe`。画面の操作と同じく書き込みの門（`StoreWriteGate.HoldAsync`）を持って、
Core の `StoreMover.Move`・`BackupArchive.Export`・`BackupArchive.Restore` を呼ぶ。

**通していない所**：最後の `location.json` の書き換えと開き直し。`location.json` の置き場は `%LOCALAPPDATA%\Chmonos` に固定で
（`CHMONOS_HOME` では変わらない）、書くと本番の指す先が変わるため。そこは App の試験（`SettingsBackupJobTests` など）が小さな作り物で見ている。

## 作り物

実際の写しに大きさを合わせた。友人の写しは 207 件で約67MB・約2,900ファイル（画像 2,121枚・1枚 約17KB）。
数GBにするため件数を増やし、1枚を少し大きくした：8,000件 × 画像10枚（25KB・乱数）＋ 商品の JSON ＋ 10MB の添付20個。
**88,027ファイル・2.11GB**。中身は乱数なので、取り違えはハッシュの控えで拾える。

PC：C は NVMe の SSD、D は SATA の SSD。

## 結果（2回目の通し。1回目も同じ傾向）

| 段 | 時間 | メモリの山（作業セット） | 結果 |
|---|---|---|---|
| 引越し C→C | 86秒 | 152MB | 成功。元のファイルは全部消え、中身はハッシュまで一致 |
| 引越し C→D（ドライブをまたぐ） | 59秒 | 178MB | 同上 |
| 引越しを半分で止める | 33秒 | 151MB | 「中断しました。」で返り、元は無傷。**運ぶ先に 44,013ファイルが残る** |
| 止めた先へもう一度運ぶ | 81秒 | 173MB | 成功・一致（上書きで運び直せる） |
| 書き出し（画像なし） | 6秒 | 127MB | 8,027ファイル・0.20GB |
| 書き出し（画像あり） | 57〜61秒（下の注） | 149MB | 88,027ファイル・2.11GB・飛ばした0 |
| 戻す（→ C） | 66秒 | 195MB | 数・中身とも一致 |
| 戻す（→ D） | 52秒 | 207MB | 一致 |
| 書き出しを半分で止める | 29秒 | 168MB | 中止が返り、zip も書きかけ（.tmp）も残らない |
| 戻すを半分で止める | 33秒 | 175MB | 中止は返るが、**展開先に 44,014ファイルが残る**（画面には中止の口が無い） |

- メモリは 2GB を運んでも山で 200MB 前後。運ぶ量に比例して増えない
- 引越しは元の**根元のフォルダを残す**（中のファイルとサブフォルダは消す）。作りどおり（本番の根元には `location.json` も置かれる）。
  1回目の通しで NG に見えたのは、道具が「根元も消える」と期待していたため

### 書き出しが7倍遅くなる条件

画像ありの書き出しは、**書き込んだばかりのファイルを初めて読むと 410〜417秒**、もう一度読むと 57〜61秒だった。
通しの中では、直前の引越しで書いたフォルダを書き出すので毎回遅い。分けて測った（D の上で `robocopy` で写した直後に書き出す → 417秒、続けてもう一度 → 61秒）。

アプリの作りではなく、Windows がファイルを初めて開くときの処理と見ている（おそらくウイルス対策の検査）。**推測で、確かめていない。**
引越し・戻すの直後に書き出すと起こり得る。書き出しには進み具合の帯と「中止」があるので、固まったようには見えない。

## 見つけた物（直すかは判断待ち）

1. **引越しを止める・失敗すると、運ぶ先に途中までのコピーが残る。**次に同じ場所を選ぶと、画面はそれを既にあるライブラリと見て
   （`StoreLocation.LooksLikeStore`）「どちらのライブラリを残しますか」を出し、「選んだ場所のデータを使う」を押すと、
   **半分しか無いライブラリに切り替わる**（`SettingsViewModel.cs` の保存先を変える流れ）。止めたときの文は「保存先は元のままです。データは失われていません」で、
   元については正しいが、残ったコピーには触れていない
2. **戻すが途中で失敗すると、展開先に途中まで展開した物が残る。**画面に中止の口は無いので、起きるのはディスクが一杯などで失敗したとき。
   残った先は空ではないので、同じ場所へ戻し直すと「展開先が空ではありません」で断られる

どちらも、おすすめは「止めた・失敗したら、今回運んだ物を消す」。運ぶ先は空だったか、置き換えで元の物を退けた後なので、消すのは今回書いた物だけになる。
