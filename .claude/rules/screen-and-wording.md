# 画面と文言の決め事

画面に表示される文は、App の XAML・ViewModel だけでなく、Core の失敗の文（`CommandHandler`・`FailureText` など）からも来る。どちらを書くときもこの決め事に従う。

## 画面の作り

- 画面はタブではなく、同じウィンドウの中の差し替え。開くのは常に1つ。戻る（Alt+←・マウスの戻るボタン）は主画面が持つ画面の履歴で行う
- XAML・一覧・画面の部品を書く前に `docs/dev/wpf.md` を読む（暗黙の Button スタイル・DockPanel・一覧の作り直し・絵のメモリ）
- 画面の決まり（ナビ・窓・幅・キー）は `docs/spec/ui-rules.md`、窓の作法は `ui-dialogs.md`、入力は `ui-input.md`、空表示と失敗は `ui-empty-and-errors.md`

## 文言

画面の文を書く・直すときは、スキル `ui-wording` を使う。決まりは `docs/spec/ui-writing.md`（書き方）と `docs/spec/ui-terms.md`（語）。

- **1つの文言に載せるのは、その場でいちばん要ることを1つ**（何が起きるか・取り返しがつくか・次に何をするか。多くても2つ）
- **作り手の判断の理由・根拠の数字・経緯は画面に書かない。**コードのコメントは「なぜ」を書くが、画面の文には当てない
- **文の終わりの括弧の補足は使わない。**要るなら1文にし、要らないなら削る
- **長さ**：吹き出しは1〜2文・40字まで。本文は一文50字を目安に、80字まで
- **語は普通の Windows のソフトで見る語にする**（追加・ドロップ・コピー・表示・すべて）。新しい語は `ui-terms.md` に書き足してから使う
- 否定に読める言い方をしない。内部の言葉（item / appTag / BoothID / variation / マスタ）と .NET の例外の文は表示しない
- 取り返しのつかない操作には、取り返しがつくかを書く。空表示とエラーには、次にやることを書く
- 書いたら `node tools/wording.mjs --list --screen <画面>` で印を見る

## 入力欄には候補を付ける

候補を表示できるなら付ける（`Controls/SuggestBox`）。ユーザータグや属性は自分で作る語なので、表記が揺れる（「かわいい」「可愛い」）と、名前でつないだ絞り込みが分かれてしまう。
候補に無い語は「（新規）」の行として示し、選ばせる。

**例外：新しく名付けて作る欄には付けない**（共通素体・大分類・小分類（タグの管理）・属性を足す欄）。今ある名前を並べても重複を誘うだけなので、ふつうの入力欄にし、
今ある名前と同じなら「既にあります」と言う。
大分類・属性は左の検索欄と1本にし、欄の右に「追加」を置き、同じ名前なら欄の下に「既にあります」を出す（`ui-input.md`）。小分類（タグの管理）は丸い＋の右に伸びる欄と「追加」で、同じ名前なら欄の下に「既にあります」（メモ25 C）。候補を付けるのは今ある物を選ぶ欄（商品にタグ・属性・小分類を付ける、統合先など）。

候補を全部並べて選ばせる画面は作らない（件数に比例して縦に伸びる）。候補付きの入力欄から1件ずつ追加するか、折りたためるようにする。
