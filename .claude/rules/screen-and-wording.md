# 画面と文言の決め事

画面に出る文は App の XAML・ViewModel だけでなく、Core の失敗の文（`CommandHandler`・`FailureText` など）からも出る。どちらを書くときもこの決め事に従う。

## 画面の作り

- 画面はタブではなく、同じウィンドウの中の差し替え。開くのは常に1つ。戻る（Alt+←・マウスの戻るボタン）は主画面が持つ画面の履歴で行う
- XAML・一覧・画面の部品を書く前に `docs/dev/wpf.md` を読む（暗黙の Button スタイル・DockPanel・一覧の作り直し・絵のメモリ）
- 画面の決まり（ナビ・窓・幅・キー）は `docs/spec/ui-rules.md`、窓の作法は `ui-dialogs.md`、入力は `ui-input.md`、空表示と失敗は `ui-empty-and-errors.md`

## 文言

新しい語を持ち込む前に `docs/research/ui-wording.md` を見る。

- 否定に読める言い方をしない（「既にライブラリにある商品です」は「登録できない」に読めた）
- 内部の言葉を出さない（item / appTag / BoothID / variation / ハッシュ / マスタ。variation は画面では「バリエーション」）。.NET の例外の文（`exception.Message`）も画面に出さず、`FailureText.Cause` で原因の見当に言い換えて、中身はログへ書く
- 取り返しのつかない操作には、取り返しがつくかを書く
- 空表示とエラーには、次にやることを書く
- ボタンは押すと何が起きるかを名乗る（「BOOTHから取り直す」はダウンロードに読めた →「商品情報を取り直す」）。行き先がアプリの中か BOOTH かも分かるようにする

## 入力欄には候補を付ける

候補を出せるなら付ける（`Controls/SuggestBox`）。ユーザタグや属性は自分で作る語彙なので、表記の揺れ（「かわいい」「可愛い」）が起きると、名前でつないだ絞り込みが割れる。
候補に無い語は「新しく足す」と明示して選ばせる。

候補を全部並べて選ばせる画面は作らない（件数に比例して縦に伸びる）。候補付きの入力欄から1件ずつ積むか、畳めるようにする。
