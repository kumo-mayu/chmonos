# 画面の文言を書く・直す

決まりの本体は2つの spec にある。このスキルは、その決まりで文を書いて確かめる手順。

- 書き方（何を載せるか・長さ・要素ごとの型）：`docs/spec/ui-writing.md`
- 語（使う語・使わない語・揃える表記）：`docs/spec/ui-terms.md`
- 良い例と悪い例：同じフォルダの [examples.md](examples.md)

## 考え方

画面の文は**使う人が次に何をするか**のためにある。作り手が何を考えたかは docs に書く。

- 1つの文言に載せるのは、その場でいちばん要ることを1つ（何が起きるか・取り返しがつくか・次に何をするか。多くても2つ）
- 作り手の判断の理由・根拠の数字・経緯は書かない。コードのコメントには「なぜ」を書くが、画面の文は別
- 文の終わりの括弧の補足は使わない。要るなら1文にし、要らないなら削る
- 吹き出しは1〜2文・40字まで。本文は一文50字を目安に、80字まで
- 語は普通の Windows のソフトで見る語（追加・ドロップ・コピー・表示・すべて・「{n} 件」）

## 手順

### 1. 今の文を集める

```
node tools/wording.mjs --list --screen <画面>
```

画面の名前は、引数なしで回したときの「画面ごと」の表の左の列（「検索」「商品ページ」「設定・初回」など）。
印の意味は下の「印の読み方」。弱い印も見るときは `--weak`、1種類だけ見るときは `--flag 括弧の補足` のように付ける。
直す前の数を控えておく（`--json <scratchpad>/before.json` で全件を残せる）。

**済んだ印**：その画面の文と印の一覧が手元にある。

### 2. 1つずつ書き直す

文ごとに、次の順で考える。

1. **この文の置き場はどれか**（ボタン・見出し・吹き出し・窓・空表示・エラー・進み具合・知らせ）。型は `ui-writing.md`「要素ごとの型」、例は [examples.md](examples.md)
2. **この場でいちばん要ることは何か**を1つ決め、それ以外を削る。削った中に「正確さを落とさない」の4つ（下）があれば残す
3. **語を `ui-terms.md` に合わせる**。表に無い語を新しく使うなら、先に表に書き足す。迷ったら決めずに、選択肢と根拠をユーザに聞く
4. **声に出して読める長さか**を数える（吹き出し40字・一文80字）

作り手の理由が書いてあった文は、消す理由が docs にも無ければ、該当する `docs/spec/*.md` に移してから画面から消す。

**済んだ印**：その画面の強い印がすべて、直したか「直さない理由」を1行で言えるかのどちらか。

### 3. 正確さを落としていないか確かめる

直した文ごとに、前の文と並べて確かめる。

- **意味**：同じ操作・同じ結果を指しているか。言い換えで対象が広がったり狭まったりしていないか
- **取り返し**：「元に戻せません」、戻し方、「ファイルは削除しません」を落としていないか
- **通信とダウンロード**：BOOTH に問い合わせるか、ファイルをダウンロードするかを落としていないか
- **押せない理由と失敗の原因**：使う人の次の手を決める情報を落としていないか

**済んだ印**：直した文すべてで4つとも「はい」。

### 4. 数を測り直す

```
node tools/wording.mjs
```

手順1で控えた数と比べ、画面ごと・印ごとに減った数を報告に書く。

### 5. 画面で通して読む

文は1つずつ読むと良くても、並ぶと長い・同じことを2回言っている、が分かる。
`ui-check` スキルで、その画面に合った写しの保存先で起動し、直した所を撮って**画面の上で通して読む**。
吹き出しは乗せて表示させてから撮る。はみ出し・折り返しの崩れもここで見る。

**済んだ印**：直した画面を撮った画像を見て、文が切れず、同じことを2回言っている所が無い。

## 印の読み方

`tools/wording.mjs` の印は見直しのきっかけで、正解ではない。意味が違う使い方にも当たる。

| 印 | 強さ | 何を見ている |
|---|---|---|
| 括弧の補足 | 強 | 文の終わりの「（…）」。数やキーだけの括弧は数えない |
| 使わない語:○○ | 強 | `ui-terms.md`「使わない語」の探す形に当たった |
| 揺れ:○○ | 強 | `ui-terms.md`「揃える表記」の揃える前の形 |
| 吹き出し40字超 | 強 | 吹き出しの字数（置き換える値は2文字と数える） |
| 一文80字超 | 強 | 吹き出し以外の、句点か改行で区切った1文 |
| 吹き出しに理由 | 強 | 吹き出しの「〜ので」「〜ため」「前は」。押せない理由は書いてよいので、読んで残すことが多い |
| Markdown | 強 | `**`・`` ` ``・行頭の `#` |
| 件の空白 | 強 | 「{n}件」（「{n} 件」にする） |
| 内部語 | 強 | item・appTag・BoothID・variation・マスタ など |
| 一文50字超 | 弱 | 目安の50字を超えた |
| 理由（本文） | 弱 | 本文の「〜ので」「〜ため」「前は」。作り手の理由なら削る |
| 否定・取り返し・次の行動 | 弱 | 否定だけで終わる文、削除の文に戻せるかが無い、空表示に次の手が無い |

「まだ決めていない揺れ」（Unity 側／Unity側・フォルダ／フォルダー など）は数だけ出る。標準はユーザが決める。

## 道具の中身を変えるとき

- 語を加える・直すのは `ui-terms.md` の表だけでよい（道具が表を読む）。探す形は JavaScript の正規表現で、表の中の `|` は `\|` と書く
- 画面に出ない文（ログ・例外・辞書の語の表）を集めてしまうときは、`tools/wording.mjs` の除くファイルと除く行の決まりを直す
- 依存を足さない（素の Node で動かす）
