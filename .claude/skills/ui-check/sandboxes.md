# 写しの保存先（サンドボックス）

どれも `%LOCALAPPDATA%\` の下。2026-10-01 に `%LOCALAPPDATA%\BoothAssetManager-<名前>` から `%LOCALAPPDATA%\Chmonos-sandboxes\<名前>` へ移した。場所は `CHMONOS_HOME` で渡す。
`Start-ChmonosApp -Store <名前>` で起動する（例：`-Store tagcheck`）。

## 画面ごとの既定

ビルドが通ったら、直した画面を確かめられる写しで**起動したままにする**（ユーザ指示 2026-09-18「ビルドしたらとりあえず確認できるデータで起動するようにしてほしい」）。

| 直した画面 | 写し |
|---|---|
| 通知（種類ごとの並び・件数） | `noticheck` |
| 通知・商品ページの「変わった行」（足した行・消した行・名前・価格・販売終了） | 台本 `notices` で自分の写しを作る（作り物だけ。例 `noticeline`） |
| タグの管理 | `tagcheck` |
| 属性の管理 | `attrcheck` |
| BOOTH の形式の変化の帯 | `structcheck` |
| アバター・一般の画面 | `friendcheck` |
| 商品ページ | `ui`（同じ中身が複数の場所にある行は `filecheck`） |
| 本番に近い少ない件数で見たいとき | `ui` |
| 改変・Unity へ送る | `d1check` |
| 取り込み・未確定・ファイルを移したとき・大容量 | 台本から自分の写しを作る（下の「台本から作る写し」） |

見るべきデータが無ければ、写しを作って作り物を入れる（下の「作り物の作り方」）。
**書き込む確かめは、先に `Backup-ChmonosSandbox`、終わったら `Restore-ChmonosSandbox -Done`**（写しの説明と中身がずれるのを防ぐ）。

## 台本から作る写し

作り物のデータだけで作れる写しは、台本から作る。**壊しても作り直せるので、確かめごとに自分の写しを作ってよい**（名前は担当や用件で。並行のときに写しを取り合わない）。

```powershell
New-ChmonosSandbox -Name mycheck -Recipe movecheck      # 台本の一覧は Get-ChmonosRecipes
```

| 台本 | 入る物 | 掛かる時間（実測） |
|---|---|---|
| `small` | 作り物の商品 12 件（絵つき・分類5種類・ショップ3つ） | 4 秒 |
| `many` | 作り物の商品 2000 件（`-Items` で変える）。絵 約4千枚・27 MB | 12 秒 |
| `manage` | `many` に、ユーザータグ（大分類20×小分類10）・属性20・知らせ1000・改変300 | 300 件で 9 秒 |
| `movecheck` | 商品 10 件＋「BOOTHに無い商品」4 件（3 件にタグとメモ）＋未確定 6 件（束が2つ：ばらのファイル・展開元の記録の付いたフォルダ）。取り込み元 2・監視 3（`使った`・`次使う`・`外`）。`-Full` で大きい zip が 400 MB | 5 秒（`-Full` は 7 秒） |
| `notices` | 商品 12 件（絵つき）＋商品ページの変化の知らせ 7 件（商品7件ぶん。変わった行を持つのは 5 件：同じ見出しの行の足し・消し・書き換え／見出しごとの足し・消し／見出しの無い説明文／同じ商品への3版続き。名前と価格・販売終了・種類の増加だけの知らせも出る）。**知らせはアプリの取り直し（`ItemService.RefreshAsync`）に台本どおりの商品ページを返して作る**（JSON を手で組まない）。台本は `tools/SandboxGen/ChangeScriptData.cs` | 3 秒 |
| `bigcheck` | 商品 10 件（2 件に大きな zip）＋未確定 約5千件（ばら 5000・件数の多い zip・unitypackage 入りの zip・壊れた zip 2）。`-Full` で ばら 8万・4.8 GB と 2.3 GB の zip・7万件の zip・1 GB の unitypackage（未確定 約8万件・作り物 8.2 GB） | 11 秒（`-Full` は 2 分半。うち取り込みは 26 秒） |

- 中身を書くのは `tools/SandboxGen`（アプリと同じ道＝`DataStore`・`CommandHandler`・取り込みそのもので書く。JSON を手で組まない）。
  データの形が変わっても、作り直せば新しい形になる。
- **BOOTH へは問い合わせない**（取り込みに、つながらない相手を渡す。呼ばれたら回数を出す）。裏の取得と起動時の取り込みは切ってある（並行で起動できる）。
- 商品の番号は 9000 万番台・URL は `example.invalid`。作り物の番号は BOOTH に無いので、**この写しで裏の取得を入れたり、商品の取り直しを押したりしない**

- `many`・`manage` は `stress-realcat`・`stress-manage` の代わりにはならない（説明が短く、絵が軽い）。**速さとメモリの数字は `stress-realcat` で測る。**

## 作り物の作り方

1. 写しを作る：台本（上）か、`New-ChmonosSandbox -From <元> -Name <新しい名前>`（**先にフォルダを作る**。無いフォルダで起動すると「保存先が見つかりません」が出て、「はい」は本番を開く）。
2. 作り物は写しの中だけに置く。本番・`friendtest` には入れない。
3. 作り物のファイル（大きな zip・件数の多い zip・壊れた zip・ばらのファイル・unitypackage・ダウンロード元の記録・読めないフォルダ）は `fixtures.ps1`（[tools.md](tools.md)）。
   取り込むのは `Invoke-ChmonosImport`（画面から）か、`SandboxGen.exe <保存先> scan <フォルダ>`（画面なし・BOOTH へ問い合わせない）。
4. JSON を手で足すときは、PowerShell の `ConvertTo-Json` で作らない。**空の配列が `null` になり**、読み込みで落ちる（`userTags.json` で 0件表示になった）。文字列を組み立てるか、既にある JSON を写して書き換える。
5. 値はアプリが書く形に合わせる。購入の種類は日本語（`自分用`・`貰った`・`贈った`）。`self` と書くと取り直しが黙って失敗した。
6. 作り物を入れたら、この表に1行足す。確かめで書き換えたら、戻す（`Restore-ChmonosSandbox`）か、表を直す。
